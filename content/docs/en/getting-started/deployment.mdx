This guide covers the most common ways to run Aleph in production — from a simple foreground process to a fully managed system service, plus reverse-proxy TLS termination.

## Local Development

The simplest way to run Aleph is straight from the command line:

```bash
# Foreground (Ctrl+C to stop)
cargo run --bin aleph-server

# Or use just
just dev
```

The gateway listens on `ws://127.0.0.1:18790` by default.

### As a System Service (the `service` subcommand)

`aleph-server` ships with a `service` subcommand for one-shot install:

```bash
# Install + start (launchd / systemd-user / Task Scheduler)
aleph-server service install
aleph-server service start

# Status / enable auto-start / uninstall
aleph-server service status
aleph-server service enable
aleph-server service uninstall
```

`service install` writes `~/Library/LaunchAgents/com.aleph.daemon.plist` on macOS, `~/.config/systemd/user/aleph.service` on Linux, and registers a Task Scheduler task on Windows. Launch-at-login is the default out of the box.

## macOS — launchd Service

If you'd rather hand-roll the plist (same output as `service install`):

### Create the plist

Create `~/Library/LaunchAgents/com.aleph.daemon.plist`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>Label</key>
    <string>com.aleph.daemon</string>
    <key>RunAtLoad</key>
    <true/>
    <key>KeepAlive</key>
    <true/>
    <key>ProgramArguments</key>
    <array>
        <string>/usr/local/bin/aleph-server</string>
        <string>start</string>
    </array>
    <key>EnvironmentVariables</key>
    <dict>
        <key>RUST_LOG</key>
        <string>info</string>
    </dict>
    <key>StandardOutPath</key>
    <string>/Users/YOUR_USERNAME/.aleph/logs/aleph.log</string>
    <key>StandardErrorPath</key>
    <string>/Users/YOUR_USERNAME/.aleph/logs/aleph-error.log</string>
</dict>
</plist>
```

### Manage the Service

```bash
launchctl load ~/Library/LaunchAgents/com.aleph.daemon.plist
launchctl start com.aleph.daemon
launchctl list | grep com.aleph
launchctl stop com.aleph.daemon
launchctl unload ~/Library/LaunchAgents/com.aleph.daemon.plist
```

## Linux — systemd Service

```bash
mkdir -p ~/.config/systemd/user
```

```ini title="~/.config/systemd/user/aleph.service"
[Unit]
Description=Aleph AI Assistant Gateway
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
ExecStart=%h/.cargo/bin/aleph-server start
Restart=on-failure
RestartSec=5
Environment=ALEPH_HOME=%h/.aleph
Environment=RUST_LOG=info

# Resource limits
MemoryMax=1G
MemoryHigh=512M
CPUQuota=80%

# Security hardening
NoNewPrivileges=true
ProtectHome=read-only
ReadWritePaths=%h/.aleph

StandardOutput=journal
StandardError=journal

[Install]
WantedBy=default.target
```

```bash
systemctl --user daemon-reload
systemctl --user enable aleph
systemctl --user start aleph
systemctl --user status aleph
sudo loginctl enable-linger $USER
journalctl --user -u aleph -f
```

## Docker Deployment

### Dockerfile

```dockerfile title="Dockerfile"
FROM rust:1.95-bookworm AS builder

WORKDIR /build
COPY . .

RUN cargo install wasm-bindgen-cli
RUN apt-get update && apt-get install -y npm

RUN cargo build -p alephcore --bin aleph-server --release

FROM debian:bookworm-slim

RUN apt-get update && apt-get install -y \
    ca-certificates \
    libsqlite3-0 \
    && rm -rf /var/lib/apt/lists/*

COPY --from=builder /build/target/release/aleph-server /usr/local/bin/aleph-server

RUN useradd -m -s /bin/bash aleph
USER aleph

RUN mkdir -p /home/aleph/.aleph/logs

EXPOSE 18790

ENTRYPOINT ["aleph-server"]
```

### Docker Compose

```yaml title="docker-compose.yml"
services:
  aleph:
    build: .
    container_name: aleph
    restart: unless-stopped
    ports:
      - "127.0.0.1:18790:18790"
    volumes:
      - aleph-data:/home/aleph/.aleph
    environment:
      - ANTHROPIC_API_KEY=${ANTHROPIC_API_KEY}
      - RUST_LOG=info

volumes:
  aleph-data:
```

```bash
echo "ANTHROPIC_API_KEY=sk-ant-..." > .env
docker compose up -d
docker compose logs -f aleph
```

## Environment Variables

| Variable | Description | Default |
|----------|-------------|---------|
| `ANTHROPIC_API_KEY` | Anthropic API key | — |
| `OPENAI_API_KEY` | OpenAI API key | — |
| `GOOGLE_AI_API_KEY` | Google AI API key | — |
| `OPENROUTER_API_KEY` | OpenRouter API key | — |
| `ALEPH_HOME` | Override config directory | `~/.aleph` |
| `ALEPH_MASTER_KEY` | Master key for the secrets vault | — |
| `RUST_LOG` | Log level (`trace`/`debug`/`info`/`warn`/`error`) | `info` |

API keys can also be set in the config file. Environment variables take precedence.

## Reverse Proxy

If you expose Aleph on a network, put it behind a reverse proxy for TLS termination and access control. The gateway uses WebSocket, so make sure your proxy supports WebSocket upgrades.

> **Real client IP**: when behind a reverse proxy, list the proxy in `[gateway] trusted_proxy` so the gateway resolves the real client IP (capacity limits, rate limits, audit, and connect-auth all depend on it). See [Gateway Protocol](/docs/en/gateway/protocol#trusted-proxy--real-client-ip).

### Nginx

```nginx title="/etc/nginx/sites-available/aleph"
upstream aleph_gateway {
    server 127.0.0.1:18790;
}

server {
    listen 443 ssl http2;
    server_name aleph.example.com;

    ssl_certificate     /etc/letsencrypt/live/aleph.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/aleph.example.com/privkey.pem;

    location / {
        proxy_pass http://aleph_gateway;
        proxy_http_version 1.1;

        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        proxy_read_timeout 86400s;
        proxy_send_timeout 86400s;
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/aleph /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

### Caddy

```txt title="Caddyfile"
aleph.example.com {
    reverse_proxy 127.0.0.1:18790
}
```

Caddy auto-handles TLS and WebSocket upgrades — no extra config.

```bash
sudo caddy reload --config /etc/caddy/Caddyfile
```

## Self-Signed TLS (No Reverse Proxy)

Aleph can also terminate TLS in-process, without a reverse proxy:

```toml
[gateway]
port = 18790
bind = "0.0.0.0"

[gateway.tls]
# cert + key left empty → auto-generate a self-signed cert
# SAN auto-discovers the host's non-loopback interface IPs; atomic regen on drift
# cert = "/etc/letsencrypt/live/aleph.example.com/fullchain.pem"
# key  = "/etc/letsencrypt/live/aleph.example.com/privkey.pem"
```

Once configured, the gateway listens on `wss://`; remote clients see a TOFU (fingerprint + SAN) approval prompt in the Panel on first connect, and the trust is pinned locally.

> **Fail-closed by default**: on non-loopback binds, TLS defaults on and plaintext is refused. When `allow_insecure_remote = false`, the gateway refuses plaintext connections from remote clients.

## HTTPS and TLS

- **Reverse proxy**: handles certificate renewal; lets you serve other services on the same host — the right choice for most deployments
- **Native self-signed**: best for internal / Tailnet / VPN; zero infrastructure deps
- **User-supplied cert**: if you already have an enterprise CA cert, just point `cert` + `key` at it

## Monitoring and Health Checks

### Health Endpoint

```bash
curl http://localhost:18790/health
# HTTP 200 + status info
```

Use this endpoint in Docker Compose, systemd, or your monitoring tools.

### Log Rotation

systemd's journald handles rotation automatically. Aleph itself also supports day-boundary auto-rotation (tune in `[logging]`). For other deployments, configure logrotate:

```txt title="/etc/logrotate.d/aleph"
/home/aleph/.aleph/logs/*.log {
    daily
    rotate 14
    compress
    delaycompress
    missingok
    notifempty
}
```

## Backup Strategy

Critical data lives under `~/.aleph/`:

| Path | Contents | Priority |
|------|----------|----------|
| `aleph.toml` | All configuration | High |
| `memory/` | Memory database + notes | High |
| `sessions/` | Session database | Medium |
| `plugins/` | Installed plugins | Low (re-installable) |
| `artifacts/` | Artifact store (deliverables) | Medium |
| `ops.log` | Signed operation ledger | High |
| `logs/` | Application logs | Low |

```bash
# Daily backup of config + sessions
0 3 * * * tar -czf ~/backups/aleph-$(date +\%Y\%m\%d).tar.gz \
    ~/.aleph/aleph.toml \
    ~/.aleph/memory/ \
    ~/.aleph/sessions/
```

## Security Checklist

Before exposing Aleph on a network:

- [ ] **Bind address** — keep `gateway.bind = "127.0.0.1"` unless you need external access
- [ ] **Authentication** — enable `gateway.require_auth = true`
- [ ] **TLS** — always use `wss://` for remote access (self-signed + TOFU, or reverse proxy)
- [ ] **Firewall** — only open 443 (via reverse proxy), never expose 18790 directly
- [ ] **Master key** — set `ALEPH_MASTER_KEY` to encrypt the secrets vault
- [ ] **Allowlists** — configure `channels.telegram.allow_from` / `channels.discord.allow_guilds` to limit access
- [ ] **Exec tier** — default `ask`; keep `ask` for remote clients
- [ ] **Signed ledger** — enable `agents.signing_keys = true` for replay-verifiable operations
