Get Aleph running in 5 minutes.

## Option 1: Desktop App (Fastest)

Download the latest version for your platform:

| Platform | Download |
|------|------|
| **macOS** | `.dmg` from [GitHub Releases](https://github.com/rootazero/Aleph/releases) |
| **Linux** | `.deb` or `.AppImage` from [GitHub Releases](https://github.com/rootazero/Aleph/releases) |
| **Windows** | `.msi` from [GitHub Releases](https://github.com/rootazero/Aleph/releases) |

1. Install and launch the app
2. Complete the setup wizard (API keys, model selection, **session mode**, **exec tier**, **TLS**)
3. Start chatting

The desktop app bundles the core server as a background daemon. The shell lives in your system tray; closing the window **doesn't** stop the server.

**Global hotkey:** `CmdOrCtrl+Shift+A` summons the window from anywhere.

### Connecting to a Remote Core

The desktop shell can connect to a remote `aleph-server` over Tailnet or VPN — **only** when the remote core uses self-signed TLS (SAN auto-discovers the host's non-loopback interface IPs; the Panel prompts TOFU fingerprint + SAN approval on first connect).

```bash
# On the remote machine, enable self-signed TLS
aleph-server start \
  --gateway-bind 0.0.0.0 \
  --gateway-port 18790 \
  --gateway-tls-auto-cert
```

Then in the local shell, enter `wss://remote-host:18790` and approve the TOFU prompt.

## Option 2: From Source (Development)

### 1. Build & Run

```bash
# Clone the repo
git clone https://github.com/rootazero/Aleph.git
cd Aleph

# Run in dev mode (auto-rebuilds WASM)
just dev

# Or build & run manually
cargo run --bin aleph-server
```

The server starts on `ws://127.0.0.1:18790` by default.

### 2. Configure

Create `~/.aleph/aleph.toml`:

```bash
mkdir -p ~/.aleph
cat > ~/.aleph/aleph.toml << 'EOF'
[agents.defaults]
model = "anthropic/claude-sonnet-4"
thinking = "medium"
session_mode = "work"
exec_tier = "ask"

[provider.claude]
protocol = "anthropic"
api_key = "${ANTHROPIC_API_KEY}"

[gateway]
port = 18790
bind = "127.0.0.1"
EOF
```

Set your API key:

```bash
export ANTHROPIC_API_KEY="sk-ant-..."
```

### 3. Connect via WebChat

Open `http://localhost:18790` in a browser (or whatever port `gateway.port` is set to).

WebChat is a WASM-based UI that connects to the Gateway WebSocket.

### 4. Connect Messaging Channels (optional)

#### Telegram

Add to `~/.aleph/aleph.toml`:

```toml
[channels.telegram]
enabled = true
token = "YOUR_BOT_TOKEN"
```

Restart the server to pick up the new channel.

#### Discord

```toml
[channels.discord]
enabled = true
token = "YOUR_BOT_TOKEN"
```

#### iMessage (BlueBubbles)

```toml
[channels.imessage]
enabled = true
server_url = "http://127.0.0.1:1234"
password = "${BLUEBUBBLES_PASSWORD}"
```

### 5. Verify

Check that the server is running:

```bash
# Server log shows "Gateway listening on ws://127.0.0.1:18790"
tail -f ~/.aleph/logs/aleph.log

# Or query the RPC endpoint
curl http://localhost:18790/health
```

### 6. Session Mode and Exec Tier

After WebChat opens, switch **session mode** (chat / work / code) and **exec tier** (Ask / Auto / Full) in the top-right. You can also set global defaults in Settings → Policies.

## Architecture at a Glance

> **One core, many channels, shell-core separation, gateway interop, access control; three user-adjustable axes: exec_tier × thinking × session_mode.**

- **One core** (`aleph-server`) drives every interface
- **Shells** (desktop app) = pure OS integration; **core** = all business logic
- Every terminal uses the same authenticated WebSocket protocol
- The desktop shell can connect to a local or remote core (remote must use `wss://` + TOFU)
- Three user-adjustable axes: `exec_tier` (permissions) / `thinking` (inference) / `session_mode` (tool presentation)
