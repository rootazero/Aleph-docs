The resilience system is Aleph's persistence and state layer. After the agent-loop migration, `src/resilience/` only retains the **database layer (`StateDatabase`) and shared types** — governance, collaboration, perception, and recovery middleware have been removed; higher-level recovery is now orchestrated by the harness in `src/agents/` together with the gateway event bus.

> `src/resilience/mod.rs` after the 26.7.x migration only exports `database` and `types`:
> ```
> pub mod database;
> pub mod types;
> ```
> The historical `recovery/`, `collaboration/`, and shadow-replay submodules no longer exist. Their responsibilities now live in `src/agents/swarm/tasks/`, `src/harness/trace.rs`, and `src/gateway/event_bus.rs`.

## StateDatabase

`StateDatabase` is the persistence backbone of the resilience system. SQLite via `rusqlite`:

| Table / entity | Purpose | Key fields |
|---|---|---|
| **AgentTask** | Task state + recovery metadata | `id`, `status`, `risk_level`, `lane`, `checkpoint_snapshot_path` |
| **TaskTrace** | Shadow Replay execution trace | `task_id`, `step_index`, `event`, `timestamp` |
| **group_chat** | Group-chat history | per-team persistence |
| **memory_events** | Memory-system events | write log |
| **paired_users** | Paired-user records | pairing |
| **channel_offsets** | Channel read offsets | webhook / event-source resync |

`aggregate_usage_by_agents` folds stored trace usage into `AgentUsageTotal` rows (`src/resilience/database/traces.rs`). The team snapshot uses this aggregation for its member agents.

### Event durability

Current session events choose their write mode through `durability_of` in `src/session/events.rs`. Memory events are written separately through `src/resilience/database/memory_events.rs`.

### `AgentTask`

```rust
pub struct AgentTask {
    pub id: String,
    pub parent_session_id: String,
    pub agent_id: String,              // "explorer" / "coder" / …
    pub task_prompt: String,
    pub status: TaskStatus,
    pub risk_level: RiskLevel,
    pub lane: Lane,
    pub checkpoint_snapshot_path: Option<String>,
    pub last_tool_call_id: Option<String>,
    pub recursion_depth: u32,
    pub parent_task_id: Option<String>,
    pub created_at: i64,
    pub updated_at: i64,
    pub started_at: Option<i64>,
    pub completed_at: Option<i64>,
    pub metadata_json: Option<String>,
}
```

Helpers: `AgentTask::new` (defaults: `Pending` + `Subagent` lane), `with_parent_task` (recursion depth), `with_lane`, `should_auto_resume` (only `RiskLevel::Low`), `needs_resume_confirmation` (only `RiskLevel::High`).

### `TaskStatus`

```rust
#[serde(rename_all = "snake_case")]
pub enum TaskStatus {
    Pending,
    Running,
    Completed,
    Failed,
    Interrupted,   // system shutdown during execution
    Idle,          // Session-as-a-Service pause
    Swapped,       // context swapped to disk
}

impl TaskStatus {
    pub const fn is_recoverable(&self) -> bool {
        matches!(self, Self::Running | Self::Interrupted)
    }
}
```

### `RiskLevel`

```rust
pub enum RiskLevel { Low, High }
```

- `Low` — read-only operations; safe to auto-resume on restart
- `High` — write operations; requires user confirmation

### `Lane`

```rust
pub enum Lane { Main, Subagent }
```

- `Main` — user interactions, abort commands (high priority)
- `Subagent` — background work (normal priority)

The Main lane is never starved by subagent work. User-facing requests (conversation, abort commands) always get priority scheduling.

### `TaskTrace`

```rust
pub struct TaskTrace {
    pub id: i64,                // assigned by the database
    pub task_id: String,
    pub step_index: u32,        // 0-based
    pub event: AgentTraceEvent, // from aleph_protocol
    pub timestamp: i64,
}

impl TaskTrace {
    pub fn new(task_id, step_index, event) -> Self;
    pub fn with_timestamp(self, ts: i64) -> Self;   // override the wall-clock stamp; for ordered fixtures
    pub const fn event_kind(&self) -> &'static str;
}
```

`AgentTraceEvent` comes from the `aleph_protocol` crate (unified protocol); `task_id` and `step_index` are written by the dispatcher; `event_kind()` returns a stable string for indexing and filtering.

## Shadow Replay & state recovery

### State machine

```
                 ┌──────────┐
                 │ Pending  │
                 └────┬─────┘
                      │ start
                 ┌────▼─────┐
         ┌──────│ Running  │──────┐
         │      └────┬─────┘      │
     SIGTERM       │        │   error
         │         │ success │     │
     ┌────▼──────┐  │  ┌────▼────┐ │
     │Interrupted│  │  │Completed│ │
     └───────────┘  │  └─────────┘ │
                    │              │
                    └─► Failed ◄───┘
```

`is_recoverable()` is true only for `Running` and `Interrupted` — those two statuses drive recovery decisions combined with `RiskLevel` and trace availability.

### Decision logic (orchestrated by `agents/swarm/tasks/` + `harness/trace.rs`)

```
For each task where status = Running | Interrupted:
    │
    ├── No traces available?
    │   └── Skip ("no execution traces available")
    │
    ├── RiskLevel::Low?
    │   └── AutoResume (Shadow Replay + continue)
    │
    └── RiskLevel::High?
        └── PendingConfirmation (wait for user approval)
```

Read-only operations (file search, code analysis) are safe to retry automatically; write operations (file modification, shell commands) need human confirmation because the system state may have changed since the interrupt.

## Trace data flow

```
Execution: every step produces a LoopTraceEvent
    │
    ▼
harness::trace::TraceSink::on_trace (src/harness/trace_sink.rs)
    │
    ▼
GatewayTraceSink → TraceFlushHandle → TracePersistence::record
(src/gateway/execution_engine/trace_sink_adapter.rs, callback.rs)
    │
    ▼
task_traces table (INSERT at src/resilience/database/traces.rs:133,
schema at src/resilience/database/state_database/schema.rs:261)
```

A `TraceSink` implementation **must not block**: the sink is invoked from the harness's async tasks, so blocking there back-pressures the entire harness loop. The production path uses `GatewayTraceSink`, which forwards synchronously into `TracePersistence::record`; that layer spawns one write task per event and keeps its handle for `flush`, so the harness-side call never blocks.

Unattended runs take a different sink, `UnattendedRedactingSink` (`src/gateway/execution_engine/unattended_redacting_sink.rs`): masking happens **once, at the producer**, so `task_traces` rows, channel messages and the WS `agent_trace` mirror all carry the same already-masked content. Replay is done by the trace replay handler (`src/gateway/handlers/trace_replay.rs`), which reads the `task_traces` table and nothing else.

`LoopTraceEvent::SessionCompleted` (`src/harness/trace.rs:59`) is the structured fact for "a run ended": `outcome` / `iterations` / `tool_calls_made` / `total_tokens` / `hit_limit` / `final_text` / `terminate_reason` (`src/orchestrator::dispatch::TerminateReason`, the precise loop-exit cause). Usage aggregation scans the `task_traces` rows whose `event_kind = 'provider_usage'` directly (`aggregate_usage_by_agents`, `src/resilience/database/traces.rs:298`) — there is no separate statistics table.

## Fail-closed

For action-aware policy, an absent file uses the curated built-in defaults; an unreadable, oversized, or malformed file makes every action require approval (`ConfigApprovalPolicy::load_from`, `src/approval/config.rs`). The deterministic completion detector was removed as inconsistent with R10. Hard stops are now bounded by `max_iterations`, the tool-loop verifier, and the model’s own stop.

## Historical: resilience event tiers

The old `AgentEvent` table used `is_structural` to distinguish state-transition records written immediately from streaming pulses that could be batched. Commit `75345d2ae` retired that unused agent-event schema; it did not remove session-event or memory-event persistence.
