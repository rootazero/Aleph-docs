This guide covers everything you need to compile Aleph from source, from installing the Rust toolchain to producing optimized release binaries.

## Prerequisites

### Rust Toolchain

Aleph requires **Rust 1.99 or later** (edition 2021, `Cargo.toml`). `rust-toolchain.toml` pins the toolchain to `1.99.1`. Install with [rustup](https://rustup.rs/):

```bash
# Install Rust (if not already installed)
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

# Accept the rust-toolchain.toml pin
rustup show

# Verify the version
rustc --version   # must be >= 1.99
cargo --version
```

If you plan to build the **Control Plane UI** (the embedded web dashboard), you also need the WASM target:

```bash
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli
```

### System Dependencies

See `Cargo.toml` for the core crate's `rusqlite` and `reqwest` features, and `justfile` and `interfaces/webchat/package.json` for the Panel CSS build.

| Dependency | Purpose | Notes |
|------------|---------|-------|
| **SQLite** | Session storage, memory DB | Bundled via `rusqlite` `bundled` feature — no system install needed |
| **OpenSSL** | TLS for HTTP clients | The Linux CI build installs `libssl-dev` (`.github/workflows/aleph-core-ci.yml`). On Fedora, use `openssl-devel`. |
| **pkg-config** | Locating system libraries | Linux only: `apt install pkg-config` or `dnf install pkgconf` |
| **C compiler** | Native dependency compilation | Xcode Command Line Tools (macOS) or `build-essential` (Linux) |
| **Node.js + npm** | Panel CSS build | `just wasm` runs `npm run build:css` |

On **macOS**, install the Xcode Command Line Tools for the native compiler. For the CI package list, see `.github/workflows/aleph-core-ci.yml`:

```bash
xcode-select --install
```

On **Debian/Ubuntu**, install the base toolchain packages below. Check `.github/workflows/aleph-core-ci.yml` for additional native libraries used by the workspace:

```bash
sudo apt update
sudo apt install build-essential pkg-config libssl-dev
```

### Environment Variables

If your runtime configuration needs an Anthropic API key, set the environment variable below. The build does not need it (`src/gateway/provider_factory.rs`):

```bash
# Set in your shell
export ANTHROPIC_API_KEY="your-api-key"
```

## Workspace Structure

This excerpt shows the workspace layout defined in `Cargo.toml`, along with the root `justfile`:

```
Aleph/
├── Cargo.toml                  # Workspace root + alephcore package
├── src/                        # alephcore — main library + server binary
│   ├── lib.rs                  # Library crate entrypoint
│   └── bin/aleph-server/       # Server binary
├── justfile                    # Build and check recipes
├── desktop/
│   ├── nsh-shell/              # NSH desktop host
│   ├── host/                   # Host helper library
│   ├── shared/                 # Desktop capability traits
│   ├── macos/                  # macOS native implementation
│   ├── linux/                  # Linux native implementation
│   └── windows/                # Windows native implementation
├── shared/
│   ├── protocol/               # aleph-protocol — shared types
│   ├── logging/                # Logging infrastructure
│   ├── ui_logic/               # Shared UI logic
│   └── client/                 # Shared client utilities
└── interfaces/
    ├── cli/                    # Terminal client
    ├── tui/                    # TUI client
    └── webchat/                # Web-based chat interface (WASM)
```

NSH is the target desktop host (`desktop/nsh-shell/Cargo.toml`, nsh `0.6.0`). During the transition, current desktop releases still build the legacy Tauri shell (`desktop/shell/`): CI uses `.github/workflows/aleph-app-release.yml`, and local packaging uses `just shell-build` in `justfile`. The legacy shell will be removed; NSH does not yet have a release pipeline of its own (`justfile`, `.github/workflows/`). See the [desktop host overview](../desktop-hosts/overview).

See `VERSION` for the workspace version and `Cargo.toml` for shared dependencies, the full member list, and release profiles.

## Feature Flags

The core crate has an empty default feature list (`Cargo.toml`). For example, `loom` enables concurrency testing and `test-helpers` enables test utilities; neither is needed for a standard server build. Embedding Panel assets does not require the `control-plane` feature (`build.rs`, `src/gateway/control_plane/assets.rs`).

### Building

```bash
# Default build
cargo run -p alephcore --bin aleph-server

# Release build
cargo build -p alephcore --bin aleph-server --release

# With Loom concurrency testing
cargo test -p alephcore --features loom --lib loom
```

## Build Profiles

### Debug Build (Development)

```bash
# Fast compilation, slower runtime, full debug symbols
cargo build -p alephcore --bin aleph-server

# Run directly (build + execute)
cargo run -p alephcore --bin aleph-server
```

Debug builds compile quickly but produce large, unoptimized binaries. Use this for day-to-day development.

### Release Build (Production)

```bash
# Optimized binary
cargo build -p alephcore --bin aleph-server --release

# Binary location
ls -lh target/release/aleph-server
```

The server uses the standard release profile in `Cargo.toml`:

```toml
[profile.release]
strip = true
```

### Verifying a Build

```bash
# Check version
./target/release/aleph-server --version

# Check help
./target/release/aleph-server --help
```

## Building the WebChat Panel UI

The WebChat Panel is a web-based chat interface compiled to WASM and served by the Gateway. The `just` build pipeline handles this automatically via the `wasm` recipe.

### Manual WASM Build

If you need to build the WASM panel separately:

```bash
# The justfile handles the full WASM build pipeline:
just wasm
```

This will:
1. Compile Tailwind CSS (`interfaces/webchat`)
2. Build the Rust code to WASM (`cargo build -p aleph-panel --target wasm32-unknown-unknown`)
3. Generate JavaScript bindings with `wasm-bindgen`
4. Create the runtime `index.html`

Next, rebuild the server and replace the running service with the new binary. Updating `interfaces/webchat/dist/` alone does not update a running release build: `rust_embed` embeds assets in `aleph-server` at compile time, and the release binary does not read the on-disk `dist/` at runtime (`src/gateway/control_plane/assets.rs`, `build.rs`).

```bash
just wasm
just check-dist
cargo build --release -p alephcore --bin aleph-server
```

`just check-dist` calls `scripts/check_panel_dist.mjs` to check that the JavaScript and WASM artifacts match (`justfile`).

## Using Just (Recommended)

The project includes a `justfile` with common build tasks. Install `just` first:

```bash
cargo install just
```

Available recipes:

```bash
# Show all available recipes
just --list

# Development: build WASM panel + run server in debug mode
just dev

# Full release build (WASM + Swift bridge + server)
just build

# Build server only (debug)
just build-debug

# Build WASM Panel UI only
just wasm

# Quick compilation check
cargo check -p alephcore

# Run core tests
just test

# Run all tests (core + desktop + proptest)
just test-all

# Lint with clippy
just clippy

# Clean build artifacts
just clean
```

## Cross-Compilation Notes

Aleph is primarily developed and tested on **macOS (ARM64)**. Cross-compilation targets to be aware of:

| Target | Status | Notes |
|--------|--------|-------|
| `aarch64-apple-darwin` | Primary | Default development target |
| `x86_64-apple-darwin` | Supported | Intel Mac builds |
| `x86_64-unknown-linux-gnu` | Supported | Linux server deployment |
| `aarch64-unknown-linux-gnu` | Supported | Linux ARM (Raspberry Pi, etc.) |
| `wasm32-unknown-unknown` | Required | Control Plane UI only |

For Linux cross-compilation from macOS, consider using [cross](https://github.com/cross-rs/cross):

```bash
cargo install cross
cross build --bin aleph-server --target x86_64-unknown-linux-gnu --release
```

## Build Troubleshooting

### `rusqlite` Fails to Compile

The `bundled` feature flag compiles SQLite from source, requiring a C compiler. On Linux:

```bash
sudo apt install build-essential
```

### OpenSSL Linking Errors

If `reqwest` fails to link OpenSSL on Linux:

```bash
sudo apt install libssl-dev pkg-config
```

On macOS, this should not occur because `native-tls` uses the system Security framework.

### WASM Build Fails

If the Control Plane WASM build fails, ensure the target is installed:

```bash
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli
```

For a usable embedded Panel, generate the complete asset set with `just wasm` before compiling the server. A successful server compile does not prove that Panel artifacts were generated (`justfile`, `build.rs`).

### Port Already in Use

If the server fails to start because port 18790 is occupied:

```bash
# Find the process using the port
lsof -i :18790

# If this is a process you intend to stop, use its normal shutdown procedure

# Or start on a different port
cargo run -p alephcore --bin aleph-server -- start --port 8080
```

### Slow Builds

For faster incremental builds during development:

```bash
# Use the mold linker (Linux)
cargo install mold
RUSTFLAGS="-C link-arg=-fuse-ld=mold" cargo build

# Or reduce codegen units in dev profile (already the default)
# [profile.dev]
# codegen-units = 256  # More units = faster compile, slower runtime
```

Consider using `cargo check` instead of `cargo build` when you only need to verify compilation without producing a binary.

### Harness 12 Files + Line-Count Ratchet

**Code is the authority** — every doc number is just a copy of `CEILING`:

- Top-level 8 + `agent/` 4 = **12 files** (tests under `tests/` do not count toward the ratchet)
- Line count gated by `src/harness/tests/budget.rs` ratchet, bound to the `CEILING` constant
- At the time, `CEILING` = **5,055** (during 26.7.x); the current value is **5,535** (`src/harness/tests/budget.rs:795`); treat any line count reproduced here as a stale copy
- The 3 questions before adding code: scaffolding vs cognition? Will a model upgrade still need it? How many real consumers does it have?

### YAGNI Withdrawal

Any abstraction with zero consumers is deleted immediately. ~5,200 lines of dead code were removed cumulatively during harness dissolution.
