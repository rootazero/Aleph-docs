This page explains how the Panel and local clients reach the Gateway, and where the Gateway checks origin, identity, and execution approval.

## Entry Points and Trust Boundaries

| Entry point | Transport and identity | RPC scope | Implementation |
|-------------|------------------------|-----------|----------------|
| Desktop IPC | Unix domain socket; verifies the peer without granting network privileges | `system.hello` first, then the [Protocol v1 method list](../gateway/protocol-v1) | `src/gateway/server/connection/local_ipc.rs` |
| Web v1 | Native Gateway TLS; `POST /v1/session` issues a session cookie, and `GET /v1/ws` checks the session before upgrading | `system.hello` first, then the [Protocol v1 method list](../gateway/protocol-v1) | `src/gateway/server/mod.rs`, `src/gateway/server/connection/web_v1.rs` |
| Compatibility WebSocket | Default URL `ws://127.0.0.1:18790/ws`; `connect` distinguishes direct loopback from remote callers presenting credentials | Compatibility control plane; see [Gateway authentication](../gateway/auth) for authentication and transport gates | `src/gateway/config.rs`, `src/gateway/server/connection/upgrade.rs`, `src/gateway/handlers/connect.rs` |

## Desktop IPC over a local socket

Enable the Unix listener explicitly with `aleph-server start --desktop-ipc <socket>` (`src/bin/aleph-server/cli.rs`, `src/bin/aleph-server/commands/start/mod.rs`). The server handles up to 8 concurrent connections per listener. The listener requires a peer with the same effective user, and serving requests requires an active desktop owner. Each connection has a shared 16 MiB wire budget and a 5-second write deadline. Dispatch uses the placeholder IP `0.0.0.0`, so local IPC does not inherit the loopback privileges of the network entry point (`src/gateway/server/connection/local_ipc.rs`).

`shared/protocol/src/framing.rs` defines the bounded framing. The client caps frames at 8,388,608 bytes, allows up to 8 in-flight requests, and times out `system.hello` after 5 seconds (`shared/client/src/local_ipc.rs`). NSH's `--desktop-ipc-status <socket>` reads health from a running Gateway without opening the Panel or falling back to WebSocket (`desktop/nsh-shell/src/main.rs`, `desktop/nsh-shell/src/ipc_status.rs`).

## Panel Origin Checks and Cross-Site Protection

### Web v1: Strict HTTPS Same-Origin Checks

`same_origin` requires `Origin` to match the HTTPS origin derived from the request authority on both the session exchange and WS upgrade. It also rejects query strings. `throttle` rate-limits by client address. `redeem` validates a device token or exchanges a bootstrap ticket. `cookie_handle` reads the session handle; the upgrade also checks the bound origin and current device identity. The cookie is marked `Secure`, `HttpOnly`, and `SameSite=Strict` (`src/gateway/server/connection/web_v1.rs`). This entry point does not use the compatibility `/ws` allowlist.

### Compatibility `/ws`: Origin and Authentication Are Separate

`ws_upgrade_handler` calls `OriginPolicy::is_allowed` and returns `403` for disallowed origins (`src/gateway/server/connection/upgrade.rs`, `src/gateway/origin_policy.rs`). The rules are:

| `Origin` | Default decision |
|----------|------------------|
| Absent or blank | Passes the origin check, not authentication |
| Exact case-insensitive match in `[gateway] allowed_origins` | Allowed |
| HTTP(S) authority matches request `Host`, which is an IP literal or loopback host | Allowed; for example, `http://127.0.0.1:18790` with `127.0.0.1:18790` |
| Dedicated scheme for the legacy desktop webview | Still accepted for compatibility; not the origin rule for NSH |
| Other origins | Denied; a same-origin domain or a loopback page on a different port is not automatically allowed |

`allow_any_origin = true` bypasses this check and is not recommended (`src/gateway/config.rs`, `src/gateway/origin_policy.rs`). NSH constrains Panel origins through `ConnectionTarget`: remote origins use HTTPS, and navigation checks the scheme, host, and port. The host handles the exact deep link `aleph://open` separately. It is not a Panel origin and does not grant RPC privileges (`shared/client/src/connection_target.rs`, `desktop/nsh-shell/src/panel_bridge.rs`).

## Sensitive Actions and Audit

### Execution Approval

Permission to connect is not permission to execute. The Panel submits the user's decision through `exec.approval.resolve`. The Gateway handles approval, and the execution gate binds grants to the tool and normalized arguments. The visible approval summary is redacted; the grant fingerprint is not computed from the redacted values (`interfaces/webchat/src/api/exec_approval.rs`, `src/gateway/handlers/exec_approvals.rs`, `src/sandbox/exec_approval/action.rs`). The two v1 entry points leave execution approval RPCs unmounted (`src/gateway/server/connection/local_ipc.rs`, `src/gateway/server/connection/web_v1.rs`).

### Credential Storage and Logs

The Gateway security store lives in `src/gateway/security/store/`; device tokens are checked against hashes (`src/gateway/security/device_token_manager.rs`). The NSH credential service uses the shared client's OS keyring store and does not fall back to plaintext storage if the keyring is unavailable (`desktop/nsh-shell/src/credentials.rs`, `shared/client/src/credential_store.rs`).

Authentication failures and unauthorized request floods on the compatibility endpoint can be written to the security audit log. The Desktop IPC peer-close log records only the error kind. This review did not verify a common redactor for all logs; redaction of approval summaries is not a guarantee that applies to every log (`src/gateway/server/connection/mod.rs`, `src/security/audit.rs`, `src/gateway/server/connection/local_ipc.rs`).

### Trace Correlation and Health Probes

The Gateway's shared dispatcher can adopt a caller's `traceparent` from RPC parameters for request correlation (`src/gateway/server/connection/dispatch.rs`, `src/gateway/trace_context.rs`). The Gateway router also exposes separate HTTP probes at `/health`, `/ready`, and `/metrics`; these are not methods on the Desktop IPC socket (`src/gateway/server/mod.rs`, `src/gateway/server/probe.rs`, `src/gateway/server/metrics_endpoint.rs`).
