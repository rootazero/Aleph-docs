WebChat is Aleph's built-in web-based chat interface. It is a **WebAssembly Panel** (`interfaces/webchat/`) served directly by the Gateway's HTTP server alongside the WebSocket endpoint. The Panel is a Leptos app that mounts to the browser `<body>` and talks to the Gateway over the same JSON-RPC 2.0 protocol used by every other Aleph client.

See `interfaces/webchat/src/lib.rs` for the entry point and `src/gateway/control_plane/server.rs` for asset serving.

│             │ WebSocket (JSON-RPC 2.0)                        │
└─────────────┼────────────────────────────────────────────────┘
              │

│             ▼                                                  │
│  ┌────────────────────────────────────────────────────────┐  │
│  │              Gateway HTTP Server                        │  │

│  │  /ws            → WebSocket endpoint                   │  │

└──────────────────────────────────────────────────────────────┘

`interfaces/webchat/src/lib.rs` exports the WASM entry point:

```rust
#[wasm_bindgen(start)]
pub fn main() {
    panic_overlay::install();
    appearance::init_appearance();
    mount_to_body(app::App);
}
```

The Panel is a single-page application (SPA). The same JSON-RPC protocol used by the macOS app, [desktop hosts](/docs/en/desktop-hosts/overview), and CLI is exposed at `/ws` on the Gateway.

## Panel Topology

`PanelMode` has **10 variants**: Chat, Dashboard, Memory, Agents, Teams, Projects, Terminal, Extensions, Settings, and More. The primary switcher, `ALL_MODES: [PanelMode; 8]`, contains eight entries (excluding Extensions and More), including Settings. See `interfaces/webchat/src/components/mode_sidebar.rs` and `interfaces/webchat/src/components/nav_menu.rs`.

| Section | Route | Purpose |
|---------|-------|---------|
| Chat | `/chat` | Primary conversation surface |
| Dashboard | `/dashboard` | Status, activity, and overview |
| Memory | `/memory` | Memory Hub |
| Agents | `/agents` | Browse and configure agents |
| Teams | `/teams` | Multi-agent teams |
| Projects | `/projects` | Project management |
| Terminal | `/terminal` | Operator terminal |
| Settings | `/settings` | Configuration |

`PanelMode::from_path` maps `/memory`, `/agents`, `/teams`, `/projects`, `/extensions`, `/dashboard`, `/more`, `/settings`, and `/terminal` to their corresponding variants; other paths fall back to Chat (`interfaces/webchat/src/components/mode_sidebar.rs`).

- **Extensions** (`/extensions`) and **More** (`/more`) remain reachable but do not participate in the primary switcher. Extensions is deliberately omitted: its launcher lives in the Chat sidebar's advanced-features zone, below project management. Its `label_of` / `icon_of` branches exist only for the trigger button (`interfaces/webchat/src/components/nav_menu.rs`). See [Extensions Store](/docs/en/concepts/extensions-store).
- **Terminal** is visible to everyone in navigation, but the server permits only operators. The view explains a denial rather than hiding the destination and making “not allowed” look like “does not exist” (`interfaces/webchat/src/components/nav_menu.rs`, `interfaces/webchat/src/components/mode_sidebar.rs`, `src/gateway/handlers/pty.rs`).
- **More** is a phone-only menu for management sections; desktop never routes here (`interfaces/webchat/src/components/mode_sidebar.rs`).

Form-factor UI lives in `interfaces/webchat/src/platform/wide/` and `interfaces/webchat/src/platform/phone/`. The tablet layer is still a skeleton with screens deferred, not a completed multi-tab UI (`interfaces/webchat/src/platform/tablet/mod.rs`).

## Configuration

### Gateway Config (Implicit)

WebChat uses the Gateway's HTTP server. See `src/gateway/config.rs` for these binding and connection-count defaults:

```toml
[gateway]
host = "127.0.0.1"
port = 18790
max_connections = 100
```

### Explicit WebChat Config

The Panel is served by the Gateway ControlPlane, not a separate WebChat channel HTTP server. See `src/gateway/control_plane/server.rs` for asset serving and `src/gateway/config.rs` for browser-origin checks via `[gateway].allowed_origins`.

### Static File Directory

Panel assets are embedded from `interfaces/webchat/dist/` at build time using `rust_embed`; runtime serving does not read a configurable disk directory (`src/gateway/control_plane/assets.rs`). Unknown extensionless paths fall back to the embedded `index.html`, without any extra setting (`src/gateway/control_plane/server.rs`).

## WebSocket Protocol

The old `/ws` endpoint is a historical compatibility entry; the target protocol is [Protocol v1](/docs/en/gateway/protocol-v1). See `src/gateway/server/connection/web_v1.rs` for the v1 ingress.

WebChat communicates with the Gateway using the standard JSON-RPC 2.0 protocol over WebSocket.

### Connecting

```javascript
const ws = new WebSocket("ws://127.0.0.1:18790/ws");
```

Start the legacy `/ws` connection with a `connect` handshake (`src/gateway/handlers/connect.rs`):

```json
{
  "jsonrpc": "2.0",
  "id": "1",
  "method": "connect",
  "params": {
    "minProtocol": 1,
    "maxProtocol": 1,
    "client": {
      "id": "webchat",
      "version": "1.0.0",
      "platform": "web"
    },
    "role": "operator"
  }
}
```

### Sending a Message

For `agent.run`, `message` is a compatibility alias for `input`; `session_key` is optional (`src/gateway/handlers/agent.rs`).

```json
{
  "jsonrpc": "2.0",
  "id": "msg-001",
  "method": "agent.run",
  "params": {
    "message": "What is the weather today?",
    "session_key": "agent:main:main"
  }
}
```

### Receiving Streaming Events

Subscribe to streaming events to receive the response in real-time:

```json
{
  "jsonrpc": "2.0",
  "id": "sub-001",
  "method": "events.subscribe",
  "params": { "topics": ["agent.*", "run.*"] }
}
```

Events arrive as JSON-RPC notifications:

```json
{
  "jsonrpc": "2.0",
  "method": "stream.response_chunk",
  "params": {
    "type": "response_chunk",
    "run_id": "run-123",
    "seq": 1,
    "delta": "Hello",
    "full_text": "Hello",
    "content": "Hello",
    "chunk_index": 0,
    "is_final": false,
    "is_intermediate": false
  }
}
```

### Event Types

Subscriptions use topic names; streaming delivery uses JSON-RPC notification methods. Do not interchange them. `events.subscribe` takes a `topics` array (`src/gateway/handlers/events.rs`); see `src/gateway/events/frame.rs` for the mapping and `src/gateway/event_bus.rs` for notification envelopes.

| Subscription topic | Notification method | Description |
|-------|-------|-------|
| `agent.response.chunk` | `stream.response_chunk` | Text delta |
| `agent.tool.start` | `stream.tool_start` | Tool execution started |
| `agent.tool.end` | `stream.tool_end` | Tool execution completed |
| `run.accepted` | `stream.run_accepted` | Run accepted |
| `agent.run.complete` | `stream.run_complete` | Run completed |
| `agent.run.error` | `stream.run_error` | Run error |

## Static File Serving

`/` serves the embedded `index.html`. Assets are looked up by embedded path; missing paths with an extension return 404, while extensionless paths fall back to the entry page. Responses use `Cache-Control: no-cache`, with ETag revalidation for assets (`src/gateway/control_plane/server.rs`).

## Embedding in Websites

The following iframe loads the Panel served by the Gateway (`src/gateway/control_plane/server.rs`).

### iframe Embedding

```html
<iframe
  src="http://localhost:18790"
  width="400"
  height="600"
  style="border: none; border-radius: 12px;"
></iframe>
```

### CORS Configuration

Cross-origin WebSocket upgrades use the `[gateway].allowed_origins` allowlist; this is not CORS configuration for a separate WebChat HTTP server. Keep `allow_any_origin` disabled by default (`src/gateway/config.rs`).

```toml
[gateway]
allowed_origins = ["https://your-website.com", "https://app.your-website.com"]
```

## Authentication

`connect` distinguishes loopback authorization, device tokens, pairing credentials, and the legacy shared token. Missing or invalid credentials do not automatically authorize remote connections (`src/gateway/handlers/connect.rs`). Do not use the old `require_auth = false` example as a security configuration.

<Callout type="warn">
Use TLS and trusted origins for remote deployments; non-loopback plaintext is denied by default (`src/gateway/config.rs`).
</Callout>

## Session Management

The following example uses a main-session key; `agent.run` accepts an explicit `session_key` (`src/gateway/handlers/agent.rs`):

```
agent:main:main
```

The WebChat UI can specify custom session keys to support multiple conversations:

```json
{
  "method": "agent.run",
  "params": {
    "message": "Hello",
    "session_key": "agent:main:webchat:session-1"
  }
}
```

Session persistence uses the shared session manager; see `src/gateway/session_manager/mod.rs` for its SQLite connection.

## InteractionManifest

WebChat uses the **WebRich** paradigm, which provides the most complete set of capabilities:

```rust
use alephcore::thinker::interaction::{InteractionManifest, InteractionParadigm};

let manifest = InteractionManifest::new(InteractionParadigm::WebRich);
```

`MermaidCharts` is a paradigm capability declaration, not proof of Mermaid rendering in the current Panel. See `interfaces/webchat/src/components/markdown.rs` for actual rendering support.

## Health Check

The HTTP server provides a health endpoint:

```bash
curl http://127.0.0.1:18790/health
```

This can be used for monitoring and load balancer health checks.

## Troubleshooting

| Issue | Check |
|---------|----------|
| Blank page / asset 404 | Verify the running binary embeds a complete Panel build (`src/gateway/control_plane/assets.rs`) |
| WebSocket connection refused | Check the Gateway address, TLS, and `allowed_origins` (`src/gateway/config.rs`) |
| Authentication failure | Check `connect` credentials; do not rely on the obsolete `require_auth` switch (`src/gateway/handlers/connect.rs`) |
| Streaming not working | Check `events.subscribe` topics and `stream.response_chunk` notification handling (`src/gateway/handlers/events.rs`, `src/gateway/events/frame.rs`) |
| SPA routing failure | Only extensionless paths fall back to the embedded entry page (`src/gateway/control_plane/server.rs`) |
