`config.*` exposes runtime configuration management. Every method below takes effect without a gateway restart; per-method side effects are noted inline.

## Methods

| Method | Description |
|--------|-------------|
| [`config.schema`](#configschema) | Return the full JSON Schema (no params) |
| [`config.get`](#configget) | Read the currently active configuration (secret fields report presence only) |
| [`config.patch`](#configpatch) | Partial override (JSON Merge Patch / RFC 7386-style) |
| [`config.reload`](#configreload) | Reload the configuration from disk |

Registered in `HandlerRegistry::new()` but not normally called via RPC — they back the boot path:

| Method | Description |
|--------|-------------|
| `config.get_full_config` | Raw config read used by the boot path |
| `config.path` | Absolute path of the active config file |
| `config.validate` | Validate a config object without persisting |
| `config.reload_with_subsystems` | Trigger subsystem hot-reload |
| `config.get_tool_permissions` / `config.update_tool_permissions` | Tool-permission read/write |

> `config.apply` (full overwrite) is not currently registered. To replace the configuration wholesale, use `config.patch` followed by `config.reload`.

### config.schema

Return the full JSON Schema for `~/.aleph/config.json`. Takes no parameters.

**Request:**
```json
{ "jsonrpc": "2.0", "id": 1, "method": "config.schema" }
```

**Response:**
```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "schema": { "type": "object", "$schema": "...", "properties": { "...": { "...": "..." } } }
  }
}
```

### config.get

Read the active configuration as seen by `ConfigWatcher`.

**Request:**
```json
{ "jsonrpc": "2.0", "id": 1, "method": "config.get" }
```

**Response:**
```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "config": {
      "general": { "default_provider": "openai", "fallback_providers": [] },
      "execution": { "default_timeout_secs": 600, "max_runs_global": 16 },
      "channels": { "telegram": { "enabled": true, "has_bot_token": true } }
    }
  }
}
```

The result carries a single `config` member (or just the requested section when a `section` param is given). Secrets are never echoed back: a channel's secret fields are stripped and replaced by a presence flag such as `has_bot_token` (see `report_channel_secret_presence`); provider keys are exposed the same way as `has_api_key`. The configuration file path comes from `config.path`.

### config.patch

Apply a partial override using JSON Merge Patch (RFC 7386-style). Only the fields you provide are modified; everything else is preserved.

**Request:**
```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "config.patch",
  "params": {
    "patch": {
      "execution": { "max_runs_global": 32 },
      "general": { "fallback_providers": ["anthropic", "openai"] }
    }
  }
}
```

**Response:**
```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "result": {
    "success": true,
    "applied_sections": ["execution", "general"],
    "diff": [
      { "path": "execution.max_runs_global", "old_value": 16, "new_value": 32 },
      { "path": "general.fallback_providers", "old_value": [], "new_value": ["anthropic", "openai"] }
    ],
    "health_check": null,
    "warnings": [],
    "live_applied": ["execution"],
    "reload_impact": { "kind": "live", "hint": "此改动将即时生效（下一轮对话），无需重启。" }
  }
}
```

**Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `patch` | object | Yes | Merge Patch object. Set a field to `null` to clear it |

`reload_impact` states how the change takes effect: `kind` is `live` when the change was hot-applied (`live_applied` lists the sections that were actually pushed onto the running runtime), `restart` when it was written but needs an `aleph-server` restart to become effective, and `inert` when the section has no runtime consumer left. `hint` is the human-readable guidance; the RPC always fills the Chinese variant (`user_hint_zh`). A no-op patch carries no `reload_impact` — nothing was persisted, so no reload semantics apply.

### config.reload

Reload the configuration from the config file on disk. Use this after manually editing the file or syncing it from a dotfiles repository.

**Request:**
```json
{ "jsonrpc": "2.0", "id": 1, "method": "config.reload" }
```

**Response:**
```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "ok": true,
    "reloaded": ["app_config", "live:execution", "providers"],
    "failed": [],
    "config": { "agents": ["main"], "bindings_count": 2 }
  }
}
```

`reloaded` lists the subsystems that were reloaded, with hot-applied sections prefixed by `live:`; each entry of `failed` names a subsystem and the reason it failed.

## Hot Reload & Reloadable Fields

The `[gateway.config_watcher]` controls the file watcher; any save triggers the reload pipeline:

1. **Debounce** -- wait 500 ms so all writes settle
2. **Parse** -- read and parse the new configuration
3. **Validate** -- check against the schema
4. **Diff** -- compute changed field paths
5. **Apply** -- update the in-memory config and restart affected interfaces
6. **Notify** -- emit a `config.changed` event to subscribed clients

```json
{
  "jsonrpc": "2.0",
  "method": "event",
  "params": {
    "topic": "config.changed",
    "data": {
      "section": "execution",
      "value": { "max_runs_global": 32 },
      "timestamp": 1706400000000
    }
  }
}
```

**Hot-reloadable:** `[general]` model catalog and failover chain, `[providers.*]` provider config, channel on/off, `[execution]` run caps, `[cron]` scheduler settings, `[exec]` approval rules.

**Requires restart:** core port, bind address, TLS certificates, `[memory]` embedding model and vector store, `[browser]` CDP settings.
