The Aleph Gateway exposes its functionality through namespaced JSON-RPC 2.0 methods. Each namespace groups related operations, and every method follows the same request/response conventions. The namespace registry lives in [`src/gateway/handlers/mod.rs`](../../../reference/GATEWAY.md) and `src/bin/aleph-server/commands/start/builder/handlers/` on the boot path.

## Request Format

All RPC requests use the JSON-RPC 2.0 envelope:

```json
{
  "jsonrpc": "2.0",
  "id": "unique-id",
  "method": "namespace.method",
  "params": { ... }
}
```

- `id` can be a string, number, or `null` (`null` for notifications)
- `method` follows the `namespace.action` naming convention
- `params` is an optional JSON object specific to each method

## Response Format

**Success:**
```json
{
  "jsonrpc": "2.0",
  "id": "unique-id",
  "result": { ... }
}
```

**Error:**
```json
{
  "jsonrpc": "2.0",
  "id": "unique-id",
  "error": {
    "code": -32601,
    "message": "Method not found",
    "data": null
  }
}
```

## Error Codes

| Code | Name | Description |
|------|------|-------------|
| -32700 | Parse error | Malformed JSON |
| -32600 | Invalid Request | Missing required fields |
| -32601 | Method not found | Unknown method name |
| -32602 | Invalid params | Bad or missing parameters |
| -32603 | Internal error | Server-side failure |
| -32000 | Auth required | No credentials provided |
| -32001 | Auth failed | Invalid token or signature |
| -32002 | Permission denied | Insufficient permissions |
| -32003 | Rate limited | Too many requests |
| -32004 | Resource not found | Requested entity does not exist |
| -32005 | Timeout | Operation timed out |
| -32006 | Tool error | Tool execution failed |

## Placeholders & Status Codes

`HandlerRegistry::new()` in `src/gateway/handlers/mod.rs` pre-registers a set of methods so `METHOD_NOT_FOUND` is deterministic:

- **Ready immediately** — `health` / `echo` / `version` / `system.info` / `request.state` / `config.schema` / `logs.getLevel` / `logs.setLevel` / `logs.getDirectory` / `services.*` / `pty.*` / `plugins.*` / `plugin.*` / `hooks.*` / `mcp.list_pending_approvals` / `mcp.respond_approval` / `mcp.cancel_approval` / `skills.*` / `bundled.sync` / `daemon.logs`
- **Stub until boot overrides** — `cron.*` / `heartbeat.*` / `chat.send` / `chat.abort` / `chat.history` / `chat.clear` / `session.usage` / `session.compact` / `session.truncate` / `workspace.*` / `channels.set_agent` / `agents.bindings` / `groups_*` / `daemon.status` / `daemon.shutdown` / `teams.*` / `agents.*` / `runtimes.*` / `tools.*` / `insights.tools` / `gateway.identity.get` / `gateway.metrics.*` / `gateway.credentials` / `trace.*` / `wizard.*`
- **Not registered (METHOD_NOT_FOUND until injected)** — `identity.get` / `identity.set` / `identity.clear` / `identity.list` (must go through `register_identity_handlers`); `graph.*` (must go through `register_graph_handlers`)

Stubs are overridden by the corresponding `register_*_handlers` call on the boot path (`src/bin/aleph-server/commands/start/builder/handlers/`) before the first request is served.

## Common Patterns

### Pagination

Methods that return lists accept optional `limit` / `offset` (exact semantics vary per method; see each sub-page):

```json
{ "jsonrpc": "2.0", "id": 1, "method": "cron.list", "params": { "limit": 20, "offset": 0 } }
```

### Streaming Events

`agent.run` and `chat.send` emit events on the `stream.*` and `agent.*` topics. Subscribe first:

```json
{ "jsonrpc": "2.0", "id": 1, "method": "events.subscribe", "params": { "topics": ["agent.*"] } }
{ "jsonrpc": "2.0", "id": 2, "method": "agent.run", "params": { "input": "Hello" } }
{ "jsonrpc": "2.0", "method": "event", "params": { "topic": "agent.response.chunk", "data": { "content": "Hi!" } } }
```

See [events.*](./events).
