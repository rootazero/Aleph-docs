The Aleph Gateway uses JSON-RPC 2.0 over WebSocket for all communication.

## Connection

```
ws://127.0.0.1:18790
```

When `require_auth: true`, the first message must be a `connect` request:

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "connect",
  "params": {
    "minProtocol": 1,
    "maxProtocol": 1,
    "client": {
      "id": "cli",
      "version": "0.1.0",
      "platform": "macos"
    },
    "role": "operator",
    "auth": {
      "token": "bearer_token"
    }
  }
}
```

## Message Types

### Request (Client → Gateway)

```json
{
  "jsonrpc": "2.0",
  "id": "unique-id",
  "method": "method.name",
  "params": { ... }
}
```

### Response (Gateway → Client)

Success:
```json
{
  "jsonrpc": "2.0",
  "id": "unique-id",
  "result": { ... }
}
```

Error:
```json
{
  "jsonrpc": "2.0",
  "id": "unique-id",
  "error": {
    "code": -32600,
    "message": "Invalid Request"
  }
}
```

### Event (Gateway → Client)

```json
{
  "jsonrpc": "2.0",
  "method": "event",
  "params": {
    "topic": "stream.token",
    "data": { ... }
  }
}
```

## Method Categories

| Prefix | Description |
|--------|-------------|
| `agent.*` | Agent execution and control |
| `session.*` | Session management |
| `config.*` | Configuration operations |
| `exec.*` | Execution approval |
| `wizard.*` | Configuration wizard |
| `cron.*` | Scheduled jobs |
| `events.*` | Event subscription |
| `browser.*` | CDP browser control |

## Streaming

For methods that support streaming (like `agent.run`), events are sent as separate messages:

```json
// Start of stream
{
  "jsonrpc": "2.0",
  "method": "event",
  "params": {
    "topic": "stream.start",
    "data": { "run_id": "..." }
  }
}

// Token stream
{
  "jsonrpc": "2.0",
  "method": "event",
  "params": {
    "topic": "stream.token",
    "data": { "text": "Hello" }
  }
}

// End of stream
{
  "jsonrpc": "2.0",
  "method": "event",
  "params": {
    "topic": "stream.end",
    "data": { "run_id": "..." }
  }
}
```

## Error Codes

| Code | Meaning |
|------|---------|
| -32700 | Parse error |
| -32600 | Invalid Request |
| -32601 | Method not found |
| -32602 | Invalid params |
| -32603 | Internal error |
| -32000 | Auth required |
| -32001 | Auth failed |
| -32002 | Permission denied |

## Event Subscription

Subscribe to events:

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "events.subscribe",
  "params": {
    "patterns": ["stream.*", "agent.*"]
  }
}
```

Unsubscribe:

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "events.unsubscribe",
  "params": {
    "patterns": ["stream.*"]
  }
}
```

## 26.7.x Addendum

### TLS

26.7.17+ introduces `[gateway] tls`:

```toml
[gateway]
bind = "0.0.0.0"
allow_insecure_remote = false  # default false; non-loopback binds fail closed

[gateway.tls]
# cert and key left empty → auto-generate a self-signed cert
# SAN auto-discovers the host's non-loopback interface IPs
# cert = "/path/to/cert.pem"
# key  = "/path/to/key.pem"
```

When TLS is enabled, the connection URL becomes `wss://...`; the port stays the same.

### Real Client IP

26.7.17+:

```toml
[gateway]
trusted_proxy = ["127.0.0.1", "::1"]
```

When listed in `trusted_proxy`, the gateway parses the real client IP from `X-Forwarded-For` / `X-Real-IP` (capacity limits, rate limits, audit, and connect-auth all depend on this).

### Atomic Regen Marker

26.7.18+: when the self-signed cert's SAN drifts, the gateway writes an **atomic regen marker** first, then regenerates the cert; if regeneration fails, the old cert is still used.

### Single-Source Error Receipt

26.7.21+: the gateway returns a **single-source** user-readable error. The raw error chain never leaks to the Panel.

```json
// Error-receipt example
{
  "jsonrpc": "2.0",
  "id": 1,
  "error": {
    "code": -32603,
    "message": "Tool 'shell_exec' failed: exit code 1",
    "data": {
      "receipt_id": "err-...",
      "category": "tool_execution",
      "user_message": "Command failed (exit 1)"
    }
  }
}
```

### WS Task-Leak Fixes

26.7.21+:

- Per-connection event-forward tasks no longer leak
- `broadcast::RecvError::Lagged` recovers rather than dies permanently
- Webhook receivers return 503 under congestion rather than silently dropping

### Request IDs Switched to Atomic Counter

26.7.21+: wire request IDs no longer use UUIDs (the `uuid` dependency is dropped from `aleph-protocol`); switched to an **atomic counter**. IDs are now monotonically increasing, not random.

### Full RPC ~265

26.7.x the gateway exposes **~265 RPC methods** — see [Methods Reference](/docs/en/gateway/methods).
