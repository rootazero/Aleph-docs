Aleph has no single `core` module. Shared types live in their owning modules; see the current inventory below. The former src/core/ data containers are documented under History.

## History: src/core module

The orphan directory and its old type definitions were removed in `7c24bc55c`, after the module was undeclared.

The src/core/ module was a pure data container — no business logic, no platform-specific code, only `serde` plus std containers — designed for high cohesion and zero coupling. It was removed as its types migrated to owning modules or were dropped entirely. The four types it held are recorded below for reference.

### MediaAttachment

Multimodal content support for images, documents, and video from clipboard or file uploads (formerly src/core/types.rs; the unified `MediaType` now lives at `src/media/types.rs`).

```rust
pub enum MediaType {
    Image, Document, Video, File,
}

pub enum ContentEncoding {
    Base64, Utf8,
}

pub struct MediaAttachment {
    pub media_type: MediaType,
    pub mime_type: String,
    pub data: String,
    pub encoding: ContentEncoding,
    pub filename: Option<String>,
    pub size_bytes: u64,
}
```

- `ContentEncoding::Base64` — binary content encoded as Base64 (images, PDFs)
- `ContentEncoding::Utf8` — plain text content (markdown, extracted text)

`MediaAttachment` carried a `Debug` impl that rewrote `data` to `<REDACTED: N bytes>` to keep payloads out of logs. Both `MediaType` and `ContentEncoding` were `#[non_exhaustive]`.

### CapturedContext

Context from the user's active application, bridged from the native desktop layer (formerly src/core/types.rs).

```rust
pub struct CapturedContext {
    pub window_title: Option<String>,
    pub attachments: Vec<MediaAttachment>,
    pub session_id: Option<String>,
}
```

- `window_title` — title of the active window
- `attachments` — clipboard content (images, files) captured at interaction time
- `session_id` — session identifier for multi-turn conversations

The Desktop Bridge's `CapturedContext` injection was removed; clipboard capture is now handled by `src/builtin_tools/system_tool.rs` (clipboard_read / clipboard_write) and the desktop submodule.

### CompressionStats

Statistics about the memory compression state, used by the Settings UI to display memory health (formerly src/core/types.rs).

```rust
pub struct CompressionStats {
    pub total_raw_memories: u64,
    pub total_facts: u64,
    pub valid_facts: u64,
    pub facts_by_type: BTreeMap<String, u64>,
}
```

- `total_raw_memories` — Layer 1 raw user messages
- `total_facts` — Layer 2 compressed facts
- `valid_facts` — non-invalidated active facts
- `facts_by_type` — breakdown by type (preference, plan, learning, …); `BTreeMap` for deterministic iteration order

### MemoryEntry

A memory record returned by the Memory system's API for serialization to clients. The current wire projection lives at `src/gateway/handlers/memory/mod.rs` with fields `id` / `agent_id` / `content` / `session_id` / `timestamp` — the old `window_title` / `user_input` / `ai_output` / `similarity_score` fields were dropped because `RawMemory` stores a single `content` field, so `ai_output` and `window_title` were always empty strings.

```rust
pub struct MemoryEntry {
    pub id: String,
    pub window_title: String,
    pub user_input: String,
    pub ai_output: String,
    pub timestamp: i64,
    pub similarity_score: Option<f32>,
}
```

The `similarity_score` field was filtered through `deserialize_with = "deserialize_finite_f32_opt"` to drop NaN/Inf values at deserialization.

> The internal long-term-memory record is a separate `crate::memory::MemoryEntry` (src/memory/context/mod.rs) with `embedding` / `namespace` / `agent` / `context: ContextAnchor` fields for storage.

### Where These Types Were Used

| Type | Used By | Purpose |
|---|---|---|
| `MediaAttachment` | Desktop Bridge, Thinker, Tools | Multimodal content passing |
| `CapturedContext` | Desktop Bridge, Orchestrator | Context injection |
| `CompressionStats` | Memory, Gateway, Panel UI | Memory health display |
| `MemoryEntry` | Memory, Gateway | API response serialization |

## 26.7.x Addendum

### New Types

- **`SessionEvent` / `SessionEventRecord` / `TurnId`** (`src/session/events.rs`) — 26.7.7+ `session_events` is the canonical event log; `TurnId` distinguishes turns within a session. `SessionEvent` itself is `#[non_exhaustive]`, with variants covering `SessionWoken` / `RunStarted` / `TurnStarted` / `UserMessage` / `AssistantMessage` / `ToolCall*` / `Approval*` / `Compaction` and others.
- **`UnifiedMessage` / `ContentBlock`** (`src/providers/message.rs`) — 26.7.7+ LLM-agnostic intermediate message representation. `UnifiedMessage` has three variants (`User` / `Assistant` / `ToolResult`) covering what a single turn may carry; `ContentBlock` has five variants (`Text` / `Json` / `Thinking` / `ToolCall` / `Image`).
- **`ProviderDelta`** (`src/providers/delta.rs`) — streaming output events; variants include `TextDelta` / `ThinkingDelta` / `ThinkingSignatureDelta` / `ToolCallStart` / `ToolCallArgDelta` / `ToolCallArgsComplete` / `ToolCallEnd` / `Usage` / `Done` / `Error`.
- **`LoopStatus` / `LoopState`** (`src/looping/types.rs`) — 26.7.25+ loop state machine: `LoopStatus` is the `Active` / `Paused` / `Stopped` tri-state enum; `LoopState` is the per-session serializable struct (`session_id`, `prompt`, `cadence`, `next_wake_ms`, `pending_tick_wake_ms`, `iterations_used`, etc.), updated immutably (`with_*` / `spent_*` return new copies).
- **`GoalStatus` / `Goal` / `GoalStore`** (`src/goal/types.rs`) — 26.7.x new goal subsystem. `GoalStatus` is `Active` / `Paused` / `Blocked` / `Complete`; `PursuitMode` is `Passive` / `Active { max_iterations }`; `GateOutcome` splits the maker/checker confirmation (`Unchecked` / `Passed`).
- **`ArtifactRecord`** (`src/artifacts/store.rs`) — the artifact-store record type; `MAX_ARTIFACT_BYTES = 50 MiB` and `MAX_ARTIFACTS_PER_SESSION = 200` are the gates, rooted at `<aleph_data_dir>/artifacts`.
- **`AgentKeystore` / `AgentLedger` / `LedgerRecord` / `LedgerAction` / `LedgerOutcome` / `ChainReport` / `as_actor` / `current_actor`** (`src/identity/{keystore,ledger,record,verify,actor}.rs`) — per-agent Ed25519 key, hash-chained signed ledger, and the "act as" `task_local` for sub-agent / delegation attribution.
- **`NoteRelationArg`** (`src/builtin_tools/note_manage/args.rs`) — typed relation edge; an input arg of the `note_manage` tool. The read side is the `note_graph_query` tool (`src/builtin_tools/note_graph_query.rs`).
- **`CapabilityLedger`** (`src/runtimes/ledger.rs`) — per-install visible capability list rebuilt from disk (underpins `plugin.install` / `runtimes.install`); persisted as JSON.
