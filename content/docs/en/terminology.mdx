# Terminology

This page establishes canonical names for Aleph concepts to ensure consistency across documentation, code, and UI.

> **Panel top-level modes** (顶层模式): the desktop panel has seven, in nav order — Chat (`/chat`), Dashboard (`/dashboard`), Memory (`/memory`), Agents (`/agents`), Teams (`/teams`), Extensions (`/extensions`), Settings (`/settings`). Settings groups MCP / Plugins / Skills under an **Advanced** group; the ClawHub settings tab was removed.

## Core Concepts

| English | Chinese | Definition |
|---------|---------|------------|
| **Agent** | 智能体 | An AI instance with a specific configuration (model, tools, prompts) |
| **Harness** | 执行驱动 | The Think→Act loop that drives agent execution |
| **Thinker** | 思考器 | The LLM interaction layer — prompt building, model routing, streaming |
| **Orchestrator** | 编排器 | Resolves AgentDef + FlowSpec, assembles dependencies, dispatches to Harness |
| **Gateway** | 网关 | WebSocket control plane — routing, sessions, events, authentication |
| **Session** | 会话 | A persistent conversation context identified by a session key |
| **Turn** | 轮次 | One complete Think→Act cycle within a session |
| **Flow** | 流程 | A single execution request from ingress to completion |
| **FlowSpec** | 流程规范 | Defines execution parameters for a single flow |
| **AgentDef** | 智能体定义 | Static configuration defining an agent's behavior |

### The Three Twins (user-adjustable)

| English | Chinese | Definition |
|---------|---------|------------|
| **exec_tier** | 执行等级 | Determines which tools may execute and how they're approved; the permission axis |
| **think_level** | 思考等级 | LLM reasoning budget and extended-thinking toggle; the inference axis |
| **session_mode** | 会话模式 | `chat` / `work` / `code` — statically partitions the tool **presentation** surface (progressive-disclosure core set + deferred-tool tier); does not affect permissions |
| **session_set_mode** | 模式切换工具 | Runtime tool called by the model to switch mode; the new value must be carried on the same send |

### Loop-Graph Governance

| English | Chinese | Definition |
|---------|---------|------------|
| **Loop Graph** | 治理拓扑 | The governance topology layer on top of the Harness (`src/loop_graph/`); a topological answer to the four single-loop failure modes (Goodhart, reference blindness, ring conflict, measurement decay) |
| **Team Node** | 团队节点 | Node kind fusing the multi-agent system into the graph; disband triggers victory-claim watchers |
| **Audit Ring** | 审计环 | Closed-set audit action log; objective ACL source for graph audits |
| **Objective ACL** | 客观 ACL | Access control list authorized objectively by graph node identity |
| **Victory Claim** | 胜利声明 | The action by which a team/loop declares completion; triggers watchers and audit |
| **Watcher** | 观察器 | Listens for governance events (victory claim, goal settled, team disbanded) and initiates audit |
| **loop-auditor** | 循环审计员 | Built-in protected agent; audit/supervision templates default to independent-context evidence |
| **Goal** | 目标 | Persistent goal managed by GoalStore; loop settlement can trigger it |
| **LoopState** | 循环状态 | State machine of the `looping/` subsystem (Active / Paused / …) |
| **Pause / Resume** | 暂停 / 恢复 | Cross-session lifecycle control over loops and goals |

## Desktop Hosts and the Panel

| English | Chinese | Definition |
|---------|---------|------------|
| **NSH** | NSH | The target shape of the Aleph desktop end: the native desktop host crate `aleph-nsh-shell` (`desktop/nsh-shell/`), built on nsh 0.6.0 (`nsh-core` / `nsh-base` / `nsh-engine` all pinned to `=0.6.0`) |
| **Desktop Host** | 桌面宿主 | A thin native shell: window container, tray, global hotkey, notifications, credential storage, login-item status — and **no chat or session projection of its own** (`desktop/nsh-shell/src/shell_host.rs`) |
| **Panel** | 面板 | The single source of truth for the business UI: Rust + Leptos/WASM in `interfaces/webchat/`. NSH hosts this one Panel; it is not a second business UI |
| **Panel Runtime** | 面板运行时 | The modular runtime inside the Panel (`interfaces/webchat/src/panel/`): `TabRegistry` / `PanelProjection` / `PanelLoader` / `PanelSdk`; `panel-modular` is an opt-in feature |
| **Legacy Shell** | 旧桌面壳 | The transition-era Tauri v2 app (`desktop/shell/`): its own daemon supervisor, tray, auto-update, deep links, hotkey, menus, notifications. **It will be removed** |
| **embedded-core** | 内嵌核心 | An opt-in NSH compile-time feature (off by default): on a local target with the port genuinely free, it may start the bundled `aleph-server` next to the host; when the port is taken it only checks compatibility and never takes over an existing service |
| **aleph:// deep link** | aleph:// 深链 | The URL scheme NSH registers; today only the exact `aleph://open` is recognised (opens Chat), every other `aleph://` URL is ignored |

## Capability Model and Slots

| English | Chinese | Definition |
|---------|---------|------------|
| **Capability** | 能力 | The subject of the capability model in `src/capability/`: a resolvable descriptor carrying kind, facets, schema, ownership and a backend binding; it supersedes the same-named concept of the old extension model (see "Capability (extension era)" below) |
| **Capability (extension era)** | 能力（扩展期） | The old extension model's permission declaration (filesystem / network / process), backed by the historical structures in `src/extension/`; now superseded by the capability model above |
| **CapabilityKind** | 能力种类 | The kind enum of a capability (`src/capability/descriptor.rs`) |
| **CapabilityFacet** | 能力面 | A facet declared on a descriptor (e.g. permissions, UI exposure, event audience) |
| **SchemaRef** | 模式引用 | The structural contract a capability's inputs and outputs refer to (`src/capability/descriptor.rs`) |
| **OwnerGeneration / FencingToken** | 属主世代 / 围栏令牌 | The owner's generation number and fencing token, which stop a retired owner from staying effective (`src/capability/ownership.rs`) |
| **OwnershipChange** | 归属变更 | The event emitted when a capability's ownership changes |
| **Backend / BackendLease** | 后端 / 后端租约 | Where a capability is actually implemented, and the lease on it; `BackendSourceEvidence` records the source evidence (`src/capability/backend.rs`, `facade.rs`) |
| **PolicyDenial** | 策略拒绝 | The result of the policy engine refusing a capability call (`src/capability/policy_runtime.rs`) |
| **Zahir** | Zahir | The one live host for capability resolution and dispatch: `ZahirFacade` (`src/capability/zahir_facade.rs`) composes the tool backend adapter (the single source of truth for callable tools) with the `OwnershipTree` (the single source of truth for ownership / revocation / disposal), and keeps no second descriptor or handler map |
| **Slot API** | 插槽 API | `crates/aleph-slot-api/`: the pure contract authority for the slot API (error, text, tool, search / embedding, channel, approval, cancellation, webhook, AI provider). **No I/O, no platform, no LLM**, with a one-way dependency: `alephcore → aleph-slot-api` |

| **Trace** | 追踪 | Execution event stream for observability |
| **Error Receipt** | 错误回执 | Single-sourced user-readable error returned by the gateway; the raw error chain never leaks out |
| **Dead Letter** | 死信 | Messages that failed to deliver via channel.*; re-drivable from the Panel |
| **Webhook Backpressure** | Webhook 反压 | Webhook receiver returns 503 under congestion rather than silently dropping |
