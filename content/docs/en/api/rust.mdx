The `alephcore` crate is the Rust library behind every Aleph component — the Gateway daemon, the CLI, the desktop app, and the messaging interfaces. You can also use it as a library and embed Aleph's AI agent capabilities in your own Rust application.

The crate lives at the repository root (the historical `core/` sub-crate was merged into the root `Cargo.toml` in 2026-04):

```toml
# Cargo.toml
[dependencies]
alephcore = { path = "../Aleph" }
tokio = { version = "1", features = ["rt-multi-thread", "macros"] }
```

## Crate Metadata

| Field | Value |
|-------|-------|
| Crate name | `alephcore` |
| Location | the repository root `Cargo.toml` |
| Edition | 2021 |
| Minimum Rust version | 1.99 |
| Crate types | `rlib` |
| Async runtime | Tokio (multi-threaded) |
| Binaries in the same crate | `aleph-server`, `aleph-migrate` |

The crate produces an `rlib` only: the `cdylib` half had no consumer after the 2026-04 repository merge (`alephcore` exports no `extern "C"` symbols), and the WASM artifact that does ship belongs to Panel.

`aleph-server` is the Gateway daemon. `aleph-migrate` performs configuration migrations.

### Harness (Think→Act)

The harness is the Think→Act driver that owns the agent loop. It is bound by R10 ("the harness is scaffolding, not cognition"), and the ratchet in `src/harness/tests/budget.rs` enforces exactly **12 files** whose combined line count stays below `CEILING = 5,535`.

| Type | Module | Description |
|------|--------|-------------|
| `AgentHarness` | `harness` | The core Think→Act execution engine |
| `AgentHarness::new` | `harness` | Construct from `HarnessDeps` |
| `AgentHarness::run` | `harness` | Drive one full run (session id + callback + cancellation token) |
| `AgentHarness::terminate_reason` | `harness` | Why the run stopped |
| `AgentHarness::token_breakdown` | `harness` | Token counts per category |
| `AgentHarness::last_turn_context_tokens` | `harness` | Context token count of the previous turn |
| `AgentHarness::tool_timeline` | `harness` | Tool call timeline |
| `AgentHarness::duration_ms` | `harness` | Wall-clock duration |
| `AgentHarness::total_tokens` | `harness` | Total tokens consumed by the run |
| `AgentHarness::hit_limit` | `harness` | Whether the run ended on an iteration cap or context pressure |
| `HarnessDeps` | `harness::deps` | Injected dependencies: a 27-field struct literal with no `Default` and no constructor |
| `HarnessRunner` | `orchestrator::dispatch` | Polymorphic execution seam: runs an orchestration flow given a `FlowSpec` |
| `HarnessCallback` | `harness::callback` | Live event callback |
| `NoopHarnessCallback` | `harness::callback` | Default callback that drops every event |
| `HarnessError` | `harness::trait_def` | Harness error |

| `ModelRobustnessProfile` | `verification` | Per-model robustness profile |

The `HarnessCallback` hooks are `on_delta` / `on_reasoning` / `on_tool_call_start` / `on_tool_call_done` / `on_context_usage` / `on_safety_block` / `on_complete_with_outcome`.

| `SwappableProviderRegistry` | `thinker` | Registry whose current provider can be hot-swapped |

| `TokenBudget` | `thinker::prompt_budget` | Prompt budget |

### Error Handling

| Type | Module | Description |
|------|--------|-------------|
| `AlephError` | `error` | Unified error enum (forwarded from `aleph-slot-api`) |
| `AlephException` | `error` | Exception type |
| `ErrorClass` | `error` | Error classification |
| `Result<T>` | `error` | Type alias for `std::result::Result<T, AlephError>` |

Every `AlephError` variant carries an optional `suggestion` field with a user-friendly fix. Call `.suggestion()` to read it, or `.user_friendly_message()` for the formatted display string; `.class()` and `.is_transient()` support classification and retry decisions.

## Core Traits

### `AlephTool` — Static Tool Trait

```rust
#[async_trait]
pub trait AlephTool: Clone + Send + Sync + 'static {
    const NAME: &'static str;
    const DESCRIPTION: &'static str;
    const MAX_RESULT_TOKENS: Option<usize> = None;

    fn services() -> Vec<aleph_slot_api::capability::Service> {
        Vec::new()
    }

    type Args: Serialize + DeserializeOwned + JsonSchema + Send;
    type Output: Serialize + Send;

    // provided methods
    fn category(&self) -> ToolCategory { ToolCategory::Builtin }
    fn requires_confirmation(&self) -> bool { false }
    fn mutates_file_content(&self) -> bool { false }
    fn strict_schema(&self) -> bool { true }
    fn definition(&self) -> ToolDefinition { /* auto-generated JSON Schema */ }
    fn format_validation_error(&self, err: &serde_json::Error) -> String { err.to_string() }

    async fn call(&self, args: Self::Args) -> Result<Self::Output>;
    async fn call_json(&self, args: serde_json::Value) -> Result<serde_json::Value> { /* default impl */ }
}
```

The blanket implementation turns any `AlephTool` into an `AlephToolDyn`, so static tools can be stored in a dynamic collection:

```rust
let tools: Vec<Box<dyn AlephToolDyn>> = vec![
    Box::new(SearchTool::new()),
    Box::new(WebFetchTool::new()),
];
```

### `AiProvider` — LLM Backend Trait

```rust
pub trait AiProvider: Send + Sync {
    fn process<'a>(
        &'a self,
        payload: adapter::RequestPayload<'a>,
    ) -> Pin<Box<dyn Future<Output = Result<ProviderResponse>> + Send + 'a>>;

    fn name(&self) -> &str;
    fn color(&self) -> &str;
    fn supports_native_tools(&self) -> bool { false }
    fn protocol(&self) -> Cow<'_, str> { Cow::Borrowed("unknown") }

    // hint-style methods: model behavior override, behavior hint,
    // the model / provider actually serving
    fn model_behavior_override(&self) -> Option<Cow<'_, str>> { None }
    fn behavior_hint(&self) -> Option<Cow<'_, str>> { None }
    fn serving_model_hint(&self) -> Option<Cow<'_, str>> { None }
    fn serving_provider_hint(&self) -> Option<Cow<'_, str>> { None }
}
```

There is a single core method, `process`: it takes a `RequestPayload` carrying structured `UnifiedMessage` history, and the protocol adapter translates that into each vendor's native format. Streaming is handled by a provider's own delta channel rather than by the trait surface.

### `HarnessCallback` — Agent Loop Events

```rust
pub trait HarnessCallback: Send {
    fn on_delta(&mut self, text: &str) {}
    fn on_reasoning(&mut self, text: &str) {}
    fn on_tool_call_start(&mut self, id: &str, name: &str, args: &serde_json::Value) {}
    fn on_tool_call_done(
        &mut self,
        id: &str,
        result: Option<&ToolOutput>,
        error: Option<&str>,
        duration_ms: u64,
    ) {}
    fn on_context_usage(&mut self, context_tokens: u32, total_tokens: u64) {}
    fn on_safety_block(&mut self, reason: &str) {}
    fn on_complete_with_outcome(&mut self, outcome: &FlowOutcome) {}
}
```

Implement this trait to receive live events while the agent runs. The built-in implementations are `NoopHarnessCallback` (drops every event) and the Gateway-side `BroadcastCallback` (fans events out to the Gateway stream).

## Feature Flags

| Feature | Description |
|------|------|
| (default) | `default = []` — no feature is enabled |
| `loom` | Concurrency model checking (replaces the standard sync primitives) |
| `test-helpers` | Integration test helpers |
| `control-plane` | Embedded control plane (Panel assets) |
| `disabled-tests` | Disabled test modules awaiting rewrite |
| `plugin-wasm` | WASM plugin runtime (currently a reserved placeholder) |

Use feature combinations to keep the build small:

```toml
# minimal library usage (no server, no channels)
alephcore = { path = "../Aleph", default-features = false }

# control plane only
alephcore = { path = "../Aleph", features = ["control-plane"] }
```

## Usage Example

### Running an Agent Loop

`HarnessDeps` has neither `Default` nor a constructor, so every field is spelled out; seams you do not use get `None`.

```rust
use alephcore::harness::{AgentHarness, HarnessDeps, NoopHarnessCallback};
use alephcore::memory::tool_signal_sink::NoopToolSignalSink;
use alephcore::providers::{create_provider, ProviderConfig};
use alephcore::verification::ModelRobustnessProfile;
use std::sync::Arc;

#[tokio::main]
async fn main() -> alephcore::Result<()> {
    // 1. Create one provider. The harness only ever sees one AiProvider —
    //    failover is layered inside by providers::FailoverProvider.
    let provider = create_provider(
        "anthropic",
        ProviderConfig::test_config("claude-sonnet-4-20250514"),
    )?;

    // 2. Assemble the dependencies
    let deps = HarnessDeps {
        session: session_service,          // Arc<dyn SessionService>
        tools: tool_service,               // Arc<dyn ToolService>
        llm: provider,
        robustness_profile: ModelRobustnessProfile::conservative(),
        tool_descriptor_lookup: None,
        verifier_chain: None,
        context_budget: None,
        context_compactor: None,
        context_fabric: None,
        trace_sink: None,
        system_prompt: Some("You are Aleph.".to_string()),
        system_prompt_parts: None,
        recall_context: None,
        guardrails: None,
        max_iterations: Some(20),
        power: None,
        stall_config: None,
        consecutive_failure_cap: Some(8),
        turn_timeout: None,
        turn_budget: None,
        result_store: None,
        session_epoch_registrar: None,
        tool_signal_sink: Arc::new(NoopToolSignalSink),
        in_flight_tool_calls: None,
        parallel_tool_concurrency: Some(8),
    };

    // 3. Build and run
    let harness = AgentHarness::new(deps);
    let outcome = harness
        .run(&session_id, &mut NoopHarnessCallback, &cancel)
        .await?;

    println!("terminate reason: {:?}", harness.terminate_reason());
    Ok(())
}
```

### Implementing a Custom Tool

```rust
use alephcore::tools::AlephTool;
use alephcore::error::Result;
use async_trait::async_trait;
use schemars::JsonSchema;
use serde::{Deserialize, Serialize};

#[derive(Clone)]
struct WeatherTool;

#[derive(Serialize, Deserialize, JsonSchema)]
struct WeatherArgs {
    /// City to look up
    city: String,
    /// Temperature unit (Celsius or Fahrenheit)
    unit: Option<String>,
}

#[derive(Serialize)]
struct WeatherOutput {
    temperature: f64,
    condition: String,
    city: String,
}

#[async_trait]
impl AlephTool for WeatherTool {
    const NAME: &'static str = "weather";
    const DESCRIPTION: &'static str = "Get the current weather for a city";

    type Args = WeatherArgs;
    type Output = WeatherOutput;

    async fn call(&self, args: Self::Args) -> Result<Self::Output> {
        // your implementation goes here
        Ok(WeatherOutput {
            temperature: 22.0,
            condition: "clear".into(),
            city: args.city,
        })
    }
}
```

## Error Handling

`AlephError` is a `thiserror` enum defined in the `aleph-slot-api` crate and forwarded by `alephcore::error`. Every variant carries structured context:

```rust
match result {
    Err(AlephError::AuthenticationError { provider, message, suggestion }) => {
        eprintln!("{} failed to authenticate: {}", provider, message);
        if let Some(hint) = suggestion {
            eprintln!("hint: {}", hint);
        }
    }
    Err(AlephError::RateLimitError { .. }) => {
        tokio::time::sleep(Duration::from_secs(60)).await;
        // retry...
    }
    Err(e) => eprintln!("{}", e.user_friendly_message()),
    Ok(val) => { /* success */ }
}
```

Key error variants: `NetworkError`, `AuthenticationError`, `RateLimitError`, `ProviderError`, `Timeout`, `NoProviderAvailable`, `InvalidConfig`, `ConfigError`, `ToolNotFound`, `Cancelled`, `RuntimeError`, `ExecutionTimeout`, `SandboxUnavailable`.

## Async Runtime

Aleph uses Tokio with the `rt-multi-thread` feature. Every public async API returns a `Send` future compatible with the multi-threaded Tokio runtime. The key Tokio features in use:

- `rt-multi-thread` — work-stealing thread pool
- `sync` — channels, mutexes, RwLocks, semaphores
- `time` — timeouts, intervals, sleeps
- `process` — child process management
- `fs` — async filesystem operations
- `signal` — Unix signal handling
- `net` — TCP/UDP networking
