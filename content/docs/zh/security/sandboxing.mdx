## 概览

`Sandbox` trait（`src/sandbox/mod.rs`）是 exec-class 工具与操作系统之间的
**唯一** seam：

```rust
#[async_trait]
pub trait Sandbox: Send + Sync + 'static {
    async fn execute(&self, command: SandboxCommand)
        -> Result<SandboxOutput, SandboxError>;
}
```

生产装配的 `Arc<dyn Sandbox>` 指向 `WorkspaceSandbox`
（`src/sandbox/workspace/mod.rs`），它拥有三件事：

1. **工作空间供应** —— 首次执行时物化
   `~/.aleph/workspaces/{hash(session_id)}/`，保持会话生命周期，后续调用
   复用。
2. **能力强制** —— 把每个 `SandboxCommand` 与会话基线
   `SandboxCapabilities` 分类，越界请求通过 `ApprovalGate` 升级，按
   会话缓存已批准的升级。
3. **OS 隔离** —— 把实际子进程启动委托给
   `OsSandboxDriverTrait` 实现（macOS：`sandbox-exec` + Seatbelt；
   Linux：`bwrap` + Landlock + seccomp-bpf + cgroup v2；Windows：
   `AppContainer` / `RestrictedToken` / `JobObject`）。

```
exec-class 工具 (bash, code_exec, …)
        │   Arc<dyn Sandbox>
        ▼
WorkspaceSandbox   ──► ApprovalGate（能力升级）
        │
        │   OsSandboxDriverTrait
        ▼
OsSandboxDriver    ──► macOS sandbox-exec  / Linux bwrap  / Windows 三级软降级
```

**源位置：**
- Trait + re-export + 测试 helper：`src/sandbox/mod.rs`
- 六步管道：`src/sandbox/workspace/mod.rs`
- 命令策略层：`src/sandbox/command_policy/`（`rules.rs`、
  `normalize.rs`、`hooks.rs`）
- 能力：`src/sandbox/capabilities.rs`（`SandboxCapabilities` +
  `NetworkPolicy` + `is_within`）
- OS 驱动：`src/sandbox/driver.rs`（trait）+ 平台实现
- 工厂：`src/sandbox/factory.rs`
- 配置：`src/sandbox/config.rs`
- 任务局部 `SESSION_ID`：`src/sandbox/context.rs`
- Managed proxy：`src/sandbox/proxy/`（HTTP CONNECT + SOCKS5）
- Linux / macOS / Windows 适配：`src/sandbox/platforms/`

## 生命周期 —— 每会话一个工作空间

`WorkspaceSandbox` 在 `RwLock` 后维护一个
`HashMap<(SessionId, PathBuf), Arc<SessionWorkspace>>`。
`for_session(&sid, cwd, owned)` 是入口：

- **快路径**：`read().await` → 缓存命中 → 返回现有
  `Arc<SessionWorkspace>`。
- **慢路径**：`write().await` → 双重检查（另一个任务可能已创建）→
  `tokio::fs::create_dir_all(cwd)` → 插入 map。owned worktree 跳过建目录：
  沙箱不拥有那个目录。

磁盘路径是确定性的：

```
workspace_root / session_key_to_filename(session_id)
```

`session_key_to_filename`（`src/sandbox/workspace/path.rs:74`）对
JSON-serialized `SessionId` 做 SHA-256，截断到 16 字节（32 个 hex 字符）——
路径短且跨每个 `SessionKey` 变体安全。

每个 `SessionWorkspace` 持有：

- `cwd: PathBuf` —— 物化的目录
- `baseline: SandboxCapabilities` —— 政策上限（今天：`::session_baseline()`）
- `granted_elevations: RwLock<HashSet<SandboxCapabilities>>` —— 本会话
  缓存的用户已批准升级

键是 `(会话, 根)` 而不是只有会话：`granted_elevations` 描述的是**根**
不是会话，只按会话做键会把为项目 A 批的授权交给跑在项目 B 里的命令。

## 六步 `execute` 管道

`WorkspaceSandbox::execute`（`src/sandbox/workspace/mod.rs:206`）实现 spec §8
管道。进管道之前先跑 `self.os_driver.execution_preflight()?`：它只回答
「这台机器上原生沙箱的前置条件在不在」，通过**不代表**原生启动一定成功；
前置条件缺失直接返回 `SandboxError::BackendUnavailable`。

1. **Session resolve** —— `self.for_session(&cmd.session_id, jail_root,
   owned)` → 首次调用懒创建目录；否则返回缓存的
   `Arc<SessionWorkspace>`。
2. **cwd validate** —— `cmd.cwd` 要么是 `None`（默认为 workspace 根），
   要么必须 `canonicalize + starts_with(&ws.cwd)`（BUG-3 hardening：符号
   链接无法逃出）。其他情况返回 `SandboxError::CapabilityDenied { reason:
   "cwd outside workspace root" }`。
   这个判定只对当下成立：如果第 3 步真的等了人，路径会在被使用前由
   `revalidate_cwd_containment` 重新确认包含关系。
3. **Capability check** —— `cmd.capabilities.is_within(&ws.baseline)` 是
   快路径（不审批）。否则查 `granted_elevations`；请求在已批准的范围内
   通过。否则问 `ApprovalGate::request_approval_for_action`（请求带的是
   整个 `ApprovalAction`，不是工具名）。
   - `ApprovalOutcome::Approved` → 把 `cmd.capabilities` 插入
     `granted_elevations`（同一或更窄的未来请求被缓存）。
   - `ApprovalOutcome::Denied` | `Timeout` | `Unavailable` →
     `SandboxError::CapabilityDenied`。
4. **Profile generate** —— `os_driver.profile_for(&caps, &cwd)` 返回一个
   不透明的 `OsSandboxProfile`（macOS 上：SBPL profile 文本）。
5. **Run** —— `os_driver.run(program, args, env, stdin, cwd, profile,
   timeout, max_output_bytes)`。默认 60 秒超时、1 MiB 输出预算（stdout
   + stderr 分割）。两者都可以在 `WorkspaceSandbox` 上通过
   `with_timeout` / `with_max_output_bytes` 覆盖。`cmd.timeout` >
   `SandboxCapabilities.timeout_secs` > 配置的默认。
6. **Audit** —— `tracing::info!(target: "capability_ledger", …)` 记录
   `session_id`、`program`、`caps`、`exit_code`、`signal`、`duration_ms`。
   这是 capability-ledger 钩子；下游 tracing 订阅者可以下沉到想要的
   存储。

管道内，`SandboxCapabilities::is_within`
（`src/sandbox/capabilities.rs:36`）强制四个单调检查：`fs_read` ⊆（前缀）、
`fs_write` ⊆（前缀）、`network`（`None ⊆ AllowHosts ⊆ AllowAll`）、
`spawn_subprocess`（`false ⊆ any`）。

## 拥有型 worktree 与工作空间归属

生效的工作空间由运行时发布到 `EXEC_WORKSPACE`：

```rust
pub enum ExecWorkspace {
    Directory(PathBuf),
    OwnedWorktree(Arc<WorktreeHandle>),
}
```

**位置**：`src/sandbox/context.rs`

`Directory` 是普通目录（项目覆盖目录，或 agent 自己的
`~/.aleph/workspaces/{agent_id}`）；`OwnedWorktree` 是**由别人拥有**的
git worktree，比如团队 G2 为成员任务开的 detached-HEAD worktree。
沙箱只读它的路径：不创建、不删除、不修复。

两条硬规则：

- **策略根与启动目录分离** —— owned worktree 下，OS profile 用
  canonical 化后的 worktree 根作为可写根，`CARGO_TARGET_DIR` 指向
  `<root>/target`，构建产物不污染 checkout。准备执行时重新解析一次
  owned 根，结果变了就拒绝执行（`owned worktree root changed while
  preparing execution`）。
- **缺失的 worktree 绝不重建** —— `resolve_owned_root` 在目标不再是目录
  时返回 `owned worktree is no longer a directory: <path>`。创建一个同名
  空目录会让命令「成功」地跑在没有代码的空 checkout 里。

## `SandboxCapabilities`

```rust
pub struct SandboxCapabilities {
    pub fs_read: Vec<PathBuf>,
    pub fs_write: Vec<PathBuf>,
    pub network: NetworkPolicy,
    pub spawn_subprocess: bool,
}

pub enum NetworkPolicy {
    None,
    AllowAll,
    AllowHosts { hosts: Vec<String> },
}
```

`::strict()`（等价于 `::default()`）是工作空间基线：cwd 外没有 fs 访问
（OS 驱动通过 seatbelt profile 自动授予），没有网络，没有子进程生成。
任何需要更多的命令必须经 `ApprovalGate` 升级。

## 任务局部 `SESSION_ID`

exec-class 工具不知道当前 session id —— 它们的 `AlephTool::execute`
签名不携带。沙箱子系统使用 tokio `task_local!` 来传递 id 而不接触每个
工具 trait：

- `crate::sandbox::context::SESSION_ID` —— 在 `src/sandbox/context.rs`
  声明
- `current_session() -> Option<SessionId>` —— 读助手
- **写入器**：`crate::session::invoke_with_session_trace`
  （`src/session/tool_trace.rs:17`）把 `tool_svc.execute(...)` 包裹在
  `SESSION_ID.scope(session_id.clone(), async move { ... })`。

这给工具一个单一、窄的机制：
`crate::sandbox::context::current_session()` 在 scope 内返回 `Some(sid)`、
scope 外返回 `None`。需要一个工作空间但被在 session 外调用的工具可以
选择自己的 fallback 策略（今天它们依赖调用方已经显式传了
`SandboxCommand { session_id, ... }`）。

## `SandboxConfig`

```rust
pub struct SandboxConfig {
    pub workspace_root: PathBuf,       // 默认: ~/.aleph/workspaces
    pub enabled: bool,                 // 默认: true
    pub default_timeout_seconds: u64,  // 默认: 60
    pub max_output_bytes: usize,       // 默认: 1 MiB
}
```

serde 读 `[sandbox]` TOML 段并填默认值。测试 / CI 可以设 `enabled = false`
来禁用子系统；`build_sandbox` 这时会返回 `NoopSandbox`，它的 `execute`
总是用 `SandboxError::Other("sandbox disabled: …")` 报错 —— 这是有意的
fail-fast，不是静默绕过。

## 平台实现

### macOS —— sandbox-exec + Seatbelt

`src/sandbox/platforms/macos/seatbelt.rs` 走完整的 codex
`restricted_read_only_platform_defaults.sbpl`（mach-lookups 到
logd / trustd / runningboard / analyticsd、IOSurface、
system-mac-syscall、firmlink ancestors、terminal / PTY / dev handles、
`/tmp` scratch space、opt-homebrew lib）。

**`NetworkPolicy::AllowHosts`** 走**managed proxy**（Cycle 6）——
macOS 不再要求 hostname 在调用点预先解析为 IP：
- `WorkspaceSandbox::maybe_spawn_proxy` 在 `127.0.0.1:0` 上 spawn 一个
  in-process HTTP CONNECT + SOCKS5 proxy；
- `cmd.capabilities.network` 被收紧到 `AllowHosts(["127.0.0.1"])`；
- 注入标准 `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` 环境变量；
- seatbelt profile 收敛到"allow loopback only"；
- proxy 在内部强制 hostname allowlist（精确名、`*.suffix` 通配符、IP 字面量）。

### Linux —— bwrap + Landlock + seccomp-bpf + cgroup v2

`src/sandbox/platforms/linux/bwrap.rs`（`#[cfg(target_os = "linux")]`-gated）。

**Defense-in-depth（SP-2）**：bwrap 的命名空间隔离之下还有两个 LSM 机制，
由 bwrap 在挂载命名空间内启动的隐藏 `aleph-server sandbox-init` 子命令
应用：

- **Landlock**（内核 ≥ 5.13）：在 bwrap 已经给子的挂载里 in-process FS ACL。
  `READ_FILE | READ_DIR | EXECUTE` 在 `SYSTEM_READ_PATHS`（`/usr`、`/lib`、
  `/lib64`、`/bin`、`/sbin`、`/etc`）+ `SandboxCapabilities.fs_read` 上；
  完全 RW + Exec 在 `SandboxCapabilities.fs_write` + 会话 cwd 上。
- **seccomp-bpf**（内核 ≥ 3.5）：syscall denylist，返回 `EPERM`，覆盖文件
  系统操作（`mount` / `umount` / `pivot_root` / `chroot`）、内核重载
  （`kexec_*`）、模块加载（`*_module`）、eBPF、perf、`ptrace`、跨进程内存
  （`process_vm_readv` / `process_vm_writev` —— 在 `allow_fork=true`
  共享 PID-ns 路径下的独立读 / 写原语，target 不能读
  `aleph-server` 地址空间）、内核 keyring、`userfaultfd`、io_uring、
  `mknodat`、swap、syslog、reboot、命名空间切换、`clone` / `unshare` 带
  `CLONE_NEWUSER`（嵌套 user-ns 逃逸）、文件系统句柄逃逸原语
  `open_by_handle_at` / `name_to_handle_at`（用不透明句柄重新打开 inode，
  无路径名，绕过**基于路径**的 Landlock 层次检查 —— 拒绝它们关闭了
  Landlock 与 seccomp 限制层之间的缝隙）。
- **seccomp socket gate**（`SeccompNetworkMode`，按 `NetworkPolicy`
  派生）：
  - `Unrestricted`（`AllowAll` / 原始 `AllowHosts`）—— seccomp 不能按 IP
    过滤；不限制 socket family。
  - `UnixOnly`（`None`）—— 仅允许 `AF_UNIX`，deny `connect`，deny 其余
    socket surface（`accept` / `accept4` / `bind` / `listen` 等），让一个
    残留 / `AF_UNIX` fd 无法立起意外的端点。镜像 codex Restricted arm。
  - `ProxyRouted`（loopback 折叠的 `AllowHosts`，在 netns→UDS→loopback
    bridge 后面）—— 仅允许 `AF_INET` / `AF_INET6` 到达本地 bridge，deny
    `AF_UNIX` socketpair。Phase B 把 Cycle 6 的 managed proxy 扩到 Linux。

**cgroup v2 资源限制（SP-5）**：在 cgroup v2 已委派给用户时，
`BubblewrapDriver::run` 在 aleph-server 自己的 cgroup 下创建一个 per-
execution sub-cgroup 并应用：

- **`memory.max`** 从 `SandboxCapabilities.max_memory_mb`（RSS-based，让
  `mmap(PROT_NONE)` 绕过 `RLIMIT_AS` 的把戏被抓到）。
  `memory.swap.max=0` 始终（无 swap-pressure 逃逸）。
- **`cpu.max`** 从 `LinuxSandboxConfig.cpu_quota_percent`。`None` →
  不限；`Some(50)` → 一个核的 50%。
- **`pids.max`** 从 `LinuxSandboxConfig.max_pids`（默认 `Some(200)`）——
  fork bomb 防御。

`SandboxCapabilities.max_memory_mb` 在所有三个 OS 上限制沙箱进程的虚拟
地址空间：

- macOS / Linux：通过 `pre_exec` 在沙箱 helper 上 `setrlimit(RLIMIT_AS)`。
- Windows：`JOBOBJECT_EXTENDED_LIMIT_INFORMATION.ProcessMemoryLimit`。

`SandboxCapabilities.timeout_secs` 是 `SandboxConfig.default_timeout_seconds`
的 per-call 覆盖，作为 `WorkspaceSandbox::execute` 的 wall-clock 超时。
优先级，最具体的优先：显式 `SandboxCommand.timeout` >
`SandboxCapabilities.timeout_secs` > 配置的默认。`SandboxCapabilities.timeout_secs` 是
**唯一**的 timeout 载体 —— 内部 `ProcessPolicy` 不再有 `timeout_secs`
字段。

### Windows —— AppContainer（首选）→ RestrictedToken → JobObject

`src/sandbox/platforms/windows/`。

SP-6 三级软降级链（`sandbox-init-windows`）：

1. **AppContainer**（SP-6）：per-execution 唯一 profile 通过
   `CreateAppContainerProfile`；capability SID 从
   `SandboxCapabilities.network` 派生（`AllowAll` ⇒ `internetClient` /
   `privateNetworkClientServer`；`None` ⇒ nothing）；
   `CreateProcessW` 带 `EXTENDED_STARTUPINFO_PRESENT` +
   `PROC_THREAD_ATTRIBUTE_SECURITY_CAPABILITIES`。target 在 Low IL 之下
   信任级运行，带 capability-gated 资源访问。Profile 在 `wait` 后
   `DeleteAppContainerProfile`。AppContainer setup 失败时软降到 tier 2。
2. **Restricted token + Low IL**（SP-3a）：
   `CreateRestrictedToken(self, DISABLE_MAX_PRIVILEGE)` →
   `SetTokenInformation(TokenIntegrityLevel = S-1-16-4096)` →
   `CreateProcessAsUserW(target)`。target 没特权、Low IL。
3. **`CreateProcessW` 底线**：host token、Medium IL，仅在 JobObject 内。
   最后一道 —— JobObject 限制跨所有三级始终应用。

JobObject（cycle 1）：active-process limit（fork bomb 防御）、
kill-on-close、die-on-unhandled-exception、虚拟内存上限、UI 限制。

Cycle 3 / 5 收紧了 `{.git, .aleph, .codex, .agents}` 的 DACL —— 现有
路径打上 `DENY_ACCESS` ACE，缺失路径创建 stub 然后打 ACE（NTFS ACL 不能
按名 deny "create a child named `.git`"）。Cycle 5 收紧 symlink
escapes（`push_metadata_protection_args` 走
`protected_paths::first_writable_symlink_component` —— 在 writable root
内的 symlink 是 TOCTOU 载体）。

Windows 上的 `AllowHosts` **仍然硬失败**，带包含精确预解析 IP 的可读
拒绝消息 —— AppContainer SID 模型不能原生表达按 hostname 的网络过滤。
WFP（SP-3b）需要 admin 并被无限期推迟。

### R1 carve-out —— 进程隔离 FFI 留在内核

沙箱是 `src/` 里直接调平台 FFI 的**唯一**地方
（`windows-sys` 在 `src/sandbox/platforms/windows/*`、
`src/sandbox/windows_init/*`），这是**有意的 R1 carve-out，不是违反**。
restricted-token / job-object / AppContainer / integrity-level / SID·ACL
调用必须由父**在 spawn 时**做出 —— 你无法从一个独立 helper 沙箱化一个
进程，把 spawn-time restricted token 走一个 IPC round-trip 会削弱安全
模型。`src/builtin_tools/desktop/session_lock.rs` 里的本地 PID 活性探测
（`OpenProcess` / `GetExitCodeProcess`）也出于同样原因留在内核。

R1 瞄准桌面 UI / 屏幕 / Vision 这些**四肢**，它们仍然走 Swift bridge 证明
—— 由 `src/` 携带零直接 `cocoa` / `objc` / `core-graphics` 使用证明。

## `[sandbox.command_policy]` —— 硬线命令过滤

`src/sandbox/command_policy/` 在 OS 沙箱**之前**增加命令**内容**级的
hard-filter，模仿 clawshell 的 DLP `[[patterns]]` 引擎，但专门用于 shell
命令，并通过 `regex::RegexSet`（Aho-Corasick 备份）单次扫描求值，而不是
顺序 `Vec<Regex>` 扫描。它是 R7 批准的硬过滤，**不是**意图分类器：
它拒绝一小套经过策划的"永远不合法"的模式并审计一个略大的可疑集合；
它从不推理模型意图。

- **布线**：实现为 `SandboxBeforeHook`（`RateLimitHook` 的兄弟），并由
  `build_sandbox` **第一个**安装在 hook 链里 —— 一个被阻止的命令在消耗
  rate-limit 预算或到达驱动之前被拒绝。**管道零变更** —— 它复用现有的
  `hooks.run_before()` → `Deny` 路径，工作空间已经把它映射到
  `SandboxError::Other`。
- **规则集**（`rules.rs`）：`Block` = fork bomb、`rm --no-preserve-root`、
  裸根 `rm -rf /` / `rm -rf //` / `/.`（cycle 7 收紧 multi-slash /
  dot bypass）、`dd of=/dev/<disk>`、`mkfs /dev/…`、重定向到裸块设备、
  `wipefs` / `blkdiscard` / `shred` 一个设备。`Warn`（仅审计） =
  `rm -rf` 绝对系统路径、`curl|wget … | sh`、`chmod 777` 系统路径、
  写到 `/etc/{passwd,shadow,sudoers}`、`/dev/tcp/` reverse shell、host
  shutdown / reboot、`sudo -S` / `--stdin` / `--askpass` / `-s`、写到
  `~/.ssh/authorized_keys`。
- **Windows 形状**（2026-06-15 添加，2026-07-27 加深）：`Block` =
  `format <drive:>` / `Format-Volume`；驱动器 / 注册表单元根的递归
  删除（`del` / `rd` / `rmdir /s` 与 `Remove-Item -Recurse` 全部别名）、
  shadow-copy 销毁（`vssadmin delete shadows` / `wmic shadowcopy
  delete`）、backup-catalog 销毁（`wbadmin delete catalog|systemstatebackup`）、
  raw-disk 销毁（`Clear-Disk -RemoveData`、`diskpart … clean`、写到
  `\\.\PhysicalDriveN`）、`bcdedit /delete`、`bcdedit /set …
  recoveryenabled No`、`bootstatuspolicy ignoreallfailures`、全 hive
  `reg delete HKLM /f`。`Warn` = Windows 系统位置的递归删除
  （`\Windows`、`\Program Files`、`\ProgramData`、bare `\Users` 根）、
  `powershell -EncodedCommand`（包装本身）、下载执行 cradle
  （`IEX (…).DownloadString`、`iwr … | iex`、`certutil -urlcache`、
  `bitsadmin /transfer`）、禁用 Defender、禁用防火墙、弱化执行策略、
  AMSI 篡改、事件日志清除、本地账户后门、自动启动持久化、ACL takeover。
- **规范化**（`normalize.rs`）折叠 shell 逐字执行的 evasion：隐形字符、
  cmd `^` 与 PowerShell `` ` `` 转义、空引号对，以及三个 Windows 特定
  读法（`\` 的双重读法、路径前缀规范化、`-EncodedCommand` 展开）。因为
  这发生在规范化器里，**早于** tier 分割，`enforcement = "off"` 不能恢复
  盲点。
- **配置**（`[sandbox.command_policy]`）：`enabled`、`enforcement`
  （`block` / `warn` / `off`）、`use_default_rules`、`custom_rules[]`
  （`{name, regex, action, description}`）。一个格式错的 custom regex
  **安全失败** —— boot log 出错的规则名并 fallback 到策划的默认值，
  而不是没过滤器地运行。
- **扫描目标**：`program` + 空格连接的 `args` + 任何 UTF-8 `stdin` 载荷
  （`bash -s` 大脚本路径），限制到 256 KiB。
- **审计**：匹配 log 到 `command_policy` tracing target（与
  `capability_ledger` / `sandbox_rate_limit` 并行）。
- **非破坏**：默认只 block 基本上没有合法工作空间用途的模式；相对路径
  `rm -rf build/` 与普通命令不受影响。OS 沙箱仍是真正的强制器。

## 测试模式

沙箱栈在每个 seam 都可测，无需真实子进程或 OS 沙箱：

- **Fake OS driver** —— 实现 `OsSandboxDriverTrait`，统计 `run` 调用，
  返回 canned `SandboxOutput`。被 `src/sandbox/workspace/mod.rs` 单元测试与
  集成测试使用。
- **Fake approval requester** —— 实现 `ApprovalRequester`，把结果 box
  给 `ApprovalGate::new(cfg, Some(Box::new(requester)))`。单元测试用它
  驱动步骤 3 的每个分支（approve / deny / cached）。
- **`MockSandbox`**（`src/sandbox/mod.rs:89`，`#[cfg(test)]`）—— 记录
  每个 `SandboxCommand` 并返回 canned `SandboxOutput`。被 exec-class 工具
  （`bash`、`code_exec`）用来断言它们走沙箱 seam。
- **集成** —— `tests/sandbox_capability_approval.rs` 用 fake driver + fake
  requester 装配走完整管道。四种情况：strict caps 跳过审批；网络提升
  approve 到达驱动；spawn denied 返回 `CapabilityDenied` 不到达驱动；
  审批在同一会话内跨两次调用缓存。

不接触 exec 的测试可以通过构造 `SandboxConfig { enabled: false, .. }`
完全跳过子系统 —— `build_sandbox` 返回 `NoopSandbox`。

## Desktop Bridge 边界

Swift `AlephBridge` helper 进程运行在 Rust 沙箱**之外**：它必须在自己的
bundle 里持有 camera / microphone / speech / accessibility TCC 授权，并调
用不能跑在 `sandbox-exec` profile 里的原生框架。反过来，Rust core 保持
沙箱友好因为所有原生 API 调用都通过 helper over stdio 代理。

绝不能被任何 bridge handler 违反的硬规则：

- Bridge 进程**不得**打开任何 TCP 或 Unix domain socket。IPC 只使用继承的
  stdio pipes。
- Bridge **不得**读写 `~/.aleph/data/`、`.shared_token` 文件或任何其他
  vault 路径。Vault 访问专属于 Rust core。任何第二个进程并发写入会损坏
  加密 vault 并不可恢复地破坏存储的 API key、OAuth token 与 embedding key。
- 权限状态由 macOS TCC 拥有；bridge 仅通过 `perm.check` 反映它，并在
  `-32001` 错误中返回 `PermissionGuide`。bridge 不授予也不撤销权限。
- 任何未来新增的 bridge handler **必须**包含一条注释解释它为什么不碰
  `~/.aleph/`。bridge 代码评审检查这个不变量。
