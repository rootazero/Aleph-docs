本页说明 Gateway 如何识别调用者，以及工具权限、执行审批、沙箱和审计如何分别约束操作。

## 安全架构

| 层 | 负责什么 | 实现 |
|----|----------|------|
| 入口 | 检查连接传输、来源、凭据或 Unix socket 对端 | `src/gateway/server/connection/`、`src/gateway/origin_policy.rs` |
| 工具权限 | 在分发时应用工具权限和执行级别 | `src/tools/scoped/` |
| 执行审批 | 把操作员决策绑定到本次操作，而不是只看工具名 | `src/sandbox/exec_approval/` |
| 沙箱 | 按工作区和能力限制执行，并应用平台沙箱 | `src/sandbox/workspace/`、`src/sandbox/platforms/` |
| 审计 | 保存安全事件、审批决策及签名身份记录 | `src/security/audit.rs`、`src/tools/scoped/dispatch.rs`、`src/identity/` |

## 网络边界与 Gateway 凭据

Gateway 默认在环回地址上监听。兼容 `/ws` 只对未带设备凭据的直连环回提供隐式 `operator` 授权；远端需要有效设备令牌、引导票或旧共享令牌。非环回明文连接默认被拒绝；可用原生 TLS 或为兼容入口配置受信 TLS 代理。浏览器通过来源检查并不意味着通过身份验证（`src/gateway/config.rs`、`src/gateway/server/mod.rs`、`src/gateway/server/connection/upgrade.rs`、`src/gateway/handlers/connect.rs`）。

默认连接地址不是所有入口共同的信任模型。Desktop IPC 通过 Unix socket 校验对端；Web v1 使用原生 TLS、同源检查与设备会话。两者均执行共享的[协议 v1 方法清单](../gateway/protocol-v1)（`src/gateway/server/connection/local_ipc.rs`、`src/gateway/server/connection/web_v1.rs`）。详见[网关认证](../gateway/auth)和 [IPC 协议](./ipc)。

### 远程 TLS 与客户端信任

Gateway 可加载指定证书，也可生成自签证书。传输加密与调用者授权是两道检查；使用自签证书仍需让客户端信任该证书。NSH 的远端 `--connect` 目标必须使用 HTTPS（`src/gateway/tls.rs`、`src/gateway/server/connection/upgrade.rs`、`desktop/nsh-shell/src/main.rs`、`shared/client/src/connection_target.rs`）。

## 配对

### 设备配对

`gateway.ticket.create` 创建一次性引导票；兼容 `/ws` 的 `connect.bootstrap_ticket` 可兑换设备令牌，用于后续重连。Web v1 的交换要求票绑定主体。撤销一个设备用 `gateway.devices.revoke`；共享令牌轮换会撤销 Panel 设备凭据（`src/gateway/handlers/gateway_ticket.rs`、`src/gateway/handlers/connect.rs`、`src/gateway/security/device_token_manager.rs`、`src/gateway/server/connection/web_v1.rs`、`src/gateway/handlers/gateway_devices.rs`、`src/gateway/handlers/gateway_token.rs`）。

### 频道发送者配对

未知发送者的频道配对与 Gateway 设备身份无关。配对码由独立存储管理，操作员用 `pairing.list` 查看请求，再用 `pairing.approve` 或 `pairing.reject` 处理（`src/gateway/pairing_store.rs`、`src/gateway/handlers/pairing.rs`）。

## 工具权限

`ScopedToolService` 合并全局、agent 和频道工具权限，分发时结合显式 `allow` / `ask` / `deny` 和执行级别。`ToolFacts` 提供是否幂等、是否需要审批等元数据；命令硬拒绝由沙箱命令策略处理，不因 Gateway 已认证而放行（`src/tools/scoped/`、`src/sandbox/command_policy/`）。

## 执行审批门

Panel 上的审批控件让操作员允许或拒绝待处理的敏感调用，并经 `exec.approval.resolve` 发送决策（`interfaces/webchat/src/components/approval_card.rs`、`interfaces/webchat/src/api/exec_approval.rs`、`src/gateway/handlers/exec_approvals.rs`）。审批门通过 `ApprovalAction` 将授权绑定到工具与原始的规范化参数；用户可见的脱敏摘要不参与授权指纹计算（`src/sandbox/exec_approval/action.rs`）。

## 沙箱

`WorkspaceSandbox` 根据工作区和能力约束执行。命令策略先过滤明确禁止的命令，不能用审批绕过。平台实现位于 `src/sandbox/platforms/macos/`、`src/sandbox/platforms/linux/` 和 `src/sandbox/platforms/windows/`；各平台机制与限制见[沙箱](./sandboxing)（`src/sandbox/workspace/`、`src/sandbox/command_policy/`）。

## 审计

- 安全审计记录包括兼容 WS 的远端认证失败和未授权请求洪泛（`src/security/audit.rs`、`src/gateway/server/connection/mod.rs`）。
- 工具分发可把 `ToolCallApproved`、`ToolCallDenied` 写入会话事件（`src/tools/scoped/dispatch.rs`）。
- Agent 签名账本用 Ed25519 签名和哈希链记录与 agent 身份关联的操作（`src/identity/`）。

## 跨进程状态保护

Aleph 用实例锁保护服务启动；Vault 与 JSON 文件有各自的原子写入路径；SQLite 使用统一的安全打开辅助函数。CLI 通过 `CommandPolicy` 区分不取锁、取锁或走管理 IPC 的命令（`src/utils/instance_lock.rs`、`src/utils/vault_io.rs`、`src/utils/atomic_io.rs`、`src/utils/sqlite_open.rs`、`src/cli/policy.rs`）。
