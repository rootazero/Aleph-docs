本页说明 Panel 与本地客户端如何进入 Gateway，以及来源、身份和执行审批分别在哪里检查。

## 入口与信任边界

| 入口 | 传输与身份 | RPC 范围 | 实现 |
|------|-----------|----------|------|
| Desktop IPC | Unix domain socket；校验对端身份，不授予网络连接权限 | 只读：先 `system.hello`，随后只允许 `health`、`sessions.list` | `src/gateway/server/connection/local_ipc.rs` |
| Web v1 | Gateway 原生 TLS；`POST /v1/session` 换取会话 cookie，`GET /v1/ws` 校验会话后升级 | 只读：先 `system.hello`，随后只允许 `health`、`sessions.list` | `src/gateway/server/mod.rs`、`src/gateway/server/connection/web_v1.rs` |
| 兼容 WebSocket | 默认 `ws://127.0.0.1:18790/ws`；`connect` 区分直连环回与出示凭据的远端 | 兼容控制平面；认证与传输门见[网关认证](../gateway/auth) | `src/gateway/config.rs`、`src/gateway/server/connection/upgrade.rs`、`src/gateway/handlers/connect.rs` |

## Desktop IPC：本地只读 socket

用 `aleph-server start --desktop-ipc <socket>` 显式启用 Unix listener（`src/bin/aleph-server/cli.rs`、`src/bin/aleph-server/commands/start/mod.rs`）。服务端每个 listener 最多同时处理 8 个连接，要求 socket 对端有效用户相同，并且只在存在有效桌面所有者时处理请求。每连接共享 16 MiB 的 wire budget，单次写入期限 5 秒。分发使用占位 IP `0.0.0.0`，不因本地 IPC 获得网络入口的环回特权（`src/gateway/server/connection/local_ipc.rs`）。

有界帧由 `shared/protocol/src/framing.rs` 定义。客户端帧上限为 8,388,608 字节，同时在途请求最多 8 个，`system.hello` 超时 5 秒（`shared/client/src/local_ipc.rs`）。NSH 的 `--desktop-ipc-status <socket>` 只查询已有 Gateway 的健康状态，不打开 Panel，也不降级到 WebSocket（`desktop/nsh-shell/src/main.rs`、`desktop/nsh-shell/src/ipc_status.rs`）。

## Panel 来源校验与跨站防护

### Web v1：严格 HTTPS 同源

`same_origin` 在会话交换和 WS 升级时都要求 `Origin` 精确匹配请求 authority 推导出的 HTTPS origin，并拒绝带查询串的请求；`throttle` 按客户端地址限流。`redeem` 验证设备令牌或兑换引导票；`cookie_handle` 读取会话句柄，升级还会核对绑定的 origin 与当前设备身份。Cookie 标有 `Secure`、`HttpOnly`、`SameSite=Strict`（`src/gateway/server/connection/web_v1.rs`）。这个入口不借用兼容 `/ws` 的来源白名单。

### 兼容 `/ws`：来源与认证分开

`ws_upgrade_handler` 调用 `OriginPolicy::is_allowed`，来源不符返回 `403`（`src/gateway/server/connection/upgrade.rs`、`src/gateway/origin_policy.rs`）。规则如下：

| `Origin` | 默认判定 |
|----------|----------|
| 缺失或为空 | 通过来源检查；不代表通过认证 |
| 与 `[gateway] allowed_origins` 中一项精确匹配（忽略大小写） | 通过 |
| HTTP(S) 的 authority 与请求 `Host` 一致，且 `Host` 是 IP 字面量或环回主机 | 通过；例如 `http://127.0.0.1:18790` 对应 `127.0.0.1:18790` |
| 旧桌面 webview 的专用 scheme | 仍有兼容例外，不是 NSH 的来源规则 |
| 其他 | 拒绝；域名同源、不匹配端口的环回页面均不会自动放行 |

`allow_any_origin = true` 会绕过此检查，不建议开启（`src/gateway/config.rs`、`src/gateway/origin_policy.rs`）。NSH 加载的 Panel origin 由 `ConnectionTarget` 约束：远端使用 HTTPS，导航比较 scheme、host、port。`aleph://open` 是宿主单独处理的精确深链，不是 Panel 来源，也不授予 RPC 权限（`shared/client/src/connection_target.rs`、`desktop/nsh-shell/src/panel_bridge.rs`）。

## 敏感操作与审计

### 执行审批

允许页面连接不等于批准执行。Panel 通过 `exec.approval.resolve` 提交用户决策；Gateway 处理审批，执行门按工具和规范化参数绑定授权。可见的审批摘要做脱敏，不拿脱敏值计算授权指纹（`interfaces/webchat/src/api/exec_approval.rs`、`src/gateway/handlers/exec_approvals.rs`、`src/sandbox/exec_approval/action.rs`）。两条只读入口均不开放审批 RPC（`src/gateway/server/connection/local_ipc.rs`、`src/gateway/server/connection/web_v1.rs`）。

### 凭据存储和日志

Gateway 的安全存储在 `src/gateway/security/store/`，设备令牌按哈希校验（`src/gateway/security/device_token_manager.rs`）。NSH 的凭据服务使用共享客户端的 OS 钥匙串存储；不可用时不回退到明文存储（`desktop/nsh-shell/src/credentials.rs`、`shared/client/src/credential_store.rs`）。

兼容连接的认证失败和未认证请求洪泛可写入安全审计日志；Desktop IPC 的 peer 关闭日志只记录错误类别。未在本阶段核实所有日志都经过同一脱敏器，不要把审批摘要的脱敏范围扩展成对所有日志的保证（`src/gateway/server/connection/mod.rs`、`src/security/audit.rs`、`src/gateway/server/connection/local_ipc.rs`）。

### 请求追踪与健康探针

Gateway 共用分发器可采用 RPC 参数中的 `traceparent` 关联请求（`src/gateway/server/connection/dispatch.rs`、`src/gateway/trace_context.rs`）。Gateway 路由还提供 `/health`、`/ready` 和 `/metrics` 三个独立 HTTP 探针；它们不是 Desktop IPC socket 的方法（`src/gateway/server/mod.rs`、`src/gateway/server/probe.rs`、`src/gateway/server/metrics_endpoint.rs`）。
