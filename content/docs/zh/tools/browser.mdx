## 概述

Aleph 的浏览器自动化以一组 **单职责工具** 的形式暴露给 agent —— 不是
一个带 `action` 参数的单一 `browser` 工具。每个工具聚焦一个动作
（点击、导航、截图、快照、填充、按下按键、上传、悬停、滚动、评估 JS …），
通过 `Arc<ProfileManager>` 共享浏览器实例。

底层支持两个后端：

- **Playwright CLI**（`src/browser/playwright_cli_backend.rs`）
- **Chrome DevTools MCP**（`src/browser/chrome_mcp_backend.rs`）

二者通过统一的 `BrowserBackend` trait 暴露 —— `browser_*` 工具不区分
后端，profile 决定哪一个会启动。

**源位置：**
- 后端：`src/browser/backend.rs`
- Per-action 工具：`src/builtin_tools/browser_tools/`（每个动作一个文件）
- Profile 管理：`src/browser/profile.rs`、`src/browser/manager.rs`
- 网络策略：`src/browser/network_policy.rs`（SSRF 防护）
- 标签页注册：`src/browser/tab_registry.rs`
- Chromium 发现：`src/browser/discovery.rs`

## 浏览器后端

每个 profile 在创建时绑定一个 backend：

| 后端 | 何时使用 |
|------|---------|
| `PlaywrightCliBackend` | 默认；最广泛支持，无外部服务。 |
| `ChromeMcpBackend` | 已经运行了 Chrome DevTools MCP 服务器，或需要 CDP 精细控制。 |

`browser_profile` 工具创建 / 列出 / 删除 profile；`browser_session` 工具
查询当前活跃会话。

## 元素定位

元素定位有三种方式，按优先级：

### 1. ARIA `ref_id`（首选）

ARIA 快照里的每个元素都有一个唯一的 `ref_id`。这是最可靠的定位方法，
因为它通过可访问性树的位置引用元素：

```json
{ "action": "click", "tab_id": "...", "ref_id": "e42" }
```

先调用 `browser_snapshot` 获取 `ref_id`，再定位。

### 2. 坐标 `(x, y)`

后备：当 `ref_id` 不可用时，直接传视口坐标。

```json
{ "action": "click", "tab_id": "...", "x": 312, "y": 540 }
```

### 3. CSS 选择器 —— **已撤除**

`browser_click`（以及其它定位工具）不再接受 `selector` 字段。传
`selector` 现在返回错误：

```
CSS selector targeting is no longer supported. Use 'ref_id' from browser_snapshot.
```

ARIA `ref_id` 与坐标同时是稳定且通用的方式。

## 工具清单

### 生命周期

| 工具 | 描述 |
|------|------|
| `browser_profile` | 创建 / 列出 / 删除 profile。 |
| `browser_session` | 查询当前活跃会话。 |
| `browser_open` | 启动 profile 的浏览器实例并打开一个新标签页。 |
| `browser_tabs` | 列出 / 打开 / 关闭标签页。 |

### 导航与观察

| 工具 | 描述 |
|------|------|
| `browser_navigate` | 导航现有标签页到 URL。 |
| `browser_snapshot` | 获取 ARIA 可访问性树。 |
| `browser_screenshot` | 截图（PNG / JPEG / WebP），可选 `full_page`。 |
| `browser_evaluate` | 在标签页中执行 JavaScript。 |

### 元素交互

| 工具 | 描述 |
|------|------|
| `browser_click` | 点击元素（`ref_id` 或坐标；`double=true` 双击）。 |
| `browser_type` | 追加文本（**追加**到 value，触发 `input` 事件）。 |
| `browser_fill_form` | 一次性填充多个字段（结构化 JSON）。 |
| `browser_press_key` | 按下单个键（`Enter` / `Tab` / 箭头键 / 等）。 |
| `browser_hover` | 触发 `mouseenter` / `mouseover`。 |
| `browser_scroll` | 滚动（方向 + 增量）。 |
| `browser_select` | 选择 `<select>` 选项。 |
| `browser_drag` | 拖拽（`from` + `to`）。 |
| `browser_upload` | 上传文件到 input。 |

### 观察与调试

| 工具 | 描述 |
|------|------|
| `browser_console` | 读控制台日志。 |
| `browser_network` | 读网络请求 / 响应。 |
| `browser_cookies` | 列出 / 设置 / 清除 cookies。 |
| `browser_dialog` | 接受 / 关闭浏览器对话框（alert / confirm / prompt）。 |

### 会话状态

| 工具 | 描述 |
|------|------|
| `browser_emulate` | 模拟设备 / 网络条件。 |
| `browser_resize` | 视口尺寸。 |
| `browser_wait_for` | 等待选择器 / 文本 / 函数返回值。 |
| `browser_pdf` | 标签页另存为 PDF。 |

## 典型工作流

```
browser_open → browser_snapshot → browser_click / browser_fill_form
                                  → browser_screenshot (可选验证)
                                  → browser_evaluate (可选数据提取)
                                  → browser_tabs (action="close") (或 browser_session 结束)
```

每个工具都接受 `profile` 字段（默认 `"default"`）以及后端特定的额外字段。

## ARIA 无障碍快照

无障碍快照给页面提供结构化表示。`browser_snapshot` 返回：

```json
{
  "elements": [
    {
      "ref_id": "e1",
      "role": "heading",
      "name": "Welcome",
      "bounds": { "x": 100, "y": 50, "width": 300, "height": 40 }
    },
    {
      "ref_id": "e42",
      "role": "button",
      "name": "Submit",
      "state": ["focused"],
      "bounds": { "x": 200, "y": 400, "width": 120, "height": 36 }
    }
  ],
  "page_title": "My Page",
  "page_url": "https://example.com",
  "focused_ref": "e42"
}
```

`ref_id` 是一次快照有效的；后续的 `browser_snapshot` 会重新分配。

## 审批策略

所有 `browser_*` 工具接受一个用户定义的 `ApprovalPolicy`
（`src/approval/`），对敏感动作进行门控：

门控的粒度是**动作类别**而不是工具名：`src/approval/types.rs` 用
`declare_action_types!` 声明 `ActionType`（`#[non_exhaustive]`），每个
`browser_*` 工具在执行前把自己的动作类别交给
`check_browser_approval`（`src/builtin_tools/browser_tools/mod.rs`）。

| 动作类别 | 覆盖的工具 | 默认决策 |
|---------|-----------|---------|
| `BrowserNavigate` | `browser_navigate`、`browser_exec` 的 navigate | Allow |
| `BrowserClick` | `browser_click`、`browser_exec` 的 click / dblclick | Allow |
| `BrowserType` | `browser_type`、`browser_exec` 的 type | Allow |
| `BrowserFill` | `browser_fill_form`、`browser_exec` 的 fill | Allow |
| `BrowserPressKey` | `browser_press_key`、`browser_exec` 的 press_key | Allow |
| `BrowserScroll` | `browser_scroll`、`browser_exec` 的 scroll | Allow |
| `BrowserHover` | `browser_hover`、`browser_exec` 的 hover | Allow |
| `BrowserEvaluate` | `browser_evaluate`、`browser_exec` 的 evaluate | Ask |
| `BrowserOpen` | `browser_open` | Ask |
| `BrowserSwitchEngine` | `browser_session` 的引擎切换 | Ask |
| `BrowserSessionState` | `browser_session` 的保存 / 加载 | Ask |
| `BrowserSelect` | `browser_select`、`browser_exec` 的 select | Ask |
| `BrowserDialog` | `browser_dialog`、`browser_exec` 的 dialog | Ask |
| `BrowserDrag` | `browser_drag` | Ask |
| `BrowserUpload` | `browser_upload` | Ask |
| `BrowserCookiesWrite` | `browser_cookies` 的写操作 | Ask |
| `BrowserIdentityOverride` | `browser_emulate` | Ask |
| `BrowserNetworkMock` | `browser_network` 的 mock 路由 | Ask |
| `BrowserRecord` | `browser_record` 的 start | Ask |

默认决策来自 `src/approval/config.rs` 的策展默认值：读页与导航类动作
放行，会改页面状态或读页面外数据的动作（脚本执行、开新实例、换引擎、
存会话、选选项、点对话框、拖拽、上传、写 cookie、改身份、装网络 mock、
开始录制）一律 `Ask`，由人来裁决。

不进策略面的工具：`browser_profile`、`browser_tabs`（含关闭标签页）、
`browser_snapshot`、`browser_screenshot`、`browser_console`、`browser_resize`、
`browser_wait_for`、`browser_pdf`、`browser_qa`。其中 `browser_network` 的
**读取**请求记录也不走闸，只有 mock 路由走 `BrowserNetworkMock`。

策略拒绝时调用返回 `success: false` 加拒绝原因；策略要求确认时返回
`success: false` 加 `Approval required: …` 提示；agent 据此转交用户。

## 网络策略

所有浏览器导航都通过 `BrowserSsrfGuard`
（`src/browser/network_policy.rs`）—— 与工具 SSRF 引擎共享
`SsrfPolicy`。私网、链接本地、loopback 与云元数据端点默认被拒。

## 优雅降级

未配置 profile 的 `browser_*` 调用返回友好消息而不是错误：

```json
{
  "success": false,
  "message": "No browser profile configured. Use browser_profile to create one first."
}
```

agent 据此自动创建 profile 并启动浏览器，无需错误样板。

## 安全注意事项

- **进程隔离**：浏览器作为独立 Chromium 进程运行在自己的沙箱里。
- **无头模式**：在生产环境用 `headless: true` 避免视觉干扰。
- **审批策略**：通过审批系统控制敏感动作（导航、JS 评估、上传）。
- **用户数据目录**：用专用浏览器 profile 把 cookie 和存储与用户个人
  浏览器隔离。
- **JS 评估**：`browser_evaluate` 可在页面上下文执行任意 JS —— 强大但在
  安全敏感部署中应被审批策略控制。
- **反自动化标志**：默认 Chromium 标志减少机器人检测，但部分网站可能
  仍会阻止自动化访问。

## 示例：搜索并提取

```
1. browser_profile(action="create", id="default", headless=true)
   -> profile created

2. browser_open(profile="default", url="https://blog.rust-lang.org/")
   -> tab_id="TAB_001"

3. browser_snapshot(profile="default", tab_id="TAB_001")
   -> { elements: [
         { ref_id: "e1", role: "heading", name: "Rust Blog" },
         { ref_id: "e5", role: "link", name: "Rust 1.84.0" },
         …
       ]}

4. browser_click(profile="default", tab_id="TAB_001", ref_id="e5")
   -> success

5. browser_snapshot(profile="default", tab_id="TAB_001")
   -> new ref ids for the announcement page

6. browser_evaluate(profile="default", tab_id="TAB_001",
                    js="document.body.innerText")
   -> extracted text

7. browser_tabs(action="close", tab_id="TAB_001")
```
