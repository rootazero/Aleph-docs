## 概述

你可以通过创建自定义工具来扩展 Aleph 的功能。三种主要路径，按集成深度排序：

| 方法 | 语言 | 注册 | 最适合 |
|------|------|------|--------|
| **Rust 内置** | Rust | 编译时 | 核心功能，最大性能 |
| **MCP 服务器** | 任意（Node.js、Python 等） | 运行时 | 外部集成，多语言团队 |
| **Markdown 技能** | Markdown + 提示 | 运行时 | 基于提示的工作流，无需代码 |

所有工具调用最终都通过 **同一个强制点**：`ScopedToolService`
（`src/tools/scoped/`）。它把按频道合并的 `tool_permissions`、执行 tier
（Ask / Auto / Full）与沙箱命令策略层统一在一个路径上 —— 写新工具时，
这个强制点决定你的工具是否需要在注册时携带 `requires_confirmation` 元数据
或沙箱依赖。

## 创建 Rust 内置工具

这是集成最深的方法。你的工具被编译到 Aleph 的二进制文件中，静态分发，
零成本抽象。

### 步骤 1：定义参数类型

为你的工具的输入参数创建一个结构体。派生 `JsonSchema` 让 schema 自动
生成 —— 字段上的文档注释会成为 LLM 看到的参数描述：

```rust
// src/builtin_tools/weather.rs

use schemars::JsonSchema;
use serde::{Deserialize, Serialize};

/// 天气工具的参数
#[derive(Debug, Clone, Serialize, Deserialize, JsonSchema)]
pub struct WeatherArgs {
    /// 城市名称或坐标（例如 "Tokyo" 或 "35.6762,139.6503"）
    pub location: String,

    /// 温度单位："celsius" 或 "fahrenheit"（默认：celsius）
    #[serde(default = "default_unit")]
    pub unit: String,

    /// 预报天数（1-7，默认：1）
    #[serde(default = "default_days")]
    pub days: u8,
}

fn default_unit() -> String { "celsius".to_string() }
fn default_days() -> u8 { 1 }
```

`required` 数组是自动计算的 —— 只有不带 `#[serde(default)]` 的字段才是
必需的。

### 步骤 2：定义输出类型

输出结构体被序列化为 JSON 并返回给 LLM：

```rust
/// 天气工具的输出
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct WeatherOutput {
    pub city: String,
    pub temperature: f64,
    pub unit: String,
    pub condition: String,
    pub forecast: Vec<ForecastDay>,
}
```

### 步骤 3：实现 `AlephTool` trait

```rust
use async_trait::async_trait;
use crate::error::Result;
use crate::tools::AlephTool;

#[derive(Clone)]
pub struct WeatherTool {
    api_key: String,
    client: reqwest::Client,
}

#[async_trait]
impl AlephTool for WeatherTool {
    const NAME: &'static str = "weather";

    const DESCRIPTION: &'static str =
        "Get current weather and forecast for a location. \
         Returns temperature, conditions, and multi-day forecast.";

    type Args = WeatherArgs;
    type Output = WeatherOutput;

    async fn call(&self, args: Self::Args) -> Result<Self::Output> {
        let response = self.client
            .get("https://api.weather.example.com/v1/forecast")
            .query(&[
                ("location", &args.location),
                ("unit", &args.unit),
                ("days", &args.days.to_string()),
                ("key", &self.api_key),
            ])
            .send()
            .await?
            .json::<WeatherOutput>()
            .await?;
        Ok(response)
    }
}
```

### 步骤 4：在注册表中注册

内置工具不通过手写 builder 注册；它们由 executor 的 builtin 注册表
（`src/executor/builtin_registry/`）装配。把工具添加到
`src/builtin_tools/mod.rs`：

```rust
pub mod weather;
pub use weather::{WeatherTool, WeatherArgs, WeatherOutput};
```

注册表会创建实例并把共享依赖（`Arc<Sandbox>`、`Arc<ProfileManager>`、
`Arc<McpManagerHandle>` …）注入到需要它们的工具里。一个没有携带必需
依赖的工具返回结构化的"sandbox 未配置"或"manager 未配置"错误，**不会**
回退到无沙箱执行 —— 默认是安全的，不是宽松的。

如果你的工具执行子进程，必须持有 `Arc<dyn Sandbox>` 并把命令交给它
（`src/sandbox/mod.rs::Sandbox` trait）。`src/builtin_tools/` 内 exec 类
工具里 **不允许** `Command::new`。

### 步骤 5：标记审批语义

`ScopedToolService` 读取 `ToolDefinitionMetadata`，**不**读工具名：

- `idempotent` ← `LoopTool::is_idempotent()` 或一个 MCP 服务器的
  `idempotentHint`。未声明 = `false` ⇒ `Ask` tier 下要求审批。
- `requires_approval` ← `destructiveHint`（MCP）或工具在
  `CONFIRMATION_REQUIRED_TOOLS` 中（如 `vault_store` / `agent_delete` /
  `team_disband`）。

修改这两个语义的方式是声明它们 —— 用名字白名单不会带来附加的覆盖。

### 生成的 JSON Schema

当你的工具被注册时，Aleph 自动生成这个工具定义发给 LLM：

```json
{
  "type": "function",
  "function": {
    "name": "weather",
    "description": "Get current weather and forecast for a location. Returns temperature, conditions, and multi-day forecast.",
    "parameters": {
      "type": "object",
      "properties": {
        "location": {
          "type": "string",
          "description": "城市名称或坐标（例如 \"Tokyo\" 或 \"35.6762,139.6503\"）"
        },
        "unit": {
          "type": "string",
          "description": "温度单位：\"celsius\" 或 \"fahrenheit\"（默认：celsius）",
          "default": "celsius"
        },
        "days": {
          "type": "integer",
          "description": "预报天数（1-7，默认：1）",
          "default": 1
        }
      },
      "required": ["location"]
    }
  }
}
```

## 创建 MCP 服务器工具

Rust 之外的语言，或不想为每次迭代重新编译 Aleph 时，MCP 是合适的路径。
服务器作为独立进程运行，通过模型上下文协议与 Aleph 通信。

### Node.js 示例

使用官方的 `@modelcontextprotocol/sdk`：

```typescript
// weather-server/index.ts
import { Server } from "@modelcontextprotocol/sdk/server/index.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";

const server = new Server(
  { name: "weather-server", version: "1.0.0" },
  { capabilities: { tools: {} } }
);

server.setRequestHandler("tools/list", async () => ({
  tools: [
    {
      name: "get_weather",
      description: "Get current weather for a location",
      inputSchema: {
        type: "object",
        properties: {
          location: { type: "string", description: "城市名称或坐标" },
          unit: {
            type: "string",
            enum: ["celsius", "fahrenheit"],
            default: "celsius",
          },
        },
        required: ["location"],
      },
      annotations: {
        readOnlyHint: true,
        idempotentHint: true,
      },
    },
  ],
}));

server.setRequestHandler("tools/call", async (request) => {
  if (request.params.name === "get_weather") {
    const { location, unit } = request.params.arguments;
    const response = await fetch(
      `https://api.weather.example.com/v1?q=${location}&units=${unit}`
    );
    const data = await response.json();
    return {
      content: [{ type: "text", text: JSON.stringify(data, null, 2) }],
    };
  }
  throw new Error(`Unknown tool: ${request.params.name}`);
});

const transport = new StdioServerTransport();
await server.connect(transport);
```

### Python 示例

使用官方的 `mcp` 包：

```python
# weather_server.py
import json
import httpx
from mcp.server import Server
from mcp.server.stdio import stdio_server
from mcp.types import Tool, TextContent

app = Server("weather-server")

@app.list_tools()
async def list_tools():
    return [
        Tool(
            name="get_weather",
            description="Get current weather for a location",
            inputSchema={
                "type": "object",
                "properties": {
                    "location": {"type": "string"},
                    "unit": {"type": "string", "enum": ["celsius", "fahrenheit"]},
                },
                "required": ["location"],
            },
        )
    ]

@app.call_tool()
async def call_tool(name: str, arguments: dict):
    if name == "get_weather":
        location = arguments["location"]
        unit = arguments.get("unit", "celsius")
        async with httpx.AsyncClient() as client:
            resp = await client.get(
                "https://api.weather.example.com/v1",
                params={"q": location, "units": unit},
            )
            data = resp.json()
        return [TextContent(type="text", text=json.dumps(data, indent=2))]
    raise ValueError(f"Unknown tool: {name}")

async def main():
    async with stdio_server() as (read, write):
        await app.run(read, write)

if __name__ == "__main__":
    import asyncio
    asyncio.run(asyncio.run(main()))
```

### 注册到 Aleph

把服务器加入 `~/.aleph/mcp_config.json`：

```json
{
  "version": 1,
  "servers": {
    "weather": {
      "id": "weather",
      "name": "Weather Server",
      "transport": "stdio",
      "command": "npx",
      "args": ["tsx", "/path/to/weather-server/index.ts"],
      "requires_runtime": "node",
      "auto_start": true,
      "timeout_seconds": 30
    }
  }
}
```

修改后必须重启 `aleph-server`，配置才会生效。

### MCP 工具命名约定

你的服务器声明的工具名（`get_weather`）会以 `<server>__<tool>` 的形式
出现在 Aleph 的注册表中（`weather__get_weather`）。`McpHandler::qualified_name`
是命名唯一权威 —— 它去掉管理器加上的冗余 `{server}:` 前缀，然后把
所有不在 `[A-Za-z0-9_-]` 集合中的字符映射为 `_`，并截断到 64 字符
（OpenAI 函数调用 / Anthropic / Gemini 都接受的字符集）。不要再在工具名
里写冒号或点。

### 注解 = 元数据驱动的门

`ToolAnnotations` 是 `ScopedToolService` 用来决定 `idempotent` /
`requires_approval` 的真正信号：

| 注解 | 字段 |
|------|------|
| `readOnlyHint: true` | `concurrent_safe`（自动重试） |
| `idempotentHint: true` | `idempotent`（tier 视为安全） |
| `destructiveHint: true` | `requires_approval`（Ask 默认值下仍需审批） |

不在服务器响应里写注解意味着字段为 `false` —— 含义是"未知 ⇒ 非幂等 ⇒
mutating ⇒ Ask 必然 fail-closed"。这是按设计；用名字白名单覆盖不了它。

## 创建 Markdown 技能

Markdown 技能是扩展 Aleph 最简单的方式 —— 无需代码。技能在
`SKILL.md` 文件中定义基于提示的工作流。

### 技能文件结构

在其中一个技能目录下创建 `SKILL.md` 文件：

```markdown
---
name: summarize_article
description: Summarize a web article into key points
---

# Summarize Article

Given the URL: {{url}}

Please:
1. Fetch the content from the URL
2. Identify the main topic and key arguments
3. Produce a concise summary with bullet points
4. Note any important data or statistics mentioned

Output the summary in markdown format.
```

技能目录由配置给出，技能在启动时自动加载，并通过文件 watcher 支持热重载
（修改 `SKILL.md` 后无需重启）。

## 工具设计最佳实践

### 命名约定

- **snake_case**：`web_fetch`，`file_read`，`bash`。
- **描述性但简洁**：`memory_search` 足够，不要把实现细节（底层是数据库）写进名字。
- **MCP 工具**：写干净的内部名（`get_weather`）；`server__` 前缀由
  `McpHandler` 添加。
- **不要**在工具名里写冒号或点 —— 它们会被映射为 `_` 并截断到 64
  字符。

### 描述质量

工具描述是 LLM 用来决定是否调用你的工具的依据。写清楚、具体、说明输入
和返回内容。

### 元数据而不是名字白名单

如果你的工具执行破坏性操作，**不要**寄希望于某个名字匹配来强制审批。
`ScopedToolService` 读的是 `ToolDefinitionMetadata`：

- 内置工具：在 `CONFIRMATION_REQUIRED_TOOLS` 集合里登记一次（在
  `src/tools/scoped/` 中）。
- MCP 服务器：在 `tools/list` 的 `annotations` 里返回 `destructiveHint`
  或 `requires_approval`。

### 错误处理

工具应返回 `Result<Self::Output>` 并使用 Aleph 的错误类型。HTTP / 网络
失败映射到 `ToolError::Transport` 或 `Timeout`；其他失败映射到
`ToolError::Execution`，让模型看到并修复。

### 沙箱契约

如果你的工具启动子进程，**必须**接受 `Arc<dyn Sandbox>` 并通过它
执行命令（`WorkspaceSandbox::execute`）。`src/builtin_tools/` 中不允许
裸的 `Command::new`。沙箱 + 命令策略层（`src/sandbox/command_policy/`）
会替你处理工作目录、能力升级和硬线命令过滤。

## 测试自定义工具

### 单元测试

直接测试 `AlephTool` 实现：

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_tool_definition() {
        let tool = WeatherTool::new("test_key".to_string());
        let def = AlephTool::definition(&tool);
        assert_eq!(def.name, "weather");
        assert!(def.description.contains("weather"));
    }

    #[tokio::test]
    async fn test_tool_call() {
        let tool = WeatherTool::new("test_key".to_string());
        let result = AlephTool::call(&tool, WeatherArgs {
            location: "Tokyo".to_string(),
            unit: "celsius".to_string(),
            days: 1,
        }).await;
        assert!(result.is_ok());
    }
}
```

### 集成测试

集成测试走完整的 `ScopedToolService` 管道：把工具注册到共享的
`LoopToolRegistry`，构造一个绑定到该注册表的 `ScopedToolService`（含
权限与 tier），然后发一个 `execute(name, args)`。`tests/` 下的
`sandbox_capability_approval.rs` 是这种集成测试的范例。

## 总结

| 要构建什么 | 使用此方法 |
|-----------|-----------|
| 高性能核心工具 | Rust `AlephTool` trait |
| 与外部 API 集成 | MCP 服务器（Node.js / Python） |
| 基于提示的工作流 | Markdown 技能 |
| 需要热重载的工具 | MCP 服务器或 Markdown 技能 |
| 需要类型安全的工具 | Rust `AlephTool` trait |
