本页说明本机与远端客户端如何取得 Gateway 权限，以及传输加密与身份认证的区别。

## 按入口区分认证

| 入口 | 身份检查 | 实现 |
|------|----------|------|
| Desktop IPC | Unix socket 对端校验；只读，不继承兼容 WS 的环回授权 | `src/gateway/server/connection/local_ipc.rs` |
| Web v1 | 原生 TLS；`POST /v1/session` 用有效设备令牌或绑定主体的引导票创建会话，`GET /v1/ws` 要求有效会话 cookie，校验同源和设备主体 | `src/gateway/server/mod.rs`、`src/gateway/server/connection/web_v1.rs` |
| 兼容 `/ws` | 升级时独立检查传输与 `Origin`，再由 `connect` 认证；缺失或无效凭据的远端连接不能使用已授权的 RPC | `src/gateway/server/connection/upgrade.rs`、`src/gateway/handlers/connect.rs`、`src/gateway/server/connection/mod.rs` |

两条只读入口先用 `system.hello` 协商，不是兼容 `/ws` 的 `connect` 登录流程；其 RPC 范围和跨站防护见 [IPC 协议](../security/ipc)（`src/gateway/server/connection/local_ipc.rs`、`src/gateway/server/connection/web_v1.rs`）。

## 兼容 `/ws` 凭据

仅直连环回、且未提交非空 `device_token` 或 `bootstrap_ticket` 时，`resolve_connect_auth` 提供隐式 `operator` 授权。带了设备凭据但校验失败的环回连接不回退到隐式授权。远端按下表顺序尝试；设备凭据认证连接时还可以从用户记录解析角色，并非一律使用 `operator`（`src/gateway/handlers/connect.rs`）。

| 顺序 | `connect` 参数 | 用途与存储 | 实现 |
|------|----------------|-----------|------|
| 1 | `device_token`（`aleph-dt-*`） | 长期设备凭据，服务端保存 SHA-256 哈希 | `src/gateway/security/device_token_manager.rs`、`src/gateway/security/store/tokens.rs` |
| 2 | `bootstrap_ticket`（`aleph-bt-*`） | 单次配对，默认有效 5 分钟；兑换后返回新的设备令牌 | `src/gateway/security/device_token_manager.rs`、`src/gateway/handlers/connect.rs` |
| 3 | `token`（`aleph-<uuid>`） | 仅用于远端的旧共享网关令牌回退 | `src/gateway/handlers/connect.rs`、`src/gateway/security/shared_token.rs` |

### 配对与撤销

已授权客户端可以用 `gateway.ticket.create` 发引导票。兼容连接以 `connect.bootstrap_ticket` 兑换，再用返回的 `device_token` 重连；兑换会拒绝与非 Panel 设备冲突的 `device_id`。NSH 的凭据服务使用 OS 钥匙串保存设备凭据，不以明文文件作为后备（`src/gateway/handlers/gateway_ticket.rs`、`src/gateway/handlers/connect.rs`、`src/gateway/security/device_token_manager.rs`、`desktop/nsh-shell/src/credentials.rs`、`shared/client/src/credential_store.rs`）。

`gateway.devices.revoke` 撤销指定设备；`gateway.token.rotate` 轮换共享令牌并撤销已配对 Panel 设备。Web v1 的会话校验也会复查设备主体是否仍有效（`src/gateway/handlers/gateway_devices.rs`、`src/gateway/handlers/gateway_token.rs`、`src/gateway/server/connection/web_v1.rs`）。

### 无头凭据工具

`aleph-server pair [--ttl SECONDS]` 可在没有运行中 Gateway 的情况下签发引导票；需要为 Web v1 创建绑定主体的票时可加 `--user <id>`。`aleph-server bootstrap-token` 把旧共享令牌以明文写入标准输出；不要将其输出留在共享日志中（`src/bin/aleph-server/cli.rs`、`src/bin/aleph-server/commands/pair.rs`、`src/bin/aleph-server/commands/bootstrap_token.rs`）。

## 本机、远端与 TLS

Gateway 的 `check_network_exposure` 拒绝没有原生 TLS、受信代理或明确明文许可的非环回绑定。兼容 `/ws` 的 `refuse_insecure_remote` 对远端逐连接执行传输门：既无原生 TLS、也无受信代理的 `X-Forwarded-Proto: https`，且未设置 `allow_insecure_remote` 时，返回 `426 Upgrade Required`。直连环回可用明文，但 NSH 的远端 `--connect <origin>` 要求 HTTPS；`aleph://open` 是打开宿主窗口的深链，不是连接目标（`src/gateway/server/mod.rs`、`src/gateway/server/connection/upgrade.rs`、`desktop/nsh-shell/src/main.rs`、`shared/client/src/connection_target.rs`、`desktop/nsh-shell/src/panel_bridge.rs`）。

### 原生 TLS

在 `[gateway.tls]` 中设置 `enabled = true`。可提供 PEM 格式的 `cert_path` 和 `key_path`，或留空生成自签证书。客户端仍须信任呈现的证书；TLS 本身不授予 Gateway 权限。Web v1 只在原生 TLS 路由器注册，不能用兼容入口的明文开关或仅在代理终止 TLS 来启用（`src/gateway/config.rs`、`src/gateway/tls.rs`、`src/gateway/server/mod.rs`）。

### 受信反向代理与客户端 IP

若代理替兼容 `/ws` 终止 TLS，应开启 `[gateway.trusted_proxy] enabled`，并在 `trusted_ips` 中指定实际代理的单个 IP（不支持 CIDR）。否则，同机代理的环回连接可能被误认为直连、获得隐式授权（`src/gateway/config.rs`、`src/gateway/trusted_proxy.rs`、`src/gateway/server/connection/upgrade.rs`）。

`resolve_client` 只接受受信 peer 的转发头：从 `X-Forwarded-For` 最右侧非空项解析客户端 IP，缺失或无效则回退至 peer IP。这个地址用于限流和审计；通过受信代理的连接始终标作非本地，即使回退的地址是环回（`src/gateway/trusted_proxy.rs`、`src/gateway/server/connection/upgrade.rs`、`src/gateway/server/connection/mod.rs`）。

## 浏览器来源与审计

兼容 `/ws` 使用 `OriginPolicy::is_allowed`：缺失或空的 `Origin` 通过来源检查；浏览器通常需匹配 `[gateway] allowed_origins`，或用与请求 `Host` 同 authority 的 HTTP(S) IP/环回来源。旧桌面 webview 的专用 scheme 仍有兼容例外，不是 NSH 规则。Web v1 改用严格 HTTPS 同源检查。两种检查都不替代身份验证；完整规则见 [Panel 来源校验](../security/ipc)（`src/gateway/origin_policy.rs`、`src/gateway/server/connection/upgrade.rs`、`src/gateway/server/connection/web_v1.rs`）。

兼容 `/ws` 可记录远端凭据失败（`AuthFailure`）及未授权请求洪泛（`RateLimited`）；Web v1 的 `throttle` 在会话交换、升级两步均执行认证限流（`src/gateway/server/connection/mod.rs`、`src/gateway/server/flood_guard.rs`、`src/security/audit.rs`、`src/gateway/server/connection/web_v1.rs`）。
