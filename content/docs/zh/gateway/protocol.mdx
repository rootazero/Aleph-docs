<Callout type="warn">
`/ws` 是历史兼容入口，不是新客户端（Protocol v1 的 Desktop IPC / Web v1）的接入面。NSH 桌面宿主有两种形态：默认的 Leptos `web_view` 经 `http://127.0.0.1:18790/` 加载 Panel 并连接旧 `/ws`（`desktop/nsh-shell/src/shell_host.rs`、`desktop/nsh-shell/src/credentials.rs`）；`ALEPH_SHELL_PANEL=tsx` 的 TSX Panel 宿主只连本地 Desktop IPC，任何其它目标都报 `unavailable`（`desktop/nsh-shell/src/panel_host.rs`）。新客户端请使用 [Protocol v1](./protocol-v1)。本页只描述 `/ws` 现状，便于维护旧客户端与排查。
</Callout>

`/ws` 用 WebSocket Text 消息承载 JSON-RPC 2.0：所有 RPC、事件和连接握手共用同一条连接，消息边界由 WebSocket 自己提供，没有长度前缀。收到 Binary 消息只记录警告并忽略（`src/gateway/server/connection/mod.rs`）。

## 端点

```text
ws://127.0.0.1:18790/ws          # 默认绑定，loopback
wss://<host>:<port>/ws           # 启用原生 TLS 后
```

- 默认绑定 `127.0.0.1:18790`（`src/gateway/config.rs`）；loopback 客户端直接是 `operator`。
- 路由 `/ws` 挂在 `src/gateway/server/mod.rs`，升级处理器是 `src/gateway/server/connection/upgrade.rs` 的 `ws_upgrade_handler`。
- 非 loopback 绑定必须启用 TLS、受信代理或 `allow_insecure_remote` 之一，否则 `check_network_exposure`（`src/gateway/server/mod.rs`）让进程拒绝启动。

## 会话初始化（`connect` 握手）

连接建立后的**第一帧**必须是 `connect`；任何其他首帧都收到 `AUTH_REQUIRED`（`First request must be 'connect'`）并断开（`src/gateway/server/connection/mod.rs`）。

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "connect",
  "params": {}
}
```

loopback 连接可以省略凭据。远程连接的凭据解析顺序在 `src/gateway/handlers/connect.rs` 的 `resolve_connect_auth`，可用的字段是 `device_token`、`bootstrap_ticket`（搭配 `device_id`）和旧版共享 `token`；三种凭据的区别、有效期与撤销见[身份认证](./auth)。

握手成功后的结果由 `handle_connect` 给出基线字段，连接层再叠加授权结论：

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "role": "operator",
    "state_version": 17,
    "keepalive": { "ping_interval_secs": 30, "idle_timeout_secs": 90 },
    "authorized": true,
    "needs_token": false
  }
}
```

`state_version` 与 `keepalive` 的数值为示例。`system.hello` 在 `/ws` 上只是 `connect` 之后的版本探测方法，它不准入连接，也不设置身份，见 [Protocol v1](./protocol-v1#握手-systemhello)。

## 升级门：TLS、来源与连接上限

HTTP 升级为 WebSocket 之前，`ws_upgrade_handler` 依次检查：

| 检查 | 失败响应 | 代码 |
|------|---------|------|
| 非 loopback 且连接未加密（`refuse_insecure_remote`） | `426`，`TLS required for remote connections` | `src/gateway/server/connection/upgrade.rs` |
| 来源策略（防跨源与 DNS rebinding） | `403`，`origin not allowed` | `src/gateway/origin_policy.rs` |
| 全局连接数达到 `max_connections` | `503`，`Connection limit reached` | `src/gateway/server/connection/upgrade.rs` |
| 单 IP 连接数达到 `max_connections_per_ip` | `503`，`Per-IP connection limit reached` | `src/gateway/server/connection/upgrade.rs` |

- `max_connections` 默认 100，`max_connections_per_ip` 默认 64，二者在 `src/gateway/config.rs`；loopback 不受单 IP 上限限制，设为 `0` 关闭该上限。
- 前置受信代理时，真实客户端地址与是否加密由 `src/gateway/trusted_proxy.rs` 的 `resolve_client` 解析；`trusted_ips` 只接受单个 IP，不支持 CIDR（无法解析的条目会被丢弃并告警）。只有对端在 `trusted_ips` 内，转发头才被采信。
- 通过升级门的连接按来源归类：本机为 Desktop，其他为 Bot。

TLS 的三种组合（自签、受信代理、自带证书）与审计见[身份认证](./auth)，不在此重复。

## 登录墙与洪泛保护

未授权的远程连接只能调用 `connect`：

- 其他方法立即得到 `AUTH_REQUIRED`，判定函数是 `src/gateway/server/connection/auth.rs` 的 `wall_admits`。
- `src/gateway/server/flood_guard.rs` 按连接统计登录墙拒绝次数，达到 `MAX_UNAUTHORIZED_STRIKES`（10）后关闭连接，防止过期客户端无限重试。
- 请求本身还受 `src/gateway/rate_limiter.rs` 的按 IP 与方法范围限流。

## 消息类型

消息形态与 [JSON-RPC](../api/jsonrpc) 一致，`/ws` 上没有额外的信封。

```json
{ "jsonrpc": "2.0", "id": "req-1", "method": "health" }
```

```json
{ "jsonrpc": "2.0", "id": "req-1", "result": { "status": "healthy", "timestamp": "2026-11-24T00:00:00Z" } }
```

```json
{ "jsonrpc": "2.0", "method": "event", "params": { "topic": "session.lifecycle.changed", "data": {} } }
```

- 响应的 `timestamp` 为示例值，字段定义见 `src/gateway/handlers/health.rs`。
- 事件是不带 `id` 的通知，`method` 恒为 `"event"`，订阅用 `events.subscribe`，参数键是 `topics`（`src/gateway/handlers/events.rs`）。事件目录与错误码全集见[事件方法](./methods/events)与 [JSON-RPC](../api/jsonrpc)。
- 完整 RPC 目录见[方法参考](./methods)。只有 `/ws` 提供完整方法面；Desktop IPC 与 Web v1 两个 v1 入口共用 `V1_METHODS`（`src/gateway/server/connection/mod.rs`），只放行 `health`、`sessions.list`、`panel.capabilities.snapshot`。

## 历史：协议从无版本演进到 v1

| 形态 | 特点 | 代码 |
|------|------|------|
| `/ws` + `connect` | 握手结果只有 `role`、`state_version`、`keepalive` 等会话字段，没有协议版本，也不协商限额；消息边界依赖 WebSocket | `src/gateway/handlers/connect.rs` |
| `/ws` 上的 `system.hello` 探针 | 在 `connect` 之后做版本探测；handler 注释称之为 legacy 探针，响应里的 `limits` 只是提示值，不强制 | `src/gateway/handlers/system_hello.rs` |
| Protocol v1：Desktop IPC 与 Web v1 | 有界长度前缀帧，`system.hello` 必须是首帧，限额由传输强制；两个入口共用 `V1_METHODS`，只挂载 `health`、`sessions.list`、`panel.capabilities.snapshot` | `src/gateway/server/connection/local_ipc.rs`、`src/gateway/server/connection/web_v1.rs` |

`/ws` 仍保留完整 RPC 面与 `connect` 认证，旧客户端不需要改动；它没有被移除，但不再是新增能力的落点。Protocol v1 的 Desktop IPC 与 Web v1 两个入口已经落地，帧格式、握手与传输矩阵见 [Protocol v1](./protocol-v1)。v1 尚未实现的部分（事件重放、快照、二进制通道、背压策略）见 [Protocol v1 的「规划中」一节](./protocol-v1#规划中尚未落地的部分)。
