本页是网关事件的主题册：每个主题的规范名、线上方法名、负载字段、订阅匹配规则与可见性。事件的线上形态与整体投递链路见 [网关架构](../../architecture/gateway)，协议细节见 [Protocol v1](../../gateway/protocol-v1)。

## 事件如何到达客户端

服务端把内部事件封装成 JSON-RPC 通知发给客户端，客户端先订阅感兴趣的主题，再按通知里的主题分发。通知有两种线上形态。

### 通知形态

`GatewayEventFrame` 里带 `stream_method()` 的帧直接以方法名发出，`params` 就是帧体：

```json
{
  "jsonrpc": "2.0",
  "method": "stream.run_complete",
  "params": {
    "run_id": "run-...",
    "seq": 12,
    "summary": { "...": "..." },
    "total_duration_ms": 4820
  }
}
```

### 事件形态

没有 `stream_method()` 的帧先发裸事件 `{"topic": "...", "data": {...}}`，投递层再把它包成方法名为 `event` 的通知。`event` 就是 `TOPIC_EVENT_METHOD`（`shared/protocol/src/jsonrpc.rs:85`），包装发生在 `src/gateway/server/connection/forward.rs:228`：

```json
{
  "jsonrpc": "2.0",
  "method": "event",
  "params": {
    "topic": "config.changed",
    "data": { "section": "execution", "value": { "...": "..." } }
  }
}
```

两种形态的区别只有一处：线上方法名不同。规范主题名（`agent.run.complete`）与线上方法名（`stream.run_complete`）是两套命名，前者主要出现在 `surface.notify` 的 `source_topic` 诊断字段里，线上订阅用的是后者。

## 订阅与匹配

`events.subscribe`、`events.unsubscribe`、`events.list` 三个方法不在方法注册表里，而是在连接循环中被单独拦截（`src/gateway/server/connection/mod.rs:630`），处理器在 `src/gateway/handlers/events.rs`。

订阅请求的形状：

```json
{
  "jsonrpc": "2.0",
  "id": 4,
  "method": "events.subscribe",
  "params": {
    "topics": ["stream.*", { "topic": "team.changed", "where": [{ "field": "team_id", "equals": "team-1" }] }]
  }
}
```

`topics` 为空数组会回 `INVALID_PARAMS` / `Topics array cannot be empty`。订阅状态由 `SubscriptionManager`（`src/gateway/handlers/events.rs:17`）保存，每个连接一个过滤器。

匹配时用的是事件的线上主题串：裸事件形态取 `topic` 字段，通知形态取 `method` 字段（`src/gateway/server/connection/forward.rs:187` 的 `extract_topic_and_data`）。所以流式帧是按 `stream.` 前缀匹配的。

### 通配模式

匹配逻辑在 `src/gateway/event_bus.rs:150` 的 `topic_matches`：

| 模式 | 语义 |
|------|------|
| `*` 或 `**` | 匹配全部主题 |
| 最后一段是 `*` 或 `**` | 匹配剩余任意深度，`stream.*` 能匹配 `stream.run_complete`，也能匹配 `voice.transcribe.delta` |
| 中间的 `*` | 只吃一段，`*.complete` 匹配不到 `stream.run_complete` |

两端必须同时耗尽才算命中。

### where 谓词

`topics` 的元素也可以是对象，带一个 `where` 数组。谓词用 `FieldPredicate` 描述（`{"field": "...", "equals": ...}`），字段路径按 `.` 分段取值，不是 JSON Pointer。谓词非空而负载里没有对应字段时判为不匹配。

### 例外与退订

`except` 是与 `topics` 平级的键，列出要从订阅里排除的顶层主题。`events.unsubscribe` 移除指定模式，`events.list` 返回当前连接的订阅快照（`subscribed` 是模式列表，`entries` 是条目全量）。

## 可见性与授权

一帧事件要送达某个连接，必须逐层通过过滤链（`src/gateway/server/connection/mod.rs:1373`）。其中与主题相关的有两道机制，分工不同。

### 作用域规则

`src/gateway/event_scope.rs` 是粗粒度的前缀规则。`default_rules` 只登记了几条前缀——配对、访客、配置变更、节点与 PTY——命中的前缀要求调用方持有管理员作用域；没有规则命中的主题默认放行。`scope_for_role` 对 operator 返回通配作用域，对其他角色返回空。

因此 `config.changed`、`node.` 前缀与 `pty.` 前缀下的主题，只有 operator 能收到。

### 逐帧归属裁决

`src/gateway/event_visibility.rs` 负责「这一帧属于谁」。`classify`（`:440`）把主题与负载映射成一种身份：

| 身份 | 覆盖的主题 | 裁决 |
|------|------------|------|
| 按会话 | `stream.ask_user`、`stream.clarification_ended`、`stream.run_accepted`、`stream.run_queued`、`stream.session_updated`、`stream.session_user_message`、`session.lifecycle.changed`、`sessions.changed` | 会话归属者可见 |
| 按运行 | `stream.reasoning`、`stream.tool_start`、`stream.tool_update`、`stream.tool_end`、`stream.agent_trace`、`stream.response_chunk`、`stream.context_gauge`、`stream.run_complete`、`stream.run_error`、`stream.uncertainty_signal`、`stream.model_resolved`、`stream.run_retrying` | 先由 `run_id` 解析到会话，再按会话归属裁决 |
| 按会话或管理员 | `approval.requested`、`approval.reminder`、`approval.resolved`、`approval.expired`、`surface.approval` | operator 直通，其余按会话归属 |
| 按用户 | `voice.transcribe.delta` | 调用方 id 与 `owner_user_id` 相等 |
| 按 PTY 会话 | `pty.screen`、`pty.exit` | 按 PTY 会话归属 |
| 按画布 | `canvas.updated` | 按画布可见性谓词 |
| 按项目 | `projects.changed` | 按项目花名册，无管理员豁免 |
| 仅管理员 | `workspace.changed`、`config.embedding.providers.changed`、`config.generation.providers.changed`，以及 `host.` 前缀 | 角色必须是 operator |
| 全局 | `channel.message`、`channel.typing`、`channel.status`、`channel.error`、`acp.sessions.changed`、`gateway.token.rotated`、`gateway.device.revoked`、`cron.job.changed`、`heartbeat.task.changed`、`team.changed`、`surface.notify`、`pairing.requested`、`pairing.completed`、`config.changed`、`system.tick`、`presence.joined`、`presence.left`、`tools.changed`、`config.reloaded`、`config.error`、`extension.reloaded`、`memory.reembed.progress`、`memory.reembed.completed`、`runtimes.install.progress`、`agent.lifecycle.registered`、`agent.lifecycle.deleted`、`agent.lifecycle.bound`、`agent.lifecycle.unbound` | 对所有已登录连接放行 |
| 能力受众 | `capability.event`、`capabilities.ui.display`、`capability.event.status` | 按能力受众裁决 |

两点补充：

- `config.changed` 既命中作用域规则里的配置前缀，也在逐帧裁决里算全局。前缀规则先执行，所以实际只有 operator 收到。
- 团队相关的主题里，带团队 id 的那类按团队归属裁决；不带 id 的 `team.changed` 才是全局。

### 投影帧

`stream.running_set_changed` 是链上唯一的投影帧：它被判定为全局（没有人拥有这一帧），但它的 `running` 数组会按连接裁剪，每个连接只看到与自己相关的运行集。

## 重放与快照

当前实现里没有事件重放与快照订阅。

- `shared/protocol/src/trace_replay.rs` 定义的是持久化 trace 的查询 DTO（`AgentTraceReplay`、`AgentTraceReplayEntry`、`AgentTraceListRow` 等），它读的是已经落盘的轨迹记录，不是从事件流里重放。
- `shared/protocol/src/resume.rs` 定义的是恢复任务的回执（`ResumeReceipt`、`ResumeStatus` 及其常量），与事件重放无关。
- 订阅语义本身也不支持重放：`events.subscribe` 只记录模式，不记录游标。

> **状态：规划中** — 蓝图为 `docs/research/NSH_PROTOCOL_V1.md`（第 9 章 Snapshot + Replay，含 9.3 无丢失订阅要求、9.4 历史不可用、9.5 去重游标）；当前实现见 `shared/protocol/src/trace_replay.rs`、`shared/protocol/src/resume.rs` 与 `src/gateway/handlers/events.rs`。`session.get_snapshot` 在 `src/gateway/method_census.rs` 里没有登记，快照接口尚未存在。

## 历史：事件名从旧命名收敛

早期文档里的事件名是扁平的命名，例如 agent.completed、agent.started、agent.error、stream.chunk。现行代码里已经没有这些字符串，它们只在历史文档与早期计划里出现。

收敛到现在的命名空间之后，`agent.run.complete` 表示一次运行完成，而 `session.user.message` 表示一条用户消息——两者不再混在同一个扁平名字里。`stream.chunk` 则落到 `agent.response.chunk`，与 `agent.reasoning`、`agent.trace` 归到同一个 agent 输出族。

另一次收敛是规范名与线上方法名的分离：规范主题名描述「这是什么事件」，线上方法名描述「它怎么送达」。两套名字并存期间，`agent.run.complete` 主要作为 `source_topic` 诊断字段出现，线上订阅一直用 `stream.*`。
