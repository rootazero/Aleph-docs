`memory.*`(以及伴随的 `dreaming.*` / `insights.tools`)是分层记忆流水线的读 / 可观测性面:

- **第 1 层**——`raw_memories`(原始对话记录;每个 user + assistant 轮次一行)
- **第 2 层**——`notes_index`(编译的知识笔记;自 26.6.x 重构以来的基于笔记的规范模型)
- **第 3 层**——`notes_graph_cache`(Louvain 社区、相似性边、图健康洞察)

写入仍由 LLM / 工具驱动;RPC 面刻意只读第 1 层 + 第 2 层,加上少量会**失败关闭**的批量清除端点(老的"无操作伪造成功"形态已被删除——见 [批量清除](#批量清除))。

十二个方法在 `register_memory_handlers`(`src/bin/aleph-server/commands/start/builder/handlers/memory.rs:28-268`)中连接。处理函数位于 `src/gateway/handlers/memory.rs`;`dreaming.run_now` / `dreaming.list_insights` / `insights.tools` 伴随方法直接在 `HandlerRegistry::new()` 中注册。

## 方法

### memory.search

搜索原始记忆(第 1 层)。`content` 的子串匹配;空 `query` 按时间倒序返回最近行。**这是唯一的原始记忆入口**——之前基于笔记搜索的分支被删除,因为它重复了 `graph.search`,并导致 Panel 中 `delete_raw_memory` 用了错误的笔记路径。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `query` | string | 否 | 子串过滤;省略 = 浏览 |
| `agent_id` | string | 否 | 工作区隔离(默认为 `routing::DEFAULT_AGENT_ID`) |
| `window_title` | string | 否 | (保留;当前模型不暴露) |
| `limit` | number | 否 | 默认为 20 |
| `offset` | number | 否 | 默认为 0(分页器尺寸) |

**响应:** `{ "memories": [ ...MemoryEntry... ], "total" }`。每个 `MemoryEntry` 包含 `id`、`agent_id`、`window_title`(空)、`user_input`(原始内容)、`ai_output`(空)、`session_id?`、`timestamp`(created_at,epoch 秒)。`total` 是相同 `(agent_id, query)` 过滤下的计数——不是整库总数,所以感知过滤的分页器不会出现"幻影页"。

### memory.delete

按 id 删除单个原始记忆行。第 1 层行没有外键,所以单行删除是安全的;第 2 层知识笔记不受影响。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 原始记忆 id |

**响应:** 成功时 `{ "ok": true }`;未命中返回 `INTERNAL_ERROR: No raw memory found with id '<id>'`。

### memory.stats

每个计数共享同一作用域。省略 `agent_id`(`scope: "global"`)只返回原始 + 笔记计数;图计数是 `null`,因为笔记是按 agent 隔离的,无作用域视图不能诚实地给出"零节点"。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `agent_id` | string | 否 | 将每个计数限定到一个 agent |

**响应:** `{ "totalMemories", "totalFacts", "validFacts", "totalGraphNodes" | null, "totalGraphEdges" | null, "scope": "agent"|"global" }`。在当前基于笔记的模型中,`totalFacts` 和 `validFacts` 相等(笔记没有失效状态)。

### memory.compress

触发一次压缩周期。需要 live `CompressionService`(无服务则无处理器)。

**请求:** 无参数。

**响应:** `{ "memoriesProcessed", "factsExtracted", "factsInvalidated", "durationMs" }`。

### memory.listFacts

列出编译的知识笔记(第 2 层)。分页,限定到一个 agent。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `agent_id` | string | 否 | 默认为 `routing::DEFAULT_AGENT_ID` |
| `limit` | number | 否 | 默认为 50 |
| `offset` | number | 否 | 默认为 0 |
| `include_invalid` | boolean | 否 | 默认为 `false`(无操作:笔记没有失效状态) |

**响应:** `{ "facts": [ ...FactEntry... ], "total" }`。每个 `FactEntry` 包含 `id`(路径)、`agent_id`、`content`(文件名)、`fact_type`(类别)、`created_at`、`updated_at`、`category`、`path`、`tags`、`link_count`。

### memory.appList

列出有相关记忆的窗口。基于笔记的模型没有按窗口分组,因此此接口始终为空列表——为与旧客户端兼容而保留。

**请求:** 无参数。

**响应:** `{ "windows": [] }`。

### memory.list_corrections

列出用户纠正(`aleph://correction/...` 原始行)及其蒸馏状态。只读——蒸馏仍由 LLM 驱动。

`distilled` 标志从 `FeedbackDistill` 水位线读取,**不**从 `is_processed` 读取。`is_processed` 属于 `CompressionService` 排出器,在纠正落地后几秒内被设置;使用它会在梦境阶段真正消费之前就把每行渲染为"已蒸馏"。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `agent_id` | string | 否 | 默认为 `routing::DEFAULT_AGENT_ID` |
| `limit` | number | 否 | 默认为 50 |
| `include_distilled` | boolean | 否 | 默认为 `true` |

**响应:** `{ "corrections": [ ...{id, content, severity, suggested_rule?, status: "distilled"|"pending", created_at}... ] }`。

### memory.trace

将记忆声明一路回溯到 ground-truth 证据。只读;`MemoryTraceTool::call_impl` 的薄 I/O 包装。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `agent_id` | string | 否 | 默认为 `routing::DEFAULT_AGENT_ID` |
| `target` | string | 是 | 要回溯的实体 / 笔记 / profile-section |
| `kind` | string | 是 | `TraceKind` 变体之一(`note` / `raw` / `profile`) |
| `max_results` | number | 否 | 限制返回的证据 |

**响应:** `MemoryTraceTool` 的完整结果序列化为 JSON(按行的证据链)。

### memory.reembed

启动后台 reembed 迁移(用当前 embedder 重建笔记向量)。需要 live embedding provider;否则处理器返回"缺少 embedding provider"的错误 stub。一次只能运行一个 reembed——第二次 `memory.reembed` 返回 `-32001: Reembed already in progress`,直到第一个完成。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `target_dim` | number | 否 | 默认为当前 embedder 的维度 |

**响应:** `{ "status": "started", "task_id": "reembed-<unix_ms>" }`。进度发布到 `memory.reembed.progress` 主题;完成时发布到 `memory.reembed.completed`。

### memory.reembed.cancel

取消运行中的 reembed。

**响应:** 成功时 `{ "status": "cancelled" }`;当没有 reembed 在运行时返回 `-32001: No reembed task is running`。

### memory.retrieve_with_trace

运行真实的 `NoteFactRetrieval` 评分流水线,返回结果加上每阶段遥测,这样调试面板能看到某个事实为何浮现或未浮现。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `query` | string | 是 | 搜索查询 |
| `limit` | number | 否 | 最大结果数 |
| `agent_id` | string | 否 | 默认为 `routing::DEFAULT_AGENT_ID` |

**响应:** 排名结果 + `trace` 阶段数组,每项 `{ stage, count, elapsed_ms, scores }`。流水线阶段顺序: `query → candidate pool → BM25 + vector scores → RRF fusion → cutoff → ranked`。

### dreaming.run_now

强制触发全局注册守护进程上的一次梦境周期,绕过调度器的窗口 / 空闲 / 当日已运行检查。仅给 E2E 测试工具使用。

**请求:** 无参数。

**响应:** 成功时 `{ "ok": true, "report": { ...DreamReport... } }`;当记忆被禁用或处于模拟模式时返回 `INTERNAL_ERROR: DreamDaemon is not initialised`(单元测试进程也从未有守护进程,因此这在测试工具中浮现)。

### dreaming.list_insights

梦境洞察的只读列表:最近的每日摘要、周合成笔记(类别 = `synthesis`)以及梦境运行审计跟踪,带从存储 JSON 解析的 SkillOpt 进化门判定。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `agent_id` | string | 否 | 默认为 `routing::DEFAULT_AGENT_ID` |
| `limit` | number | 否 | 默认为 30 |

**响应:** `{ "daily": [ ...{date, content, source_memory_count, created_at}... ], "synthesis": [ ...{path, title, tags, updated_at}... ], "runs": [ ...{id, pipeline_type, started_at, finished_at, duration_ms, synthesis_count, errors?, evolution?}... ] }`。

### insights.tools

`ToolInvocation` 原始行上的每工具使用可观测性。只读;由 Panel 的"工具洞察"视图消费。

**请求:** 无参数(Panel 取自己的 `agent_id` 窗口)。

**响应:** 按活动/成功率排序的工具列表。

## 批量清除

两个老的"始终返回 `{ "deletedCount": 0 }`"的伪造已经**消失**——两者现在都失败关闭:

| 方法 | 新行为 |
|------|--------|
| `memory.clear` | `INTERNAL_ERROR: Bulk memory clearing is not supported in the notes-based memory model.` |
| `memory.clearFacts` | `INTERNAL_ERROR: Bulk note clearing is not supported; manage knowledge notes via the note_manage tool.` |

`memory.delete` 是唯一合法的逐行删除。批量删除走 `note_manage`(第 2 层)或永远不运行(第 1 层)。

## 内建聊天工具(伴随面)

Panel 的"Memory"标签和 LLM 通过**内建聊天工具**访问平行面——它们由 `tools.invoke` / `chat.send` 分发,而不是通过 `memory.*`。此处仅列出供参考,JSON-RPC 面并不直接调用它们。

| 工具 | 用途 |
|------|------|
| `memory_search` | 在知识库中搜索相关事实(第 2 层) |
| `memory_reflect` | 从记忆中合成连贯答案,而不是返回原始事实 |
| `session_search` | 跨会话记录搜索 |
| `remember` | 将事实固定到精选热记忆 |
| `forget` | 从记忆中移除事实 |
| `memory_status` | 记忆系统健康 + 统计 |
