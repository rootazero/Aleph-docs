---
title: "channels.*"
description: "通信频道管理 RPC 方法"
---

`channels.*` 是对 `ChannelRegistry` 的运行时接口。方法在两次连接中分布:

- `register_channel_handlers`(`src/bin/aleph-server/commands/start/builder/handlers/session.rs`)——核心生命周期方法(`channels.list/status`、`channel.start/stop/pairing_data/send/create/delete/health`、`channels.set_agent`)。
- `start/mod.rs:2431-2466`——频道配对方法(`channel.pairing.list/approve/reject/approved/revoke`)。
- Discord Control-Plane 面板方法(`discord.validate_token`、`discord.list_guilds`、`discord.list_channels`、`discord.audit_permissions`)与其他频道处理器一起注册。

所有这些方法共享同一注册表。已配置但尚未实例化的频道(例如 `~/.aleph/config.toml` 中存在但缺少 `bot_token` 的 Telegram 频道)在 `channels.list` 中显示为 `pending_config`。

## 方法

### channels.list

列出每个已注册频道以及已配置但未实例化的集合。也展示持久出站投递队列的深度(R8),让算子能发现积压。

**请求:** 无参数。

**响应:** `{ "channels": [ ...ChannelInfoResponse... ], "summary": { "total", "connected", "connecting", "pairing", "disconnected", "error", "disabled" }, "delivery_queue" | null }`。每个 `ChannelInfoResponse` 包含 `id`、`name`、`channel_type`、`status` 和 `capabilities` 块(`attachments`、`images`、`audio`、`video`、`reactions`、`replies`、`editing`、`deletion`、`typing_indicator`、`read_receipts`、`rich_text`、`max_message_length`、`max_attachment_size`)。`pending_config` 频道携带空 capabilities。

### channels.status

单个频道的实时状态(用 live `ChannelStatus` 覆盖存储的状态)。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `channel_id` | string | 是 | 频道 id |

**响应:** 该频道的 `ChannelInfoResponse`。未知时返回 `INVALID_PARAMS: Channel not found: <id>`。

### channel.start

启动频道。从 `~/.aleph/config.toml` 重新读取频道配置(使 Panel 保存无需重启守护进程即生效),在构造频道前将 vault 解析的密钥重新注入配置。Telegram 频道的 `ToolCatalog` 会被重新挂载,以便斜杠命令被注册。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `channel_id` | string | 是 | 频道 id |

**响应:** `{ "channel_id", "status": "started" }`。

### channel.stop

停止频道。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `channel_id` | string | 是 | 频道 id |

**响应:** `{ "channel_id", "status": "stopped" }`。

### channel.create

创建新的频道实例,持久化其配置(密钥剥到 vault),注册,自动启动。如果配置不完整(如缺少 `bot_token`),请求仍然以 `status: "pending_config"` 成功,以便用户能通过 Panel 补全缺失字段。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 唯一频道 id |
| `type` | string | 是 | `telegram` / `discord` / `slack` / `imessage`(BlueBubbles)/ … |
| `config` | object | 是 | 类型相关配置;密钥字段(`bot_token`、`app_token`、`app_secret`、`access_token` …)存入 vault(`channel:<id>:<field>`)并从持久化配置中剔除 |

**响应:** `{ "id", "type", "status" }`,其中 `status: "started" | "created_but_start_failed" | "pending_config"`。

### channel.delete

停止频道(如在运行中)并从注册表和持久化配置中移除。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 频道 id |

**响应:** `{ "id", "status": "deleted" }`。若频道既不在注册表中也不在配置中,返回错误。

### channel.send

通过频道发送消息。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `channel_id` | string | 是 | 频道 id |
| `to` | string | 是 | 会话 id(频道特定目标:聊天 id、频道 id、用户 id 等) |
| `text` | string | 是 | 消息正文(非空) |

**响应:** `{ "channel_id", "message_id", "timestamp", "sent": true }`。

### channel.pairing_data

获取支持配对的频道的配对数据(QR 码、code 或 deep link)。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `channel_id` | string | 是 | 频道 id |

**响应:** 频道的配对载荷(形态由频道定义)。

### channel.health

读取一个频道(或每个频道,汇总)的频道健康监控。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `channel_id` | string | 否 | 省略 ⇒ 每个频道的健康 + 集群摘要 |

**响应(单个频道):** 该频道的 `ChannelHealthResponse`(`id`、`channel_type`、`status`、`health_status`(`healthy` / `stale` / `degraded`)、`last_event_at`、`failure_count`、`status_reason?`)。

**响应(所有):** `{ "channels": [ ...ChannelHealthResponse... ], "summary": { "total", "healthy", "stale", "degraded" } }`。

### channel_outbox: dead_letters

这是内建工具 `channel_outbox`,**不是 Gateway RPC 方法**。使用 `action: "dead_letters"` 查看耗尽重试预算或因其他安全原因停止投递的出站消息。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `action` | string | 是 | `dead_letters` |
| `channel_id` | string | 否 | 限定通道,省略为全部 |
| `limit` | number | 否 | 默认 10,上限 25 |

**输出:** `message`、`durable_queue`、`dead_letters`。条目含 `channel_id`、`conversation_id`、`preview`(最多 200 字符)、`attempts`、`last_error`、`reason`、`redrivable`、`age_secs`。未配置持久队列时 `durable_queue` 为 `false`。

### channel_outbox: redrive

同一内建工具的恢复操作,**不是 Gateway RPC 方法**。使用 `action: "redrive"` 把可安全重放的死信移回出站队列;并非所有死信都能重放。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `action` | string | 是 | `redrive` |
| `channel_id` | string | 否 | 限定通道 |
| `confirm_redrive` | boolean | 否 | 只有 `true` 才真正重放;省略仅预览 |

**输出:** `message`、`durable_queue` 及适用的 `redriven`、`skipped_queue_full`、`skipped_not_replay_safe` 等字段。先检查预览,确认目标后再重放。

### channels.set_agent

将 agent 绑定到频道或解绑。委派到共享的绑定接缝(`gateway::agent_binding`)——与 `agent_switch` 工具相同的实现——所以两个面共享 ghost 验证、无操作检测和 `Bound` / `Unbound` 事件。**必须指定一个真实存在的 agent**(之前的宽松行为已被移除:26.7.15+)。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `channel_id` | string | 是 | 频道 id |
| `agent_id` | string | 否 | agent id;`null` / 缺失则解绑 |

**响应(绑定):** 新绑定时 `{ "ok", "previous_agent" | null, "no_op": false }`;无操作重绑定时 `{ "ok", "previous_agent", "no_op": true }`。

**响应(解绑):** `{ "ok", "previous_agent" | null }`。

当 `agent_id` 在 live `AgentRegistry` 中不存在时返回 `INVALID_PARAMS`。`agent_registry: None` 的最小化服务器跳过验证。

### agents.bindings

获取每个 agent 绑定的所有频道,按频道 id 排序。响应形态是 `{ "bindings": { "<agent_id>": [ "<channel>", … ] } }`,并展示绑定到 agent 的所有频道。

**请求:** 无参数。

**响应:** `{ "bindings": { "agent-1": [ "discord", "telegram" ], … } }`。

## 频道配对

支持未知发送者审批的频道(Telegram、iMessage BlueBubbles)维护每频道的配对存储。入站路由器的自动批准和 Panel 的手动 UI 共享同一存储;下方的 RPC 是手动 UI。

| 方法 | 参数 | 说明 |
|------|------|------|
| `channel.pairing.list` | `channel?` | `{ "requests": [ ...PairingRequest... ], "count" }`;可选 `channel` 过滤。每个 `PairingRequest` 包含 `channel`、`sender_id`、`code`、`created_at`。 |
| `channel.pairing.approve` | `channel`(必填),`code`(必填) | `{ "approved": true, "request": PairingRequest }` |
| `channel.pairing.reject` | `channel`(必填),`code`(必填) | `{ "rejected": true, "channel", "code" }` |
| `channel.pairing.approved` | `channel`(必填) | `{ "channel", "approved": [ ...sender_id... ], "count" }` |
| `channel.pairing.revoke` | `channel`(必填),`sender_id`(必填) | `{ "revoked": true, "channel", "sender_id" }` |

## Discord Control-Plane 面板

四个方法在 Discord modal 流的 Discord Control-Plane 面板中注册:

| 方法 | 说明 |
|------|------|
| `discord.validate_token` | 验证 Discord bot token(不持久化) |
| `discord.list_guilds` | 列出 bot 加入的 guilds |
| `discord.list_channels` | 列出 guild 的 channels |
| `discord.audit_permissions` | 审计 guild 的权限集与算子的意图 |

这些方法需要 live `ChannelRegistry`,始终存在;它们不依赖于已连接的频道状态。

## 频道类型 → 密钥字段映射

`channel.create` 接受下列命名的密钥字段。每个字段都存到 `channel:<id>:<field>`,并**从持久化配置中剔除**。

| 频道族 | 密钥字段 |
|--------|----------|
| `telegram` | `bot_token` |
| `discord` | `bot_token` |
| `slack` | `bot_token`,`app_token` |
| `feishu` | `app_secret` |
| `msteams` | `app_password` |
| `matrix` | `access_token` |
| `xmpp` / `irc` / `email` | `password` |
| `nostr` | `private_key` |
| `webhook` | `secret` |
| `whatsapp` | `session_data` |
| `qq` | `client_secret` |

已配置的字段也会在 `channels.list` 上以 `has_<field>: true` 暴露(以及在设置页上)——可编辑输入始终从空开始,保存时空值表示"保留现有 vault 值"。
