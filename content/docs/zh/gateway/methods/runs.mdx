当前运行时没有 `runs.*` JSON-RPC 命名空间，也没有独立的运行等待或消息排队 RPC；注册表见 `src/gateway/method_census.rs`。

之前页面暗示的功能——等待运行结束、或向活动运行推入消息——通过其他名称暴露:

- **运行状态**:`chat.send` / `chat.abort` / `agent.run` / `agent.cancel`。事件总线上 `agent.*` 主题的订阅者会看到 `agent.started`、`agent.run.complete`、`agent.run.error`,以及按轮的 `stream.agent_trace` 事件（定义见 `src/gateway/events/frame.rs`）。
- **运行中转向**:来自源频道(默认)的 `Steer` 消息会被注入到活动事件日志,在下一轮边界被消费。事件总线负责扇出,没有单独的"队列" RPC。
- **运行中 HITL 审批**:`exec.approval.resolve` 和 `clarification.resolve` 是运行中交互的合法入口(一卡一提示)。

## 实际存在的内容

在线上最接近的对应物:

- `agent.*`——每个运行的生命周期 RPC(启动、状态、取消、恢复)位于 `/docs/zh/gateway/methods/agent`。
- `subagent.tree`——快照活动的后台子代理树(`{ "nodes": [...], "count": N }`)。
- `chat.send`——发起一次聊天轮次;响应携带 `run_id`,可与事件总线关联。
