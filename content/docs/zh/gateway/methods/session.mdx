网关暴露**两个并行的会话命名空间**——`sessions.*`(复数,基于 SQLite 的实时数据库存储)和 `session.*`(单数,每个会话的运行时 RPC)。两者都在 `register_session_handlers`(`src/bin/aleph-server/commands/start/builder/handlers/session.rs`)中于服务器启动时连接,代码位于 `src/gateway/handlers/session/`。

`sessions.*` 面面向 `SessionStore`(位于 `src/gateway/session_store/` 的 SQLite 实现);`session.*` 面面向每个会话的状态,加上工件存储,单次调用 API 与 CRUD 面不同。

运行时在每个状态变更调用上保留 `events_retired` 计数:`sessions.reset` / `sessions.delete` 在投影之前作废权威的 `session_events` 日志,因此被删除的对话无法通过回放、BM25 搜索或下次启动时的 `ProjectionReconciler` 重新浮现。

## `sessions.*`(数据库存储)

### sessions.list

列出所有会话。内部的 `task` 和 `ephemeral` 会话被过滤掉,使侧边栏永远不显示 cron / heartbeat 类杂质。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `agent_id` | string | 否 | 按 agent id 过滤 |

**响应:** `{ "sessions": [ ...SessionInfo... ], "count": N }`。每行包含 `key`、`agent_id`、`session_type`、`message_count`、`created_at`(RFC3339)、`last_active_at`(RFC3339)、`updated_at`(Unix 秒,驱动 Panel 排序)、`topic`(解析顺序:`topic` → `identity_meta` → `custom` → `topic` → 未泄漏的 `derived_title`)、`status`、`state`、`label`、`input_tokens`、`output_tokens`、`model`、`model_provider`、`parent_session_key`、`compaction_count`、`channel`(来源:`telegram` / `discord` / `gui:chat` / `null`)、`project_root`、`exec_tier`(每会话覆盖,或 `null`)、`mode`(每会话覆盖,或 `null`)。

### sessions.history

取一个会话的消息历史。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `session_key` | string | 是 | 规范 session key(如 `agent:main:main`) |
| `limit` | number | 否 | 最大消息数(省略则取全部) |

**响应:** `{ "session_key", "messages": [ ...HistoryMessage... ], "count": N }`。每个 `HistoryMessage` 是 `{ role, content, timestamp, metadata? }`。

### sessions.new

关闭当前会话(可选附带 `topic`),并创建相同 key 的新 epoch。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `session_key` | string | 是 | 当前 session key |
| `topic` | string | 否 | 存储在关闭的会话上(最多 100 字符,按字符边界截断) |

**响应:** `{ "old_session_key", "new_session_key", "topic" | null }`。在 epoch 提升**之前**先终止旧 epoch 下键的自主延续,这样 `sessions.new` 总是返回干净的开始。

### sessions.reset

清空一个会话的消息历史。`session_events` 日志在 `messages` 投影**之前**被作废,这样该对话无法被任何后续读路径回放。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `session_key` | string | 是 | 规范 session key |

**响应:** `{ "session_key", "reset", "events_retired" }`。

### sessions.delete

删除一个会话及其附带内容。默认 `sessions.delete` 是宏生成的条目;`*_with_capture` 变体在转写被丢弃**之前**触发 `SessionEnd` 扩展钩子并写入 `SessionEnd` 原始记忆行(这样 `CompressionService` / `ProfileSynthesizer` 能从垂死的会话中挖掘持久知识)。捕获的尾部还会清除该会话的工件和事件日志。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `session_key` | string | 是 | 规范 session key |

**响应:** `{ "session_key", "deleted", "events_retired" }`。

### sessions.preview

会话最近历史的有界预览,带完整元数据。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `session_key` | string | 是 | 规范 session key |
| `limit` | number | 否 | 默认 10 |

**响应:** `{ "session_key", "meta": { ...SessionMeta... }, "messages": [ ...{role, content, timestamp, metadata?}... ], "message_count": N }`。`meta` 包含 `key`、`agent_id`、`session_type`、`message_count`、`total_tokens`、`state`、`label`、`input_tokens`、`output_tokens`、`model`、`model_provider`、`parent_session_key`、`compaction_count`、`derived_title`、`last_message_preview`、`runtime_ms`、`estimated_cost_usd`、`checkpoints`、`created_at`、`last_active_at`。

### sessions.patch

增量修改会话元数据。运行时内联校验:无法被运行循环解析的 `exec_tier` 或 `session_mode` id 会被拒绝(`INVALID_PARAMS`),这样垃圾覆盖值不会偷偷解除安全控制。`null` 用于清除覆盖。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `session_key` | string | 是 | 规范 session key |
| `label` | string | 否 | 新 label |
| `status` | string | 否 | 新 status |
| `model` | string | 否 | 新 model id |
| `model_provider` | string | 否 | 新 provider 名 |
| `metadata` | object | 否 | `identity_meta` → `custom` 补丁——`exec_tier` / `session_mode` 在此校验 |

**响应:** `{ "session_key", "updated" }`。

### sessions.set_topic

设置会话主题(自动命名的目标)。按字符边界截断到 100 字符。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `session_key` | string | 是 | 规范 session key |
| `topic` | string | 是 | 新主题(≤ 100 字符) |

**响应:** `{ "session_key", "updated": true }`。

### sessions.set_project_root

在会话上固定一个项目工作目录。`null` / 缺失清除覆盖(回退到默认的 `~/.aleph/workspaces/{agent_id}`)。路径校验(绝对 / 存在 / 是目录)在运行时的 `agent.run` 中发生——此 RPC 只记录偏好,因此尚不存在的文件夹可以被记住而不会让调用失败。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `session_key` | string | 是 | 规范 session key |
| `project_root` | string | 否 | 绝对路径;`null` 清除 |

**响应:** `{ "session_key", "project_root", "updated": true }`。

### sessions.compaction.list

列出会话的压缩检查点。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `session_key` | string | 是 | 规范 session key |

**响应:** `{ "session_key", "checkpoints": [ ...{checkpoint_id, created_at, message_count, retained_message_count}... ] }`。

### sessions.compaction.restore

将会话恢复到一个检查点。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `session_key` | string | 是 | 规范 session key |
| `checkpoint_id` | string | 是 | 检查点 id |

**响应:** `{ "session_key", "checkpoint_id", "message_count", "updated": true }`。

### sessions.compaction.branch

从一个检查点分叉出新会话。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `session_key` | string | 是 | 源 session key |
| `checkpoint_id` | string | 是 | 检查点 id |
| `new_session_key` | string | 是 | 目标 session key(必须与源不同) |

**响应:** `{ "session_key", "checkpoint_id", "new_session_key", "message_count", "created": true }`。

## `session.*`(每会话运行时)

### session.create

创建新会话并返回规范 key。`name` 参数作为人类可读提示被接受,但不存储实体(新的 session key 生成为 `session_<unix_ms>`)。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | string | 否 | 人类可读标签 |

**响应:** `{ "session_key", "name" }`。

### session.usage

获取一个会话的 token / 消息统计,加上来自核心价格表的每模型真实 USD 成本(shell 中重复的价格表已被删除)。当 provider / model 对未定价时,成本为 `null`。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `session_key` | string | 是 | 规范 session key |

**响应:** `{ "session_key", "tokens", "input_tokens", "output_tokens", "messages", "created_at" | null, "last_active_at" | null, "cost_usd" | null, "cost_status": "unknown" | "complete" | "partial_missing_price" }`。

### session.compact

手动触发压缩。`KeepLastN` 策略被硬编码(`SESSION_COMPACT_KEEP_LAST_N`);代理循环的自动压缩也使用同一策略。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `session_key` | string | 是 | 规范 session key |

**响应:** `{ "message", "before_messages", "after_messages", "tokens_saved" }`。`tokens_saved` 是粗略估计(`deleted * 50`)。

### session.truncate

将历史截断到前 `keep_count` 条消息,按时间正序。驱动 TUI `/undo` 命令"丢弃最近一对 user+assistant 轮次"的路径。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `session_key` | string | 是 | 规范 session key |
| `keep_count` | number | 是 | 要保留的前导消息数 |

**响应:** `{ "messages_removed", "tokens_removed_estimate" }`。

### session.export_html

将会话导出为自包含 HTML 文档。字节通过 `ArtifactStore` 写入(没有第二条交付机制),因此文件与任何其他工件一样被列出、按能力寻址、被淘汰。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `session_key` | string | 是 | 规范 session key |

**响应:** `{ "url", "filename", "size" }`。`url` 是 `/artifact/<cap>/<id>/<filename>`;能力限定到该会话,因此操作员不能读取他人会话的导出。

## 工件(配套面)

`artifacts.list` 和 `artifacts.read_text` 由 `register_artifact_handlers` 与 `session.export_html` 一同连接。它们不在 `session.*` 下,但是与每会话运行时自然配套的只读面。

| 方法 | 参数 | 说明 |
|------|------|------|
| `artifacts.list` | `session_key` | 列出会话的每个工件,最新优先。每行包含 `id`、`filename`、`mime_type`、`size`、`origin`、`run_id`、`created_at`、`url`。 |
| `artifacts.read_text` | `session_key`,`id` | 读取文本工件的预览(≤ 512 KB),含 `content` + `truncated`。非文本 MIME 类型返回 `INVALID_PARAMS`(因此 PNG 不会被作为"二进制未渲染"错误地以字符串形式返回)。 |
