`extensions.*` 是 Aleph 三种扩展类型——`Skill` / `Plugin` / `Mcp`——之上的统一门面。对于日常用户,这些是同一个概念(扩展);该命名空间为**扩展商店**面板提供动力,并按 `kind` 路由到现有的 `skills.*` / `plugins.*` / `mcp.*` 后端。

七个方法在两次连接中分布:

- `register_extensions_handlers`(`src/bin/aleph-server/commands/start/builder/handlers/extensions.rs`)——四个生命周期/读方法。
- `register_extensions_install_handlers`(同文件,60-98 行)——三个受信任门控的安装流方法,它们还需要 vault 和 `MarketplaceManager`。

整个命名空间在启动时 `hub_catalog.db` 成功打开时才能连接;若本地缓存无法创建,四个生命周期方法会被跳过并记录警告。安装侧方法另外需要 `MarketplaceManager` 被构造。

## 历史:`sources.*` 方法已撤回

之前版本中描述的两个 `sources.*` 方法(列表与刷新)已在 26.6.22+ Hub 收敛中移除,现在不在 census 中——目录源是由 `AlephHubCatalog` 持有的内部概念,操作员通过捆绑同步循环和 `extensions.catalog` 视图达成相同效果。

## 目录条目形态

`extensions.catalog` 和 `extensions.installed` 返回 `ExtensionEntry` 行。`id` 带 kind 前缀(`mcp:registry/exa-search`、`plugin:acme/foo`、`skill:user/web_search`);`via` 字段是上游出处标签(如 `Aleph Hub`、`MCP Registry`)。

```json
{
  "id": "mcp:registry/exa-search",
  "kind": "Mcp",
  "name": "Exa Search",
  "description": "Web and code search via the Exa API.",
  "category": "Search",
  "trust_tier": "Verified",
  "installed": false,
  "enabled": false,
  "requires_config": true,
  "via": "Aleph Hub"
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 稳定的扩展标识符(带 kind 前缀) |
| `kind` | string | `Skill` / `Plugin` / `Mcp` |
| `name` | string | 显示名 |
| `description` | string | 简短描述 |
| `category` | string | 功能类别(`Search` / `Developer` / `Data` / `Productivity` / `Writing` / `Communication` / `Knowledge` / `Files` / `Design` / `Automation` / `Finance` / `Utilities` / `Other`) |
| `trust_tier` | string | `Official` / `Verified` / `Community` / `Unverified` |
| `installed` | boolean | 当前是否已安装 |
| `enabled` | boolean | 已安装后是否启用(只在 `installed` 时有意义) |
| `requires_config` | boolean | 运行前是否需要配置/密钥值 |
| `via` | string | 上游出处标签(由目录源设置) |

## 方法

### extensions.catalog

读取已缓存的、可离线的目录,与实时已安装集合对账。过滤在内存中执行;缺失后端降级为空而不是错误。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `kind` | string | 否 | `Skill` / `Plugin` / `Mcp` |
| `category` | string | 否 | 功能类别 |
| `source_id` | string | 否 | 目录源 id(如 `aleph-hub`、`mcp-registry`) |
| `query` | string | 否 | 在 `name` 和 `description` 上的自由文本搜索 |

**响应:** `{ "extensions": [ ...ExtensionEntry(带 `via` 导出的 source_label)... ] }`。每行的 `installed` 和 `enabled` 字段通过与 live MCP actor + 插件注册表 + 技能系统对账来盖章。

### extensions.installed

跨所有三个后端的实时已安装扩展对账。任一后端失败会被记录并跳过,所以出问题的 MCP actor 不会让面板的"已安装"列表清空。

**请求:** 无参数。

**响应:** `{ "extensions": [ ...ExtensionEntry... ] }`。每行带有规范 `id`(如 `local:mcp:<id>`、`local:plugin:<id>`、`local:skill:<id>`)和 `installed: true` 戳。

### extensions.disclosure

为目录条目返回强制的安装前披露载荷。Panel 在 `extensions.install` 之前渲染它。披露从已解析的安装 spec 构建;缺失 spec 返回错误。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 目录扩展 id |

**响应:** `{ "disclosure": { ...DisclosurePayload... }, "injection_findings": [ ...InjectionFinding... ], "post_install": { ...安装后验证载荷... } }`。

`DisclosurePayload` 包含精确的 `command` / `args`、声明的 `secrets` 及其用途、`network` / `filesystem` 触达范围、`version`、`sha256`、`risk_class`(`mcp-remote` / `mcp-stdio` / `plugin-…` / `skill-*`)、`trust_tier`、`ack_required`、`requires_ack`(社区或 LLM 派生的 MCP 条目为 `true`)。

`risk_class`:
- `mcp-stdio`——运行命令,风险最高
- `mcp-remote`——较温和(仅网络)
- `plugin-*`——可指导 agent
- `skill-*`——可指导 agent

社区或 LLM 派生的 MCP 条目设置 `ack_required: true` 和 `requires_ack: true`,要求在安装时显式确认"我了解此风险"。

### extensions.configure

根据 spec 校验提交的配置。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 目录扩展 id |
| `values` | object | 否 | 键/值配置;密钥字段由 spec 的 `secret: true` 标志识别 |

**响应:** `{ "ok", "missing": [ ...string... ] }`。`missing` 列出缺失或为空的必填字段。

### extensions.install

受信任门控的安装流水线。服务端重新校验 spec、信任判定、固定版本和 SHA256。密钥字段写入 vault,在 MCP 配置中按 `{{secret:NAME}}` 引用(在每个服务器启动时解析——永不以明文持久化)。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 目录扩展 id |
| `values` | object | 否 | 键/值配置;密钥字段入 vault,普通字段入配置 |
| `acknowledge_risk` | boolean | 否 | 社区/LLM 派生的 MCP 条目需要 `true`(否则安装停在 `needs_ack`) |

**响应(needs_ack):** `{ "ok": false, "needs_ack": true, "disclosure": { ...DisclosurePayload... }, "injection_findings": [...] }`。

**响应(missing):** `{ "ok": false, "missing": [ ...必填字段... ] }`。

**响应(installed):** `{ "ok": true, "outcome": { "kind": "mcp|plugin|skill", "id" | "path" }, "verify": { "ok", "tool_count"? | "error"? }, "pin": { "version", "sha256" }, "injection_findings": [...] }`。成功的 MCP 安装,`verify.tool_count` 确认服务器在启动尝试后已列出。成功的插件/技能安装,会调用 `extensions.reload()`,使新能力无需重启守护进程即可生效。

**OCI / Docker MCP 条目在 v1 中不可安装**——请求返回 `INVALID_PARAMS: OCI/Docker MCP containers are not installable in this version`。沙箱执行是快速跟进项。

### extensions.toggle

启用或禁用已安装的扩展。id 必须是 `installed (local:)` id;目录 id(`mcp-official:io.x/y`)被 `INVALID_PARAMS` 拒绝。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 已安装(local:)的扩展 id |
| `enabled` | boolean | 是 | 目标启用状态 |

**响应:** `{ "ok": true }`。

按 kind 行为:
- `local:mcp:<id>`——内部调用 `McpManagerHandle::start_server` / `stop_server`(Rust 方法,不是 Gateway RPC)
- `local:plugin:<id>`——`ExtensionManager::set_plugin_enabled`(同步内存注册表,然后重新检查服务状态)
- `local:skill:<id>`——`SkillSystem::update_config` 带 `SetEnabled(enabled)`

### extensions.uninstall

移除已安装的扩展并撤销其存储的密钥。id 必须是 `installed (local:)` id。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 已安装(local:)的扩展 id |

**响应:** `{ "ok": true }`。

按 kind 行为:
- `local:mcp:<id>`——内部调用 `McpManagerHandle::remove_server`(Rust 方法,不是 Gateway RPC)
- `local:plugin:<id>`——运行时下线 + `remove_dir_all` 插件目录(路径穿越保护镜像 `plugins::handlers::manage::is_safe_plugin_name`;`..` 或 `/` 之类的相对组件会被拒绝)
- `local:skill:<id>`——`SkillSystem::remove_skill`

在移除之后触发新的 `extensions.reload()`,所以 live `extensions.installed` 视图立即反映变更。

## 按 kind 后端

`extensions.*` 是一层薄门面。每个方法的实际工作委派给按 kind 后端;目录和后端保持同步,因为每个方法在响应之前也会与 live 集对账。

| Kind | 后端命名空间 | 工作发生位置 |
|------|--------------|--------------|
| `Skill` | `skills.*` | `SkillSystem` + 捆绑同步循环 |
| `Plugin` | `plugin.*` / `plugins.*` | `ExtensionManager` + `MarketplaceManager` |
| `Mcp` | `mcp.*` / `mcp_config.*` | `McpManagerActor` + `McpManagerHandle` |

对后端的修改(如通过 `mcp_config.create` 新增 MCP 服务器)会在 Panel 下次重新获取 `extensions.installed` 时被反映出来(总线也会发出 `tools.changed`)。

## 能力 ledger

每安装的可见能力列表在每次安装时从磁盘**重新构建**(Capability Ledger 在 `~/.aleph/runtimes/ledger.json`)。安装处理函数的安装前披露从这个 ledger 构建,这样 Panel 可以渲染扩展在运行时实际看到的内容——而不是目录中"它声称能做到"的乐观版本。
