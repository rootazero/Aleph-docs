`graph.*` 是网关对 agent 知识图谱(同一份 Panel 以 2D / 3D 星系渲染的数据)的读写接口。数据是核心 `MemoryBackend` 上的 `NoteStore` + `notes_graph_cache`,**不**是按调用的 LLM 合成——这里每个方法都是确定性读或直接索引器写。

三个读方法(`graph.query`、`graph.search`、`graph.node_detail`)是无条件的。三个写方法(`graph.update_note`、`graph.rename_note`、`graph.delete_note`)需要 live `NoteIndexer`;在模拟模式下,写方法返回 `Method not found`。

26.7.21 CHANGELOG 添加了**循环图治理层**(用于目标 / 审计 / 团队节点的 harness 持久存储);它位于 `teams.task.trace` + `governance.*` 事件主题之上,通过 `events.subscribe` 到达,**不**通过 `graph.*`。

## 方法

### graph.query

读取一个 agent 的笔记索引——节点(带 Louvain 缓存的 community id)和边(带类型和置信度)。`GraphRecompute` 物化的相似性边会针对真实 wikilink 边去重。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `limit` | number | 否 | 默认为 100 |
| `agent_id` | string | 否 | 默认为 `routing::DEFAULT_AGENT_ID` |

**响应:** `GraphQueryResponse`: `{ "nodes": [ ...NoteNodeDto... ], "edges": [ ...NoteLinkDto... ], "total": <number> | null, "bridge_nodes": [ ...path... ], "surprising_edges": [ [from, to]... ] }`。`bridge_nodes` 和 `surprising_edges` 被过滤到响应中可见的节点/边;在第一次 `GraphRecompute` 之前为空。

`NoteNodeDto` 包含 `id`(路径 `category/title`)、`name`(文件名)、`path`、`category`、`tags`、`link_count`、`community_id?`、`updated_at?`。`NoteLinkDto` 包含 `from`、`to`、`label?`、`kind`(普通正文 wikilink 为 `wikilink`,物化的相似性边为 `related_similarity`)、`confidence?`。

### graph.search

通过 `NoteStore` FTS 索引对笔记内容做全文搜索。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `query` | string | 是 | FTS 查询字符串 |
| `limit` | number | 否 | 默认为 20 |
| `agent_id` | string | 否 | 默认为 `routing::DEFAULT_AGENT_ID` |

**响应:** `{ "results": [ ...SearchResultDto... ] }`。每行包含 `id`、`name`、`category`、`match_field`(查询命中文件名为 `title`,否则为 `content`)、`agent_id`、`created_at`、`updated_at`、`tags`、`link_count`。

### graph.node_detail

获取一个节点的完整行、markdown 内容(从磁盘通过 `notes_dir()` 读取)、入站 backlinks,以及带完整生命周期溯源的出站链接。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `node_id` | string | 是 | 笔记路径 `category/title` |
| `agent_id` | string | 否 | 默认为 `routing::DEFAULT_AGENT_ID` |

**响应:** `NoteDetailResponse`: `{ "node": { ...NoteNodeDto... }, "content", "backlinks": [ ...path... ], "outgoing": [ ...OutgoingLinkDto... ] }`。`outgoing` 包含 `to`(解析或原始)、`raw`、`relation?`、`label?`、`confidence`、`resolved_by?`、`status`(`active` / `dangling` / `tombstone`)。

### graph.update_note

逐字持久化单个笔记的编辑后 markdown——正文**逐字节**写入(不是有损的 `KnowledgeNote::to_markdown` 重建),所以手写的散文、标题、代码块都能保留。持久化之前会扫描输入内容中的数据外泄载荷(仅外泄范围,所以用户自己的安全研究笔记不会被拒)。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `node_id` | string | 是 | 笔记路径 `category/title` |
| `content` | string | 是 | 完整原始 markdown(frontmatter + 正文) |
| `agent_id` | string | 否 | 默认为 `routing::DEFAULT_AGENT_ID` |

**响应:** `{ "node_id", "saved": true }`。`node_id` 不带 `category/` 前缀、category 或 `agent_id` 含路径穿越组件(`..`、`\`、`agent_id` 中的 `/`),或外泄扫描拒绝正文时,返回 `INVALID_PARAMS`。

### graph.rename_note

重命名文件,重写每个入站 `[[old]]` wikilink,重新索引,反向填充。新路径从 `find_by_filename` 重新推导,所以客户端的过期 category 不会破坏重命名。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `node_id` | string | 是 | 当前笔记路径 `category/title` |
| `new_title` | string | 是 | 新文件名(不带 `.md`);在服务端净化 |
| `agent_id` | string | 否 | 默认为 `routing::DEFAULT_AGENT_ID` |

**响应:** `{ "node_id", "new_id", "renamed": true }`。`new_id` 是规范的 `category/new_title`(从文件系统重新推导,不只用客户端提供的 category)。路径穿越情形与 `graph.update_note` 相同。

### graph.delete_note

删除文件 + 索引。入站链接变成**墓碑**(源正文不动,所以重命名恢复路径得到保留)。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `node_id` | string | 是 | 笔记路径 `category/title` |
| `agent_id` | string | 否 | 默认为 `routing::DEFAULT_AGENT_ID` |

**响应:** `{ "node_id", "deleted": true }`。路径穿越情形返回 `INVALID_PARAMS`。

## 不作为 RPC 存在的方法

之前版本中描述但**未在当前 alpeh-server 上注册**的方法:

| 方法 | 不作为 RPC 存在的原因 |
|------|---------------------|
| `graph.entities` / `graph.add_entity` / `graph.add_relation` / `graph.delete_entity` | 没有独立的 `Entity` 表;图由 `notes_index`(`KnowledgeNote` + wikilink + 相似性边)构建。Panel 调用 `graph.query` 进行渲染,从未有过单实体插入路径。 |
| `graph.neighbors` | 与 `graph.query` 的 `edges` 数组数据相同;Panel 在客户端迭代。 |

`graph.neighbors` 在旧设计文档中偶尔被引用;在运行时它只是 `graph.query` 返回的 `edges` 的一个属性。
