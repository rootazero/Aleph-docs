---
title: "heartbeat.*"
description: "心跳任务 RPC 方法"
---

`heartbeat.*` 是守护进程侧心跳调度器的生命周期接口。八个方法通过 `register_heartbeat_handlers` 在服务器启动(`src/bin/aleph-server/commands/start/builder/handlers/agents.rs:142-196`)构造了 `SharedHeartbeatService` 后注册;若服务未构造(例如没有调度器的模拟模式),JSON-RPC 方法不存在,调用返回 `Method not found`。

源码中每个方法都有两个变体:一个由 `HeartbeatService` 支持的真实处理器,一个返回固定空响应的 `_stub`。启动时仅连接真实处理器。

## 方法

### heartbeat.list

列出所有心跳任务。

**请求:** 无参数。

**响应:** `{ "tasks": [ ...HeartbeatTaskView... ] }`。每个任务包含 `id`、`name`、`agent_id`、`enabled`、`interval_ms`、`probe`(`tool_name` / `tool_params` / `trigger_condition`),以及调度器状态(`next_due_ms`、`last_probe_at_ms`、`last_probe_result`、`consecutive_errors`、`last_error`)。

### heartbeat.get

按 id 获取单个任务。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `task_id` | string | 是 | `heartbeat.create` 返回的任务 id |

**响应:** `{ "task": { ...HeartbeatTaskView... } }`,或 `INTERNAL_ERROR: Task not found: <task_id>`。

### heartbeat.create

创建新任务。接受 `interval_ms`(数字)或 `interval`(字符串如 `"5m"` / `"1h"` / `"30s"` / 原始毫秒数)。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | string | 是 | 人类可读的任务名称 |
| `agent_id` | string | 否 | 默认为 `"main"` |
| `interval_ms` | number | 条件 | 周期(毫秒)。与 `interval` 互斥。 |
| `interval` | string | 条件 | 带后缀的周期(`s` / `m` / `h`)或原始毫秒 |
| `probe.tool_name` | string | 是 | 心跳每次 tick 调用的工具 |
| `probe.tool_params` | object | 否 | 传给工具的 JSON 参数 |
| `probe.trigger_condition` | string | 否 | 缺省为 `Always`,或由 `TriggerCondition` 反序列化得到的任意结构化触发条件 |
| `enabled` | boolean | 否 | 默认为 `true` |

`tool_name` 也可置于顶层而不是 `probe` 内;两种写法都接受。

**响应:** `{ "task": { ...HeartbeatTaskView... } }`(新创建的任务)。

### heartbeat.update

增量更新任务。只触碰 `params` 中出现的字段。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `task_id` | string | 是 | 任务 id |
| `name` | string | 否 | 新的人类可读名称 |
| `agent_id` | string | 否 | 新的 agent id |
| `interval_ms` | number | 否 | 新周期(毫秒) |
| `interval` | string | 否 | 带后缀的新周期 |
| `enabled` | boolean | 否 | 新的启用状态 |
| `probe` | object | 否 | 整 `ProbeConfig`(`tool_name` / `tool_params` / `trigger_condition`)替换 |

**响应:** `{ "task": { ...HeartbeatTaskView... } }`(更新后的任务)。

### heartbeat.delete

删除任务。在内存调度器上是幂等的;运行历史保留在 SQLite 存储中。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `task_id` | string | 是 | 任务 id |

**响应:** `{ "deleted": "<task_id>" }`。

### heartbeat.toggle

启用或禁用任务。若提供 `enabled`,则强制设为该值;否则翻转当前启用标志。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `task_id` | string | 是 | 任务 id |
| `enabled` | boolean | 否 | 若提供,设为该确切值;否则切换当前状态 |

**响应:** `{ "task_id": "<task_id>", "enabled": <bool> }`。

### heartbeat.wake

入队一次手动唤醒。以 `WakePriority::UserAction` 优先级入队;调度器在下一 tick 取出。未知 `task_id` 返回 `INTERNAL_ERROR`。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `task_id` | string | 是 | 任务 id |
| `reason` | string | 否 | 自由文本原因;记录在运行条目上 |

**响应:** `{ "triggered": "<task_id>", "status": "queued", "reason": "<reason>" | null }`。

### heartbeat.runs

返回任务的执行历史(从 SQLite `heartbeat_runs` 表中),按时间正序。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `task_id` | string | 是 | 任务 id |
| `limit` | number | 否 | 最大行数;默认 20 |

**响应:** `{ "task_id": "<task_id>", "runs": [ ...RunRecord... ] }`。每个运行条目包含 `id`、`trigger_source`、`l1_status` / `l2_status`、`started_at` / `ended_at`、`l1_duration_ms` / `l2_duration_ms`、`error`、`delivery_status`、`created_at`。

## 接线

`register_heartbeat_handlers` 仅在 `agent_result.heartbeat_service.is_some()` 时才被调用(`register_agents_handlers` 内部)。未构造服务的最小化 `aleph-server` 启动不会暴露该命名空间。运行时不存在回退到占位符 stub 的兜底。
