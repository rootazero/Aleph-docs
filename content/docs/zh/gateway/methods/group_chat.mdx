`group_chat.*` 是低层多代理群聊**会话原语**,持久的 `teams.chat.*` 线程(以及 Panel 的三栏群聊窗口)构建于其上。六个方法在 `HandlerRegistry::new()` 中以 `service_unavailable` 占位符注册,然后在 `register_group_chat_handlers` 中替换为真实处理器——一旦 `GroupChatOrchestrator` + `GroupChatExecutor` 在服务器启动时存在(`src/bin/aleph-server/commands/start/builder/handlers/system.rs:95-150`)。

占位符在注册表构造和 orchestrator 安装之间被调用——这段时间窗口内的调用返回 `INTERNAL_ERROR: group_chat.<method> requires GroupChatOrchestrator runtime - wire Gateway first`。正常操作下,orchestrator 在第一个 RPC 到达前就已安装。

Panel 实际使用的持久每团队线程,见 [teams.*](/docs/zh/gateway/methods/teams)(`teams.chat.send` / `teams.chat.history` / `teams.chat.thread`)。

## 方法

### group_chat.start

在一组 personas 上启动新的群聊会话。当提供 `initial_message` 时,立即执行第一轮并返回该轮的消息。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `personas` | object[] | 是 | 每项是 `PersonaSource`(如 `{ "kind": "Agent", "agent_id": "reviewer" }`) |
| `topic` | string | 否 | 会话主题 |
| `initial_message` | string | 否 | 第一条用户消息——执行第一轮 |
| `source_channel` | string | 否 | 默认为 `"rpc"` |
| `source_session_key` | string | 否 | 默认为 `"rpc:direct"` |

**响应(无 initial_message):** `{ "session_id" }`。

**响应(带 initial_message):** `{ "session_id", "messages": [ ...{session_id, speaker, content, round, sequence, is_final}... ] }`。

### group_chat.continue

用新消息推进会话。Agent 轮流响应,直到 `max_rounds`;一旦达到限制,会话被强制结束,调用返回 `INTERNAL_ERROR: Round limit exceeded`。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `session_id` | string | 是 | `group_chat.start` 返回的 id |
| `message` | string | 是 | 用户消息(非空) |

**响应:** `{ "session_id", "messages": [ ...{session_id, speaker, content, round, sequence, is_final}... ] }`。

### group_chat.mention

类似 `group_chat.continue`,但 `targets` 数组在轮中优先考虑提到的 personas。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `session_id` | string | 是 | `group_chat.start` 返回的 id |
| `message` | string | 是 | 用户消息(非空) |
| `targets` | string[] | 否 | 要优先考虑的 persona id(如 `["@all"]` 或具体 `agent_id`) |

**响应:** 形态与 `group_chat.continue` 相同。Panel 的 `@` 提及自动补全映射到 `targets`;`@all` 展开为每个参与者。

### group_chat.history

获取会话的对话历史。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `session_id` | string | 是 | `group_chat.start` 返回的 id |

**响应:** `{ "session_id", "history": [ ...{round, speaker, content, timestamp}... ], "current_round" }`。只读,任何时候都能安全调用。

### group_chat.list

列出每个活动会话。状态不是 `Active` 的会话被过滤掉。

**请求:** 无参数。

**响应:** `{ "sessions": [ ...{id, topic, participants: [{id, name}], current_round, status, created_at}... ] }`。

### group_chat.end

结束群聊会话。Session Arc 被丢弃,orchestrator 忘记该会话,任何进行中的执行器轮次会穿透。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `session_id` | string | 是 | `group_chat.start` 返回的 id |

**响应:** `{ "ended": "<session_id>" }`。

## 运行时生命周期

```
HandlerRegistry::new()        →  group_chat.* = service_unavailable 占位符
   ↓
register_group_chat_handlers  →  group_chat.* = 真实处理器(orchestrator 绑定)
   ↓
会话可以被启动
```

未构造 `GroupChatOrchestrator` 的最小化/模拟服务器永远保留占位符。没有回退指向 `teams.chat.*` 的兜底——两个命名空间共享同一 fan-out 机制(`teams` 线程构建在 orchestrator 的 `GroupChatBroadcaster` 之上),但 JSON-RPC 契约不同。

## 并发性

每个会话在轮期间持有自己的每会话锁;orchestrator 锁仅短暂持有以获取会话句柄。不同会话并发进行,轮本身使用与 `teams.chat.send` 相同的并行 fan-out 防护(chain depth + fan-out width)。
