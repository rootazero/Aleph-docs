> *"这是人类历史上第一次，机器的灵魂被赋予了身体。"*
> — 《攻壳机动队》

**Aleph** 是用 Rust 构建的个人 AI 助手。它把高性能的 Gateway 控制平面与多通道消息、记忆治理、工具执行、本地与远程执行体（节点集群）整合到同一个核心，让 AI Agent 能在你的硬件上跨平台工作，并保持端到端的可见性。

> **一核多端，壳核分离；网关互通，权限控制。**
>
> 一个 `aleph-server` 核心驱动所有界面——桌面应用、CLI、TUI、Telegram、Discord、iMessage、iPhone / iPad Panel 等。原生桌面壳是零业务逻辑的薄容器；所有推理、工具和状态都在核心中。每个终端通过同一个经过认证的 WebSocket 网关连接，无论是本地还是远程。

## 主要特性

- **多提供商 AI** — Claude、GPT、Gemini、Ollama（含多模），带原子计数器与原子 regen marker 的故障转移；`session.usage` 走核心定价
- **多通道** — Telegram、Discord、iMessage、WebChat 与桌面应用共享同一认证网关、入站路由、会话模型、记忆和工具生态
- **会话模式（chat / work / code）** — 与 `exec_tier`、`think_level` 并列的第三维，对工具**呈现**面做静态分区；可被 `session_set_mode` 工具动态切换
- **原生性能** — 100% Rust 核心，无解释型语言
- **壳核分离** — 桌面壳纯 OS 集成；核心可独立运行
- **远程核心 + 自签名 TLS** — 桌面壳可通过 Tailnet/VPN 连接远程 `aleph-server`；SAN 自动覆盖本机非环回接口 IP；漂移 sidecar 原子 regen
- **TOFU 证书信任** — 桌面面板内完成指纹 + SAN 审批与本地固定（macOS WKWebView + iOS Keychain 适配器）
- **集群联邦** — 一个中心核编排多台机器（节点）作为执行臂；节点键按 Unicode 归一化（CJK 节点名正确）
- **三层安全模型** — 失败关闭的审批 / 沙箱 / 配对，加上 `exec_tier`、会话模式、能力账本
- **治理拓扑层（loop_graph）** — 团队节点 / 独立证据审计员（`loop-auditor`） / 胜利声明 watcher / 客观 ACL
- **Loop / Goal / Strategy 三角** — 当前会话的持续循环 / 自主目标追求（客观 gate）/ 团队或裸循环的 plan（composite-keyed）（`src/goal/`、`src/strategy/`）
- **Aleph Hub 单一源（`aleph-hub`）** — 官方 MCP / 插件 / 技能统一目录；`hub::primer` 冷启动投影（`src/hub/primer.rs`）
- **Artifact / Deliverables** — 50 MB 上限 + 4 个 origin 的 artifact store；模型用 `artifact_publish` 发布可交付物，Panel 钉到顶部（`src/artifacts/`、`src/builtin_tools/artifact_publish.rs`）
- **Vault 面板重构** — 卡片视图 + 双轨搜索 + 证据链 + 跨代理选择 + 来源三元组（`interfaces/webchat/src/platform/wide/views/memory/`）
- **流式语音对话** — Deepgram / WhisperLiveKit 流式 ASR；TTS provider fallback 上限 2；Voice-as-Context 接入上下文聚合（`src/config/types/voice_local.rs`、`src/gateway/voice/outbound.rs`）
- **可扩展** — 类型安全的内置工具、能力门控的 MCP 发现、插件、Markdown 技能和自定义工具共享 scoped tool service 与审批路径
- **自托管** — 在你自己的硬件上运行，完全控制

## 架构

```
    ┌────────────────────────────────────────────────────────────────────────┐
    │ Capability 契约层: capability / plugin / slot                          │
    └───────────────────────────────────▲────────────────────────────────────┘
                                        │
    ┌──────────────────┐   ┌───────────────────────────┐   ┌──────────────────┐
    │ Leptos/WASM      │◄─►│ shared/ui_logic/src/panel │◄─►│ TSX (nsh)        │
    │ interfaces/      │   │ 运行时中立的模型          │   │ interfaces/      │
    │ webchat/         │   │ 仅依赖 aleph_protocol     │   │ panel/           │
    └──────────────────┘   └───────────────────────────┘   └──────────────────┘

    Panel / CLI / TUI / Telegram / Discord / iMessage
                    │
                    WebSocket (JSON-RPC 2.0, wss:// 可选)
                    ▼
    ┌────────────────────────────────────────────────────────────────────────┐
    │                       Aleph 核心 (aleph-server)                        │
    │  ┌──────────────────┐  ┌──────────────────┐  ┌──────────────────────┐  │
    │  │ Gateway          │  │ Harness          │  │ Tool Registry        │  │
    │  │ (TLS/TOFU)       │  │ (Think→Act)      │  │ (builtin/MCP/plugin) │  │
    │  └──────────────────┘  └──────────────────┘  └──────────────────────┘  │
    │  ┌──────────────────┐  ┌──────────────────┐  ┌──────────────────────┐  │
    │  │ Thinker          │  │ Session          │  │ Memory + Loop        │  │
    │  │ (PromptBuilder)  │  │ Service          │  │ Graph (governance)   │  │
    │  └──────────────────┘  └──────────────────┘  └──────────────────────┘  │
    │  ┌──────────────────┐  ┌──────────────────┐  ┌──────────────────────┐  │
    │  │ Approval /       │  │ Extension        │  │ Heartbeat / Cron     │  │
    │  │ Guardrails       │  │ / Skill          │  │ 调度与探测           │  │
    │  └──────────────────┘  └──────────────────┘  └──────────────────────┘  │
    └────────────────────────────────────────────────────────────────────────┘
                                        │
                                        经认证的执行调度
                                        ▼
                                  集群节点（远程执行体）
```

**两套渲染器，共享模型。** Leptos/WASM（`interfaces/webchat/`）与 TSX（`interfaces/panel/`）共享 `shared/ui_logic/src/panel/` 的运行时中立模型；模型只依赖 `aleph_protocol`（`shared/ui_logic/src/panel/mod.rs`）。可用 tab 取决于运行时：TSX 目前只实现 overview、sessions、capabilities 三个内置 tab，其余面向 Leptos DOM/WASM 的 tab 显示为 unavailable（`interfaces/panel/src/lib.rs`）。这不意味着 TSX 已取代 Leptos。

**桌面宿主双轨。** 过渡期遗留的 Tauri 壳仍承担发版中的桌面应用（`desktop/shell/`，crate `aleph-desktop-shell`）；发布流水线仍在该目录运行构建（`.github/workflows/aleph-app-release.yml`）。目标形态是 NSH 0.6.0 宿主（`desktop/nsh-shell/`，crate `aleph-nsh-shell`，版本见 `desktop/nsh-shell/Cargo.toml`），目前没有对应发版流水线（`.github/workflows/`）。它默认承载同一份 Leptos/WASM Panel，不是另一套业务 UI；只有启用 `tsx-panel` feature、设置 `ALEPH_SHELL_PANEL=tsx` 且不处于 QA 模式时才切换到 TSX surface（`desktop/nsh-shell/src/main.rs`）。

NSH 接入已经运行的 Gateway，不默认管理其生命周期（`desktop/nsh-shell/src/main.rs`）；显式启用 `embedded-core` 时才有本地核心启动路径（`desktop/host/src/local_server.rs`）。这不代表默认桌面切换、守护进程监管迁移、发版分发、Windows/Linux NSH 验收或遗留 Tauri 移除已完成；旧宿主仍可用，并曾作为 G7 对照（`docs/reference/DESKTOP_SHELL.md`）。iPhone / iPad 宿主位于 `mobile/ios/AlephPaneliOS/`，设备支持见 `mobile/ios/project.yml`；它通过全屏 WKWebView 承载同一份 WASM Panel，而非独立 iOS 业务 UI（`mobile/ios/AlephPaneliOS/Views/PanelWebView.swift`）。

能力契约已在 `src/capability/` 落地；从[能力模型](/capabilities/capability-model)了解当前边界。

**第三双生子：会话模式。** `chat` / `work` / `code` 是与 `exec_tier`（执行审批等级）、`think_level`（思考预算）并列的第三个用户可调维度。它**只对工具呈现面**做静态分区（progressive-disclosure + deferred-tool tier），不影响权限——权限仍由 `exec_tier` 与审批门控制。可在面板 composer pill、Settings → Policies 或 `session_set_mode` 工具里切换。

**治理拓扑层。** `loop_graph` 在 harness 之上叠加一层治理拓扑：团队节点 / 审计环 / 客观 ACL / 胜利声明 watcher / 内置 `loop-auditor` 智能体。它给单循环的四种失败模式（Goodhart、参考盲、环冲突、测量衰减）一个拓扑答案。

## 快速开始

```bash
# 从源码构建核心（Rust 1.99+）
git clone https://github.com/rootazero/Aleph.git
cd Aleph
cargo build --bin aleph-server --release

# 创建 ~/.aleph/config.toml，然后启动核心
./target/release/aleph-server doctor
./target/release/aleph-server start
```

打开 `http://127.0.0.1:18790/`，或让 CLI 连接 `ws://127.0.0.1:18790/ws`。

## 设计理念

Aleph 构建于五层涌现架构之上：

1. **知识之海** — AI 的预训练基础
2. **领域分类** — 组织化的专业知识
3. **原子技能** — 从知-什么到知-如何
4. **功能模块** — 可组合的能力
5. **多态 Agent** — 灵魂获得身体

目标不仅仅是构建一个工具，而是探索通往 AGI 的路径——当智能获得行动能力时。
