`alephcore` crate 是为每个 Aleph 组件提供支持的 Rust 库——Gateway 守护进程、CLI、桌面应用和消息接口。你也可以直接把它当作库，把 Aleph 的 AI Agent 能力嵌入自己的 Rust 应用。

crate 定义在仓库根目录（历史上还有一个 `core/` 子 crate，已于 2026-04 并入根 `Cargo.toml`）：

```toml
# Cargo.toml
[dependencies]
alephcore = { path = "../Aleph" }
tokio = { version = "1", features = ["rt-multi-thread", "macros"] }
```

## Crate 元数据

| 字段 | 值 |
|-------|-------|
| Crate 名称 | `alephcore` |
| 位置 | 仓库根目录的 `Cargo.toml` |
| Edition | 2021 |
| 最低 Rust 版本 | 1.99 |
| Crate 类型 | `rlib` |
| 异步运行时 | Tokio（多线程） |
| 同一 crate 的二进制 | `aleph-server`、`aleph-migrate` |

crate 只产出 `rlib`：`cdylib` 那一半在 2026-04 的仓库合并后已无消费者（`alephcore` 不导出任何 `extern "C"` 符号），随发布的是 Panel 自己的 WASM 产物。

`aleph-server` 是 Gateway 守护进程，`aleph-migrate` 执行配置迁移。

## 关键公共类型

### 配置

`config` 模块本身是私有的，下表类型全部在 crate 根重新导出，用 `alephcore::Config` 这样的路径取用。

| 类型 | 描述 |
|------|-------------|
| `Config` | 主配置结构体（从 `config.toml` 解析） |
| `ProviderConfig` | 单个提供商的设置（模型、API 密钥、基础 URL） |
| `MemoryConfig` | 记忆系统设置 |
| `BehaviorConfig` | Agent 行为调整 |
| `RoutingRuleConfig` | 意图路由规则 |
| `GeneralConfig` | 一般应用程序设置 |
| `ChannelInstanceConfig` | 单个频道实例的声明（`type` / `enabled` / 平台键） |
| `PluginMarketplaceEntry` | 插件市场条目 |
| `EmbeddingProviderConfig` | 嵌入提供商设置 |
| `GenerationProviderConfig` | 生成提供商设置 |
| `MemoryInjectionMode` | 记忆注入模式 |
| `AssemblerConfig` | 上下文装配参数 |

### Harness（Think→Act）

Harness 是拥有 Agent 循环的 Think→Act driver。它受 R10 约束（"harness 是 scaffolding，不是 cognition"），并由 `src/harness/tests/budget.rs` 通过棘轮强制：恰好 **12 文件**，行数总和压低于 `CEILING = 5,535`。

| 类型 | 模块 | 描述 |
|------|--------|-------------|
| `AgentHarness` | `harness` | 核心 Think→Act 执行引擎 |
| `AgentHarness::new` | `harness` | 用 `HarnessDeps` 构造 |
| `AgentHarness::run` | `harness` | 驱动一次完整运行（会话 ID + 回调 + 取消令牌） |
| `AgentHarness::terminate_reason` | `harness` | 运行停止原因 |
| `AgentHarness::token_breakdown` | `harness` | 按类别统计 token |
| `AgentHarness::last_turn_context_tokens` | `harness` | 上一轮的上下文 token 数 |
| `AgentHarness::tool_timeline` | `harness` | 工具调用时间线 |
| `AgentHarness::duration_ms` | `harness` | 实际耗时 |
| `AgentHarness::total_tokens` | `harness` | 本次运行消耗的 token 总数 |
| `AgentHarness::hit_limit` | `harness` | 是否因为迭代上限 / 上下文压力而收尾 |
| `HarnessDeps` | `harness::deps` | 注入的依赖：27 个字段的结构体字面量，没有 `Default`、没有构造函数 |
| `HarnessRunner` | `orchestrator::dispatch` | 多态执行 seam：带 `FlowSpec` 跑一条编排流 |
| `HarnessCallback` | `harness::callback` | 实时事件回调 |
| `NoopHarnessCallback` | `harness::callback` | 忽略全部事件的默认回调 |
| `HarnessError` | `harness::trait_def` | Harness 错误 |
| `TurnState` | `harness::trait_def` | Turn 状态 |
| `TurnStep` | `harness::trait_def` | 轮次控制信号（必须被消费，丢弃即丢失该轮的推进指令） |
| `ChainContext` | `harness::chain_context` | 每轮执行上下文 |
| `TraceSink` / `NoopTraceSink` | `harness::trace_sink` | Trace sink trait + 默认实现 |
| `StallConfig` | `harness::deps` | 连续失败 watchdog 配置 |
| `ModelRobustnessProfile` | `verification` | 按模型解析的健壮性档案 |

`HarnessCallback` 的钩子是 `on_delta` / `on_reasoning` / `on_tool_call_start` / `on_tool_call_done` / `on_context_usage` / `on_safety_block` / `on_complete_with_outcome`。

### Thinker（LLM 层）

Thinker 是决策层，没有单一的 `Thinker` 结构体——它由「提供商注册表 + 提示词构建 + 上下文聚合」几块拼起来。

| 类型 | 模块 | 描述 |
|------|--------|-------------|
| `ProviderRegistry` | `thinker` | 提供商查找和选择的 trait（`get` / `default_provider` / `list_providers`；不携带健康状态） |
| `SingleProviderRegistry` | `thinker` | 包装单个 `AiProvider` 的简单注册表 |
| `SwappableProviderRegistry` | `thinker` | 可热替换当前提供商的注册表 |
| `MultiProviderRegistry` | `thinker` | 多提供商注册表 |
| `PromptBuilder` / `PromptConfig` | `thinker::prompt_builder` | 从上下文构建系统 + 用户提示词 |
| `TokenBudget` | `thinker::prompt_budget` | 提示词预算 |
| `ContextAggregator` / `TurnEnvelope` | `thinker::context` | 上下文聚合与轮次信封 |
| `PromptLayer` / `LayerInput` | `thinker::prompt_layer` | 可叠加的提示词层 |
| `SoulManifest` / `SoulVoice` | `thinker::soul` | 灵魂设定（manifest + 语气） |
| `MemoryContextProvider` | `thinker::memory_context_provider` | 记忆上下文提供者 |

### 提供商

| 类型 | 模块 | 描述 |
|------|--------|-------------|
| `AiProvider` | `providers` | AI 后端的核心 trait（单个 `process` 方法） |
| `create_provider` | `providers` | 按名称与配置构造提供商 |
| `HttpProvider` | `providers::http_provider` | 协议无关的 HTTP 提供商 |
| `OllamaProvider` | `providers::ollama` | 原生 Ollama 集成 |
| `FailoverProvider` | `providers::failover` | 自动提供商故障转移 |
| `DefaultProviderHandle` / `StaticDefault` | `providers::default_handle` | 默认提供商的持有与替换 |
| `ProviderRegistry` | `providers::registry` | 名称 → 提供商的并发注册表（与 thinker 的同名 trait 不是一回事） |

Aleph 提供 OpenAI 兼容、Anthropic、Gemini 和 Ollama 协议的适配器。通过实现 `AiProvider` 或注册 YAML 定义的协议适配器来添加新的提供商。

### 错误处理

| 类型 | 模块 | 描述 |
|------|--------|-------------|
| `AlephError` | `error` | 统一错误枚举（转发自 `aleph-slot-api`） |
| `AlephException` | `error` | 异常类型 |
| `ErrorClass` | `error` | 错误分类 |
| `Result<T>` | `error` | `std::result::Result<T, AlephError>` 的类型别名 |

每个 `AlephError` 变体都携带一个可选的 `suggestion` 字段，包含用户友好的修复建议。调用 `.suggestion()` 获取它，或 `.user_friendly_message()` 获取格式化的显示字符串；`.class()` 与 `.is_transient()` 用于分类与重试判断。

## 核心 Trait

### `AlephTool` — 静态工具 Trait

```rust
#[async_trait]
pub trait AlephTool: Clone + Send + Sync + 'static {
    const NAME: &'static str;
    const DESCRIPTION: &'static str;
    const MAX_RESULT_TOKENS: Option<usize> = None;

    fn services() -> Vec<aleph_slot_api::capability::Service> {
        Vec::new()
    }

    type Args: Serialize + DeserializeOwned + JsonSchema + Send;
    type Output: Serialize + Send;

    // 提供的方法
    fn category(&self) -> ToolCategory { ToolCategory::Builtin }
    fn requires_confirmation(&self) -> bool { false }
    fn mutates_file_content(&self) -> bool { false }
    fn strict_schema(&self) -> bool { true }
    fn definition(&self) -> ToolDefinition { /* 自动生成 JSON Schema */ }
    fn format_validation_error(&self, err: &serde_json::Error) -> String { err.to_string() }

    async fn call(&self, args: Self::Args) -> Result<Self::Output>;
    async fn call_json(&self, args: serde_json::Value) -> Result<serde_json::Value> { /* 默认实现 */ }
}
```

全覆盖实现将任何 `AlephTool` 转换为 `AlephToolDyn`，因此静态工具可以存储在动态集合中：

```rust
let tools: Vec<Box<dyn AlephToolDyn>> = vec![
    Box::new(SearchTool::new()),
    Box::new(WebFetchTool::new()),
];
```

### `AiProvider` — LLM 后端 Trait

```rust
pub trait AiProvider: Send + Sync {
    fn process<'a>(
        &'a self,
        payload: adapter::RequestPayload<'a>,
    ) -> Pin<Box<dyn Future<Output = Result<ProviderResponse>> + Send + 'a>>;

    fn name(&self) -> &str;
    fn color(&self) -> &str;
    fn supports_native_tools(&self) -> bool { false }
    fn protocol(&self) -> Cow<'_, str> { Cow::Borrowed("unknown") }

    // 提示型方法：模型行为覆盖、行为提示、实际服务的模型 / 提供商
    fn model_behavior_override(&self) -> Option<Cow<'_, str>> { None }
    fn behavior_hint(&self) -> Option<Cow<'_, str>> { None }
    fn serving_model_hint(&self) -> Option<Cow<'_, str>> { None }
    fn serving_provider_hint(&self) -> Option<Cow<'_, str>> { None }
}
```

核心方法只有一个 `process`：它接收带结构化 `UnifiedMessage` 历史的 `RequestPayload`，由协议适配器翻译成各家原生格式。流式输出由提供商实现自己的 delta 通道完成，不在 trait 表面。

### `HarnessCallback` — Agent 循环事件

```rust
pub trait HarnessCallback: Send {
    fn on_delta(&mut self, text: &str) {}
    fn on_reasoning(&mut self, text: &str) {}
    fn on_tool_call_start(&mut self, id: &str, name: &str, args: &serde_json::Value) {}
    fn on_tool_call_done(
        &mut self,
        id: &str,
        result: Option<&ToolOutput>,
        error: Option<&str>,
        duration_ms: u64,
    ) {}
    fn on_context_usage(&mut self, context_tokens: u32, total_tokens: u64) {}
    fn on_safety_block(&mut self, reason: &str) {}
    fn on_complete_with_outcome(&mut self, outcome: &FlowOutcome) {}
}
```

实现这个 trait 就能在 Agent 执行期间接收实时事件。内置实现是 `NoopHarnessCallback`（丢弃全部事件）和 Gateway 侧的 `BroadcastCallback`（把事件广播到 Gateway 的流）。

## 使用示例

### 运行 Agent 循环

`HarnessDeps` 没有 `Default` 也没有构造函数，所有字段都要显式写出来；用不到的接缝一律填 `None`。

```rust
use alephcore::harness::{AgentHarness, HarnessDeps, NoopHarnessCallback};
use alephcore::memory::tool_signal_sink::NoopToolSignalSink;
use alephcore::providers::{create_provider, ProviderConfig};
use alephcore::verification::ModelRobustnessProfile;
use std::sync::Arc;

#[tokio::main]
async fn main() -> alephcore::Result<()> {
    // 1. 创建一个提供商。harness 只看见一个 AiProvider——故障转移
    //    由 providers::FailoverProvider 在这一层内部叠加。
    let provider = create_provider(
        "anthropic",
        ProviderConfig::test_config("claude-sonnet-4-20250514"),
    )?;

    // 2. 装配依赖
    let deps = HarnessDeps {
        session: session_service,          // Arc<dyn SessionService>
        tools: tool_service,               // Arc<dyn ToolService>
        llm: provider,
        robustness_profile: ModelRobustnessProfile::conservative(),
        tool_descriptor_lookup: None,
        verifier_chain: None,
        context_budget: None,
        context_compactor: None,
        context_fabric: None,
        trace_sink: None,
        system_prompt: Some("你是 Aleph。".to_string()),
        system_prompt_parts: None,
        recall_context: None,
        guardrails: None,
        max_iterations: Some(20),
        power: None,
        stall_config: None,
        consecutive_failure_cap: Some(8),
        turn_timeout: None,
        turn_budget: None,
        result_store: None,
        session_epoch_registrar: None,
        tool_signal_sink: Arc::new(NoopToolSignalSink),
        in_flight_tool_calls: None,
        parallel_tool_concurrency: Some(8),
    };

    // 3. 构造并运行
    let harness = AgentHarness::new(deps);
    let outcome = harness
        .run(&session_id, &mut NoopHarnessCallback, &cancel)
        .await?;

    println!("停止原因: {:?}", harness.terminate_reason());
    Ok(())
}
```

## 错误处理

`AlephError` 是基于 `thiserror` 的枚举，定义在 `aleph-slot-api` crate 里，由 `alephcore::error` 转发。每个变体都包含结构化上下文：

```rust
match result {
    Err(AlephError::AuthenticationError { provider, message, suggestion }) => {
        eprintln!("{} 的认证失败: {}", provider, message);
        if let Some(hint) = suggestion {
            eprintln!("提示: {}", hint);
        }
    }
    Err(AlephError::RateLimitError { .. }) => {
        tokio::time::sleep(Duration::from_secs(60)).await;
        // 重试...
    }
    Err(e) => eprintln!("{}", e.user_friendly_message()),
    Ok(val) => { /* 成功 */ }
}
```

关键错误变体：`NetworkError`、`AuthenticationError`、`RateLimitError`、`ProviderError`、`Timeout`、`NoProviderAvailable`、`InvalidConfig`、`ConfigError`、`ToolNotFound`、`Cancelled`、`RuntimeError`、`ExecutionTimeout`、`SandboxUnavailable`。

## 异步运行时

Aleph 使用带 `rt-multi-thread` 功能的 Tokio。所有公共异步 API 返回与 Tokio 多线程运行时兼容的 `Send` Future。使用的关键 Tokio 功能：

- `rt-multi-thread` — 工作窃取线程池
- `sync` — 通道、互斥锁、RwLocks、信号量
- `time` — 超时、间隔、睡眠
- `process` — 子进程管理
- `fs` — 异步文件系统操作
- `signal` — Unix 信号处理
- `net` — TCP/UDP 网络
