本页说明 Gateway 的 JSON-RPC 消息语义，不承担方法参数手册。

## 消息形态

Gateway 的 JSON-RPC 2.0 消息分为请求、响应与通知。共享定义为 `JsonRpcRequest`、`JsonRpcResponse`、`JsonRpcError`，见 `shared/protocol/src/jsonrpc.rs`。方法清单见[方法参考](../gateway/methods)。

## 请求与响应

`JsonRpcRequest.id` 是 `Option<Value>`，共享类型没有把它收窄为字符串：`new()` 生成字符串 ID，`with_id()` 接受 JSON 值。需要响应的请求携带 `id`；`notification()` 设为 `None`，序列化时省略字段，`is_notification()` 检查是否为 `None`。不要把显式 JSON `null` 当成客户端应使用的请求关联 ID。`params` 为可选的 `Option<Value>`，不局限于对象。见 `shared/protocol/src/jsonrpc.rs`。

响应的 `id: Value` 关联请求；`success()` 与 `error()` 分别构造只有 `result` 或只有 `error` 的响应。错误对象有 `code`、`message` 与可选 `data`。这是构造器约定，不是类型层面的互斥枚举。见 `shared/protocol/src/jsonrpc.rs`。

下面给出 `echo` 的请求与成功响应（`src/gateway/handlers/echo.rs`），随后单独展示错误信封格式：

```json
{"jsonrpc":"2.0","id":"req-1","method":"echo","params":{"text":"hello"}}
```

```json
{"jsonrpc":"2.0","id":"req-1","result":{"echo":{"text":"hello"}}}
```

```json
{"jsonrpc":"2.0","id":"req-1","error":{"code":-32602,"message":"Invalid params: missing field"}}
```

## 错误码

下表逐项对应 `shared/protocol/src/jsonrpc.rs` 的常量及其定义语义；不是每个传输入口都保证发出全部错误码。

| 码 | 常量 | 含义 | 何时出现 |
|---|---|---|---|
| -32700 | `PARSE_ERROR` | 解析错误 | 收到的内容不是有效 JSON |
| -32600 | `INVALID_REQUEST` | 无效请求 | JSON 不是有效请求对象 |
| -32601 | `METHOD_NOT_FOUND` | 方法不存在或不可用 | 分发器无法找到可用方法 |
| -32602 | `INVALID_PARAMS` | 参数无效 | 方法参数校验失败 |
| -32603 | `INTERNAL_ERROR` | 内部错误 | 发生内部 JSON-RPC 错误 |
| -32000 | `AUTH_REQUIRED` | 需要认证或角色授权 | 需要认证；也用于 operator 方法拒绝 |
| -32002 | `RATE_LIMITED` | 请求限流 | 超过速率限制 |
| -32003 | `AGENT_ERROR` | Agent 执行错误 | Agent 执行失败 |
| -32004 | `TOOL_ERROR` | 工具执行错误 | 工具执行失败 |
| -32008 | `PERMISSION_DENIED` | 权限不足 | 操作不被许可 |
| -32009 | `RESOURCE_NOT_FOUND` | 资源不存在 | 找不到目标资源 |
| -32010 | `TIMEOUT_ERROR` | 操作超时 | 操作未在时限内完成 |
| -32031 | `REVISION_CONFLICT` | 画布版本冲突 | canvas.apply 的 base_revision 已过期 |

## operator 拒绝消息

`ADMIN_REQUIRED_MESSAGE` 的原文如下，定义于 `shared/protocol/src/jsonrpc.rs`。运行期 `src/gateway/method_admin.rs` 的 `method_requires_admin` 判定需要 operator 的方法；已认证 member 被拒绝时使用 `AUTH_REQUIRED`（-32000），而非 `PERMISSION_DENIED`。门控调用位于 `src/gateway/server/connection/dispatch.rs`。

```text
Not authorized: this method requires operator privileges
```

## 事件通知

`TOPIC_EVENT_METHOD = "event"` 是主题事件信封的 `method`，不是主题名。通知没有 `id`；`params` 携带 `topic` 与 `data`，见 `shared/protocol/src/jsonrpc.rs`。它与逐帧使用独立方法名的流式事件不同。主题目录见[网关事件](../gateway/methods/events)。

事件可见性受 `src/gateway/event_visibility.rs` 的所有者与作用域检查约束；订阅主题不代表可读取其他用户的事件。

```json
{"jsonrpc":"2.0","method":"event","params":{"topic":"agent.run.complete","data":{}}}
```

这里只展示信封；`data` 的具体结构由事件定义决定，见 `src/gateway/events/frame.rs`。

## 工具调用专用信封

反向 RPC 的共享载荷定义在 `shared/protocol/src/jsonrpc.rs`：服务端请求客户端执行工具，客户端回传结果。这些是 JSON-RPC 内承载的业务载荷，不替代外层 `id`。

| 类型 | 字段与约束 |
|---|---|
| `ToolCallParams` | `call_id: String`, `tool_name: String`, `params: Value`, `context: ToolCallContext`（省略时默认） |
| `ToolCallContext` | 均可选：`run_id: String`, `session_key: String`, `timeout_ms: u64` |
| `ToolCallResult` | `call_id: String`, `success: bool`; 可选：`result: Value`, `error: String`, `duration_ms: u64` |

结果的 `call_id` 必须匹配调用。`ToolCallResult::success()` / `error()` 分别填充结果或错误字符串；`with_duration()` 添加耗时，见 `shared/protocol/src/jsonrpc.rs`。

## 与 Protocol v1 的关系

JSON-RPC 定义消息语义；帧、握手与传输见 [Protocol v1](../gateway/protocol-v1)。相应代码是 `shared/protocol/src/framing.rs`、`shared/protocol/src/system_hello.rs` 与 `src/gateway/server/connection/`。
