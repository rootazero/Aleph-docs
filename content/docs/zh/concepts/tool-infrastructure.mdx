Aleph 的生产工具栈以 `ToolService` 为消费接口，以 `ScopedToolService` 为 Gateway 的请求范围实现。内置、MCP、技能和扩展工具可以进入同一个请求视图，但每轮实际暴露的工具仍由允许集、拒绝策略、健康状态、延迟层和会话模式共同决定。

## 生产服务接口

`src/tools/service.rs:152` 定义了主要操作：

```rust
pub trait ToolService: Send + Sync + 'static {
    async fn execute(&self, name: &str, input: serde_json::Value) -> Result<ToolOutput, ToolError>;
    async fn list(&self) -> Vec<ToolDefinition>;
    async fn dispatchable_list(&self) -> Vec<ToolDefinition>;
    async fn describe(&self, name: &str) -> Option<ToolDefinition>;
    fn metadata_schema(&self) -> Arc<[ToolDefinition]>;
}
```

`list` 是模型当前看到的工具数组；`dispatchable_list` 还包含被延迟展示但仍可执行的工具，供名称修复使用；`describe` 返回单个定义；`metadata_schema` 对模型提供缓存的定义数组。生产实现位于 `src/tools/scoped/`。

## 注册与定义

- `BUILTIN_TOOL_DEFINITIONS` 是内置名称、描述和配置要求的单一来源。
- `ToolCatalog` 聚合内置、技能、插件和自定义命令，并负责冲突处理、健康探针和查询。
- Gateway 的运行时 `LoopToolRegistry` 再合并请求所需的子代理、MCP 和扩展工具。
- `ScopedToolService` 在执行前应用允许集、拒绝策略、健康过滤、确认门和工具定义重写器。

权限过滤同时作用于展示和执行：拒绝的工具不会进入 `list`，即使模型直接提交名称，`execute` 仍会再次拒绝。`ask` tier 对未知或未声明工具失败关闭。

## Schema 与渐进披露

工具定义包含名称、描述、输入 Schema、来源和元数据。`ProgressiveDisclosureRewriter` 是请求级的静态展示重写器，而不是按消息猜测意图：

1. 核心集合中的工具保留完整 Schema；
2. 其他工具保留名称和描述，将 Schema 折叠为可接受对象，并提示调用 `get_tool_schema`；
3. `get_tool_schema` 使用折叠前的请求快照返回完整参数；
4. `tool_search` 对延迟工具的名称和描述做无依赖 BM25 检索，返回完整 Schema，并把命中工具提升回工具数组；
5. 核心集合为空或含 `*` 时不挂载这套重写器，工具面保持字节级旧行为。

`get_tool_schema` 只在渐进披露启用时注册；`tool_search` 只在存在延迟工具时注册，并在启用披露时固定进入核心集合，避免它自己被折叠。MCP 延迟由 `[tools] defer_mcp_tools` 控制；会话模式使用相同的延迟集合。

## `ConcurrencyClaim` 与并行分区

`src/tools/concurrency.rs:30` 用资源声明替代单一的 `concurrent_safe` 布尔值：

- `Shared`：面向调度的只读或无副作用调用；只与另一个 `Shared` 无冲突；
- `Exclusive { scope: Global }`：资源集合未知或无界，例如 `bash`，与任何声明冲突；
- `Exclusive { scope: Paths(...) }`：规范化路径集合，只有相同路径或祖先/后代路径重叠时冲突；
- `Exclusive { scope: Nodes(...) }`：集群节点集合，只有目标节点重叠时冲突；
- `Exclusive { scope: Sessions(...) }`：本机代理会话集合，不同会话可并行，但与其他资源范围保守地冲突。

`call_concurrency_claim` 根据工具名称和本次输入计算实际声明，因此同一个 `file_ops` 工具的读取、单路径写入和未知操作可以得到不同结果。路径比较按组件进行：`foo/a` 与 `foo/ab` 不冲突，`foo/a` 与 `foo/a/b.rs` 冲突；无法提取范围时退化为 `Global`。

`partition_parallel_groups` 从左到右生成连续、保持顺序的区间。当前组中的新调用若与任一成员冲突，就开启下一组；组之间串行完成，组内才并发。于是多个读取可以先并发，之后的 `bash` 单独串行，而不同文件或不同节点的有界写入可以保持并行。它不是把所有调用粗略分成一个并发桶和一个串行桶。

## 执行与错误

`ScopedToolService` 将 `TURN_CONTEXT`、取消令牌、确认流程、扩展 hook、重试和工具结果预算汇聚到一次调用。`ToolError` 区分未找到、权限拒绝、输入校验、执行、超时、确认过期、传输和重复名称等情况；调用者可据此决定重试、请求批准或报告失败。
