`core` 模块提供在 Aleph 所有层之间共享的纯数据类型。它没有业务逻辑，没有平台特定代码，外部依赖只有 `serde` 与标准库容器。

## 设计理念

`core` 模块遵循**高内聚零耦合**的原则。此模块中的每个类型都是具有 `Debug`、`Clone`、`Serialize` 和 `Deserialize` 派生实现的纯数据容器。除了简单的字段访问之外没有方法 —— 业务逻辑存在于消费这些类型的模块中。

这种设计确保：
- 类型可以在服务器、桌面桥接和客户端接口之间共享，而不会引入繁重的依赖
- 序列化合约通过 `serde` 保持稳定和版本化
- 模块编译快速，永远不会阻塞其他模块

## MediaAttachment

多模态内容支持，用于来自剪贴板或文件上传的图像、文档和视频（`src/core/types.rs`）。

```rust
pub enum MediaType {
    Image, Document, Video, File,
}

pub enum ContentEncoding {
    Base64, Utf8,
}

pub struct MediaAttachment {
    pub media_type: MediaType,
    pub mime_type: String,
    pub data: String,
    pub encoding: ContentEncoding,
    pub filename: Option<String>,
    pub size_bytes: u64,
}
```

`encoding` 字段决定如何解释 `data`：

- `ContentEncoding::Base64` — 二进制内容编码为 Base64（图像、PDF）
- `ContentEncoding::Utf8` — 纯文本内容（markdown、提取的文本）

`MediaAttachment` 自带 `Debug` 实现，会把 `data` 重写成 `<REDACTED: N bytes>` 防止日志泄露载荷。`MediaType` 与 `ContentEncoding` 都标了 `#[non_exhaustive]`，新增变体是非破坏性变更。

**用法：** 由 `CapturedContext` 用于将剪贴板内容从 Desktop Bridge 传递到 Thinker；由生成或接收文件的工具输出使用。

## CapturedContext

来自用户活动应用程序的上下文，从原生桌面层桥接（`src/core/types.rs`）。

```rust
pub struct CapturedContext {
    pub window_title: Option<String>,
    pub attachments: Vec<MediaAttachment>,
    pub session_id: Option<String>,
}
```

**字段：**
- `window_title` — 活动窗口的标题（例如，"Notes.app", "VS Code"）
- `attachments` — 交互时刻捕获的剪贴板内容（图像、文件）
- `session_id` — 多轮对话的会话标识符

**用法：** 当用户通过 Desktop Bridge 交互时注入到提示词上下文中，使 AI 了解用户当前正在处理的内容。

## CompressionStats

关于内存压缩状态的统计信息，供设置 UI 使用以显示内存健康状态（`src/core/types.rs`）。

```rust
pub struct CompressionStats {
    pub total_raw_memories: u64,
    pub total_facts: u64,
    pub valid_facts: u64,
    pub facts_by_type: BTreeMap<String, u64>,
}
```

**字段：**
- `total_raw_memories` — 第 1 层：压缩前存储的原始用户消息
- `total_facts` — 第 2 层：从记忆中提取的压缩事实
- `valid_facts` — 仍然被视为活动的未失效事实
- `facts_by_type` — 按类型细分（偏好、计划、学习等）；用 `BTreeMap` 而非 `HashMap` 是为了给出确定性的迭代顺序

**用法：** 由 Gateway 的配置处理程序查询，以在 Panel UI 中填充内存仪表板。

## MemoryEntry

由 Memory 系统的 API 返回的记忆记录，适合序列化到客户端（`src/core/types.rs`）。

```rust
pub struct MemoryEntry {
    pub id: String,
    pub window_title: String,
    pub user_input: String,
    pub ai_output: String,
    pub timestamp: i64,
    pub similarity_score: Option<f32>,
}
```

`similarity_score` 通过 `deserialize_with = "deserialize_finite_f32_opt"` 过滤 NaN/Inf——载荷里的坏值会让排序/排名下游中毒，因此在反序列化时直接丢弃比留一个无效分安全。

**用法：** 由内存搜索查询返回。当通过向量搜索检索条目时，`similarity_score` 字段被填充，指示与查询的相关性。

> 内层长生命周期记忆另有一个 `crate::memory::MemoryEntry`（`src/memory/context/mod.rs`），带 `embedding`/`namespace`/`agent`/`context: ContextAnchor` 等字段用于内存存储。Wire/面板所用的 `core::MemoryEntry` 是其序列化形态。

## 这些类型的使用位置

| 类型 | 使用者 | 目的 |
|---|---|---|
| `MediaAttachment` | Desktop Bridge, Thinker, Tools | 多模态内容传递 |
| `CapturedContext` | Desktop Bridge, Orchestrator | 上下文注入 |
| `CompressionStats` | Memory, Gateway, Panel UI | 内存健康显示 |
| `MemoryEntry` | Memory, Gateway | API 响应序列化 |

## 26.7.x 补充

### 新增类型

- **`SessionEvent` / `SessionEventRecord` / `TurnId`**（`src/session/events.rs`）—— 26.7.7 起 `session_events` 是规范事件日志；`TurnId` 区分同一会话内的不同轮次。`SessionEvent` 自身是非穷举枚举（`#[non_exhaustive]`），变体覆盖 `SessionCreated`/`RunStarted`/`TurnStarted`/`UserMessage`/`AssistantMessage`/`ToolCall*`/`Approval*`/`Compaction` 等。
- **`UnifiedMessage` / `ContentBlock`**（`src/providers/message.rs`）—— 26.7.7+ 引入的 LLM 无关中间消息表示。`UnifiedMessage` 三变体（`User` / `Assistant` / `ToolResult`）覆盖一轮中可能携带的内容；`ContentBlock` 五变体（`Text` / `Json` / `Thinking` / `ToolCall` / `Image`）。
- **`ProviderDelta`**（`src/providers/delta.rs`）—— 流式输出事件；变体包括 `TextDelta` / `ThinkingDelta` / `ThinkingSignatureDelta` / `ToolCallStart` / `ToolCallArgDelta` / `ToolCallArgsComplete` / `ToolCallEnd` / `Usage` / `Done` / `Error`。
- **`LoopStatus` / `LoopState`**（`src/looping/types.rs`）—— 26.7.25 引入的循环状态机：`LoopStatus` 是 `Active` / `Paused` / `Stopped` 三态枚举；`LoopState` 是会话级可序列化结构（`session_id`、`prompt`、`cadence`、`next_wake_ms`、`pending_tick_wake_ms`、`iterations_used` 等），不可变更新（`with_*` / `spent_*` 返回新副本）。
- **`GoalStatus` / `Goal` / `GoalStore`**（`src/goal/types.rs`）—— 26.7.x 新增的目标子系统。`GoalStatus` 是 `Active` / `Paused` / `Blocked` / `Complete`；`PursuitMode` 是 `Passive` / `Active { max_iterations }`；`GateOutcome` 拆分 maker/checker 验收（`Unchecked` / `Passed`）。
- **`ArtifactRecord`**（`src/artifacts/store.rs`）—— 工件存储的记录类型；`MAX_ARTIFACT_BYTES = 50 MiB` 与 `MAX_ARTIFACTS_PER_SESSION = 200` 守门，根目录 `<aleph_data_dir>/artifacts`。
- **`AgentKeystore` / `AgentLedger` / `LedgerRecord` / `LedgerAction` / `LedgerOutcome` / `ChainReport` / `as_actor` / `current_actor`**（`src/identity/{keystore,ledger,record,verify,actor}.rs`）—— 每代理 Ed25519 密钥、哈希链签名账本，以及子代理/委派场景下的「扮演角色」 task-local。
- **`NoteRelationArg`**（`src/builtin_tools/note_manage.rs`）—— 类型化关系边，`note_manage` 工具的输入参数；返回面是 `note_graph_query` 工具（`src/builtin_tools/note_graph_query.rs`）。
- **`CapabilityLedger`**（`src/runtimes/ledger.rs`）—— 每次安装时从磁盘重建的可见能力清单（`plugin.install` / `runtimes.install` 的支撑），以 JSON 持久化。
