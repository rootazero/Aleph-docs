`thinker` 模块是 Aleph 的提示词构建引擎。它在 SYSTEM prompt 阶段拼装每个 session 的提示词，同时维护运行时记忆（`recall_context`）与 transient tail（`transient_recall`）两条平行的轨道。Round 9 之后用 **~28 个细粒度 PromptLayer** 替代了旧的 6 层心智模型；每个 layer 拥有优先级与简短 contract，由 `prompt_pipeline` 装配。

## 设计理念

1. **细粒度层** — ~28 个独立 PromptLayer 各管一件事（`agent_role` / `environment` / `mcp_instructions` / `extra_files` / `guidelines` / `security` / `voice_mode` / `graph_topology` / `curated_memory` / `recall_context` / ...），R10「智能在提示词」要求每层可被独立评审。
2. **Priority 排序** — 每个 layer 拥有 `priority()` 整数，pipeline 按升序拼装，让 cache-friendly（不变）的内容排在前面、动态（带时间戳 / 计数器）的内容排在后面。
3. **stable / live 双轨** — SYSTEM prompt 部分（`stable_summary`）是 cache 前缀，**绝不**含倒计时；live 计数（deadline / next-wake）走 transient tail message，让 prompt cache 读写 0.1× / 1.25× 的不对称不被倒计时字节变动触发。
4. **Provider-specific 渲染** — 同一段内容对 OpenAI / Anthropic / Ollama 的渲染格式不同；`thinker::prompt_pipeline` 拿到 provider 名字后调对应 `RenderStyle`（XML / fenced / inline）拼装。
5. **契约守卫** — `prompt_contract::reachable_layers` 保证每个 layer 都能在 enabled 状态下出场或带理由进白名单；`scaffold_bytes_ratchet` 只允许减小字节数（任何「向上调整」必须显式 commit 论证）；`aleph-server prompt-size` 报告实时字节数。

## 架构

```text
┌─────────────────────────────────────────────┐
│                  Thinker                     │
├─────────────────────────────────────────────┤
│                                             │
│  Priority 0–800: 静态身份 / 配置 / 知识层   │
│  Priority 800–1500: 静态 / 缓存友好         │
│  Priority 1500–1720: 静态 / 缓慢变更         │
│  Priority 1720: RuntimeContextLayer（动态    │
│                  —— token / 计数 / 会话名）  │
│  Priority >1720: transient recall（仅        │
│                  transient tail）            │
└─────────────────────────────────────────────┘
```

`PromptPipeline::assemble(provider, input)` 按上述顺序渲染所有 enabled 的 layer，得到一个 `String` 注入 SYSTEM prompt；`transient_recall` 部分另走 `HarnessDeps::recall_context`，不进 SYSTEM。

## 核心组件

### PromptLayer trait

```rust
#[async_trait]
pub trait PromptLayer: Send + Sync {
    fn name(&self) -> &'static str;
    fn priority(&self) -> i32;
    async fn render(&self, input: &ThinkerContext) -> Result<String>;
    /// 缺省按 contract.rs 推断；当某 layer 不该出现时显式返回 false 走「理由白名单」路径
    fn is_reachable(&self, input: &ThinkerContext) -> bool { true }
}
```

每个 layer 拥有：
- `priority()`：拼装顺序；同优先级内 stable / 排序确定
- `render(&ctx)`：纯函数 / IO-free（不许读 LLM 调用）；失败回退为「该层不出现」并记 warn
- `is_reachable(&ctx)`：缺省 `true`；配置禁用 / 不在白名单的 layer 返回 `false` 并附理由进 `prompt_contract::reachable_layers` 的白名单

### ThinkerContext

```rust
pub struct ThinkerContext {
    pub session_key: SessionKey,
    pub agent_id: AgentId,
    pub voice: Option<VoiceContext>,         // 语音轮次上下文
    pub running: RunningStats,              // 运行时统计（回合数 / token / 时间）
    pub profile: Option<ProfileView>,
    pub skills: Vec<SkillView>,
    pub goals: Vec<GoalView>,
    pub strategies: Vec<StrategyView>,
    pub diagnostics: Vec<DiagnosticView>,   // 来自 doctor
    pub memory: Option<MemoryEnvelope>,     // 已 recall 的 envelope
    pub session_recent: Vec<ChatMessageView>, // 当前 session 近期
    pub plan: Option<PlanView>,             // 当前 welded Strategy 渲染
    pub vault: Option<VaultView>,           // vault 里的 secrets（加密态）
    pub mcp: Option<McpView>,               // 当前 session 激活的 MCP servers
    pub todo: Option<TodoView>,             // 当前 execution list
    pub runtime: RuntimeView,                // OS / cwd / model / 计数
    pub scratchpad: ScratchpadView,         // execution list + objective
}
```

`render(&ctx)` 拿到这个上下文，按自己关心的字段渲染，**不**做 IO。`VoiceContext` 由 `voice_mode::get(session_key)` 注入；`MemoryEnvelope` 由 `MemoryContextProvider::build_envelope` 拼好；`PlanView` 由 `StrategyLayer` 拉 welded plan；`TodoView` 由 `ScratchpadLayer` 拉 `scratchpad_registry::get_active`。

### PromptPipeline 装配

`PromptPipeline::assemble(provider, input)` 按层 priority 升序逐个调 `layer.render(&input)`，结果用换行符拼为单个字符串。失败 layer 记 warn 但不中断（`fail-soft`）；`prompt_contract` 校验所有 enabled layer 都有「出场」或「带理由进白名单」。

```rust
pub struct PromptPipeline {
    layers: Vec<Arc<dyn PromptLayer>>,
}
```

构造在 `bin/aleph-server/commands/start/builder/constructor/mod.rs::build_thinker_pipeline`：

## 两把尺（`src/thinker/prompt_contract.rs`）

R10 红线在「智能在提示词 / 智能不在循环里」，新版本提供**两把尺**显式度量：

```rust
pub const fn reachable_layers(pipeline: &PromptPipeline) -> Vec<(&str, bool, Option<String>)>;
pub fn scaffold_bytes_ratchet(input: &ThinkerContext) -> Result<usize, ContractError>;
```

- **`reachable_layers`** —— 列出所有 enabled layer；`is_reachable == false` 的 layer 必须带理由进白名单（`whitelist_disabled(name, reason)`），否则测试失败。
- **`scaffold_bytes_ratchet`** —— 计算当前 `ThinkerContext` 下 SYSTEM prompt 的**仅 scaffold**字节数（即不含 RuntimeContext / recall_context / transient_recall），与上次记录对比，**只允许减小**，增大需要显式白名单。
- `prompt_size` CLI 子命令 (`aleph-server prompt-size`)：报告当前 scaffold 字节数 + 每个 layer 的字节分布 + 距 R10 红线 CEILING 的余量。

> `prompt_size` 也供 loop / goal 的 continuation prompt 路径用（continuation 调 `build_system_prompt` 时也走同一 contract）；同一个 R10 红线是 SYSTEM prompt 共用的字节数预算。

## `prompt_pipeline`（Round 9 引入）

`PromptPipeline` 替代了旧的 `Thinker::build_prompt`，是 ~28 layer 的统一拼装点：

```rust
pub struct PromptPipeline {
    layers: Vec<Box<dyn PromptLayer>>,
}

impl PromptPipeline {
    pub fn new(layers: Vec<Box<dyn PromptLayer>>) -> Self;
    pub fn assemble(&self, input: &ThinkerContext) -> Result<String>;
    pub fn with_layers(self, layers: Vec<Box<dyn PromptLayer>>) -> Self;
}
```

`ProviderRenderStyle` 三种（`xml` / `fenced` / `inline`）按 provider 决定每层的包裹（Anthropic XML 标签 / OpenAI fenced code / Ollama 平文本），由 `PromptPipeline::render_section(layer, ctx, style)` 选。

## 流式状态机

`thinker::streaming` 提供 per-token 状态机 `BlockState`：

```rust
pub struct BlockState {
    pub buffer: String,
    pub current_block: Option<BlockType>,
}

impl BlockState {
    pub fn feed(&mut self, token: &str) -> Vec<BlockEvent> { /* ... */ }
}
```

`BlockType` 五种：`Text` / `ToolCall` / `Code` / `Thinking` / `Image`。`BlockState::feed` 收到 token 后解析并产出 `BlockEvent`（进入新块 / 当前块继续 / 当前块结束）。Panel 端用 `BlockState` 渲染两阶段字幕（详见 `interfaces/webchat/src/views/chat/state/streaming.rs`）。

## provider-specific 渲染

不同 provider 对 prompt 的解析方式不同 —— 同一段内容对 Anthropic 是 XML，对 OpenAI 是 fenced code，对 Ollama 是平文本。`PromptLayer::render` 返回纯文本（**不**带 `<example>` / ` ``` ` 包裹），**包裹**由 `PromptPipeline::render_section` 按 `ProviderRenderStyle` 决定：

```rust
pub enum ProviderRenderStyle { Xml, Fenced, Inline }
```

- **Anthropic / XML**：每层包成 `<section name="<layer_name>">…</section>`，子内容**不**做二次转义
- **OpenAI / Fenced**：每层包成 `` ```<layer_name>\n…\n``` ``，子内容里的 ``` 需要再转义
- **Ollama / Inline**：每层直接平文本，加一行 `--- <layer_name> ---` 标题

`style_for_provider(provider_name)` 在 pipeline 装配时调一次，结果缓存到 pipeline 结构里。

## 26.7.x 补充

### Round 9 层重组

26.7.x 把旧 6 层心智模型（Identity / Skills / Memory / Tools / Rules / Conversation）拆成 ~28 个细粒度 PromptLayer，每个独立可审、可禁用、可白名单。R10「智能在提示词 / 不在循环里」要求每层都有自己的 contract 与 priority。

### 两把尺（R10 红线）

`prompt_contract::reachable_layers` + `scaffold_bytes_ratchet` 把 R10 红线从「手工心算」变成代码可度量。`aleph-server prompt-size` 报告实时字节数 + 每层字节分布，让 R10 触手可测。CEILING ratchet 在 harness / thinker 之间共享：SYSTEM prompt 的字节数上限于 `the_harness_line_budget_does_not_grow` 测试的 `CEILING` 是**同一把尺**（都是 R10 唯一字节预算的两个子集）。

### 语音模式适配

26.7.x `VoiceModeLayer`（priority 1710）注入语音轮次的提示词规则 —— 包括「请修复 ASR 转写中的同音字错误」、「口语冗余保留作为 user 的语用信息」等。`VoiceContext` 字段由 `voice_mode::get()` 注入（active 才有值，transcription 标志由 `inbound_router` 设定）。

### `transient_recall` 与 cache 友好

26.7.1+：双轨设计 —— stable `MemoryEnvelope` 走 SYSTEM prompt（cache 友好），live 倒计时（deadline / next-wake）走 transient tail message（cache 断点之后，字节变动只花自己）。**对应于 `looping::LoopState` 的 `stable_summary` vs `live_status`** —— 同一设计，thinker 与 looping 共享 R10 缓存调度。

### 提示词缓存调度

`RuntimeContextLayer` 故意放在 priority 1720，是 SYSTEM prompt 中**唯一**含 token 计数 / 终止原因 / session_key 数字的层。其它 ~27 个 layer 全是 cache 友好内容（identity / profile / soul / environment / security / plan 等），**全部**排在 1720 之前 —— Anthropic prompt cache 是 prefix-keyed，每字节变动让后续 history 1.25× 写而 0.1× 读，**单次倒计时字节变化**会抵销整个对话的 cache 收益。
