`thinker` 模块通过可组合层构建系统提示词。稳定的精选记忆进入系统提示词；自动召回的记忆通过 `HarnessDeps::recall_context` 作为独立的临时尾部消息传递。

## 设计理念

1. 每个 `PromptLayer` 持有一个职责及排序优先级。
2. `LayerStability` 区分稳定前缀与动态后缀。
3. `AssemblyPath` 选择基础或缓存入口。
4. 各层自行包装输出，XML 辅助函数位于 `src/thinker/xml_util.rs`。
5. `prompt_contract` 测试守卫可达性、脚手架增长与重复句子。

## 架构

```text
TurnEnvelope + EnvironmentContract
    → ContextAggregator → ResolvedContext
    → LayerInput → PromptPipeline
    → 稳定前缀 + 动态后缀（缓存路径）
召回记忆 → 独立临时消息
```

## 核心组件



### PromptLayer trait

`src/thinker/prompt_layer.rs` 中的 trait 是同步的，核心方法如下：

```rust
fn name(&self) -> &'static str;
fn priority(&self) -> u32;
fn inject(&self, output: &mut String, input: &LayerInput);
```

各层还声明装配路径、提示模式与稳定性。层向传入的缓冲区追加内容，不返回异步结果。

### ResolvedContext 与 LayerInput

`src/thinker/context.rs` 定义 `EnvironmentContract`、`VoiceContext`、`TurnEnvelope`、`EnvelopeParent`、`ResolvedContext` 和 `ContextAggregator`。解析结果供各层读取；`LayerInput` 补充提示配置与装配入口相关输入。

`ResolvedContext` 包含可选运行上下文、沙箱摘要、已渲染执行计划、常驻目标、图拓扑、策略及语音状态。`execution_plan` 是已渲染的 scratchpad 进度，由 `ExecutionPlanLayer` 消费，不是独立的 todo 视图对象。harness bridge 通过 `build_memory_user_message` 获取召回记忆，通过 `build_curated_message` 提供稳定的精选记忆信封。

### PromptPipeline 装配

`PromptPipeline` 持有 `Vec<Box<dyn PromptLayer>>`，`new` 按优先级排序。`execute` 将指定装配路径渲染为字符串；缓存装配使用 `execute_stable_with_mode` 和 `execute_dynamic_with_mode` 按稳定性拆分内容，没有 provider 专用渲染风格选择器。

## 两把尺（`src/thinker/prompt_contract.rs`）

`reachable_layers` 测试验证生产形状输入能唤醒已注册层，或在 `CONDITIONALLY_SILENT` 中解释条件性静默。这是测试清单，不是运行时白名单 API。

`scaffold_bytes_ratchet` 限制脚手架增长，动态尾部与重复句子检查提供独立守卫。`aleph-server prompt-size` 报告测量的各层体积。这些是测试与 CLI 测量，不是提示词装配函数签名。

## `prompt_pipeline`

默认层列表定义于 `src/thinker/prompt_pipeline.rs`。`PromptBuilder` 提供生产入口；各层通过 `LayerInput` 向共享缓冲区注入内容。共享 XML 转义辅助函数包括 `escape_xml` 和 `escape_xml_attr`。

## 历史：流式状态机

早期 `thinker::streaming` 模块提供 per-token `BlockState` 状态机（`BlockType`：`Text` / `ToolCall` / `Code` / `Thinking` / `Image`；`BlockEvent`：进入新块 / 继续 / 结束），供 Panel 在流式回复期间渲染两阶段字幕。该模块及其流式渲染器已移除——现已无 per-token 字幕状态机。

---

## 历史：provider-specific 渲染

早期 `ProviderRenderStyle` 枚举（`Xml` / `Fenced` / `Inline`）按 provider 选择每层包裹，配一个 `render_section` 分发点和 `style_for_provider(provider_name)` 助手在装配时缓存选择。该渲染模型已移除：每个 `PromptLayer` 现通过 `inject(&mut String, &LayerInput)` 自行包裹，使用 `src/thinker/xml_util.rs` 的共享助手；已无按 provider 的包裹样式。

## 26.7.x 补充



### 层重组

各层可独立审查。已注册层以 `default_layers` 与 `layer_info` 为准，不应假定旧的固定层数量。

### 语音模式适配

`VoiceModeLayer` 读取解析后的 `VoiceContext` 并注入语音回合指令。

### 召回记忆与缓存友好

稳定精选记忆由 `CuratedMemoryLayer` 注入；实时召回记忆保留在系统提示词之外的临时消息路径。传输字段名为 `recall_context`。

### 提示词缓存调度

缓存分区遵循 `LayerStability`，不是优先级 1720 必须最后的规则。`RuntimeContextLayer` 是动态层，但执行计划和治理层可以排在它之后。 运行数据描述环境（例如 `src/thinker/runtime_context.rs` 中的 `current_model` 与 `current_time`），不是累计 token 计数字段。稳定前缀的字节变化会使前缀缓存失效；动态内容应放在动态后缀或临时消息。技能提示预算是独立机制：`SkillPromptBudget` 位于 `src/skill/prompt.rs`，不是 thinker 全局层数预算。
