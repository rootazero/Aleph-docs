技能是目录中以 `SKILL.md` 为入口的一组可复用 Markdown 指令；它是给模型使用的「方法」，不是另一个硬编码工具。在统一扩展模型中，Skill 与 Plugin、Mcp 并列为三种 Kind。

发现与安装请使用[扩展商店](/docs/zh/concepts/extensions-store)。本页只覆盖 `SKILL.md` 的编写契约与运行时行为。

## 编写契约

技能就是一个包含 `SKILL.md` 的目录：

```text
~/.aleph/skills/code-review/SKILL.md
.aleph/skills/project-review/SKILL.md
```

项目级技能也可以从 `.claude/skills/` 发现。插件内捆绑的技能位于插件的 `skills/` 目录，会被并入同一 SkillSystem 索引。

frontmatter 必填项：

- `name`：人类可读的名称，运行时 ID 由此推导。
- `description`：单句路由描述。

Markdown 正文是模型在选中技能后加载的完整指令。解析器把 `name` 转为小写、用连字符拼接空白并据此生成 ID；同名重复由来源优先级裁决。

## 描述与触发提示

`description` 是模型路由的主要输入，应说明技能做什么、何时适用、关键输入输出，以及如何排除邻近但不属于它的请求。把用户实际会说的词和短语放进这句话中。当前 `SkillManifest` 不支持 `triggers` 字段，不要再维护独立的关键词列表。

当简短的主动调用提示装不进 description 时，可使用 `when-to-use`：

```markdown
---
name: code-review
description: 对变更后的源代码做正确性、安全、性能与可维护性审查；用于代码评审、检查补丁或复核 PR。
when-to-use: 当代码被编写或修改后需要独立质量评审时
scope: system
user-invocable: true
disable-model-invocation: false
---

按系统化方式评审变更后的代码，并给出附文件与行号的具体发现。
```

`when-to-use` 会以 `<when>` 输出到可用技能目录。匹配由模型语义完成，Aleph 不再运行 BM25 或编辑距离类的确定性触发器。请求匹配时模型会主动加载技能，而不是等用户显式点名。

## 可选 frontmatter

当前 SkillSystem 解析器支持的可选字段：

| 字段 | 用途 |
|---|---|
| `scope` | 提示词注入范围：`system`、`tool`、`standalone`、`disabled` |
| `user-invocable` | 用户能否直接调用 |
| `disable-model-invocation` | 不允许模型自动调用 |
| `bound-tool` | 将 tool 范围技能绑定到工具 |
| `eligibility` | 操作系统、二进制、环境、配置和启用检查 |
| `install` | 平台相关的依赖安装方式 |
| `primary-env` | 技能主要使用的环境变量 |
| `homepage` | 外部文档或凭证获取页 |
| `emoji` | UI 图标 |
| `automation` | 建议的定时任务与提示，自身不会创建任务 |

依赖元数据示例：

```yaml
eligibility:
  required-bins:
    - git
  required-env:
    - GITHUB_TOKEN
install:
  - id: git
    kind: brew
    package: git
    bins:
      - git
```

`enabled: false` 让技能变为 ineligible；`always: true` 跳过其他检查，但不会覆盖显式禁用。未知的 prompt scope 默认为 `disabled`。

### Markdown CLI 兼容字段

兼容的 Markdown CLI 读取器还支持必需二进制、安全声明、输入提示与 Docker 设置等元数据字段，这些字段描述旧的 CLI 执行路径；新写的 SkillSystem 技能应使用上面的顶层字段表达 eligibility 和依赖安装。安全声明无法替代 Aleph 的运行时审批与安装门槛。

## 保持正文简洁

渐进披露原则：

1. `SKILL.md` 聚焦路由、规则与标准工作流。
2. 细节参考资料放在 `references/guide.md` 等文件中。
3. 适当时把确定性辅助逻辑放入 `scripts` 目录。
4. 让模型通过 `skill_read(skill_id, file_name=...)` 读取支撑文件。

`skill_read` 路径会做目录约束、字节限制并展开 `${ALEPH_SKILL_DIR}` 与内联 shell 片段。技能不应教模型用裸绝对路径或 `cat` 读自己的 Markdown 资源。`skill_read` 返回的绝对 `location` 仅用于执行被引用的脚本，不能绕过技能读取器。

声明 `automation` 块仅是建议；安装后模型可在取得用户同意后通过 `cron_manage` 创建定时任务，安装本身不会静默调度。

## 发现与优先级

共享 SkillSystem 会扫描已配置的根目录与插件发布根目录，无需重启。来源优先级：

1. Workspace
2. Plugin
3. Global
4. Bundled

高优先级技能替换低优先级副本。符号链接或重复路径会按优先级解析，而不是直接拒绝为歧义。已安装插件的技能会出现在同一索引里并可由 `skill_read` 访问。

## 提示词形态

模型可见的技能以紧凑 XML 注入：

```xml
<available_skills>
  <skill>
    <name>Code Review</name>
    <description>对变更后的源代码做正确性与安全审查</description>
    <when>当代码被编写或修改后</when>
    <version>sha256:a1b2c3d4</version>
  </skill>
</available_skills>
```

未声明 `when-to-use` 时省略 `<when>`。`<version>` 是指令正文的短摘要，若发生变化说明正文已变，模型必须重新调用 `skill_read`。提示词预算在压力大时只保留名称、触发提示与摘要，把描述与正文降级到 `skill_read` 加载；`skill_list` 始终是兜底枚举入口。

## 安装期安全

第三方技能包在注册前会经过扫描，覆盖提示注入、不可见 Unicode、凭证路径、反弹 shell、破坏性命令、下载即执行模式以及过大文件。在社区信任等级下命中 caution 直接阻止；危险内容对不可信来源阻止，捆绑内容遵循内置信任策略。该扫描是纵深防御，不替代通用沙箱。

## 管理接口

内置工具：

- `skill_list`：发现技能元数据与支撑文件
- `skill_read`：读取 `SKILL.md` 或目录内的支撑文件
- `skill_status`：检查 eligibility、缺失项、来源与使用统计
- `skill_install`：安装声明的依赖
- `skill_manage`：创建、编辑、配置、删除技能

对应的网关方法包括 `skills.status`、`skills.update`、`skills.install_dep` 与 `skills.remove`。扩展安装会通过同一 SkillSystem 处理 Skill 入口，而不是另设一套 store-only 注册表。
