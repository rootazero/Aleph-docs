群聊是[团队](/docs/zh/concepts/teams)的对话界面。发送给团队的消息会启动一棵有界扇出树：被提及的成员或适用的成员列表并发运行，并可在后续回复中继续提及其他成员。消息与系统通知会持久化，因此对话可以重新打开并重放。

## Panel 体验

团队聊天复用普通聊天时间线，而不是独立的三栏窗口：

- 代理回复使用带归属的气泡，颜色由 `agent_id` 稳定派生；同一代理的连续回复会在视觉上分组。
- 左上角的参与者头像簇可展开成员列表并显示实时活动状态，它取代了旧的常驻左侧成员栏。
- 团队任务抽屉让协调任务始终可从对话中访问；共享工作区仍是普通的右侧工作区。
- 侧边栏显示 `agents.teams` 返回的团队，包括成员预览与最新对话摘要。

未命名团队会在第一次 `teams.chat.send` 时获得生成的名称。

## 提及与扇出

输入 `@` 会打开成员自动补全。匹配按成员名称或 id 进行且不区分大小写，选中后插入规范的 `@<agent_id>`；`@all` 面向整个成员列表。未知 id 不会被路由。

广播器通过操作者配置的 `[team_broadcast]` 限制递归对话，包括链深度、每轮宽度、总激活数、对话记录预算与成员运行超时。`teams.chat.send` 返回的 `run_id` 标识整棵扇出树。`teams.chat.cancel` 会先阻止新后代，再取消仍在运行的成员。

## 实时状态与历史

Panel 订阅 `team.<id>.*` 主题族：

| 主题 | 用途 |
|---|---|
| `team.<id>.message` | 成员最终回复及其归属 |
| `team.<id>.system` | 与代理气泡分开渲染的系统通知 |
| `team.<id>.activity` | 成员的 `working`、`done` 或 `error` 状态 |
| `team.<id>.fanout` | 扇出的 `started` 与 `settled` 状态 |
| `team.<id>.task.<verb>` | 任务条与抽屉使用的任务更新 |

`teams.chat.history` 只返回共享团队消息存储中的对话行，并标记为 `user`、`agent` 或 `system`。定向收件箱流量会被排除，因此通知与升级提示不会显示为聊天气泡。

## 团队聊天 RPC

| 方法 | 用途 |
|---|---|
| `teams.chat.send` | 发送用户消息并启动团队扇出树 |
| `teams.chat.cancel` | 按 `run_id` 取消扇出树 |
| `teams.chat.history` | 重放持久对话 |
| `teams.chat.thread` | 加载持久任务与工件工作线程 |
| `agents.teams` | 为侧边栏列出某代理所属团队 |
| `teams.usage` | 读取团队聚合模型用量 |

不存在 `teams.run` RPC。团队执行由 `teams.chat.send`、协调任务与团队工具驱动。

## 独立的人设群聊

`group_chat.start`、`group_chat.continue`、`group_chat.mention`、`group_chat.end`、`group_chat.list` 与 `group_chat.history` RPC 属于 `src/group_chat/` 下独立的人设圆桌系统。它们不支撑 Panel 的团队对话；后者使用 `teams.chat.*`。
