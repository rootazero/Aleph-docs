Aleph 在库边界使用类型化错误，在应用层累积上下文。内部错误链用于诊断；面向客户端的错误必须经过 Gateway 的统一用户可读回执。

## 错误链

实现应保留 source chain，使根因、边界和调用上下文可追踪。日志可以记录诊断所需的链，但必须清理秘密、内部路径和敏感 payload。用户界面不应直接显示 `serde_json`、数据库或 I/O 的原始错误。

安全截断必须按 UTF-8 字符边界进行，避免在字节边界切断多字节文本。公共库 API 应返回类型化错误；应用入口可用上下文包装底层错误。

## Gateway 单一错误源

Gateway 对客户端返回单一来源的用户可读错误回执（`ErrorReceipt`）。原始错误链只留在服务端诊断路径，不向 Panel 或其他客户端泄漏。客户端应依据回执处理错误，不应解析内部错误文本或拼接第二套错误协议。

这条边界适用于配置、会话、工具、provider、WebSocket/HTTP 和存储错误。Gateway 仍可在服务端记录完整 source chain，但日志与回执是不同的输出面。

## 失败关闭

策略文件缺失、无法读取或无法解析时，授权必须被拒绝；默认行为不得因错误而意外变为开放。
