`event` 模块实现一个事件驱动架构，解耦 Aleph 的子系统。模块之间不是直接方法调用，而是组件将事件发布到总线并订阅它们关心的事件。`src/event/` 只提供一条进程级总线：

- **`GlobalBus`**（`src/event/global_bus.rs`）—— 进程级**单例**，由 `once_cell::sync::Lazy` 守门，通过 `GlobalBus::global()` 访问。生产者通过 `GlobalBus::broadcast(agent_id, session_id, event)` 广播；订阅者通过 `subscribe_async` + `EventFilter` 挂载。每 agent 一份的 `EventBus`（src/event/bus.rs）已在 2026-08 severed-wire 审计中移除。

`AlephEvent`（`src/event/types.rs`）是共用载荷类型；`#[serde(tag = "type", content = "data")]` 让它直接可 JSON 化。

## 设计理念

事件驱动架构在 Aleph 中提供三个好处：

1. **解耦** — 内存系统不需要了解网关；两者都只使用事件
2. **可观察性** — 每个重要动作都会产生一个事件，可以被记录、审计或流式传输到客户端
3. **可扩展性** — 新功能可以订阅现有事件而无需修改发布者

`GlobalBus` 默认 buffer 为 1024 条（`DEFAULT_BUFFER_SIZE`）。它没有历史回放 ring —— `subscribe_broadcast()` 是有损的（`RecvError::Lagged(n)`），滞后后的订阅者必须重新读取权威状态。所有事件处理都是异步且非阻塞的。

## 核心组件

### GlobalBus（单例）

进程级跨智能体聚合总线：

```rust
use alephcore::event::global_bus::GlobalBus;
use alephcore::event::filter::EventFilter;
use alephcore::event::EventType;

let bus = GlobalBus::global();
let sub_id = bus.subscribe(
    EventFilter::new(vec![EventType::ToolCallStarted, EventType::ToolCallCompleted]),
    |event| println!("from agent={}", event.source_agent_id),
).await;
```

`GlobalBus::broadcast(agent_id, session_id, event)` 负责把事件加上 `source_agent_id` / `source_session_id` / `timestamp` / `sequence` 后分发给匹配 filter 的订阅者。

### EventHandler Trait

```rust
#[async_trait]
pub trait EventHandler: Send + Sync {
    fn name(&self) -> &'static str;
    fn subscriptions(&self) -> Vec<EventType>;
    async fn handle(
        &self,
        event: &AlephEvent,
        ctx: &EventContext,
    ) -> Result<Vec<AlephEvent>, HandlerError>;
}
```

实现者接收 `AlephEvent` 并可以返回新事件供发布：

- 日志处理程序写入磁盘
- WebSocket 处理程序转发到连接的客户端
- 内存处理程序更新知识图谱

注意：trait **不是** `EventHandler<E: Event>` 泛型 —— 接收方签名是 `&AlephEvent`，订阅通过 `subscriptions() -> Vec<EventType>` 声明。`EventContext`（`src/event/handler.rs`）现在是空标记结构体 —— 之前的 `bus` / `abort_signal` / `session_id` 字段已在 2026-08 severed-wire 审计中移除，`EventHandlerRegistry` 也随之移除（无生产调用方）。启动路径直接通过 `GlobalBus::global().subscribe_async(filter, |ev| handler.handle(&ev.event, &ctx))` 接线。

### EventFilter

`EventFilter`（`src/event/filter.rs`）是**结构体**而不是枚举，三类过滤维度一起 AND：

```rust
pub struct EventFilter {
    pub session_ids: Option<HashSet<String>>,   // None = 全部会话
    pub agent_ids: Option<HashSet<String>>,     // None = 全部智能体
    pub event_types: Vec<EventType>,            // 空 = 全部不匹配
}
```

构造方式：

```rust
let filter = EventFilter::new(vec![EventType::SubAgentTreeUpdate, EventType::ProcessCompleted])
    .with_session("session-123")
    .with_agent("agent-1");
```

`EventFilter::new` 的 `event_types` 为空表示不匹配任何事件。`EventFilter` 没有
「全匹配」构造（不存在 `EventType::All`），要订阅全部变体只能逐个列出。

**示例：** gateway 的子代理树中继（`src/gateway/subagent_tree_relay.rs`）用
`EventFilter::new(vec![EventType::SubAgentTreeUpdate])` 订阅全局总线，再把
子代理树的实时更新转发给 panel。

## 事件类型

`AlephEvent`（`src/event/types.rs`）的非穷举枚举变体（按用途分组）：

| 分类 | 变体 | 说明 |
|---|---|---|
| Sub-agent | `SubAgentCompleted(SubAgentCompletionEvent)` | 子代理终结 |
| Sub-agent | `SubAgentTreeUpdate(aleph_protocol::subagent_tree::SubagentTreeEvent)` | 子代理树实时更新 |
| Process | `ProcessCompleted(ProcessCompletionEvent)` | 后台 `bash` 作业自然结束 |
| Team | `TeamCreated { team_id, name }` | 团队创建 |
| Team | `TeamMemberAdded { team_id, member_id, role }` / `TeamMemberRemoved { team_id, member_id }` | 成员增删 |
| Team | `TeamTaskAssigned { team_id, task_id, assignee_id }` / `TeamTaskUpdated { team_id, task_id, status, previous_status }` | 任务分配与更新 |
| Team | `TeamTaskCompleted { team_id, task_id, result_summary }` / `TeamTaskFailed { team_id, task_id, error }` | 任务终态 |
| Team | `TeamDisbanded { team_id }` | 团队解散 |

`EventType`（`src/event/types.rs`）是订阅过滤用的 discriminant，与
`AlephEvent` 的变体一一对应：子代理 2 个、后台进程 1 个、团队 8 个，合计
11 个。2026-08 的 severed-wire 审计把一批没有生产者的变体从这两个枚举里删掉，
当时还有哪些变体见下方「历史」小节。

### 事件排序与时间戳

`GlobalEvent`（`src/event/global_bus.rs`）包装每条广播事件：

```rust
pub struct GlobalEvent {
    pub source_agent_id: String,
    pub source_session_id: String,
    pub event: AlephEvent,
    pub timestamp: i64,   // chrono::Utc::now().timestamp_millis()
    pub sequence: u64,    // 由 GlobalBus 自增
}
```

`GlobalBus` 没有历史回放 ring —— `broadcast` 通道有界且有损（`RecvError::Lagged(n)`）。滞后后订阅者必须重新读取权威状态，不能假设连续。`GlobalEvent` 的 `sequence` 用于跨 agent 投递的确定性排序。

## 使用示例

```rust
use alephcore::event::{GlobalBus, EventFilter, EventHandler, EventContext, EventType, AlephEvent, HandlerError};
use async_trait::async_trait;

struct MemoryLogger;

#[async_trait]
impl EventHandler for MemoryLogger {
    fn name(&self) -> &'static str { "MemoryLogger" }
    fn subscriptions(&self) -> Vec<EventType> {
        vec![EventType::ProcessCompleted]
    }
    async fn handle(
        &self,
        event: &AlephEvent,
        _ctx: &EventContext,
    ) -> Result<Vec<AlephEvent>, HandlerError> {
        if let AlephEvent::ProcessCompleted(p) = event {
            tracing::info!(process_id = %p.process_id, command = %p.command, "background job finished");
        }
        Ok(vec![])
    }
}

let handler = std::sync::Arc::new(MemoryLogger);
let filter = EventFilter::new(handler.subscriptions());
let ctx = EventContext::new();
GlobalBus::global()
    .subscribe_async(filter, move |global_event| {
        let handler = handler.clone();
        let event = global_event.event;
        let ctx = ctx.clone();
        tokio::spawn(async move {
            if let Err(e) = handler.handle(&event, &ctx).await {
                tracing::warn!(error = %e, "MemoryLogger handle error");
            }
        });
    })
    .await;
```

## 历史：2026-08 severed-wire 审计删除的事件变体

2026-08-16 的 severed-wire 审计（提交 `68e103c6f`，"event: severed-wire audit
fixes"）从 `AlephEvent` 与 `EventType` 里删掉了一批既无生产者也无订阅者的变体。
审计前的枚举长这样：

| 分类 | 已删除的变体 |
|---|---|
| Input | `InputReceived(InputEvent { text, session_id, context, timestamp })` |
| Tool | `ToolCallRequested(ToolCallRequest { tool, parameters })` |
| Tool | `ToolCallStarted(ToolCallStarted { call_id, tool, input, timestamp, session_id? })` |
| Tool | `ToolCallCompleted(ToolCallResult { call_id, tool, input, output, started_at, completed_at, token_usage, session_id? })` |
| Tool | `ToolCallFailed(ToolCallError { call_id, tool, input, error, error_kind, is_retryable, attempts, session_id? })` |
| Tool | `ToolCallRetrying(ToolCallRetry { call_id, attempt, delay_ms, reason? })` |
| Loop | `LoopContinue(LoopState)` / `LoopStop(StopReason)` |
| Session | `SessionCreated(SessionInfo)` / `SessionUpdated(SessionDiff)` / `SessionResumed(SessionInfo)` / `SessionCompacted(CompactionInfo)` |
| AI | `AiResponseGenerated(AiResponse { content, reasoning?, is_final, timestamp })` |
| Part | `PartAdded/Updated/Removed(crate::components::PartUpdateData)` |

至于 `MemoryUpdated`，代码仓历史里从头到尾没有这个标识符——旧文档那句「不含」
写的是一个不存在的名字。`ConfigReloaded` 则真的是 `McpManagerEvent` 的私有
变体，2026-08-02 的提交 `21ac20b6a`（"mcp: cut dead manager config knobs and
transport leftovers"）连同 `src/mcp/manager/types.rs` 里的一批死配置一起删掉；
`McpManagerEvent` 今天只剩 server 生命周期与 tools-changed 事件。

## 历史：每 agent EventBus

2026-08 severed-wire 审计前，`src/event/` 提供两条总线：

- **`EventBus`**（src/event/bus.rs）—— 每 agent 一份的 tokio `broadcast` 通道，`EventBus::new()` / `with_buffer_size` / `with_config` 创建，包装为 `TimestampedEvent { event, timestamp, sequence }`，历史 ring 上限 `MAX_HISTORY_SIZE = 10000`，可选连接 `GlobalBus`。
- **`GlobalBus`** —— 进程级单例（保留至今）。

审计发现 `EventBus` 与 `EventHandlerRegistry`（`Vec<Arc<dyn EventHandler>>` + `start`/`stop` 生命周期）均无生产调用方，一并移除；`EventContext` 的 `bus` / `abort_signal` / `session_id` 字段同时移除。启动路径改为直接 `GlobalBus::global().subscribe_async(filter, |ev| handler.handle(&ev.event, &ctx))`（见 `src/bin/aleph-server/commands/start/mod.rs`）。

## 26.7.x 补充

### `broadcast::RecvError::Lagged` 必须恢复

26.7.21 修复：Channel forwarder 在 `broadcast::RecvError::Lagged` 上不再永久死亡。WebSocket 断开时每个连接的事件转发任务不再泄漏；webhook 拥塞时返回 503 而不是默默丢弃。

### 单源错误回执

26.7.21 修复：网关返回给客户端的**单一来源**用户可读错误；原始错误链不外泄到 Panel。

### SessionEvent

26.7.7+ `session_events` 是规范事件日志——`MessageProjector` 物化到 `messages` 表，启动时 `ProjectionReconciler` 回填转写。`SessionEventRecord { seq, event, created_at_ms }` 是日志载荷；与 `AlephEvent` 是两套独立事件体系，分别承担「会话事件」与「运行事件」两种语义。

### Gateway 死信取证

26.7.17+：网关侧建立死信（dead-letter）取证通道——channel 路径下未能成功下发的消息可在 Panel 内被检查并安全重投递。

### Loop-Graph 治理事件

26.7.21+ 治理事件（胜利声明、目标结算、团队解散、watcher 触发）通过同一事件总线传递，由 `loop_graph` 层的 watcher 订阅。`NodeKind::Team` 与 `NodeKind::LoopGoal` 节点是 `loop_graph/types.rs` 的 `non_exhaustive` 枚举成员。
