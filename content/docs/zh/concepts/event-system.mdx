`event` 模块实现一个事件驱动架构，解耦 Aleph 的子系统。模块之间不是直接方法调用，而是组件将事件发布到总线并订阅它们关心的事件。`src/event/` 包含两个不同但相关的总线：

- **`EventBus`**（`src/event/bus.rs`）—— 每智能体内 tokio `broadcast` 通道；通过 `EventBus::new()` / `EventBus::with_buffer_size` / `EventBus::with_config` 创建，可选连上一个 `GlobalBus` 做跨智能体聚合。**它不是单例**。
- **`GlobalBus`**（`src/event/global_bus.rs`）—— 进程级**单例**，由 `once_cell::sync::Lazy` 守门，通过 `GlobalBus::global()` 访问；聚合多个 `EventBus` 的事件，并按 `EventFilter` 路由回调。

`AlephEvent`（`src/event/types.rs`）是两类总线共用的载荷类型；`#[serde(tag = "type", content = "data")]` 让它直接可 JSON 化。

## 设计理念

事件驱动架构在 Aleph 中提供三个好处：

1. **解耦** — 内存系统不需要了解网关；两者都只使用事件
2. **可观察性** — 每个重要动作都会产生一个事件，可以被记录、审计或流式传输到客户端
3. **可扩展性** — 新功能可以订阅现有事件而无需修改发布者

`EventBus` 默认 buffer 为 1024 条；保留历史 `MAX_HISTORY_SIZE = 10000`。`GlobalBus` 默认 buffer 同样为 1024。所有事件处理都是异步且非阻塞的。

## 核心组件

### GlobalBus（单例）

进程级跨智能体聚合总线：

```rust
use alephcore::event::global_bus::GlobalBus;
use alephcore::event::filter::EventFilter;
use alephcore::event::EventType;

let bus = GlobalBus::global();
let sub_id = bus.subscribe(
    EventFilter::new(vec![EventType::ToolCallStarted, EventType::ToolCallCompleted]),
    |event| println!("from agent={}", event.source_agent_id),
).await;
```

`GlobalBus::broadcast(agent_id, session_id, event)` 负责把事件加上 `source_agent_id` / `source_session_id` / `timestamp` / `sequence` 后分发给匹配 filter 的订阅者。

### EventBus（每智能体一份）

```rust
use alephcore::event::{EventBus, AlephEvent};

let bus = EventBus::with_buffer_size(2048);
bus.publish(AlephEvent::SessionCreated(
    SessionInfo {
        id: session_id.clone(),
        parent_id: None,
        agent_id: "main".into(),
        model: "gpt-4-turbo".into(),
        created_at: chrono::Utc::now().timestamp_millis(),
    }
)).await;
```

`EventBus`：

- 维护一个 tokio `broadcast::Sender<TimestampedEvent>`，可选 buffer 容量（默认 1024）
- 把每条事件包装成 `TimestampedEvent { event, timestamp, sequence }` —— sequence 由 `EventBus` 内单调 `AtomicU64` 自增
- 历史 ring 上限 `MAX_HISTORY_SIZE = 10000`，可通过 `EventBusConfig { buffer_size, enable_history, max_history_size }` 关闭或调小
- 可选连接 `GlobalBus`（设 `agent_id` / `session_id` 后）；连接时事件自动通过 `GlobalBus::broadcast` 广播

### EventHandler Trait

```rust
#[async_trait]
pub trait EventHandler: Send + Sync {
    fn name(&self) -> &'static str;
    fn subscriptions(&self) -> Vec<EventType>;
    async fn handle(
        &self,
        event: &AlephEvent,
        ctx: &EventContext,
    ) -> Result<Vec<AlephEvent>, HandlerError>;
}
```

实现者接收 `AlephEvent` 并可以返回新事件供发布：

- 日志处理程序写入磁盘
- WebSocket 处理程序转发到连接的客户端
- 内存处理程序更新知识图谱

注意：trait **不是** `EventHandler<E: Event>` 泛型 —— 接收方签名是 `&AlephEvent`，订阅通过 `subscriptions() -> Vec<EventType>` 声明。`EventContext`（`src/event/handler.rs`）携带 `bus: EventBus` / `abort_signal: Arc<AtomicBool>` / `session_id: Arc<RwLock<Option<String>>>`。

### EventFilter

`EventFilter`（`src/event/filter.rs`）是**结构体**而不是枚举，三类过滤维度一起 AND：

```rust
pub struct EventFilter {
    pub session_ids: Option<HashSet<String>>,   // None = 全部会话
    pub agent_ids: Option<HashSet<String>>,     // None = 全部智能体
    pub event_types: Vec<EventType>,            // 空 = 全部不匹配
}
```

构造方式：

```rust
let filter = EventFilter::new(vec![EventType::ToolCallStarted, EventType::ToolCallCompleted])
    .with_session("session-123")
    .with_agent("agent-1");
// 或
let filter = EventFilter::all();   // 等价于 EventFilter::new(vec![EventType::All])
```

**示例：** Panel 的 WebSocket 订阅走 `EventFilter::new(vec![EventType::ToolCallStarted, ...]).with_session(...)`，把与该会话相关的工具事件流给客户端。

## 事件类型

`AlephEvent`（`src/event/types.rs`）的非穷举枚举变体（按用途分组）：

| 分类 | 变体 | 说明 |
|---|---|---|
| Input | `InputReceived(InputEvent { text, session_id, context, timestamp })` | 用户输入 |
| Tool | `ToolCallRequested(ToolCallRequest { tool, parameters })` | 工具调用请求 |
| Tool | `ToolCallStarted(ToolCallStarted { call_id, tool, input, timestamp, session_id? })` | 工具调用开始 |
| Tool | `ToolCallCompleted(ToolCallResult { call_id, tool, input, output, started_at, completed_at, token_usage, session_id? })` | 工具调用完成 |
| Tool | `ToolCallFailed(ToolCallError { call_id, tool, input, error, error_kind, is_retryable, attempts, session_id? })` | 工具调用失败 |
| Tool | `ToolCallRetrying(ToolCallRetry { call_id, attempt, delay_ms, reason? })` | 工具调用重试中 |
| Loop | `LoopContinue(LoopState)` / `LoopStop(StopReason)` | 循环推进 / 停止 |
| Session | `SessionCreated(SessionInfo)` / `SessionUpdated(SessionDiff)` / `SessionResumed(SessionInfo)` / `SessionCompacted(CompactionInfo)` | 会话生命周期 |
| Sub-agent | `SubAgentCompleted(SubAgentCompletionEvent)` / `SubAgentTreeUpdate(...)` | 子代理终结 / 树更新 |
| AI | `AiResponseGenerated(AiResponse { content, reasoning?, is_final, timestamp })` | 模型响应 |
| Part | `PartAdded/Updated/Removed(crate::components::PartUpdateData)` | UI 消息流渲染 |
| Team | `TeamCreated { team_id, name, member_ids }` / `TeamMemberAdded` / `TeamMemberRemoved` / `TeamTaskAssigned` / `TeamTaskUpdated` / `TeamTaskCompleted` / `TeamTaskFailed` / `TeamDisbanded` | 多智能体团队 |

`EventType`（`src/event/types.rs`）是订阅过滤的 discriminant，**不含** `MemoryUpdated` 或 `ConfigReloaded`（后者是 `McpManagerEvent` 私有的，不挂在全局总线上）。

### 事件排序与时间戳

每个事件都被 `TimestampedEvent` 包装：

```rust
pub struct TimestampedEvent {
    pub event: AlephEvent,
    pub timestamp: i64,   // chrono::Utc::now().timestamp_millis()
    pub sequence: u64,    // 由 EventBus 的 AtomicU64 自增
}
```

`EventBus` 内置历史 ring（`Arc<RwLock<Vec<TimestampedEvent>>>`），新订阅者可回放；`GlobalEvent`（`src/event/global_bus.rs`）再叠加一层 `source_agent_id` / `source_session_id` / 自己的 `sequence`，序列号用于排序保证。

## 使用示例

```rust
use alephcore::event::{EventBus, EventHandler, EventContext, EventType, AlephEvent, HandlerError};
use async_trait::async_trait;
use std::sync::Arc;

struct MemoryLogger;

#[async_trait]
impl EventHandler for MemoryLogger {
    fn name(&self) -> &'static str { "MemoryLogger" }
    fn subscriptions(&self) -> Vec<EventType> {
        vec![EventType::ToolCallCompleted]
    }
    async fn handle(
        &self,
        event: &AlephEvent,
        _ctx: &EventContext,
    ) -> Result<Vec<AlephEvent>, HandlerError> {
        if let AlephEvent::ToolCallCompleted(t) = event {
            tracing::info!(call_id = %t.call_id, tool = %t.tool, "tool finished");
        }
        Ok(vec![])
    }
}

let bus = EventBus::new();
let mut registry = EventHandlerRegistry::new();
registry.register(Arc::new(MemoryLogger));
let _handles = registry.start(EventContext::new(bus.clone())).await;
```

## 26.7.x 补充

### `broadcast::RecvError::Lagged` 必须恢复

26.7.21 修复：Channel forwarder 在 `broadcast::RecvError::Lagged` 上不再永久死亡。WebSocket 断开时每个连接的事件转发任务不再泄漏；webhook 拥塞时返回 503 而不是默默丢弃。

### 单源错误回执

26.7.21 修复：网关返回给客户端的**单一来源**用户可读错误；原始错误链不外泄到 Panel。

### SessionEvent

26.7.7+ `session_events` 是规范事件日志——`MessageProjector` 物化到 `messages` 表，启动时 `ProjectionReconciler` 回填转写。`SessionEventRecord { seq, event, created_at_ms }` 是日志载荷；与 `AlephEvent` 是两套独立事件体系，分别承担「会话事件」与「运行事件」两种语义。

### Gateway 死信取证

26.7.17+：网关侧建立死信（dead-letter）取证通道——channel 路径下未能成功下发的消息可在 Panel 内被检查并安全重投递。

### Loop-Graph 治理事件

26.7.21+ 治理事件（胜利声明、目标结算、团队解散、watcher 触发）通过同一事件总线传递，由 `loop_graph` 层的 watcher 订阅。`NodeKind::Team` 与 `NodeKind::LoopGoal` 节点是 `loop_graph/types.rs` 的 `non_exhaustive` 枚举成员。
