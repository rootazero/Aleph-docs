## 概述

`IdentityContext` 是一个不可变的身份快照，流经整个执行链，在工具执行级别启用基于身份的权限强制执行。

每个进入 Aleph 的请求都携带一个身份——无论是来自所有者、具有有限范围的访客，还是未经认证的调用者。该身份在会话创建时捕获一次，并在请求生命周期的剩余时间内变为只读。通过使身份不可变，系统防止了调用者可能在执行过程中更改角色的特权升级攻击。

## 身份上下文流程

```
1. 会话创建
   SessionManager
   ┌────────────────────────────────────────────┐
   │ 所有者会话:                                 │
   │   metadata = SessionIdentityMeta {          │
   │     role: Role::Owner,                      │
   │     identity_id: "owner",                   │
   │     scope: None,                            │
   │     source_channel: "gateway",              │
   │   }                                         │
   │                                             │
   │ 访客会话:                                   │
   │   metadata = SessionIdentityMeta {          │
   │     role: Role::Guest,                      │
   │     identity_id: "<guest-uuid>",            │
   │     scope: Some(GuestScope { ... }),        │
   │     source_channel: "telegram",             │
   │   }                                         │
   └────────────────────────────────────────────┘
            │
            ▼
2. 解析为 IdentityContext
   IdentityContext::owner(session_key, source_channel)
   IdentityContext::guest(session_key, guest_id, scope, source_channel)
   IdentityContext::anonymous(session_key, source_channel)
            │
            ▼
3. Harness 执行（Orchestrator::dispatch）
   FlowRequest { agent_id, input, channel, ... }
   HarnessRunner::run(session_key, spec, input, sandbox, events, ...)
            │
            ▼
4. 工具执行（ScopedToolService）
   ┌────────────────────────────────────────────┐
   │ let svc = ScopedToolService::new(           │
   │     registry,                               │
   │     allowed_tools,                          │
   │ );                                          │
   │                                             │
   │ match identity.role {                       │
   │     Role::Owner => 全量工具集可用,          │
   │     Role::Guest => scope.allows_tool(name), │
   │     Role::Anonymous => Denied,              │
   │ }                                           │
   └────────────────────────────────────────────┘
```

| 组件 | 位置 | 职责 |

| **`IdentityContext` / `GuestScope` / `Role`** | `shared/protocol/src/auth.rs`（`aleph_protocol`） | 不可变身份快照、访客范围、角色枚举 |

| **`ScopedToolService`** | `src/gateway/execution_engine/` | 在工具执行层强制 `allowed_tools` |

## 角色类型

Aleph 定义了三个角色层级，决定调用者被允许执行的操作（`shared/protocol/src/auth.rs`）：

| 角色 | 权限 | 使用场景 |
|------|-------------|----------|
| **`Owner`** | 跳过工具过滤 | 服务器所有者 |
| **`Guest`** | 受 `allowed_tools` 约束 | 通过邀请获得的临时访问 |
| **`Anonymous`** | 默认拒绝 | 未认证请求；`Role` 的 `#[default]` |

### Owner

所有者角色分配给服务器管理员。`IdentityContext::owner` 在构造时填入 `role = Role::Owner`、`identity_id = "owner"`、`scope = None`；执行端会跳过 `allowed_tools` 过滤，由 `ScopedToolService` 透传全部可见工具集。

### Guest

访客会话通过邀请系统创建。访客接收一个有限的范围 `GuestScope`，定义他们可以调用哪些工具以及访问何时到期。访客工具路径走 `scope.allows_tool(name)`（`GuestScope::allows_tool`）的精确匹配——不接受通配符或类别前缀。

### Anonymous

匿名请求走 `IdentityContext::anonymous`，`Role` 派生为 `Anonymous`（`#[default]`）时同一构造路径被采用；在执行端被拒绝，除非整条调用链在禁用认证的开发模式下运行。

## GuestScope

当创建访客会话时，`SessionIdentityMeta` 携带一个 `GuestScope`（`shared/protocol/src/auth.rs`）：

```rust
pub struct GuestScope {
    pub allowed_tools: Vec<String>,   // 访客可调用的工具名（精确匹配）
    pub expires_at: Option<i64>,      // Unix 秒；None = 无到期
    pub display_name: Option<String>, // 审计日志中的人工可读名
}
```

| 字段 | 类型 | 描述 |
|-------|------|-------------|
| `allowed_tools` | `Vec<String>` | 精确匹配的工具名；调用端 `allows_tool` 逐项 `==` 比对 |
| `expires_at` | `Option<i64>` | Unix 时间戳；`GuestScope::is_expired(now)` 在 ≥ 触发时视为过期 |
| `display_name` | `Option<String>` | 审计日志中显示的友好名 |

<Callout type="warn">
访客范围在 `ScopedToolService` 的工具执行层强制执行，而不是在 API 边界。访客可以发送任何请求，但任何不在 `allowed_tools` 中的工具调用在执行层被丢弃。
</Callout>

## IdentityContext

`IdentityContext` 是「证书权威」模式：构造时拍板权限，全程不可变，所有审计信息内嵌，无需外部查询即可独立校验。

```rust
pub struct IdentityContext {
    pub request_id: String,      // crate::ids::next_id()
    pub session_key: String,
    pub role: Role,
    pub identity_id: String,     // Owner="owner" | Guest=<uuid> | Anonymous="anonymous"
    pub scope: Option<GuestScope>,
    pub created_at: i64,         // SystemTime::now().duration_since(UNIX_EPOCH).as_secs()
    pub source_channel: String,
}
```

工厂方法：

- `IdentityContext::owner(session_key, source_channel)`
- `IdentityContext::guest(session_key, guest_id, scope, source_channel)`
- `IdentityContext::anonymous(session_key, source_channel)`

每个工厂都自填 `request_id` 与 `created_at`，因此同一个调用点生成的两个上下文不会共享 `request_id`。

## 身份账本与签名

`src/identity/` 提供「谁能执行 + 发生了什么」两层账本：

- **`AgentKeystore`**（`src/identity/keystore.rs`）—— 每代理 Ed25519 密钥对；公钥/指纹存 `security.db`，私钥放共享 Vault；轮换只退役旧 key，使旧签名仍可校验。
- **`AgentLedger`**（`src/identity/ledger.rs`）—— 每代理独立的哈希链；每个工具调用（`tools::scoped::dispatch` 是全代码唯一收口）追加一条签名记录。
- **`verify_chain`**（`src/identity/verify.rs`）—— 返回 `ChainReport` / `ChainFault`，校验哈希链是否完整。
- **`as_actor` / `current_actor`**（`src/identity/actor.rs`）—— 一个 `tokio::task_local`，让子代理/委派场景下「实际签发者」落到被委派那一层，而不是父级。

注意：账本「忠实记录被赋予的身份」，它本身不是反冒充防御——`agent_id` 仍是 `chat.send` 上调用方提供的字符串，调用级认证通过后仍可冒用任何已存在代理（详见 `docs/reference/AGENT_IDENTITY.md`）。

## 示例：所有者请求

```rust
use aleph_protocol::{IdentityContext, Role};
use std::time::{SystemTime, UNIX_EPOCH};

let session_key = String::from("agent:main:main");
let metadata = SessionIdentityMeta::owner("gateway");

let identity = metadata.to_identity_context(session_key);
// identity.role == Role::Owner
// identity.identity_id == "owner"
// identity.scope == None
```

## 示例：带邀请的访客请求

```rust
use aleph_protocol::{GuestScope, IdentityContext, Role};

let scope = GuestScope {
    allowed_tools: vec!["code_exec".to_string()],
    expires_at: Some(
        SystemTime::now().duration_since(UNIX_EPOCH).unwrap().as_secs() as i64 + 3600
    ),
    display_name: Some("Alice".to_string()),
};

let session_key = String::from("agent:main:telegram:dm:<alice-uuid>");
let metadata = SessionIdentityMeta::guest(
    "<alice-uuid>".to_string(),
    scope,
    "telegram".to_string(),
);

let identity = metadata.to_identity_context(session_key);
// identity.role == Role::Guest
// identity.scope.allows_tool("code_exec")   == true
// identity.scope.allows_tool("bash")    == false
```

## 26.7.x 补充

### 委托角色链

26.7.26+：`as_actor` task-local 让委派链路上每个被委派角色都有自己的签名身份：

- 身份链路**生命周期内闭包**——委托关系一旦建立就在链内完成所有签发
- 子代理不再被记到父级账本上；`AgentKeystore` 给每个代理角色独立 key，私钥不出节点
- `verify_chain` 沿签名者所属链路回放 `LedgerRecord` 校验

### 失败关闭

26.7.21 强化：策略文件缺失、无法读取或无法解析时，授权必须**失败关闭**而不是开放。`[sandbox.command_policy]` 硬底优先级最高，不能被任何 `exec_tier` 拉低。

### 真实客户端 IP

26.7.17+：`[gateway] trusted_proxy` 反向代理信任列表决定网关是否读取真实客户端 IP——容量限制、速率限制、审计、连接认证都依赖此值。配置错误时所有这些指标都会用代理 IP。

### 设备票与令牌轮换

26.7.17+ 网关侧远程认证：

- `gateway.ticket.create` 颁发设备票
- `gateway.token.current` / `gateway.token.rotate` 管理令牌
- `gateway.devices.list` / `gateway.devices.revoke` 管理设备清单
- 远程会话在 token 轮换时被关闭，**环回会话保留**

### iOS Panel 证书信任

iOS Panel 通过 `mobile/ios/AlephPaneliOS/Views/PanelWebView.swift` 和 `mobile/ios/AlephPaneliOS/Services/CertTrustStore.swift` 处理自签名证书的首次使用信任（Trust-on-First-Use）。

- 在 Keychain 中保存固定的证书指纹
- SHA-256 指纹 + SAN/subject 解析
- 审批 splash 页面（指纹 + SAN + TOFU/change 警告）
- pending-cert 状态与 approve/reject 路径
