`cluster` 模块实现 Aleph 的中心侧集群基础设施。它把入网节点视为受信 LAN 联邦成员，提供节点注册、生命周期 SSOT、反向 RPC、命令派发、文件命令沙箱与节点审批回环。中心侧 LLM 工具 `node_list` / `node_invoke` / `node_invoke_many` / `node_file` 通过这些原语驱动节点。

## 设计理念

集群遵循三个原则：

1. **生命周期 SSOT** —— 注册 / 注销 / 在线状态唯一来源为 `NodeRegistry`，避免重复行与残留状态
2. **授权命令表** —— `CommandTable` 是节点可见命令的权威允许列表，未列入的命令被拒绝
3. **失败关闭** —— 节点审批回环 (`CenterApprovalRequester`) 与文件沙箱默认拒绝，凭证不发给节点

## 核心组件

### NodeRegistry

多级寻址 + tag fan-out + 断连 fail-fast 的中心侧节点注册表：

```rust
pub struct NodeRegistry { /* … */ }

impl NodeRegistry {
    pub fn maybe_register_node(/* … */) -> NodeMatch { /* … */ }
    pub fn match_id(/* … */) -> Option<&NodeSession> { /* … */ }
    pub fn environments_list(/* … */) -> Vec<Environment> { /* … */ }
}
```

`Environment` 是 `environments.list` 渲染的序列化外部视图（精简渲染契约）。

### Cluster 生命周期

`NodeAdmission` 是注册入口；`enroll_node_device` 是操作员预注册（幂等）；`deregister_node` 把节点从 `environments.list` 与 `node_invoke` / `node_file` 寻址中移除。`DeregisterError` / `DeregisterOutcome` 显式表达粘住注销的语义。

**确定性：** `environments_list()` 返回排序的 `Environment` 向量；节点键在归一化前先走 `normalize_node_key`（Unicode 归一化，CJK 节点名正确）。

### CommandTable

节点可见命令的权威允许列表：

```rust
pub struct CommandTable { /* … */ }
pub enum NodeCommand { /* … */ }
```

未列入 `CommandTable` 的命令被拒绝——同一道闸门在 connect 时与 invoke 时都被检查。

### FileReadCommand / FileWriteCommand

文件命令沙箱：

- `MAX_FILE_BYTES` 是单次读 / 写的硬上限
- 路径限制由中心侧策略保证；写命令不再存在 check-then-write 的 TOCTOU 窗口
- `sha256_hex` 用于一致性验证

### CenterApprovalRequester

节点侧审批的回环（fail-closed）。中心发起的人审请求通过这条通道回到中心侧 LLM / 用户，`NODE_APPROVAL_TIMEOUT_MS` 是超时硬上限。

### ReverseRpcChannel / PendingInvokes

服务器 → 已连客户端 id-bearing 请求 / 响应通道。响应通过结构（不是 id）匹配请求，因此多个并发调用无需自管 id。

## 事件与状态

节点侧通过 `cluster.*` RPC 报告状态；中心侧把节点连接 / 断连 / 离线状态广播给 Panel（实时舰队 feed）。

```rust
pub struct NodeSession { /* 在线节点视图 */ }
pub struct Environment { /* 序列化外部视图 */ }
```

`environments.list` 是只读视图，Panel 集群面板消费。连接协议：节点的 connect 帧声明其命令表 + tag；中心在 connect 握手中完成 admit + 注册，避免单独的注册往返。

---

## 持久化

`cluster.deregister` 把设备行撤销，Panel 的 `last_seen_at` 不再被当作"在线"信号：

- 参数化 SQL 查询（无注入风险）
- 锁使用 `unwrap_or_else(|e| e.into_inner())` 模式
- 所有查询使用 `params![]` 进行绑定
- `file.write` 不再存在 check-then-write TOCTOU

---

## 安全属性

- **生命周期 SSOT** —— 注册 / 注销唯一来源；`cluster.enroll` 不再每次点击铸造重复行
- **Unicode 节点键** —— `normalize_node_key` 做 Unicode 归一化，CJK 节点名不再被字节切片破坏
- **授权命令表** —— `CommandTable` 权威允许列表
- **文件沙箱** —— `MAX_FILE_BYTES` 硬上限 + 路径限制 + 无 TOCTOU 写
- **LAN-trust** —— 节点不持 token，连接身份由 connect 帧的 `commands` + `tags` 形状声明
- **审批回环失败关闭** —— `CenterApprovalRequester` 默认拒绝

### 与 Dreaming / Insights 的关联

集群并不直接驱动 Dreaming；关联是间接的：

- Dreaming Daemon（`src/memory/dreaming/`）在夜间运行，不依赖集群；它的重试风暴已加边界（`should_skip_scheduled_run`），不再耗尽 provider 额度
- `DreamReport` 字段（`links_purged`、`extra` 等）作为 dreaming 阶段的产物被下游 insights 消费（`src/memory/insights.rs`）
- `insights.tools` 是按工具使用的只读聚合（从原始 `ToolInvocation` 行计算），与集群舰队并列显示在 Memory Hub / governance 视图
- Memory Hub 把 graph canvas + vault table 合并为单一视图，新增 Dream Insights 与 Corrections 治理视图；`memory.retrieve_with_trace` 提供每阶段打分 trace
