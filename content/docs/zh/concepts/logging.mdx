Aleph 使用 `tracing` 记录结构化事件。日志输出由日志层统一格式化并进行 PII/密钥清理；日志不是业务错误的第二个协议来源。

## 输出与级别

生产默认级别为 `INFO`。`TRACE` 用于详细流程，`DEBUG` 用于诊断，`WARN` 表示可恢复问题，`ERROR` 表示需要关注的失败。运行版本实际创建的日志目录和格式是准确信息来源，不要依赖旧版 `[logging]` 字段清单。

日志应避免 API key、token、个人消息及其他秘密。Guardian Judge 等探针的 payload 也不得把密钥序列化到日志或审计数据中。

## 启动边界与轮转

守护进程按日边界轮转日志。每次启动在日志起点写入 `ALEPH-BOOT` marker，因此可以用它定位一次启动的日志范围；它不是业务事件，也不是错误回执。睡眠抑制器保持 stderr 静默。

## 结构化关联

日志事件包含时间、级别、target 和结构化字段；请求上下文通过 tracing span 关联。聚合和排障应使用字段与 span，而不是解析自然语言消息。
