Aleph 中 Extension 有两层含义：

- 面向用户的 Hub 概念：把 Skill、Plugin、Mcp 统一成一种 Extension。
- `src/extension/` 插件宿主：负责加载、注册、运行插件组件。

Hub 门面按 Kind 路由，插件宿主并不取代 `SkillSystem` 或 `McpManager`，而是与它们集成。

## 架构

```text
ExtensionManager
├── DiscoveryManager
├── AdapterRegistry
├── PluginRegistry
├── PluginLoader
├── 共享 SkillSystem
├── HookExecutor
├── ServiceManager
└── ExtensionWatcher
```

启动路径：

```text
扫描作用域
  → 解析与归一化清单
  → 校验候选
  → 解决重复来源
  → 注册静态能力
  → 加载 Static / MCP / WASM runtime
  → 发布技能与代理
  → 同步插件 MCP server
```

进程级 `SkillSystem` 接收插件技能根，因此插件技能和文件技能共享来源优先级、快照、提示词 XML、`skill_read`、状态与生命周期操作。

## 清单适配器

首选格式是 `.claude-plugin/plugin.toml`，其次是只读兼容的 `.claude-plugin/plugin.json`。`aleph.plugin.toml` 是已废弃的兼容格式，会打印警告。适配器注册表也接受受支持的 Codex、Cursor 布局以及最后的自动发现适配器。

自动发现会识别 `skills/`、`agents/`、`commands/`、`hooks/hooks.json`、`hooks.json` 与 `.mcp.json`。包含任一已识别组件的目录可被视作无清单的静态插件。

## 统一能力注册

`CapabilityDeclaration` 在生产中只有六种变体：

```rust
pub enum CapabilityDeclaration {
    Tool(ToolRegistration),
    Hook(HookRegistration),
    Service(ServiceRegistration),
    Skill(SkillRegistration),
    Agent(AgentRegistration),
    McpServer(McpServerConfig),
}
```

注册器校验所有权，划分能力层级，并派发到对应注册表。Tool、Hook、Skill 属于核心；Agent 属于重要；Service 与 McpServer 属于可插拔。命令 Markdown 以命令型技能存放。

`PluginRegistry` 记录插件及其注册的工具、钩子、服务、技能与代理。注册表同时保留 `plugin:diagnostics:check` 这类限定键与短名兼容键。注册行为并不授予插件绕过工具执行策略的权限。

## Runtime 集成

| 插件类型 | 宿主 |
|---|---|
| Static | 仅注册 Markdown 组件，不执行 |
| MCP | `.mcp.json` 被翻译为限定命名的瞬态 MCP server |
| WASM | Extism 加载模块并调用声明的导出 |

MCP 插件 server ID 形如 `plugin:<plugin-id>/<server-name>`。MCP 管理器负责进程健康与工具发现。扩展管理器的同步是幂等的，且在 CLI/测试路径下没有实时 MCP handle 时是 no-op。

WASM 工具发现基于插件注册路径。WASM 模块可通过 WASM 注册器声明能力；Node.js IPC runtime 已不再记录。

## 钩子与服务

钩子经共享 `HookExecutor` 执行：

- `interceptor` 钩子按优先级顺序执行，可改写或停止被保护操作。
- `observer` 钩子并行执行，不会成为阻塞决策点。
- 允许的形态取决于事件触发点。
- matcher 仅基于 `tool_name` 匹配。

运行时清单展示解析后的形态、优先级、动作、同意状态以及钩子是否可达。钩子输出上限 64 KiB，钩子超时上限 300 秒。

后台服务需要插件 `background` 权限以及同时声明 start 与 stop handler。服务生命周期在加载、启用、禁用、卸载、热重载与守护进程关闭时统一协调。

## 发现优先级

作用域目录按高到低检查：

```text
agent > local > project > user
```

重复插件 ID 按以下来源优先级解决：

```text
config > workspace > global > bundled
```

被激活的记录被加载；overridden 记录保留以便诊断。`.disabled` 标记阻止目录成为候选。

## 生命周期安全

`ExtensionManager::load_all` 由 load guard 保护。管理器同时维护活动插件工具快照与单调 revision，以便工具注册表在不变更循环其他部分的前提下刷新。并发 `reload` 调用是串行的。

插件卸载在删除文件前完成运行时清理。对 MCP 插件而言，瞬态 server 会从实时管理器移除，进程与工具不会跨越插件生命周期。格式错误的插件结果会作为错误返回，而不是被上报为成功的服务结果。

## 与 Hub 的关系

Hub 目录在 `src/hub/` 实现，把归一化后的目录条目持久化到 `hub_catalog.db`。它提供一个 `InstallSpec`，并把选中的 `Plugin` 入口路由到市场安装器。扩展宿主随后发现并加载已安装插件。

Hub 是目录与受信边界，本模块是插件运行时与注册边界。两边都不构成多 provider 目录模型，清单里也没有插件 provider 段。

## 代码位置

- `src/extension/mod.rs` — 管理器与子系统连接
- `src/extension/manifest/` — 适配器与归一化清单
- `src/extension/discovery/` — 候选、作用域与冲突解决
- `src/extension/capability.rs` — 声明与层级
- `src/extension/registrar/` — 注册派发
- `src/extension/registry/` — 组件注册表
- `src/extension/loader.rs` — runtime 加载
- `src/extension/hooks/` — 钩子执行与同意
- `src/extension/watcher.rs` — 变更检测与重载
- `src/hub/` — 面向用户的目录与安装路由
