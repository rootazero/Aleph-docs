`gateway` 模块是 Aleph 的 WebSocket JSON-RPC 网关。它处理客户端连接、会话管理、执行引擎以及与多个消息平台（Discord、Telegram、CLI、TUI 等）的接口。

## 设计理念

1. **接口无关核心** —— 相同的代理大脑服务每个接口
2. **会话隔离** —— 每个对话都是具有自己上下文的独立会话
3. **流式响应** —— 实时 token 流式传输到所有连接的客户端

## 核心组件

### WebSocket 处理程序

接受 JSON-RPC 2.0 连接：

```rust
pub struct WebSocketHandler;

impl WebSocketHandler {
    pub async fn handle(
        &self,
        socket: WebSocket,
    ) -> Result<()> { /* ... */ }
}
```

**方法：**
- `session.create` —— 创建新会话
- `chat.send` —— 发送消息（封装 `agent.run`）
- `chat.history` —— 获取对话历史（会话列表与历史另有 `sessions.list` / `sessions.history`）
- `chat.clear` —— 清除会话的对话历史（整体重置用 `sessions.reset`）
- `tools.invoke` —— 直接调用工具

### SessionManager

管理活动会话：

```rust
pub struct SessionManager {
    sessions: HashMap<SessionId, Session>,
}

impl SessionManager {
    pub async fn create(
        &self,
        config: SessionConfig,
    ) -> Result<SessionId> { /* ... */ }

    pub async fn get(
        &self,
        id: SessionId,
    ) -> Option<Session> { /* ... */ }
}
```

**会话类型：**
- `Owner` —— 对所有功能的完全访问
- `Guest` —— 受限访问，无持久历史
- `Paired` —— 链接到特定频道（Telegram、Discord）

### ExecutionEngine

处理消息的代理循环：

```rust
pub struct ExecutionEngine {
    thinker: Thinker,
    tool_service: ToolService,
    provider: Arc<dyn LlmProvider>,
}

impl ExecutionEngine {
    pub async fn run(
        &self,
        request: RunRequest,
    ) -> Result<RunOutput> { /* ... */ }
}
```

**流程：**
1. 接收 `RunRequest`（消息 + 附件 + 上下文）
2. 通过 `MediaProcessor` 处理附件
3. 通过 `Thinker` 构建系统提示词
4. 调用 LLM 提供商
5. 解析响应（文本 + 工具调用）
6. 执行工具
7. 将结果流式传输回客户端

### 接口

平台特定适配器：

**Discord：**
- 通过 `serenity` 的机器人集成
- 斜杠命令
- DM 和公会频道支持

**Telegram：**
- 通过 `teloxide` 的机器人集成
- 内联查询
- 群聊支持

**CLI：**
- 交互式终端界面
- 命令历史
- Tab 补全

**TUI：**
- 使用 `ratatui` 的终端 UI
- 多窗格布局
- 实时流式传输

## 路由

消息被路由到适当的处理程序：

```rust
pub struct InboundRouter {
    handlers: HashMap<InterfaceType, Box<dyn MessageHandler>>,
}
```

**路由规则：**
- WebSocket → SessionManager → ExecutionEngine
- Discord → ChannelManager → SessionManager
- Telegram → BotHandler → SessionManager
- CLI → DirectExecution

## 安全属性

- **UTF-8 安全** —— 所有字符串操作使用 `char_indices()` 或 `.find()`
- **锁恢复** —— `unwrap_or_else(|e| e.into_inner())`
- **生产中无 unwrap** —— 所有热路径返回 `Result`
- **饱和算术** —— 索引计算使用 `saturating_sub`

## 26.7.x 补充

### 错误链 Single-Source

26.7.21+：网关返回给客户端的**单一来源**用户可读错误。原始错误链不外泄到 Panel——之前的实现会把内部 `serde_json` / sqlx / io 错误直接吐给用户。

### WS 任务泄漏修复

26.7.21+：WebSocket 断开时每个连接的事件转发任务**不再泄漏**；channel forwarder 在 `broadcast::RecvError::Lagged` 上**恢复**而非永久死亡。

### Webhook 反压

26.7.21+：webhook 接收端在拥塞时返回 503 而不是默默丢弃入站消息。

### 死信与重投递

26.7.17+：投递队列会把永久投递失败的出站消息保存为死信，并可重新投递。死信的查看与重投递**不是 Gateway RPC 方法**，而是内建工具 `channel_outbox`（`status` / `dead_letters` / `redrive` 三个 op；`redrive` 需 `confirm_redrive: true` 才会真正重投，省略时只返回预览）。曾有的 `channels.dead_letters` / `channels.redrive_dead_letters` RPC 因没有任何客户端调用已移除；`channels.list` 仍会给出永久未送达推送的数量。

### 自签名 TLS + TOFU

26.7.17/18+：

- 进程内 gateway TLS（`[gateway] tls` / `trusted_proxy` / `allow_insecure_remote`）
- 自签名证书 SAN 自动覆盖主机非环回接口 IP
- 漂移检测 sidecar + 原子 regen marker
- 客户端 TOFU（fingerprint + SAN 审批 + 固定信任存储）
- macOS WKWebView + iOS Keychain 适配器

### 真实客户端 IP

26.7.17+：`[gateway] trusted_proxy` 反向代理信任列表——决定网关是否读取真实客户端 IP（容量限制、速率限制、审计、连接认证）。

### `gateway.ticket.create` / `token.rotate` / `devices.*`

26.7.x 完整设备票 / 令牌轮换 / 设备管理 RPC。远程会话在 token 轮换时关闭，**环回会话保留**。
