> **当前状态（26.7.22+）。** 在 26.7.21 之前 Aleph 只有 cron（持久、跨会话、有自己的 session）和 heartbeat（短间隔心跳）。26.7.22+ 引入三个**独立子系统**，覆盖"现在这个会话里想持续做某事 / 想自己追求目标 / 团队需要按 plan 推进"的中间地带。三者**不互斥**——一个会话里可以同时有 loop + goal + 被某 strategy 引用。

## 子系统定位

| 子系统 | 模块 | 状态机 | 触发 | 停止条件 |
|--------|------|--------|------|---------|
| **Loop**（持续循环） | `src/looping/`（`types.rs` / `pursuit.rs` / `mod.rs`） | `Active` / `Paused` / `Stopped`（**进程内** `LoopRegistry`） | 每次 run 结束**续接钩子**根据 cadence 拉下一次 tick | `max_iterations` / `deadline_ms` / `token_budget` |
| **Goal**（自主目标追求） | `src/goal/`（`pursuit.rs` / `store.rs` / `types.rs`） | `Active` / `Paused` / `Completed` / `Aborted`（**持久化**，DB-backed） | 客观 gate + stop_hooks | 客观 outcome（maker 模型自报 + checker 客观校验，**两者都成功**才 `Completed`） |
| **Strategy**（团队/裸循环策略） | `src/strategy/`（`planner.rs` / `render.rs` / `store.rs` / `types.rs`） | `Draft` / `Active` / `Superseded`（**复合键存储**） | team_key / session_key 命名的 plan 触发 | 目标变更 / plan 完成 / 团队解散 |

## Loop —— 当前会话的多轮 watch

```rust
// src/looping/types.rs
pub enum Cadence {
    Fixed { interval_ms: u64 },                                  // 每 N 毫秒 tick
    ModelPaced { fallback_ms: u64 },                             // 模型每 tick 报 next_wake_ms
}

pub enum LoopStatus { Active, Paused, Stopped }

pub struct LoopState {
    pub session_id: String,
    pub prompt: String,                  // 每 tick 原样回注
    pub cadence: Cadence,
    pub next_wake_ms: Option<u64>,       // model-paced 覆盖
    pub pending_tick_wake_ms: Option<u64>,  // 已入队 tick 的 fire 时间
    pub iterations_used: u32,
    pub max_iterations: Option<u32>,
    pub deadline_ms: Option<u64>,        // 绝对 epoch ms
    pub token_budget: Option<u64>,       // 软 token 上限
    pub tokens_at_start: u64,
    pub baseline_captured: bool,
    pub status: LoopStatus,
    pub created_at_ms: u64,
    pub stop_reason: Option<String>,     // 用户面理由：cap 触发 / 失败 / 手停
}
```

### 关键不变量

- **`LoopRegistry` 仅进程内**：daemon 重启清空所有 loop（"dies with the session"）—— 这是 loop 与 goal 的根本区别
- **`pending_tick_wake_ms` 串行化**：每次 run 完成都进续接钩子，没这个闸门每个用户回合都会再开一条 tick 链
- **`Paused` vs `Stopped`**：两者都 `is_active() = false`（无 tick 触发），但 `Paused.is_adjustable() = true`（可调 caps/cadence/prompt）；`Stopped` 不可复活，只能 `start` 新 loop
- **`over_budget` 三态**：必须同时 `token_budget.is_some()` && `baseline_captured` 才生效；没 baseline 时返回 false（防"长会话第一 tick 立刻超预算"）
- **`RearmDecision` 而非 `Exhausted`**：AgentBusy 撞期不浪费 iteration，重新 arm 同一 tick

### 渲染分层（避免污染 prompt cache）

- **`human_summary(now_ms)`**：用户面工具回复，**带倒计时**
- **`stable_summary()`**：进 SYSTEM PROMPT 的部分——**不含倒计时**（prompt cache 按前缀键，每字节变动都让后续 history 重新写入 1.25× 而非 0.1× 读取）
- **`live_status(now_ms)`**：倒计时搬到 transient trailing user message（cache 断点之后），字节变化只花自己

### `LoopRegistry`（进程内）

`try_claim_tick(session, tokens, now)` 是**唯一**的原子声明点（`Arc<Mutex<HashMap<...>>>` 下的单锁保护）：

```text
1. session 不在或 !is_active() → Idle
2. pending_tick_wake_ms 在「未到 stale grace」区间内 → Idle（fan-out gate）
3. should_continue? (max_iterations / over_budget / past_deadline):
   yes → spend_iteration(), 盖 next_wake_ms = None（防模型忘了重设的 busy-loop）, 盖 pending = Some(wake_ms), Fire
   no  → exhausted? → Exhausted { note }, 否则 Idle
4. over_budget_lazy_capture: budget.set + baseline_captured=false + tokens_total=Some(t) → with_baseline(t)（**只**capture 一次）
5. past stale grace (60s): pending 视为 dead, 重 claim（不重 spend iteration）
```

`rearm_after_busy(session, now)`：唤醒的 tick 在 confirm_fire 后 pending 清空，但跑 session slot 已被 AgentBusy 抢了 —— 不重 spend、30 s 后重试同一 tick（`BUSY_RETRY_DELAY_MS`），同 goal 子系统的 `rearm_goal_after_busy` 镜像。

`commit_field_update(next, reschedule)` 是**唯一**的工具写入点（防止 read→await→put 时间差里 `pending_tick_wake_ms` 被工具的 stale 快照覆盖），重读 live 的 `pending` 与 `continuations_used`、merged 进 `next` 后写。`reschedule = true`（用户改 cadence / 改 next_wake）才清 pending，否则保留。

`transition(to, reason)` 是 lifecycle move 单点：`Stopped` 终态（拒绝任何 from-stopped move）、`Paused` 仅可从 `Active` 进入、`Active` 仅可从 `Paused` 进入；离开 `Active` 清 pending（pause / stop 立刻让 sleeping tick 的 confirm_fire 失配跳过）。

`stop_all(reason)` 是 kill switch（跨会话）：单锁下把所有 != Stopped 改为 Stopped 并盖 reason，**已 Stopped 不动**——便于 incident response「全部暂停，逐一审视后 resume」。

## Goal —— 自主目标追求 + 客观 gate

```rust
pub struct Goal {

    pub iterations_used: u32,                  // 在 types.rs 字段名为 continuations_used
    pub deadline_ms: Option<u64>,
    pub baseline_captured: bool,
    pub objective_gate: GateConfig,           // 客观 gate 配置
    pub created_at_ms: u64,
    pub updated_at_ms: u64,
    pub note: Option<String>,
    pub gate_outcome: GateOutcome,            // Unchecked / Passed
    pub gate_command: Option<String>,
    pub lessons: Vec<String>,                // 课程（ring 5，新保留）
    pub pending_continuation_ms: Option<u64>,  // 在飞 continuation fire time
    pub waiting_until_ms: Option<u64>,        // wait_minutes 屏障（hermes parity）
    pub waiting_on_task: Option<String>,       // wait_for_task 屏障
    pub waiting_reason: Option<String>,
    pub budget_members: Vec<BudgetMember>,    // 树形 budget 成员
    pub completed_at_ms: Option<u64>,         // 沉降通知的 CAS 章键
}

pub enum PursuitMode {
    Passive,
    Active { max_iterations: u32 },
}

pub enum GateOutcome {
    Unchecked,   // 默认；未跑 gate
    Passed,      // gate 通过 = completion 真确认
}
```

### 客观 gate（**失败关闭**）

goal 子系统的停止判定**永远不能只靠模型自己说"我做完了"**：

- **`GateOutcome` 类型状态**：`maker`（模型自报）+ `checker`（客观校验）两者必须都成功才 `Completed`
- **`stop_hooks` 全局钩子**：模型的自报完成要走 `execute_stop_hooks_arc`，按既定目标逐个客观校验
- **失败关闭**（§goal 强化 ④）：任何 stop_hook 自身失败 → 默认 abort 而不是 continue（`goal_continuation::gate_veto` 把 `Error` 视为 veto，verifier 自身故障 = 不能宣称完成 = 不能验证通过 = 阻断 `complete`）
- **跨会话 kill switch**：in-place `reconfiguration` 自动失效 welded strategy（`clear_goal_welded_strategy` 在 `commit_gate_pass` 成功后清，**不是** `uninstall` 路径）

### `GoalStore` + TreeBudget 单轨

```rust
// src/goal/store.rs
pub struct GoalStore {
    conn: Mutex<rusqlite::Connection>,  // goals.db + settle_notified
}

impl GoalStore {
    pub fn open(path: &Path) -> Result<Self>;
    pub fn put(&self, goal: &Goal) -> Result<()>;
    pub fn get(&self, session_id: &str) -> Result<Option<Goal>>;
    pub fn try_claim_continuation(
        &self, session_id: &str, tokens_total: Option<u64>,
        now_ms: u64, gate_configured: bool,
    ) -> Result<ContinuationDecision>;
    pub fn rearm_after_busy(&self, session: &str, now_ms: u64) -> Result<RearmDecision>;
    pub fn try_claim_settle_notify(&self, goal: &Goal) -> Result<bool>;  // CAS on (id, completed_at_ms)
    pub fn commit_field_update(&self, next: &Goal) -> Result<bool>;     // 工具写入单点
    pub fn pause_if_active / block_if_active / pause_all_active / supersede_wait_timer / clear_wait_barrier;
}
```

**TreeBudget 单轨约束**（end-to-end 测试守）：goal 与 loop 共用同一棵 budget 树，**任何子目标超预算都强制停下整树**——避免一个目标消耗了 99% budget 而 sibling 目标饿死。`budget_members` 是 goal 注册的子 session 列表（delegation 加入时 `register_budget_member`），每个 member 的 `tokens_at_join` 是 join 时的 baseline——**只计 join 后的 spend**，首次加入前的 sibling 全部历史都忽略。

`try_claim_settle_notify` 是**CAS 章键**——`stamp = "{id}@{completed_at_ms}"`，每次 `Completed` 转移 stamp 变；`Clear` / `uninstall` / `reopen` 都不再 mint stamp（status 离开 Complete 时清 `completed_at_ms`）。`loop_graph::service::notify_goal_settled` 每轮 attempt 都先调此函数，**只有 stamp 真变才触发 watcher**——避免 60 s debounce 内每次都烧一次 cron LLM run。Legacy 行的 fallback（stamp 缺则用 `updated_at_ms`）保证老数据也能"先 fire 一次"。

`pursuit_max_iterations = 0` 在工具边界被拒（**born-dead cap** 防 P7：goal 设了 0 后**永远**走 Blocked，浪费 autonomous run）。

### Wait barriers

- **`waiting_until_ms` + `waiting_reason`**：hermes `wait_for_seconds` parity，model 调 `goal(update, wait_minutes=...)` 自己 park，store 比较时钟；到时 claim 路径会 arm 一个**精确 timer**（同 Fire machinery：confirm_fire CAS + busy re-arm + stale-grace 自愈）
- **`waiting_on_task`**：hermes `waiting_on_session` parity，park 直至 coordination task 进入 settled 状态；`GoalWakeService` 监听 GlobalBus 的 task-settle 事件自动清；**boot recheck** 兜底（重启后 task 可能已经 settled / vanished → fail-open clear）；未知 task_id 同 fail-open
- 两者**互斥**（设一个会清另一个）
- park 中的 goal 仍然 `Active`，execution cap / token budget **仍**强制停（**逃逸**：park 时 iteration 已满 → 立即 Block 而非 arm timer 永远等下去）

### `Goal` 课程（state file）

`lessons: Vec<String>` 由 `with_lesson_appended` 维护（ring cap `MAX_LESSONS = 5`，新保留）：自动收集客观 gate veto 的 `reason`，**也**供 LLM 通过 `goal(update, lessons=[...])` 主动追加。`GoalLessonsPromoteStage`（梦境守护进程）把这些课程从 `goal` 升级到 L1 长期笔记——是「同一个目标多次失败后的 wisdom 沉淀」。

## Strategy —— 团队/裸循环的 plan

```rust

    pub guardrails: Vec<String>,     // 1–3 具体可违反的 distractor
```

### Composite key 命名空间

| Key 命名空间 | 谁触发 | 范围 |
|--------------|--------|------|
| `goal_key(goal_id)` | goal 状态变更时（`auto-invalidate welded strategy on objective change`） | 单 goal |
| `loop_key(loop_id)` | loop tick 完成 | 单 loop |
| `session_key(session_id)` | 裸循环 plan 触发（默认 on，`[strategy] plan_naked_loop = true`） | 单会话 |
| `team_key(team_id)` | 团队聊天 planner（默认 on，`[strategy] plan_team = true`） | 整队 |

四个 key **互不冲突**——同 session 可同时持有 goal strategy + loop strategy + 团队 strategy + 裸循环 strategy 互不覆盖（`composite_keys_do_not_clobber_each_other` 测试守）。

### Planner + 原子 fire-once

`src/strategy/planner.rs` 的 `plan_strategy` 是无工具、失败软降级的一次性 LLM 调用。它接收 `PlannerContext`（工具描述、环境摘要、课程），构造 `RequestPayload`；provider/解析失败或 guardrails 为空时不返回策略。调用包含 provider I/O，不是纯函数。键由命名空间辅助函数生成字符串，不是键枚举。

`src/strategy/store.rs` 的 `StrategyStore` 通过同步 `put_if_absent` 原子地保留同键的一条策略；它保护插入，不避免并发 planner 调用费用。

### `[strategy]` 配置

```toml
[strategy]
plan_team = true               # 默认 on：团队聊天自动 plan
plan_naked_loop = true         # 默认 on：裸 loop 自动 plan
objective_change_invalidate = true   # 默认 on：goal 变化时失效 welded strategy
```

### `strategy` 工具（2 动作）

```text
strategy(action: "revise", reason, new_strategy)
strategy(action: "show")
```

`StrategyArgs` 不接收调用方提供的键。工具解析当前任务策略；`revise` 要求非空原因及含具体 guardrails 的完整替代策略，没有旁路校验动作。

## 团队 run mode pin

`src/teams/run_mode.rs` 的 `stamp` 通过请求元数据将团队运行固定为 `SessionMode::Work` 和 `BusyInputMode::Queue`。群聊分发与任务派发两个生产入口共用此辅助函数。团队会话不能通过 `session_set_mode` 切换模式。

`task_review` 审批可要求 `grounding` —— 接受元数据（acceptance metadata 通道，零迁移）携带 `[grounding]` 注释的证据（`exit_code` / `numeric` / `line_count`，**与 loop_graph anchor truth 闭集同词表**）。无 grounding 证据的 approve → bounce（`grounding_required`），reject 永不要求锚（拒绝天然保守）。

## Loop / Goal / Strategy 的协作

- **goal → strategy**：goal 状态变 → welded strategy 自动 invalidation（`objective_change_invalidate = true`），clear_goal_welded_strategy 路径单点（`builtin_tools/goal.rs` Passive / Blocked / clear / uninstall 与 `goal_continuation::post_run` 的 `Exhausted` / `AwaitingGate gate_veto no runway` / gate-pass 都走同条路径）
- **strategy → loop**：planner 输出 plan → loop 用 prompt 续接；welded strategy 不再是「另一次 LLM 计划」——直接是 prompt cache 里的 stable 段
- **team_chat → strategy**：队长 fire-once，原子 `put_if_absent`；`subagent_tree` 也走 team 维度的策略
- **goal_budget → loop_budget**：tree budget 单轨（一个子超预算 → 整树停）

## 26.7.x 补充

`goal` 工具：`create` / `update`（含 `pursuit_max_iterations` 边界校验、`wait_minutes` / `wait_for_task` 屏障、`lessons` 课程追加）/ `pause` / `resume` / `abort` / `complete`（走 objective gate）/ `list`（支持 `session` / `cross_session` 两种 scope）/ `status`。`pursuit_max_iterations = 0` 在工具边界被拒（born-dead cap P7）。

### TreeBudget 单轨（end-to-end 测试守）

goal 与 loop 共用同一棵 budget 树——任何子超预算 → 整树停。`budget_members: Vec<BudgetMember>` 存 delegated session 的 `tokens_at_join`，tree total = own session 累计 + Σ (member.now - member.tokens_at_join)。ring `MAX_BUDGET_MEMBERS = 32`，超容 `register_budget_member` 返 `Ok(false)` 警告不报错（delegation 仍可继续，只是这一支不计入 budget）。

### `try_claim_settle_notify`（CAS 章键）

settlement-notification 的 stamp 是 `(id, completed_at_ms)`—— `completed_at_ms` 只在进入 Complete 的转移瞬间盖、离开即清。完成后的 lesson / note 编辑（`bump updated_at_ms`）**不能再燃** settle stamp（避免一个 stale goal 反复 poke watcher cron）。legacy 行（无 `completed_at_ms`）fallback 到 `updated_at_ms`，保证老数据也能 fire 一次 watcher。

### 屏障互斥 + fail-open

`waiting_until_ms` 与 `waiting_on_task` 互斥（设一个清另一个）；`waiting_on_task` fail-open——未知 / vanished task 视为 settled（boot recheck 覆盖重启场景）。两者 **park 中 goal 仍 Active**——execution cap / token budget 仍 binding，**不是**无界 park。

### 团队 run mode pin

团队 run 拒绝 subagent `session_set_mode`——「队长盖戳，子成员继承」。`task_review` 接受元数据携带 `[grounding]` 注释（`exit_code` / `numeric` / `line_count`）作为 evidence，**与 loop_graph anchor truth 闭集同词表**。reject 永不要求锚（拒绝天然保守）；无 grounding 证据的 approve 在 `task_review(require_grounding=true)` 下 bounce（`grounding_required`）。

### 跨任务 / 跨会话 kill switch

- **loop**：`LoopRegistry::stop_all(reason)` 单锁下把所有 != Stopped 改 Stopped 并盖 reason（kill switch）
- **goal**：`GoalStore::pause_all_active(note)` 单锁下把活跃 goal 改 Paused（`pause_all` 区别于 `uninstall`：pause 保留 goal 实体供 owner resume）
- **strategy**：`auto_invalidate welded strategy on objective change`（goal 改时 welded strategy 自动失效，clear_goal_welded_strategy 单点）
