`memory` 模块为 Aleph 提供长期记忆能力。L0 是一张可重建的 SQLite 表（对话原文 + 附件文本，按行消重去重），L1 是磁盘上的 Markdown 笔记 + 重建的索引/链接/向量/事件表。检索在 L1 上做（混合 FTS5 + sqlite-vec + RRF 融合），梦境守护进程在后台离线维护 L1 的去重 / 链接 / 社区。

## 设计哲学

1. **Markdown 优先** — L1 是磁盘上的 `.md` 文件 + SQLite 索引。L1 索引 100% 可由磁盘重建：删了 `memory.db` 不会丢任何笔记内容，重建即可。
2. **混合检索** — `notes_fts`（`unicode61` + `trigram` 双 FTS 表）+ `notes_vec_{dim}`（sqlite-vec per-dim 虚拟表），RRF 融合 + 检索期调权（`recency_decay` / `reinforcement` / `mmr_diversity`）。
3. **LLM 主权** — 检索给候选，模型自己判断哪些是真相；没有「记忆层替模型判定相关性」的认知判断。
4. **事件溯源** — 每条笔记变更都记为不可变 `MemoryEvent`，重放可重建任意时点状态（默认 L0 全部 compress 完，事件不重放）。
5. **持久 + 离线** — `Memory` 是 26.7.x 后唯一落盘位置；L0 `is_processed` 是消费标记，不动语义。

## 架构

```text
Gateway / Agent Loop
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│ L0: raw_memories (SQLite)                                    │
│   sessions · transcripts · attachment_text                   │
│   consumed by CompoundIngestor (is_processed flag)            │
│   Skips ToolInvocation telemetry rows (insights/dream signals) │
└─────────────────────────────────────────────────────────────┘
    │  CompoundIngestor (realtime, per-source groups)
    ▼
┌─────────────────────────────────────────────────────────────┐
│ L1: notes (Markdown files + SQLite index)                    │
│   ~/.aleph/memory/note/{agent}/{category}/*.md               │
│   notes_index · notes_links · notes_fts · notes_fts_trigram  │
│   notes_vec_{768/1024/1536} · notes_vec_map                  │
│   notes_sources · notes_provenance · notes_graph_cache       │
│   notes_graph_insights · notes_graph_related                 │
└─────────────────────────────────────────────────────────────┘
    │  DreamDaemon (offline, idle-only)
    ▼
   consolidate → drift → lint → decay → digest
    │
    ▼
   NoteFactRetrieval.retrieve() → ScoredFact
```

`CompressionService` / `CompoundIngestor` 是写入 L1 的唯一途径；`NoteIndexer` 是 L1 索引、链接、FTS、向量、来源、去重、社区缓存的写者；`DreamDaemon` 后台维护 L1 的去重 / 链接 / 社区 / 蒸馏。

## 核心组件

### 存储 trait（4 个独立 trait，无 `MemoryStore`）

| Trait | 文件 | 用途 | 主要调用者 |
|-------|------|------|-------------|
| `NoteStore` | `src/memory/notes/store.rs` | 笔记索引、wikilink、FTS、向量搜索、社区缓存、来源、邻近、图 | `NoteFactRetrieval`、`NoteIndexer`、`GoalLessonsPromote` |
| `RawMemoryStore` | `src/memory/store/raw_memory.rs` | 原始记忆 CRUD + `is_processed` 标记 + `find_by_path` / `get_raws_by_ids` / `get_raw_by_source` | `CompoundIngestor`、`SessionCompactor`、dream `signal` 表 |
| `DreamStore` | `src/memory/store/mod.rs` | 梦境状态 + 每日洞察 + `best_health` checkpoint | `DreamDaemon` |
| `CompressionStore` | `src/memory/store/mod.rs` | 压缩运行审计元数据（含 `feedback_distill` 水位 / 课程管理） | `CompoundIngestor` |

四个 trait 都由 `SqliteMemoryBackend` 实现，封装为 `MemoryBackend = Arc<SqliteMemoryBackend>`。`SqliteMemoryBackend::new(db_path)` 把 `db_path` 当目录（自动建 `memory.db`）或文件；测试用 `in_memory()`。

### sqlite-vec 集成

向量按维度创建虚拟表（`db.exec_batch` 一并初始化）：

| 表 | 维度 |
|----|------|
| `notes_vec_768` | 768 |
| `notes_vec_1024` | 1024 |
| `notes_vec_1536` | 1536 |

`notes_vec_map` 表把 `(path, agent_id)` 映射到 vec0 表的 `rowid`，JOIN 时按维度路由到对应 `notes_vec_{dim}` 表。embedder 维度必须与已建表匹配，否则检索时该向量会被 `Reranker` 跳过而非报错。

### Knowledge Note（`src/memory/notes/note/`）

```rust
pub struct KnowledgeNote {
    pub title: String,
    pub category: String,
    pub tags: Vec<String>,
    pub facts: Vec<String>,
    pub links: Vec<String>,
    pub body: Option<String>,           // 完整 Markdown 正文（verbatim）
    pub relations: Vec<Relation>,        // 类型化边 (Gap A 实体图)
    pub source_notes: Vec<String>,      // 蒸馏来源
    pub supersedes: Vec<String>,        // 取代的笔记
    pub superseded_by: Vec<String>,     // 被谁取代
    pub fact_provenance: Vec<FactProvenance>,
    pub permanent: bool,                // 永久核心知识（不受 decay 侵蚀）
    pub stale: bool,                    // NoteDrift 写入的过时标记
    pub note_type: Option<String>,      // Obsidian / llm_wiki 兼容
    pub aliases: Vec<String>,          // Obsidian 别名（wikilink 别名解析）
    pub created_at: i64, pub updated_at: i64,
    pub content_hash: String,
    pub confidence: f32, pub severity: Severity,
}
```

**obsidian 兼容**：vault frontmatter 字段（`type` / `title` / `aliases`）字节兼容，Reader 解析这些字段后剩下的 `body` 作为 `to_markdown()` 的 verbatim 段。`body` 是新字段；旧笔记只有 `facts` / `links` 两个 index 视图（拼成 `Related:` 行），`to_markdown` 走老路。

**生命周期**（`NoteStore::upsert_note` / `remove_note_index`）：
- 写盘：先 `to_markdown` 写到临时文件，fsync，rename 原子替换
- 删盘：先 `remove_note_index`（清 `notes_index` / `links` / FTS / `notes_vec_map`），再 `std::fs::remove_file`
- `permanent: true` 或 `tags` 含 `permanent` / `pinned`（不区分大小写）→ 永久核心知识，跳过 `NoteDecay` 与 `NoteLint.relation_drift`

### Dream Daemon（`src/memory/dreaming/`）

`DreamDaemon` 是**唯一**被允许写 L1 的后台进程（在线 `CompoundIngestor` 除外）。调度循环（`tokio::time::interval(60s)`）每分钟检查一次：

```text
启动检查:
  enabled? → in_window (config)? → idle ≥ 15 min? → is_running unlocked? →
  should_skip_scheduled_run? (today cancelled ? no : yes run again)

运行:
  pick strategy (StrategySelector) →
  pick pipeline (Consolidate | Synthesize | Conserve) →
  build DreamContext (notes / report / provider / embedder / budget) →
  run stages → emit DreamReport → update manifest + best_health
```

**依赖就绪（fail-closed）**：调度 tick 与手动触发都先问 `DreamDaemon::dependencies`（`src/memory/dreaming/mod.rs`），缺 AI provider 或 embedder 时按 `DreamMissingDependencies`（`shared/protocol/src/dreaming.rs`）报出缺哪一项：

```text
定时 tick:  缺依赖 → 记 reason = "missing_dependencies" → 本轮跳过，不写运行状态（上次运行记录保持不变）
手动触发:  缺依赖 → 在占用运行位之前失败，错误文本 "dream cycle unavailable: missing AI provider"
             （缺 embedder 时是 "missing embedder"，两者都缺时是 "missing AI provider and embedder"）
```

失败不静默降级：没有 provider 就不会拿模板假装跑完一轮——那样只会写进一份看着像结果的空报告。状态里的 `missing_dependencies` 字段把缺失项暴露给查询方。

#### Evolution gate（`src/memory/dreaming/evolution/`）

SkillOpt 移植（arXiv 2605.23904）的「textual learning rate」：**`EditBudget`** 默认 `32 edits / 256 KiB`/cycle，跨 `NoteConsolidate`（merge）、`NoteDecay`（archive）、`distill::Supersede` 三种**破坏性**阶段共享。**Additive 路径**（新笔记 / 链接 / 强化）**不**走 budget，永远不被早一步预算透支饿死。

`evaluate_gate(candidate, current, best, ε)` 是纯标量比较：`candidate > current + ε && candidate > best + ε` → `AcceptNewBest`；`candidate > current + ε` → `Accept`；否则 `Reject`。`AcceptNewBest` 持久化到 `dream_best_health__{agent}`（`SqliteMemoryBackend` 的 `DreamStore`），重启后从 `best_health > 0` 重建 — 否则每次重启都会让历史最佳值归零，让第一轮退化周期蒙混过关。

`score_merge_candidate(keeper, absorbed)` 用 Jaccard fact 重叠度 + 唯一事实占比 + 共享前导 token 给出局部 merge-safety 分；`recall_support(hit_count) = hit / (hit + 3)`（饱和到 [0,1)）是 SkillOpt 的 held-out split 廉价替代。`gate_supersede_evidence(candidate_conf, target_hit_count)` 把 LLM 替换意见的置信度与目标笔记的「召唤支持度」做同标量比较 —— 召回支持度高的笔记（hot）必须以更高 LLM 置信度才能 supersede，避免「热门笔记被弱论据替换」。

`MutationGate` 检测三类病态：merge cycle（同对笔记连续 ≥ 3 周期合并）、synthesis oscillation（正则模式摇摆）、wasted distillation（成熟课程笔记召回率持续低于 10%）；任一命中即 `Conserve` 模式并进入 cooldown。

#### Dream pipeline

`DreamPipeline::from_strategy(strategy, dreaming_cfg, decay_policy)` 是**唯一**的阶段拼装点（曾经的 hand-maintained name list 漂移被删除，2026-07-24 修复）：

| Strategy | 阶段顺序 | 频率 |
|----------|----------|------|
| `Consolidate`（默认） | `lint → review → consolidate → feedback_distill → drift → index_refresher → co_recall_edges → graph_recompute → weave → mention_weave → decay → skill_lifecycle → goal_lessons_promote` | 夜里跑 |
| `Synthesize`（成长） | `lint → review → consolidate → synthesis → skill_distill → feedback_distill → workflow_proposal → corpus_narrative → daily_digest` | 少见 |
| `Conserve`（保守） | `lint → review → index_refresher → co_recall_edges → graph_recompute` | 病态检测命中后兜底 |

> 注意：`feedback_distill` 出现在 `Consolidate`（频繁）与 `Synthesize`（少见）两条路径 —— 但只有一条 strategy 在同一周期里跑，所以 LLM 蒸馏工作不重复执行。

`consolidate` 用 `batch_consolidate_candidates`（同类别 ≤ 20 个用 LLM 一批决策；> 20 个走 `title_heuristic_candidates`，纯文件名启发式，不调 LLM），单对 `consolidate_pair` 给 LLM 一对 ≤ 600 字符，决策 `MERGE / COEXIST / ABSORB_A / ABSORB_B`；unknown 答案默认 `COEXIST` 保守。

`CompoundIngestor::ingest_batch`（`src/memory/notes/ingest/ingestor/`）是 L0 → L1 的主写入路径：

```text
1. SkillExtension registry.pre_compress fires on_pre_compress（optional）
2. Partition by source (ProfileSynthesizer 等按 source 拆组)
3. ToolInvocation telemetry rows 直接 mark processed
4. Per-source batches:
   CompoundIngestor::ingest_batch(agent_id, raws, extra_context):
     retrieve related (≤ N)
     plan (LLM call: PROMPT)
     apply (read-modify-write: write_note / delete_note / link / move)
     record ApplyReport
5. mark_raw_as_processed (per group, on success)
```

- `defer-on-empty-plan`：本组 LLM 没产出任何写入（ApplyReport 全 0），但组内 row 距离创建时间 < 6 h → **不 mark processed**，让下一周期再试（保护知识，避免因 LLM 临时抽风丢失 L0 内容）；过 6 h 才放弃。
- `rearm_after_busy`：claim 了的延续因 AgentBusy 被 session slot 拒，按 `BUSY_RETRY_DELAY = 30s` 重新 arm pending marker，**不计新 iteration**，同 tick 30s 后重试。

#### Dream 阶段（详见 `src/memory/dreaming/stages/`）

| 阶段 | 行为 |
|------|------|
| `NoteLintStage` | 前置 matter 修正（缺 `category` / `tags` / `created` / `updated` 之一则补全、修正 frontmatter 格式） |
| `NoteReviewStage` | 检 `notes_review_queue` / `notes_review_archive`（高风险 candidate 入队，LLM 异步 review） |
| `NoteConsolidateStage` | 同类别 LLM 决策合并（详见上） |
| `NoteDriftStage` | 走 wikilink 邻居，对每对调用 LLM 决 `CONSISTENT / CONTRADICTORY / STALE`；CONTRADICTORY 写 `## Superseded` section，STALE 写 `stale: true` |
| `NoteSynthesisStage` | ≥ 5 笔记才跑；按类别聚类（`dbscan(eps=0.3, min_samples=2)` + Leiden refinement），跨类写 `synthesis/` 笔记 |
| `NoteWeaveStage` | 把孤儿笔记（无入站链接）织进链接图 —— 关键修复：decay 的 link_weight 算分包含新织的链接，orphan→archived 恶性循环被切断 |
| `MentionWeaveStage` | 物化未链接-提及软边（正文提到但无 wikilink 的标题） |
| `NoteDecayStage` | 时间半衰期（默认 90 d）按 `recall_signals` 调整；低于阈值按 LRU 归档到 `archive/{category}/`；**`permanent: true` / tag `permanent/pinned` 跳过**；< 7 d 跳过（too-new） |
| `GoalLessonsPromoteStage` | goal 课程（`Goal.lessons`）升级到 L1 长期笔记 —— ring 5 节，R2.2 |
| `IndexRefresherStage` | 重写 `notes_index` |
| `GraphRecomputeStage` | 4-signal 社区感知重算 + Leiden refinement，写 `notes_graph_cache` + `notes_graph_insights` |
| `CoRecallEdgesStage` | 物化行为共召回边（同一 query 多次召回的笔记对之间加 typed edge） |
| `SkillDistillStage` | 课程笔记 → `feedback/notes/` 技能 |
| `FeedbackDistillStage` | 用户纠正（`aleph://correction/`）→ `feedback/notes/` 笔记；按追加序游标分批消费（见下文「反馈自进化闭环」） |
| `WorkflowProposalStage` | 行为共召回挖掘 → `MetaSkill` 草稿（无 LLM，自动聚合） |
| `CorpusNarrativeStage` | LLM 写当日记忆叙事 |
| `DailyDigestStage` | LLM 写当日每日洞察 |
| `SkillLifecycleStage` | 课程笔记 Active→Stale（rule-based，30 d 默认） |

> `DailyInsight` 写盘 key 是日期 `(YYYY-MM-DD)`，同日重跑 upsert；D7 fetch_daily_insight 按「今天→昨天」回退。

## 反馈自进化闭环（2026-11-25 收敛）

「用户纠正 → 写进记忆 → 下次不再犯」是一条闭环。2026-11-25 的收敛把这条链上三处会产生**假成功**的地方修掉了：归属记错（把召回信号记在发起请求的 agent 名下，而不是笔记的真实归属方）、扩批漏读（按秒级时间戳取纠正，同一秒里积压的多条只读到一条）、替换丢文（先退役原文再发布新文，发布失败时两份都没了）。

### 归属：笔记的 owner，不是请求方的 agent

每条进入召回的笔记都带 `NoteProvenance`（`src/memory/assembler/envelope.rs`），其中 `owner` 是笔记在磁盘上的分区，`path` 是分区内的相对路径。`owner` 与「是谁发起了这次请求」无关——同一份记忆可以被多个 agent 召回。

`record_reflect_signals`（`src/memory/reflector/recall_signals.rs`）按 owner 分组：同一 owner 的曝光合并成一个 `SignalBatch`，逐 owner 独立写盘；某个 owner 写失败只记一条警告，不影响其它 owner 的行。

统计的依据是**呈现给模型的笔记**（曝光），不是模型最终引用了哪几条。引用选择是模型行为，不能当作笔记归属的证据。

### 纠正流：追加序 + 冻结的迁移栅栏

用户纠正由 `flag_user_correction` 工具写成一条纠正记录，路径是 `aleph://correction/` 前缀加纠正 id。存储层给每条纠正分配一个单调递增的**追加序**，追加时由数据库触发器分配，删除时回收。

每个语料在**首次消费**时用一次「插入或忽略」冻结**迁移栅栏**：记下激活时刻的最大追加序（激活序）和旧的时间戳水位（旧水位）。重复激活不移动栅栏。

消费者只读追加序大于已提交游标（`committed_seq`）的行。游标与待处理批次一起持久化，键是语料维度的批次键；写入用比较并交换（compare-and-set），避免两个消费者同时推进。

迁移边界是明确的：激活之前写入、且时间戳不晚于旧水位的旧行按旧水位视为已消费，**不按旧水位回放**；激活之后追加的行一律按追加序消费。旧水位为空时没有这类回放。

Markdown 后端用同样的两张表实现同一套语义（`src/memory/store/markdown/raw_memory.rs`），两个后端行为一致。

### 批次：quorum、紧急直通与严格覆盖

一轮取一页待处理纠正：

- 页大小 = `feedback_lookback` 与 512 取小（`DreamingConfig::feedback_page_limit`）。
- 页内待处理数 ≥ `feedback_distill_min_candidates`（默认 3）才开批；页内出现「高」或「严重」级别的纠正时**单条即可开批**（紧急直通）。
- 开批后截到 `feedback_distill_max_per_cycle`（默认 3），硬上限 128（`batch_limit`）。
- LLM 必须对页内**每一条**纠正给出**恰好一个**动作（`validate_exact_coverage`）：多一条、少一条、重复一条都是非法回复，整批被拒并阻塞本轮。
- 动作先过格式 / 语义 / 安全校验，动作集合是 `DistillAction` 的新建 / 强化 / 替换 / 跳过四种；再过候选路径校验：目标路径不在本批呈现给模型的候选里 → 结果记 `FilteredNonCandidate`；替换动作还要过召回证据门 → `FilteredEvidence`；预算不足 → `FilteredBudget`。完整结果枚举见 `DistillOutcome`。

「跳过」是合法的显式「不处理」，不是漏答。

整批决策在动手之前先落盘成待处理状态，每个动作单独记状态。中途失败可以**续跑**：已结算的动作不回滚，未结算的动作从持久化状态继续；只有整批结算完，`committed_seq` 才推进到本页最后一条追加序。因此一个反复失败的动作不会让整页纠正永远卡住——它要么被明确结算（`Skipped` / `Filtered*` / `Unchanged`），要么整批挂在待处理里等下一轮续跑。

### 先发布后退役

替换一条笔记时，先准备一份 `PreparedDistillEffect`（`src/memory/notes/indexer/distill_effect.rs`）：目标 markdown、目标路径、原文哈希（`expected_before`）、可选的退役与重建索引计划。准备与执行分成两步——`prepare_distill_effect_locked` 先算出计划，`verify_distill_effect_locked` 按固定顺序执行：

1. 复核磁盘上与索引里的原文哈希（不一致 = 冲突，停手）；
2. 发布归档副本；
3. 原子写入后继笔记（目标路径已存在时用「创建」语义，不覆盖别人的内容）；
4. 写索引并复核内容哈希；
5. **只有前四步都成功**，才退役原文：先删索引行，再删文件。

顺序反过来就少一条命。旧顺序（先退役原文，再发布新文）在发布失败时会同时丢掉两份内容；现在的顺序保证任一步失败时，后继笔记已经是可独立召回的，旧原文要么还在、要么已被替代，不会出现「两边都没有」的空洞。退役这一步失败也不回滚后继——后继已可召回，重试可以补完退役那一腿。

## 检索（`src/memory/note_retrieval/`）

`NoteFactRetrieval::retrieve(query, agent_id, k)` 流程：

```text
1. FTS5 search notes_fts (or notes_fts_trigram for CJK) → score_f
2. sqlite-vec KNN on notes_vec_{dim} (matching embedder dim) → score_v
3. RRF fusion: rrf(d) = 1 / (k + rank + 1), k = 60
   (FTS hits get an extra bm25_bonus_weight lift)
4. Optional cross-encoder rerank: blend_scores with rerank_weight;
   a failing reranker keeps the original order
5. Retrieval-time reweight:
   recency_decay (0.5^(age/half_life), weight 0.3, 90 d half-life) →
   reinforcement (score*(1+w*ln(1+hits)), weight 0.3) →
   re-sort by the adjusted score →
   mmr_diversity (λ = 0.7, opt-in, penalize near-duplicates)
6. surface_relations: backlink counts + structural-strong relations
7. Return ScoredFact with provenance
```

当前 session 的近期上下文走**独立路径**：assembler 从 raw store 按前缀 `aleph://session/{sid}/raw/` 取回本 session 的原始片段（上限 5 条），标成 `SlotKind::SessionRecent`；上一 session 的快照（`SessionSnapshot`，只存摘要）由 `SnapshotReader` 读入，同样进 `SessionRecent` 槽。槽位归类由 `rerank.rs` 的 LLM 重排给出，不是按某个分数线性加权。这些路径与笔记检索结果在 `HybridAssembler::assemble`（`src/memory/assembler/`）合并为 `MemoryEnvelope`：

```text
MemoryEnvelope {
  schema_version: "...",
  query, agent_id, session_id,
  slots: [
    { kind: UserProfile,    items: [...] },  // 永久用户偏好
    { kind: SessionRecent,  items: [...] },  // 当前会话近期
    { kind: RelevantNotes,  items: [...] },  // 笔记检索结果
    { kind: Feedback,       items: [...] },  // FeedbackFloorLoader（always-on）
    { kind: RawFragments,   items: [...] },  // 原文片段
    { kind: Nudges,         items: [...] },  // 提示
  ],
  meta: { ... }
}
```

`FeedbackFloorLoader` 把 `aleph://correction/{id}` 中的高 / 严重纠正永久提升到 `Feedback` slot，**不**被 rerank 丢弃 —— 与「UserProfile」同级，是 LLM 不能再忽视的硬信号。`UserProfileLoader` 同理（USER.md 的六段 + ProfileSynthesizer 增量合并）。

`MemoryReflector::reflect(query, hits, agent_id)` 是 Speculation-mode 反思：LLM 一轮回答给用户。`MemoryContextProvider` 把 envelope 喂给 `thinker/layers/curated_memory.rs`，注入 SYSTEM prompt 的「Memory envelope」section。

## SkillOpt 自我演化（梦境的 Discipline）

26.7.x 梦境的课程/笔记层演化**受 SkillOpt 纪律约束** —— bounded、validation-gated edit loop 加在 LLM 提出的编辑之上。

- **Strict-improvement gate**（`evolution/gate.rs::evaluate_gate`）：`candidate > current + ε` 且 `candidate > best + ε` 才接受，`ε` 默认 `0.01`（健康评分用，防浮点噪声）
- **Best-checkpoint persistence**：每次 `AcceptNewBest` 把分数持久化到 `dream_best_health__{agent}`（`SqliteMemoryBackend` 的 `DreamStore`），**重启后从持久值重建** —— 否则每次重启都让历史最佳值归零，让第一次退化周期蒙混过关
- **Edit budget（"textual learning rate"）**（`evolution/budget.rs::EditBudget`）：默认 `32 edits / 256 KiB`/cycle，跨 `NoteConsolidate`（merge）、`NoteDecay`（archival）、`distill::Supersede` 三种**破坏性**阶段共享 —— additive（new / link / strengthen）**不**走 budget，永远不被早一步预算透支饿死
- **Recall-evidence gate**（`evolution/evidence.rs::gate_supersede_evidence`）：用 recall-support (`hits / (hits + 3)` 饱和到 [0,1)) 替代 SkillOpt 的 held-out split —— recall-support 高的笔记 supersede 时必须有更高 LLM 置信度
- **Rejected-edit buffer**（`DistillRejectRecord`）：被拒 supersede 加指纹，replay 一次后**立刻**拒（防 LLM 重提同一提议）

## 检索 Score 流水线

`NoteFactRetrieval::retrieve` 的检索期调权（`src/memory/note_retrieval/`）：

```text
融合分: RRF(d) = 1 / (k + rank + 1), k = 60
 ↓
1. rerank          — 交叉编码器重排，与融合分按 rerank_weight 混合；失败保留原序
2. recency_decay   — 0.5^(age/half_life) 调权（默认 90 d 半衰期，权重 0.3）
3. reinforcement   — score*(1+w*ln(1+hits))，命中数来自 recall_signals（权重 0.3）
   ↓ 按调整后的分数重排
4. mmr_diversity   — 惩罚近重复（默认关闭，λ = 0.7）
 ↓
ScoredFact[]（带 provenance 链）
```

`hybrid_search_notes` 走 **RRF**（Reciprocal Rank Fusion，k=60）融合 FTS 与向量结果，FTS 命中额外乘一个 `bm25_bonus_weight` 提升；融合后上述调权再作用。开关在 `[memory.retrieval_scoring]`（`RetrievalScoringConfig`）：`recency_enabled` 与 `reinforcement_enabled` 默认开，`mmr_enabled` 默认关。
