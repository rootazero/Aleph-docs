执行引擎把 Gateway 请求桥接到 Orchestrator 与代理 harness。它负责运行准入、单会话互斥、全局与单代理限制、事件发射、持久化、取消、截止时间、转向，以及按请求构建工具服务。沙箱命令执行只是引擎内部的一条工具路径，并不等同于整个执行引擎。

## 运行生命周期与准入

`RunRequest` 携带运行和会话 id、输入、超时、metadata、附件，以及可选工作区覆盖、沙箱覆盖、迭代上限和模型覆盖。引擎跟踪 `Running`、`Completed`、`Cancelled` 与 `Failed` 状态，并发射有序流事件。

并发在两个层次实施：

- `SessionRunRegistry` 只允许每个会话存在一个活跃运行。
- `ConcurrencyLimiter` 在整个运行生命周期内实施 `[execution] max_runs_global` 与 `max_runs_per_agent`；这些限制可热重载。

会话繁忙时到达的消息遵循显式 channel 策略：`steer` 在下一回合边界注入，`interrupt` 取消当前运行并通过等待通道重启，`queue` 在不打扰当前运行的情况下等待。共享的单会话等待通道是 FIFO 且有界的。

## 资源感知的工具并发

当 `[tool_service] parallel_tool_concurrency` 至少为 2 且模型一次产生多个调用时，Act 阶段会针对每个调用的具体参数向工具服务查询 `ConcurrencyClaim`。

```rust
pub enum ConcurrencyClaim {
    Shared,
    Exclusive { scope: ExclusiveScope },
}

pub enum ExclusiveScope {
    Global,
    Paths(BTreeSet<String>),
    Nodes(BTreeSet<String>),
    Sessions(BTreeSet<String>),
}
```

Claim 描述调用可能影响的资源：

- `Shared` 用于只读或无副作用调用；多个 Shared 调用可共同运行。
- `Global` 是未知或无界写操作的保守回退，与所有调用冲突。
- `Paths` 指定规范化文件系统路径。相同路径或祖先/后代路径冲突；不相交的路径树可并发。
- `Nodes` 指定远程集群节点。不同节点的调用可并发，同一节点冲突。
- `Sessions` 指定被委派的本地会话。不同兄弟会话可并发；但会话 claim 与 paths、nodes、global 写操作及 shared 读取均冲突，因为委派运行的本地资源范围未知。

空或无法解析的资源集合会降级为 `Global`，而不是猜测。

## 有序分桶

调度器不会对整批调用只做一次“全并发或全串行”决定。`partition_parallel_groups` 按模型给出的顺序遍历调用，建立成员两两不冲突的连续分组。组之间顺序执行，组内调用在配置上限内并发执行。

例如，多次读取后跟一个 `bash` 会形成一个并发读取组，再跟一个串行 global 组。同一文件的写入会拆到不同组，不同文件的写入则可保留在同一组。这既保留冲突调用的相对顺序，也不会串行化无关工作。

Claim 按用于准入的参数计算并一路携带到派发。未知工具获得 global claim；重复调用保留在串行去重路径。

## 资源声明

工具默认声明是 fail-closed：`is_concurrent_safe = false` 映射为 `Global`；显式声明为并发安全的工具映射为 `Shared`。影响范围有界的工具会覆盖 `concurrency_claim(input)`：

- `file_write` 与 `file_edit` claim 目标路径。
- `apply_patch` claim 从 patch envelope 解析出的每个文件。
- 会修改内容的 `file_ops` 操作 claim 源和目标路径；读取操作为 shared。
- `node_invoke` claim 解析后的节点。
- `session_send` claim 解析后的目标会话。
- 参数相关工具可对读取模式声明 shared，对修改模式声明 global。

MCP 工具使用其只读/幂等注解参与 shared 准入；未注解工具保持 global。资源声明只影响调度，不会授予权限或绕过审批。

## 审批与沙箱边界

所有执行仍需经过作用域工具服务。动作感知审批门将授权绑定到具体动作，执行等级控制自动审批：

| 等级 | 行为 |
|---|---|
| `ask` | 非幂等执行前询问；未知工具失败关闭 |
| `auto` | 幂等工具自动允许，修改型工具需要审批 |
| `full` | 除硬安全规则介入外自动允许工具 |

`[sandbox.command_policy]` 始终是任何等级都不能削弱的硬底线。无人值守运行对需要确认的工具失败关闭。平台沙箱、命令策略、工作区范围、超时、取消与输出限制会在调度和审批决定之后继续执行。

## 代码位置

- `src/gateway/execution_engine/` — 运行生命周期、准入、转向、取消与工具服务连线
- `src/harness/agent/act.rs` — 有序 claim 收集与分组派发
- `src/tools/concurrency.rs` — claim 类型、冲突规则、路径规范化与分桶
- `src/tools/runtime.rs` — 每工具 `concurrency_claim` 声明
- `src/tools/adapters/registry_adapter.rs` — 内置工具的参数感知 claim
- `src/tools/scoped/` — 审批与策略阻塞点
- `src/sandbox/` — 命令策略与平台沙箱
