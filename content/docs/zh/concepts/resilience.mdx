title: "多代理弹性"

---

`resilience` 模块提供多代理弹性的数据库层和核心类型。它在 SQLite 中跟踪代理任务、事件、跟踪和子代理会话，以进行恢复和可观察性。

## 设计理念

1. **持久状态** — 所有代理状态通过 SQLite 在重启后生存
2. **结构化跟踪** — 任务执行跟踪启用用于调试的影子重放
3. **会话生命周期** — 子代理会话跟踪创建、空闲和交换状态
4. **分层事件** — 骨架事件用于结构，Pulse 事件用于细节

## 核心类型

### TaskStatus

任务通过状态机进行：

```rust
pub enum TaskStatus {
    Pending,      // 等待执行
    Running,      // 当前正在执行
    Completed,    // 成功
    Failed,       // 发生错误
    Interrupted,  // 系统重启
    Idle,         // 暂停 (会话即服务)
    Swapped,      // 上下文交换到磁盘
}
```

### Lane

执行车道（资源隔离），不是顺序/并行：

```rust
pub enum Lane {
    Main,         // 用户交互、abort 命令（高优先级）
    Subagent,     // 后台工作（普通优先级）
}
```

### RiskLevel

任务恢复决策的风险等级，只有两档：

```rust
pub enum RiskLevel {
    Low,          // 只读操作；可自动恢复
    High,         // 写操作；需要用户确认
}
```

### AgentTask

具有恢复检查点的任务：

```rust
pub struct AgentTask {
    pub id: String,                           // task_id
    pub parent_session_id: String,
    pub agent_id: String,
    pub task_prompt: String,
    pub status: TaskStatus,
    pub risk_level: RiskLevel,
    pub lane: Lane,
    pub checkpoint_snapshot_path: Option<String>,  // Shadow Replay 快照路径
    pub last_tool_call_id: Option<String>,
    pub recursion_depth: u32,
    pub parent_task_id: Option<String>,
    pub created_at: i64,
    pub updated_at: i64,
    pub started_at: Option<i64>,
    pub completed_at: Option<i64>,
    pub metadata_json: Option<String>,
}
```

### TaskTrace

用于影子重放的结构化执行跟踪：

```rust
pub struct TaskTrace {
    pub id: i64,
    pub task_id: String,
    pub step_index: u32,
    pub event: AgentTraceEvent,
    pub timestamp: i64,
}
```

`TaskTrace::with_timestamp` 让固定时间的 fixture 能覆盖 `new()` 写入的 `Utc::now()`，因为 trace 列表分页使用严格小于语义的 `timestamp` 游标。

### AgentEvent

骨架 / Pulse 两层持久化：

```rust
pub struct AgentEvent {
    pub id: i64,
    pub task_id: String,
    pub seq: u64,                       // Gap-Fill 排序
    pub event_type: String,
    pub payload_json: String,
    pub is_structural: bool,            // true = 骨架，立即持久化
    pub timestamp: i64,
}
```

子代理会话管理在 `src/teams/sessions/store.rs`（`SessionStatus` / `CollaborativeSession` / `SessionTurn`），不在 `resilience` 内。

## StateDatabase

SQLite 数据库提供 CRUD 操作：

| 表 | 目的 |
|-------|---------|
| `events` | 代理事件（骨架 + Pulse 层级；`seq` 用于 Gap-Fill） |
| `tasks` | 具有状态和检查点的代理任务 |
| `traces` | 任务执行跟踪（`TaskTrace`，含 `AgentTraceEvent`） |
| `channel_offsets` | 通道消费偏移 |
| `paired_users` | 配对用户状态 |
| `group_chat` | 群组聊天状态 |
| `memory_events` | 内存支持的事件索引 |

### 模式

模式在 `migration.rs` 中具有迁移工具进行版本控制。关键索引：

- `tasks(task_id, status)` — 按状态的任务查找
- `events(event_id, created_at)` — 事件时间范围查询
- `traces(trace_id, task_id)` — 跟踪到任务映射

## 安全

- **整数溢出预防** — `usize` 到 `i64` 转换使用 `try_from` 并带有 `i64::MAX` 回退
- **锁安全** — 所有 `lock()` 调用使用 `unwrap_or_else(|e| e.into_inner())`
- **参数化查询** — 所有 SQL 使用 `params![]`，无字符串插值
- **无 static mut** — `AtomicBool` 用于标志

## 关键源文件

- `src/resilience/mod.rs` — 模块概览

## 26.7.x 补充

### Guardian Judge payload 隐藏密钥

26.7.21+：`GuardianApprovalRequester`（LLM 判官，位于 `src/approval/guardian_requester.rs`）向判官 LLM 发送的 action 描述走 `SecretMasker`（`src/exec/masker`）屏蔽密钥——摘要与每个解析出的命令段都过同一 masker，避免被遮蔽的摘要遮不住 argv 中残留的 bearer / basic-auth / 通用密码赋值。判官失败也有熔断（重复 judge 调用错误超时直接升级到人，跳过 judge 调用）。

### Heartbeat 拒绝危险工具

26.7.21+：`DefaultProbeExecutor::execute`（`src/tasks/heartbeat/probe.rs`）调用 `is_denied_on_gateway_surface(tool_name)`，探针在定时器上运行、没有 LLM 在回路，因此任何 RCE / 主机变更 / 控制平面工具或确认门控工具都会被拒绝并返回错误提示；与 `tools.invoke` RPC 使用同一道闸门。

### Provider 错误读取加边界

26.7.15+：Provider 错误响应体读取现在加边界——之前可能挂在失速的代理上。

### 影子模式系统状态总线

26.7.x 影子模式：系统状态总线（System State Bus，SSB）带 PII 过滤、稳健性与隐私层；用于系统事件自动响应的动作调度器；平台抽象层（PAL）带 macOS 特定传感器。

### Dreaming Daemon 不再烧额度

26.7.15 修复：梦境守护进程夜间梦境运行的重试风暴已加边界（`should_skip_scheduled_run` 把 `error` / 残留 `running` 当作"今日已耗"；只有 `cancelled` 才允许重试），不再耗尽 provider 额度。

### 失败关闭

26.7.21 强化：策略文件缺失或 `permissive_default` 与 `Default::default()` 不一致时拒绝授权。
