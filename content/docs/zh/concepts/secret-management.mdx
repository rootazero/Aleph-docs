title: "秘密管理"
description: "AES-256-GCM 与每条目 HKDF 派生的加密金库，附泄漏检测、占位符解析与密钥使用审批 RPC。"
---

`secrets` 模块为敏感凭据（API 密钥、令牌、密码）提供加密存储。它使用 AES-256-GCM + 每条目 HKDF-SHA256 密钥派生，由 `SharedTokenManager` 作为主密钥；支持 1Password 接入；扫描工具输出与 `{{secret:NAME}}` 占位符解析路径上的意外密钥泄漏。

## 设计理念

1. **每条目加密** —— 每个条目都有自己派生的密钥与随机 nonce / salt
2. **丢弃时清零** —— 敏感数据由 `secrecy::SecretString` 持有，drop 时清零
3. **泄漏检测** —— 出站文本与回灌文本都被检查，发现密钥立刻阻断 / Redact
4. **使用需审批** —— 通过 JSON-RPC 显式批准后才能在运行时取值

## 核心组件

### SecretVault

基于文件的加密存储：

```rust
pub struct SecretVault {
    data: VaultData,
    path: PathBuf,
}
```

**位置：** `<config_dir>/secrets.vault`（默认 `~/.aleph/secrets.vault`）。

**原子写：** `VaultIo` 用临时文件 + `fs2` 上的 `secrets.vault.lock` 文件锁，再原子 rename，保证并发与崩溃安全。

**损坏恢复：** `SecretVault::open_or_backup` 在文件存在但无法解析时，把原文件改名为 `<path>.corrupt-<unix_ts>` 再开新库 —— 避免 `open().unwrap_or_else(empty)` 在下次 `save()` 时用空库覆盖原文件。

### 加密

```rust
let key = hkdf_derive(master_key, salt, info);
let ciphertext = aes_256_gcm_encrypt(plaintext, key, nonce);
```

**主密钥：** `SharedTokenManager` 持有的 32 字节 secret（HMAC 共享令牌）作为 AES-GCM 主密钥。

### DecryptedSecret

```rust
pub struct DecryptedSecret {
    value: SecretString,
}
```

`SecretString` 来自 `secrecy` crate：

- **Zeroize on drop** —— 释放时清零内存
- **`Debug` / `Display` 重写为 `[REDACTED]`** —— 调试与日志不会泄漏明文
- **`expose(&self) -> &str`** —— 显式打开；用得越多，泄漏面越大

### 密钥名校验

`validate_secret_name(name)` 强制 `[A-Za-z0-9_.-:]` 字符集、最长 128 字符 —— 这把 `{{secret:NAME}}` 占位符、可恢复键、Hub 命名空间键全部约束到同一语法。

## 密钥 Provider

```rust
#[async_trait]
pub trait SecretProvider: Send + Sync {
    fn provider_type(&self) -> &str;
    async fn get(&self, reference: &str) -> Result<DecryptedSecret, SecretError>;
    async fn health_check(&self) -> Result<ProviderStatus, SecretError>;
    async fn list(&self) -> Result<Vec<SecretMetadata>, SecretError>;
}
```

### 本地金库

`SharedTokenManager` 把 `store_secret` / `get_secret` / `delete_secret` / `list_secret_names` 注册为本地金库 Provider，`provider_type()` 为 `"local_vault"`。

### 1Password

```rust
pub struct OnePasswordProvider { /* ... */ }
```

通过 1Password CLI（`op`）取值。`health_check` 用分类后的错误类型（需登录 / 条目不存在 / 其他），错误信息固定且不外泄凭据。

## 模板注入与占位符解析

模板可以通过占位符语法引用密钥：

```rust
pub fn render_with_secrets(
    template: &str,
    resolver: &dyn AsyncSecretResolver,
) -> Result<String>;

pub fn extract_secret_refs(text: &str) -> Result<Vec<SecretRef>, SecretError>;
```

**占位符语法：** `{{secret:NAME}}`

解析器从金库取回命名密钥并替换到模板：

1. **抽取** —— 在解析之前先 `extract_secret_refs`
2. **解析** —— 通过 `AsyncSecretResolver` 取每个 `name`
3. **记录** —— 解析出的密钥登记到 `secret_leak_detector`
4. **替换** —— 长前缀优先排序，避免 `{{secret:api_key}}` 被 `{{secret:api}}` 先吃掉

`Hub vault` 命名空间键（`ext.{kind}.{id}.{field}`）经过 `src/hub/secrets.rs::field_key` 编码，与金库解析器共用同一字符集，所以 Hub 引用直接走 `{{secret:ext.mcp.…}}` 也能 round-trip。

## 泄漏检测

`src/secrets/leak_detector.rs::LeakDetector` 扫描文本中的意外密钥：

```rust
pub struct LeakDetector { patterns: Vec<Regex> }

pub enum LeakDecision {
    Clean,
    Warn,
    Redact,
    Block { reason: String, redacted_content: String },
}
```

- `Clean` —— 未检测到密钥
- `Warn` —— 命中仅作记录
- `Redact` —— 把命中替换为占位符（用于 `Bearer` token 等）
- `Block { reason, redacted_content }` —— 命中并阻断；返回的是经过 `SecretMasker::mask` 的内容，不是原始字符串

决策由 `RuntimeSecurityGuard` 编排：出站在密钥解析 + 替换之间跑一次，进站在 LLM 回灌回宿主之前再跑一次。所有命中最终进入 `AuditEventType::LeakWarning` / `ExecBlocked` 审计流。`SecretMasker` 在显示侧（审批卡片、Guardian payload、日志）二次应用。

## 安全属性

- **锁恢复** —— `unwrap_or_else(|e| e.into_inner())` 用于所有 Mutex
- **无 stderr 泄漏** —— 错误信息使用固定安全文本，原始 stderr 通过 `tracing::debug` 记录
- **JSON 解析失败记录** —— `serde_json` 错误被调试记录，不静默吞咽
- **清零** —— `SecretString` drop 时清零
- **原子写** —— `VaultIo` 文件锁 + 临时文件 + rename

## `secrets.*` RPC

`src/gateway/handlers/secrets.rs` 提供金库 CRUD：

| RPC | 参数 | 行为 |
|---|---|---|
| `secrets.list` | — | 返回已注册密钥名（按名字排序，**永不返回值**） |
| `secrets.set` | `{ key, value }` | 写入新条目 |
| `secrets.delete` | `{ key }` | 删除条目；不存在 ⇒ `-32004` |
| `secrets.verify` | `{ key }` | 报告 `{ key, bytes, present }`（长度，非明文） |
| `secrets.providers` | — | 报告已配置 Provider 列表 `{ key, type, account? }` |

`secrets.list` 与 `secrets.verify` 都只返回名字 / 字节长度 —— 明文永不进 RPC 响应。`aleph-server secret` CLI（`LockOnly` 路径）用于本地取回明文。

## 历史：密钥使用审批

`SecretApprovalManager`（原 `gateway::handlers::secret_approvals` 模块）曾提供 `secret.approval.request` / `secret.approval.resolve` / `secret.approvals.pending`，让 Agent 在使用某密钥前先向客户端申请授权。该管理器及其 RPC 已移除：现在没有 `secret.approval.*` 表面。金库 CRUD 即 `src/gateway/handlers/secrets.rs` 的 `secrets.*` 表面（`secrets.list` / `secrets.set` / `secrets.delete` / `secrets.verify` / `secrets.providers`）；同一轮清理也移除了 `SecretProvider` 外部提供商插件点（含 1Password stub）——现在密钥只通过内置本地金库（`src/secrets/vault_resolver.rs`）解析。

## 启动期密钥迁移

`src/gateway/handlers/secret_migration.rs::migrate_all_secrets_to_vault` 在服务启动时把仍以明文写在 `config.toml` 的密钥迁入金库并清空原字段。覆盖范围：

| 源节 | 目标 vault key |
|---|---|
| `providers.{name}.api_key` | `ai:{name}` |
| `generation.{type}_providers.{name}.api_key` | `gen:{name}` |
| `memory.embedding.providers[].api_key` | `embed:{id}` |
| `[memory.rerank]` 表里的 `api_key` 键 | `rerank:{provider}` |
| `search.backends.{name}.api_key` | `search:{name}` |
| `channels.{id}.bot_token` 等 | `channel:{id}:{field}` |
| `[voice.streaming]` 表里的 `api_key` 键 | `voice_streaming:api_key` |

增量保存只触及被改动的节，迁移总数大于零才落盘。

## Guardian Judge 遮蔽密钥

`GuardianApprovalRequester` 的判定 payload 由 `src/exec/masker.rs::SecretMasker` 处理：`summary` 与命令段 `raw` 在拼接之前都过一遍 masker，bearer token / URL basic-auth / 一般密钥赋值都不会随 payload 序列化到 LLM 上下文或回灌到审计流。
