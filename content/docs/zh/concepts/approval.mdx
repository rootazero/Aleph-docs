title: "审批"
description: "针对浏览器、桌面、桌面自动化、PIM 与媒体采集等动作的能力域审批引擎。"
---

`approval` 模块提供按动作类型（浏览器、桌面、桌面自动化、PIM 写入、媒体采集）分类的能力域审批引擎。该引擎与 `src/sandbox/exec_approval/` 的动作感知执行审批门是相互独立的层 —— 后者覆盖 shell / 工具调用，由 `src/tools/scoped/` 强制执行。

## 设计理念

1. **默认拒绝** —— 没有匹配的规则与默认值时一律 `Ask`
2. **失败关闭** —— 策略文件缺失或解析失败时返回 `safe_default`（全 `Ask`），默认值不与 `safe_default` 分歧
3. **配置驱动** —— 规则从 `~/.aleph/approval-policy.json` 加载，不在源码中硬编码

---

## 架构

```
ActionRequest ──▶ ApprovalPolicy::check() ──▶ ApprovalDecision
                         │
                         │  (blocklist → allowlist → defaults → ask)
                         ▼
                  ConfigApprovalPolicy
```

## 策略实现

### ConfigApprovalPolicy

从 JSON 配置加载规则的主策略实现：

```rust
pub struct ConfigApprovalPolicy { /* ... */ }

impl ConfigApprovalPolicy {
    pub fn new(config: PolicyConfig) -> Self;
    pub fn load() -> Self;
    pub fn load_from(path: PathBuf) -> Self;
}

#[async_trait]
impl ApprovalPolicy for ConfigApprovalPolicy {
    async fn check(&self, request: &ActionRequest) -> ApprovalDecision;
    async fn record(&self, request: &ActionRequest, decision: &ApprovalDecision);
}
```

**决策流程（按顺序求值）：**

1. **阻止列表** —— 若目标匹配本 `ActionType` 的任何 `blocklist` 条目 ⇒ `Deny`
2. **允许列表** —— 若目标匹配本 `ActionType` 的任何 `allowlist` 条目 ⇒ `Allow`
3. **默认值** —— 查找本 `ActionType` 在 `defaults` 中的 `DefaultDecision`
4. **回退** —— 无任何匹配 ⇒ `Ask`

**失败关闭：** 当 `~/.aleph/approval-policy.json` 缺失、不可读或解析失败时，`load_from` 返回 `safe_default`（空 allowlist / 空 blocklist / 空 defaults），所有动作一律 `Ask`。`Default::default()` 与 `safe_default` 不存在分歧。

### PolicyRule

```rust
pub struct PolicyRule {
    #[serde(rename = "type")]
    pub action_type: ActionType,
    pub pattern: String,
}
```

`PolicyConfig` 顶层结构：

```rust
pub struct PolicyConfig {
    pub defaults: HashMap<ActionType, DefaultDecision>,
    #[serde(default)] pub allowlist: Vec<PolicyRule>,
    #[serde(default)] pub blocklist: Vec<PolicyRule>,
}
```

## Glob 匹配

模式使用具有路径安全语义的 glob 语法：

```rust
pub fn matches_glob(value: &str, pattern: &str) -> bool;
```

- `*` —— 匹配除 `/` 之外的任何字符（包括换行）
- `**` —— 匹配任意路径段，包括跨 `/` 与换行
- `?` —— 匹配除 `/` 之外的任意单个字符

`?` 模式在内部以 `[^/]` 实现，因此 `**` 块规则不会因多行目标而失效；编译后的正则会在进程级缓存内复用，热路径不重复编译。

`check` 与 `record` 在写入 `tracing` 事件前都会通过 `redact_target` 把 `target` 替换为 `<redacted len=… sha=…>`，避免把剪贴板、PIM 正文、脚本体等敏感内容泄漏到日志。

## 配置文件

策略从 JSON 文件加载（路径由 `ConfigApprovalPolicy::config_path()` 解析）：

```json5
{
  "defaults": {
    "browser_navigate": "allow",
    "browser_evaluate": "ask",
    "desktop_automation": "ask",
    "pim_write": "ask"
  },
  "allowlist": [
    { "type": "browser_navigate", "pattern": "https://*.github.com/**" }
  ],
  "blocklist": [
    { "type": "browser_navigate", "pattern": "**/secrets/**" }
  ]
}
```

`DefaultDecision` 序列化使用小写（`"allow" / "deny" / "ask"`），无效值在解析阶段被拒绝。

## Guardian Judge

`src/approval/guardian_requester.rs::GuardianApprovalRequester` 是一个 LLM 风险分诊器，包裹人类审批请求器。它的判定语义：

- **风险等级 `low` 且 `allow == true`** —— 自动批准，跳过人类
- **其他一切** —— 升级到人类请求器

`GuardianApprovalRequester` 永不自主否决，也不会扩展人类原本会被问询的范围。代码解析 + provider 故障 + 30 秒超时 + 提供方断路器（连续 3 次失败后 5 分钟冷却）一律升级到人类。它消费 `src/exec/masker.rs::SecretMasker`，对 `summary` 与命令段 `raw` 做密钥遮蔽，所以密钥不会随判断 payload 一并序列化到日志或回灌到上游审计。

判决 payload 通过稳定的 `GUARDIAN_SYSTEM` 规则 + `cache: true` 的 `SystemPromptPart` 发送，支持 Anthropic 兼容 provider 跨次调用复用 prompt cache（每动作 payload 是唯一动态尾）。

接线位置：`bin/aleph-server/commands/start/mod.rs` 的 `set_requester` 站点，由 `[policies] guardian_review = true` 且存在默认 `provider` 时启用。

## 与执行审批门的关系

`src/approval/` 与执行审批 (`src/sandbox/exec_approval/`) 是两层：

- `src/approval/` —— 能力域（旧）：浏览器 / 桌面 / PIM / 自动化 / 媒体采集类型的动作判定
- `src/sandbox/exec_approval/` —— 动作感知（新）：shell 命令 / 工具调用指纹 + 拒绝账本 + Ask/Auto/Full 等级执行门

执行门在 `src/tools/scoped/` 强制为单一收口点。Ask/Auto/Full 三档由 `src/config/types/policies/exec_tier.rs` 定义，元数据驱动，未知工具在 `ask` 档失败关闭。任何执行都不能绕过 `src/tools/scoped/`。
