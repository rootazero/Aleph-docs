`discovery` 模块提供统一的目录扫描系统，用于在多个根目录中查找配置文件、技能、命令、代理与插件。同时承担**按需发现**职责 —— 模型不靠预先索引，而是通过 `mcp_list_*` 和 `tool_search` 在调用时再发现 MCP 资源/提示与延迟暴露的工具。

## 设计理念

1. **多源解析** —— 组件可以位于多个位置；后面的条目覆盖前面的条目
2. **向上遍历** —— 通过从工作目录向上搜索到 git 根目录来找到项目级配置文件
3. **Claude Code 兼容** —— 读取 `.claude/` 目录以兼容既有工作流；项目级的 `.aleph/` 与 `.claude/` 共存时，`.aleph/` 优先级更高（避免项目的本地技能被同名 `.claude/` 项压制）
4. **按需 MCP / 工具发现** —— 不再盲索引 MCP 资源/提示，也不把非核心工具塞进初始 schema；模型用 `mcp_list_*` 和 `tool_search` 即时探查

## 目录策略

### 读取路径（按优先级，后写的覆盖前面的）

| 优先级 | 路径 | 说明 |
|---|---|---|
| 0 | `~/.claude/` | Claude Code 全局（只读） |
| 10 | `~/.aleph/` | Aleph 全局 |
| 20+ | `<project>/.claude/` | 项目级 Claude Code（只读） |
| 40+ | `<project>/.aleph/` | 项目级 Aleph 原生（同冲突时压制上行的 `.claude/`） |

每个全局 / 项目级的 `~/.aleph/{skills,commands,agents,plugins}` 都会扫描；同名 ID 在 `.aleph/` 与 `.claude/` 冲突时，`.aleph/` 胜出。

### 写入路径

- 始终写入 `~/.aleph/`；`.claude/` 永不写入

## 核心组件

### `DiscoveryManager`

```rust
pub struct DiscoveryConfig {
    pub working_dir: PathBuf,
    pub scan_claude_dirs: bool,
    pub scan_project_dirs: bool,
    pub max_upward_depth: usize,    // 默认 10
}

pub struct DiscoveryManager {
    config: DiscoveryConfig,
    scanner: DirectoryScanner,
}
```

主要入口：

| 方法 | 说明 |
|---|---|
| `with_defaults()` | 用当前目录 + 默认深度构建 |
| `find_config_files(filename)` | 自下而上查找 `<filename>`（如 `aleph.jsonc`），返回 `[global, …project]`，项目级后写 |
| `discover_skill_dirs()` / `discover_command_dirs()` / `discover_agent_dirs()` | 在每个扫描根的 `<root>/<component>/` 下扫子目录 |
| `discover_plugins()` | 只扫 `~/.aleph/plugins/`（含 monorepo 一层深度） |
| `discover_plugins_with_extra(parents)` | 同时扫每个项目级 `<project>/.aleph/plugins/` |
| `aleph_home()` / `working_dir()` / `git_root()` | 取关键路径 |
| `get_scan_directories()` | 返回当前优先级排序下的全部扫描目录 |

### `DirectoryScanner`

真实文件系统扫描在 `src/discovery/scanner.rs`：

- 每个子目录必须是 *真实目录*（`symlink_metadata`），不跟随指向预期树外的符号链接
- 隐藏目录（`.git` / `.node_modules` 等）被跳过
- `agents/` 子目录必须有 `agent.md` 标记文件才算有效（避免与 Aleph 身份目录混淆）
- 插件识别多种清单格式：`aleph.plugin.toml`、`aleph.plugin.json`、`.claude-plugin/plugin.json`、`.codex-plugin/plugin.json`、`.cursor-plugin/plugin.json`、`.cursorrules`、`.mcp.json`，或 `skills/` / `commands/` / `agents/` / `hooks/` 任一目录、`.cursor/rules/` 目录

### `DiscoveredPath` / `DiscoverySource`

```rust
pub struct DiscoveredPath {
    pub path: PathBuf,
    pub source: DiscoverySource,
    pub name: String,
    pub priority: u32,
}

pub enum DiscoverySource {
    AlephGlobal,    // ~/.aleph/
    ClaudeGlobal,   // ~/.claude/
    Project,        // ./<dir>/.claude 或 .aleph（项目级）
    Plugin,         // 由已加载插件提供
}
```

`is_read_only()` 对 `ClaudeGlobal` / `Project` 返回 `true`。

## 向上遍历

```rust
let manager = DiscoveryManager::with_defaults()?;
let configs = manager.find_config_files("aleph.jsonc")?;
// 从 working_dir 向上找到 git 根（或深度上限），按 [global, …project] 返回
```

**边界情形**：`canonicalize()` 可能对 stop 目录成功而对当前目录失败（或反之），导致 stop 比较永不匹配。`find_upward` 显式跟踪 stop 是否被 canonicalize，并在两种情况下都用 raw 与 canonicalized 做比较；同时用 `max_upward_depth` 做硬上限。`find_upward` 还调用 `validate_path_component` 拒绝空串、含 `/` / `\` / `..` / `\0` 的文件名（即便 `scan_project_dirs = false` 也不会让全局分支被 path traversal 钻空）。

## 按需 MCP / 工具发现

**MCP**：`McpResourceIndexLayer`（曾经的 eager 索引层）已**回退**。模型现在通过三个 capability-gated builtin 工具发现 MCP 资源 / 提示：

| 工具 | 说明 |
|---|---|
| `mcp_list_resources` | 列出当前 MCP server 暴露的具体资源 URI |
| `mcp_list_resource_templates` | 列出 URI 模板（处理「只暴露模板、concrete count = 0」的 server） |
| `mcp_list_prompts` | 列出可调用的 prompt 名 |

每个 `mcp_list_*` 都伴随 reader（`mcp_read_resource` / `mcp_get_prompt`），且当且仅当至少有一个连接的 server 实际声明该能力时才注册到工具注册表 —— 模型永远看不到一个「调一次必失败」的工具。`mcp_tool_bridge` 是 MCP 管理器 actor 与工具注册表之间的唯一通道。

**工具 / `tool_search`**：非核心工具 schema 被延迟折叠 —— 模型只看到 `name + description`，完整 schema 通过 `get_tool_schema` 拉取。`tool_search` 是自包含的 BM25 检索 meta-tool（无新依赖），覆盖延迟层（`deferred` tier）的所有工具：模型按能力查询，得到 top 匹配 + 完整 schema，直接调用。`[tools] defer_mcp_tools` 可把 MCP 工具一并压入延迟层。MCP 限定名（`{server}__{tool}`）豁免内置折叠表。

## 插件目录识别

`~/.aleph/plugins/` 下的每个子目录被当成 plugin root（直接清单），或 monorepo（再下钻一层，扫描有清单的子目录）。读取 `path.join("skills")` 等子目录也作为 plugin 成立的充要条件 —— 与 Claude Code 的 `.claude-plugin/plugin.json` 共存。

## 插件市场（Plugin Marketplace）

- `plugin.marketplace.list` / `plugin.marketplace.add` 管理市场源
- 统一入口 `plugin.install` 按来源（市场 / zip / 路径）分类
- 信任层级：Official / Verified / Community / Unverified
- 安装前披露：command+args、密钥、网络/文件系统触达范围、固定版本 + SHA256、信任层级

## 安全性质

- **无 SQL 注入** —— 没有数据库查询（仅文件系统）
- **无锁** —— 不使用 Mutex / RwLock
- **路径遍历安全** —— `validate_path_component` 阻止空串、`/` / `\`、`.` / `..`、`\0`；`symlink_metadata` 拒绝指向预期树外的符号链接；`is_hidden()` 跳过 `.git` / `.node_modules`
- **没有 UTF-8 切片陷阱** —— 全部按 char 边界操作
- **Git root 不被符号链接劫持** —— `find_git_root` 通过 `crate::utils::paths::find_git_root` 共享实现，canonicalize 起始路径后再走 `.git` 检测，避免 `.git` 软链误把任意祖先目录判定为 repo root

## 代码位置

- `src/discovery/mod.rs` —— 模块入口 + `DiscoveryManager`
- `src/discovery/scanner.rs` —— 目录扫描、向上遍历、plugin manifest 识别
- `src/discovery/paths.rs` —— 路径常量 + `find_upward` + `validate_path_component`
- `src/discovery/types.rs` —— `DiscoveredPath` / `DiscoverySource` / `ScanDirectory`
- `src/mcp/tool_bridge.rs` —— MCP ↔ 工具注册表桥接 + 能力闸门
- `src/builtin_tools/mcp_resource.rs` —— `mcp_list_resources` / `mcp_list_resource_templates` / `mcp_read_resource`
- `src/builtin_tools/mcp_prompt.rs` —— `mcp_list_prompts` / `mcp_get_prompt`
- `src/tools/tool_search.rs` —— `tool_search` BM25 检索 + `ToolSearchTool`
- `src/tools/scoped/deferred.rs` —— 延迟工具层与 `tool_search` 提升
