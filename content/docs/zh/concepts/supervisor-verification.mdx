---

`gateway/pty` 与 `verification` 模块共同承担外部进程控制与代理循环验证职责：网关侧把交互式 CLI 工具放进伪终端（embedded terminal），验证侧给代理循环装配 Turn 级验证器链与 shell 停止钩子。所有裁决仍是 LLM 自检 + 钩子回执，代码不替代理做完成度判断（R7/R10）。

## 设计理念

1. **PTY 嵌入** — `gateway/pty/` 用 `portable-pty` 包装本地 shell / `cmd.exe`，输出经 WebSocket `pty.screen` / `pty.exit` topic 推送（不走第二个端口）。
2. **Turn 级验证** — `verification::VerifierChain` 在 Think→Act 之间跑，链上挂着 `StopHookVerifier`（shell 钩子）、`ToolLoopVerifier`（死循环看门狗）、`ExtensionStopHookVerifier`（`HookEvent::Stop` 钩子）、`ScratchpadGoalVerifier`（执行列表未完成就阻停）、`MutationEvidenceVerifier`（写入未取证柔阻一次）。
3. **只读式 shell 钩子** — `ShellStopHook` 跑外部命令，exit 0/2/3 = 通过/阻停/退出循环；exit 其它、超时、信号、shell 元字符全部走 `Error`，由调用方决定 fail-open 还是 fail-closed。

## 嵌入终端（`src/gateway/pty/`）

```text
pty/
├── mod.rs             # 模块入口 + 公共 re-export
├── session.rs         # PtySession：portable_pty master/child 包装，Send + Sync
├── manager.rs         # 进程级 PtyManager：64 个会话上限，TTL + FIFO 淘汰
└── handler (in gateway/handlers/pty.rs)
```

`PtySession::spawn(opts)` 创建 `portable_pty::native_pty_system()`，clone 出 writer / reader / killer，把 `pty.screen` 帧（渲染终端差分）推上事件总线；`PtyManager` 是 process-global 单例（`OnceLock`），并发的 `pty.spawn` 走到容量上限时淘汰最老会话。`commands`：`pty.spawn`、`pty.input`、`pty.resize`、`pty.close`、`pty.list`；流式事件 `pty.screen` / `pty.exit` 经 `events.subscribe("pty.*")` 接收。

## 验证器链（`src/verification/`）

`VerifierChain` 是 `Orchestrator::build` 阶段构造的 `Vec<Arc<dyn TurnVerifier>>` + `AtomicBool` kill-switch；Think→Act 之间按 `verifier.verify(&ctx)` 顺序调用，**首个非 `Continue` 裁决生效**：

```rust
pub struct VerifierChain {
    verifiers: Vec<Arc<dyn TurnVerifier>>,
    enabled: AtomicBool,
}
```

链上默认装的实现（顺序即裁决优先级）：

| 验证器 | 触发条件 | 裁决 | 失效语义 |
|--------|----------|------|----------|
| `StopHookVerifier` | `stop_reason.is_some()` | 跑 `ShellStopHook` 集合；exit 2→`Veto`（retry）、exit 3→`Halt`（永久退出）、其它→`Error` | harness 侧 fail-open，goal 侧 fail-closed |
| `ExtensionStopHookVerifier` | `stop_reason.is_some()` 且 `hooks.json` 配了 `HookEvent::Stop` | block→`Veto`、halt→`Halt`、action_failed→`Allow`（基础设施故障不阻停） | 连续 5 次同会话 veto 后自动让路，防止坏钩子卡死循环 |
| `ToolLoopVerifier` | `stop_reason.is_none()`（mid-turn） | 同名同参数工具连续 ≥ 5 次→`Veto`；≥ 8 次→`Halt`；同 name 但低 distinctness 且无文本→`Veto` | 纯结构判定，`(name, args_hash)` 维度 |
| `ScratchpadGoalVerifier` | `stop_reason.is_some()` 且当前会话有活跃 execution list 且有未勾选项 | `Veto`（自动注入「执行列表仍有 N 项未完成」） | 失败 fail-open（fatal 是取消） |
| `MutationEvidenceVerifier` | `stop_reason.is_some()` 且最近一次 `file_write/file_edit/apply_patch` 之后没有 `bash/code_exec/code_check` 证据 | `Veto` 但每会话只触发一次（nudge 形态，不是 gate） | warn 日志 + 软阻停一次 |

构造位置在 `bin/aleph-server/commands/start/orchestrator_init.rs::build_verifier_chain`：

```rust
let verifier_chain = VerifierChain::builder()
    .with(StopHookVerifier::new(hooks))    // 用户 [[stop_hooks]] 转 ShellStopHook
    .with(ExtensionStopHookVerifier::new()) // HookEvent::Stop（hooks.json / 插件）
    .with(ToolLoopVerifier::new())          // 死循环看门狗
    .with(ScratchpadGoalVerifier::new())    // 执行列表检查
    .with(MutationEvidenceVerifier::default()) // 写入未取证 nudge
    .build();
```

`TurnVerifyContext` 携带每轮状态：`iterations`、`tool_calls_made`、`final_text`、`recent_tool_calls: &[ToolCallSummary]`、`stop_reason: Option<&str>`、`session_id: Option<&str>`、`robustness_profile: ModelRobustnessProfile`（每模型一套防抖阈值，handoff 给具体 verifier 用）。

## shell 停止钩子

`StopHookHandler` 是 `Send + Sync` 异步 trait：

```rust
pub trait StopHookHandler: Send + Sync {
    fn name(&self) -> &str;
    async fn evaluate(
        &self,
        ctx: &StopHookContext,
        cancel: &CancellationToken,
    ) -> StopHookVerdict;
}

pub enum StopHookVerdict {
    Allow,
    Block { reason: String },
    Halt  { reason: String },   // exit 3 — claude-code preventContinuation
    Error { hook_name: String, message: String },
}
```

`ShellStopHook` 通过 stdin 投递 `StopHookContext` JSON 上下文（`final_text`、`iterations`、`tool_calls_made`、`stop_reason`），按 exit code 映射裁决：0=Allow、2=Block、3=Halt，其它 / 信号 / 超时 / 取消 / spawn 失败 = Error。

**失败关闭边界**：goal 客观 gate（`goal_continuation::gate_veto`）把 `Error` 视为 veto —— 钩子自身故障 = 无法验证完成 = 不能宣称完成。这是「verifier 跑得通就放行、跑不通就阻断」的 fail-closed 立场，与 harness 自己的 `StopHookVerifier`（fail-open）的对偶。

**shell 元字符拒绝**：`is_shell_safe(&str)` 在 `goal` 工具用 LLM 出参的 `goal_gate_command` 路径上把关 —— 通过 `ShellStopHook::shell_safe()` 标志启用，白名单 `SAFE = "abc…ABC…0123…/-._:'="`。带 `&&` / `;` / `$()` / 重定向的 `gate_command` 走 `Error` 而非 `Allow`，避免「verifier 自身语法错误被静默放行」的伪验证。

## 配置

```toml
[[stop_hooks]]
name = "lint-check"
command = "cargo clippy -- -D warnings"
timeout_secs = 60
```

`build_from_config` 读 `[stop_hooks]` 数组：每个 entry 构造一个 `ShellStopHook`，包成 `Arc<ShellStopHook> as Arc<dyn StopHookHandler>`，装入 `Vec<Arc<dyn ...>>`，再交给 `StopHookVerifier::new(hooks)`。空数组直接返回 `None`，`AgentHarnessRunner::stop_hooks` 字段保持 `None`，hook 阶段整段跳过。

## 提示级验证

Aleph 的完成度判断**永远在提示词里**，不在 Rust 代码里（`src/thinker/layers/agent_role.rs`）：

- 代理被指示在停止前发出 `VERDICT: PASS|FAIL|PARTIAL` 块做自检。
- 红线 R8（LLM 主权）+ R10（智能存在于提示词）禁止引入 `JudgeVerifier` / `ComputationalVerifier` 这类认知判定器；上面那张表里所有验证器都是**结构信号**（exit code、参数哈希、scratchpad 行数、mutate 之后有没有 bash），不是语义判定。
- 6a 阶段（`src/verification/turn_verifier.rs`）的注释永久封禁了「`Compute / Judge verifier`」形态：「`JudgeVerifier` and `ComputationalVerifier` are permanently prohibited」。

`VerifyStopHook` Rust 结构体（一个 P0 之前曾存在的 LLM-based 验证器候选）从未接入生产，**P4 阶段删除**（commit b54877d7f 起 git log 可查），删除理由与 prompt 级机制已覆盖该用例。

## 安全属性

- **生产无 unwrap** — 所有错误路径走 `map_err` + `?`，`stop_hooks.rs::is_shell_safe` 边界处不靠 panic。
- **超时与取消** — `ShellStopHook` 的 `tokio::time::timeout(per_attempt)` 配 `CancellationToken`，三层信号（`join_all` 结果、`select! { _ = cancel }`、`Stop` 帧）都会清掉子进程。
- **exit 64 KB 帧上限** — `pty.input` / `voice.stream.audio` 都用 `mpsc::error::TrySendError::Full` 静默丢帧 —— realtime 音频的拥塞策略是「丢最新帧而不是把 RPC 挂住」，不是「等消费者」。
- **白名单 shell_safe** — 不可信 `gate_command` 路径在 `ShellStopHook::shell_safe` 处把关，元字符 `; | & $ < > \` 等全部拒绝。
- **`unwrap_or_else(|e| e.into_inner())`** — 锁中毒恢复（P7 锁安全），每个 `Mutex` / `RwLock` 都用，绝不向上 propagate poison。

### Turn 级验证器

26.7.15+：`src/verification/turn_verifier.rs` 提供了 `TurnVerifier` trait + `VerifierChain`，首批出厂的 verifier 都在上面那张表里。每个 verifier 都是纯 `async fn verify(&TurnVerifyContext, &CancellationToken) -> VerifierVerdict`，不持有 mutable state，便于链上 `Arc<dyn TurnVerifier>` 共享。

只有**模型显式 stop**（`stop_reason.is_some()`）才会结束一个 Turn；中途死循环（`stop_reason.is_none()`）由 `ToolLoopVerifier` 兜底，命中后 `Veto` 让 harness 注入 feedback 消息并 Continue 一次，`halt_threshold` 达到才 `Halt` 永久退出。`max_iterations` 仍是安全上限。

### 上下文"永不破"保证

26.7.1+：早期通过 `FinalReply` 提前结束的轮次现在总是路由过 `compact_to_fit` 然后继续；外加一个确定性的 `truncate_to_fit` 底作为最后手段（hard cap fallback）。`think.rs` 的连续失败 watchdog + `ToolLoopVerifier` 是这条保证的两道闸门：先尝试 `compact_to_fit` 收缩上下文，再尝试 `truncate_to_fit` 切到尾部，再不行就让轮次正常收尾而不报错。

### 与 goal 子系统的对偶

`StopHookVerifier` 走 fail-open（hook 跑挂 = 放行，避免坏脚本卡死循环）；`goal_continuation::gate_veto` 走 fail-closed（hook 跑挂 = 不能宣称完成，避免 verifier 自身语法错误伪装成验证通过）。两边共用同一份 `ShellStopHook` 实现，区分只在使用方。`goal` 工具走 `effective_gate(deps.gate, goal.gate_command)` 拼装两边（全局 hook + per-goal 命令），每条都过 `is_shell_safe`。
