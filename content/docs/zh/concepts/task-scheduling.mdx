---

`tasks` 模块覆盖 Aleph 的时间调度：**cron** 用于周期性代理作业；**heartbeat** 用于周期性外部探测，并具备 L1→L2 升级；以及一个被两者共用的 **shared** 基础设施层（时钟抽象、投递、调度解析、持久化、reaper）。计时循环由 daemon 进程持有，cron 与 heartbeat 的 RPC 也是在该进程上落地。

## 设计理念

任务调度系统遵循三个原则：

1. **时间可测** —— 每个时间相关模块都接受 `Clock` trait，测试注入 `FakeClock`，生产代码使用 `SystemClock`（`Utc::now()`）。
2. **原子持久化** —— `CronStore` 与 `HeartbeatStore` 均为 SQLite 后端 + 内存缓存；变更在内存中应用并通过 `persist()` 落盘，使磁盘行始终与计时循环所见的实时视图一致。
3. **推送而非轮询** —— 每次成功变更在网关事件总线上发布 `CronJobChanged` / `HeartbeatTaskChanged`，面板无需自刷新。

## Cron 作业

`tasks::cron` 模块调度周期性作业。`CronService` 包覆内部 `ServiceState`，对外暴露被网关 handler 与 CLI 工具调用的异步 API。

```
┌──────────────────────────────────────────────────────────┐
│                     CronService                           │
├──────────────────────────────────────────────────────────┤
│  state: Arc<ServiceState<SystemClock>>                    │
│    ├─ store:  Arc<Mutex<CronStore>>  (SQLite + 内存缓存)  │
│    ├─ clock:  Arc<dyn Clock>                              │
│    └─ config: CronConfig                                  │
│  event_bus: Option<Arc<GatewayEventBus>>  (CronJobChanged)│
└──────────────────────────────────────────────────────────┘
            │                               ▲
            ▼                               │
   网关 handlers ◄─────handle_*─────────────┘
   （cron.list、cron.get、cron.create、cron.update、
    cron.delete、cron.status、cron.run、cron.runs、
    cron.toggle）
```

### 调度类型

`CronJob` 携带三种调度类型之一（`src/tasks/cron/config.rs`）：

```rust
pub enum ScheduleKind {
    /// 在指定时间戳触发一次。
    At { at: i64, delete_after_run: bool },
    /// 每 N 毫秒触发（可指定 anchor）。
    Every { every_ms: i64, anchor_ms: Option<i64> },
    /// 标准 6 字段 cron 表达式，可指定时区与 stagger。
    Cron { expr: String, tz: Option<String>, stagger_ms: Option<i64> },
}
```

### 对外 API

```rust
impl CronService {
    pub fn new(config: CronConfig) -> Result<Self, String>;
    pub fn with_event_bus(self, bus: Arc<GatewayEventBus>) -> Self;

    pub async fn list_jobs(&self) -> Result<Vec<CronJobView>, String>;
    pub async fn get_job(&self, id: &str) -> Result<CronJobView, String>;

    pub async fn add_job(&self, job: CronJob) -> Result<String, String>;
    pub async fn update_job(&self, id: &str, updates: CronJobUpdates) -> Result<(), String>;
    pub async fn delete_job(&self, id: &str) -> Result<(), String>;

    pub async fn enable_job(&self, id: &str) -> Result<(), String>;
    pub async fn disable_job(&self, id: &str) -> Result<(), String>;
    pub async fn toggle_job(&self, id: &str) -> Result<bool, String>;
    pub async fn run_job(&self, id: &str) -> Result<(), String>;

    pub async fn reap_history(&self) -> Result<u64, String>;
}
```

### 特性

- **三种调度类型** —— 一次性（`At`）、间隔（`Every`）、标准 6 字段 cron 表达式，支持可选时区与每作业 stagger。
- **JSON 原子持久化** + 内存缓存；每次变更通过 `persist()` 把内存工作副本写入 SQLite。
- **并发执行** —— 可配置每进程上限；作业可固定 `SessionTarget::Main`（同一会话）或 `Isolated`（默认，独立会话）。
- **作业串联** —— `on_success` / `on_failure` 触发器把作业串成 DAG；配置时即拒绝成环。
- **失败告警** —— `FailureAlertConfig`（连续失败次数后告警、冷却、目标），加上全局 `notify_on_failure_default` 策略，对未显式配置的作业默认告警到发起通道。
- **运行历史** —— 每次 run 落入 `cron_runs`，记录 `started_at`、`completed_at`、`status`（`Ok` / `Error` / `Skipped` / `Timeout`）、`ErrorReason::Transient|Permanent` 与触发来源（`Schedule` / `Chain` / `Manual` / `Catchup`）。
- **模板渲染** —— `tasks::cron::template` 在调用代理前把变量代入作业 prompt。
- **Webhook 投递** —— `tasks::cron::webhook_target` 允许作业把结果 POST 到任意 HTTP 端点。
- **Carry-over sweeper** —— `tasks::cron::carryover` 运行进程级 sweep（`OnceLock` 守护，热重载下也不会双 spawn）以恢复被中断的作业。

### 时钟抽象

cron 服务依赖 shared 的 `Clock` trait（`src/tasks/shared/clock.rs`）：

```rust
pub trait Clock: Send + Sync + 'static {
    fn now_ms(&self) -> i64;
    fn now_utc(&self) -> DateTime<Utc> { /* 默认由 now_ms 推导 */ }
}
```

`SystemClock` 是生产实现；`FakeClock`（在 `testing` 子模块中）提供确定性的时间控制。

## 心跳探测

`tasks::heartbeat` 模块运行周期性 L1 探测，并在探测触发时可选地升级到 L2 代理分析。其模式与 `CronService` 对称 —— `HeartbeatService` facade、`HeartbeatServiceState`、`HeartbeatStore` —— 让两个子系统保持一致。

```
┌──────────────────────────────────────────────────────────────┐
│                     HeartbeatService                          │
├──────────────────────────────────────────────────────────────┤
│  state: Arc<HeartbeatServiceState>                            │
│    ├─ store: Arc<Mutex<HeartbeatStore>>                       │
│    └─ config: HeartbeatConfig（tick 间隔、最大并发、          │
│                                 per-job 超时、去重）           │
│  wake_queue: Arc<WakeQueue>                                   │
│  event_bus: Option<Arc<GatewayEventBus>>（HeartbeatTaskChanged）│
└──────────────────────────────────────────────────────────────┘
```

### 特性

- **探测执行** —— `tasks::heartbeat::executor` 运行每个任务配置的 `ProbeConfig`（tool + params + trigger condition）。
- **唤醒队列** —— `tasks::heartbeat::wake` 让外部调用者把 wake 信号塞进计时循环，且不阻塞 per-task mutex。
- **去重** —— `tasks::heartbeat::dedup` 在 `DedupConfig { window_ms, similarity_threshold, max_history }` 窗口内折叠重复结果，避免噪声探测淹没模型。
- **运行历史** —— `tasks::heartbeat::history` 持久化历史 run，可通过 `heartbeat.runs` 查询。
- **可配置间隔与超时** —— `HeartbeatConfig::tick_interval_secs`、`max_concurrent`、`job_timeout_secs`。

### 对外 API

```rust
impl HeartbeatService {

}
```

## 任务基础设施

`tasks::shared` 模块为 cron 与 heartbeat 提供共用基础设施：

- `clock` —— `Clock` trait、`SystemClock`、`FakeClock`（位于 `testing`）。
- `schedule` —— 纯函数式的 schedule-kind 解析与下次运行时间计算。
- `delivery` —— `DeliveryEngine` / `DeliveryPayload` / `DeliveryTarget`（cron 结果如何落到某个频道或 webhook）。
- `store` —— 可复用的 SQLite 辅助（打开、schema 迁移、内存缓存）。
- `targets` —— 投递目标类型定义（频道、webhook）。
- `active_hours` —— 作业的静默时段与活跃时段门控。
- `retry_hint` —— 重试策略原语（transient 与 permanent 分类）。
- `reaper` —— 周期运行 `CronHistoryReaper` / `HeartbeatHistoryReaper`（`tasks::shared::reaper`），让 `cron_runs` / 心跳历史行不会无界增长。

---

## 安全属性

- **无下溢** —— 时间运算使用 `saturating_sub` / `saturating_mul`（`Clock::now_utc` 用 `from_timestamp_millis`，保证 epoch 之前的值能正确往返）。
- **无 SQL 注入** —— 所有查询使用参数化 `params![]`。
- **UTF-8 安全** —— 字符串截断使用 `char_indices()` 感知的辅助函数。
- **无 `static mut`** —— 所有共享状态走 `crate::sync_primitives`。
