Aleph 的内置工具有四个登记面。`src/executor/builtin_registry/definitions.rs:85` 的
`BUILTIN_TOOL_DEFINITIONS` 是面向代理的权威名称与描述清单；`src/builtin_tools/` 与
`src/executor/builtin_registry/` 提供实际实现与分发。某项工具是否出现在当前请求中，
还会受到依赖、健康状态、代理/频道权限和会话模式影响，因此“注册表中存在”不等于
“每个会话都可见”。

## 权威工具注册表

| 登记面 | 位置 | 覆盖的名字 |
| --- | --- | --- |
| 目录 | `BUILTIN_TOOL_DEFINITIONS`（`definitions.rs:85`） | 无条件登记的 178 项，是模型看到的清单。 |
| 仅注册表 | `REGISTRY_ONLY_DESCRIPTIONS`（`definitions.rs:1308`） | 依赖或健康状态满足时才注册（如 `scratchpad`、`permission`、`media`、`system`、`voice_mode_set`、`local_voice`、`audio_generate`、`video_generate`、`speech_generate`）。 |
| 目录外 | `TOOLS_OUTSIDE_DEFINITIONS`（`src/executor/mod.rs:30`） | `subagent`、`tool_search` —— 不在目录里，模型仍可调用。 |
| 按请求注入 | `src/tools/scoped/mod.rs` | 例如 `get_tool_schema`，逐请求追加到工具列表。 |

另有六个 MCP 桥接工具（`mcp_read_resource`、`mcp_list_resources`、
`mcp_list_resource_templates`、`mcp_get_prompt`、`mcp_list_prompts`、`mcp_login`）
由 `src/mcp/tool_bridge.rs` 按能力门注册：既不在目录里，也不走 `reg(` 点。

## 工具实现与执行

工具实现使用 `AlephTool` 的类型化调用和 JSON Schema，运行时由 `BuiltinToolRegistry` 的集中分发接收规范名称。Gateway 每个请求构造一个带权限、健康、确认、会话上下文和工具重写器的 `ScopedToolService`；它实现 `ToolService` 的 `execute`、`list`、`dispatchable_list`、`describe` 和 `metadata_schema`。

工具名称修复只用于解析已有名称或给出建议，不会把不存在的工具变成注册工具。未知工具在 `ask` 执行层级下失败关闭。

## 工具发现

当前发现路径是：

- 启用渐进披露时，非核心工具保留名称和描述，但输入 Schema 被折叠；
- `get_tool_schema(tool_name)` 按请求快照返回完整 Schema；
- 延迟工具由 `tool_search(query, limit)` 以 BM25 按名称和描述检索，并返回可调用工具的完整参数；命中的工具会被提升回下一轮工具数组；
- `[tools] defer_mcp_tools` 可将 MCP 工具放入延迟层；会话模式也使用同一延迟层；
- 核心集合为空或包含 `*` 时关闭渐进披露，保持旧的工具面。

这套机制优化的是工具展示和上下文成本，不替代权限检查；被隐藏的工具仍可能在执行层被拒绝。

## 进度通知

内置工具层不再有进度回调 trait。`src/builtin_tools/mod.rs:308` 只保留三个
legacy no-op 函数——`notify_tool_start`、`notify_tool_result`、
`notify_tool_streaming_chunk`——它们没有消费者，只为让约 85 处历史调用点保持编译。

工具进度现在走网关事件总线：`notify_tool_result` → `GatewayEventEmitter`，接线在
`src/executor/builtin_registry/registry/tool_registry_impl.rs`。
