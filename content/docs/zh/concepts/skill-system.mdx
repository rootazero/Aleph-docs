title: "技能系统"
description: "统一的 SkillSystem：负责 SKILL.md 发现、解析、资格判定、提示注入、安装与生命周期。"
---

`skill` 模块是承载技能加载与统一运行时（一个进程内共享实例）的限界上下文，被代理循环、插件宿主、网关与面板共用，负责解析、来源优先级、eligibility、快照、提示词渲染、依赖安装、状态、使用统计与热重载。

面向用户的 Skill 类型由统一的扩展门面按 Kind 路由到该子系统，并不是与扩展商店并列的第二套实现。

## 运行时架构

```text
SkillSystem
├── SkillRegistry
├── SkillSnapshot
├── EligibilityService
├── SkillsConfig
├── InstallExecutor
├── 状态与使用统计
└── 广播事件
```

`SkillSystem` 通过 `Arc` 廉价克隆；进程级共享实例同时被 `ExtensionManager` 与内置技能工具使用。

```rust
pub struct SkillSystem {
    registry: SkillRegistry,
    snapshot: SkillSnapshot,
    eligibility: EligibilityService,
    config: SkillsConfig,
}
```

初始化时扫描已配置根目录，原子地替换注册表并重建快照，过程中发出生命周期事件。单文件重载会替换单条 manifest 并重建快照，无需重启守护进程。

## 技能清单模型

当前领域聚合包含：

```text
SkillManifest
├── id, name, description
├── content
├── scope 与 bound_tool
├── eligibility
├── install 规格
├── invocation 策略
├── source
├── primary_env, homepage, emoji
├── when_to_use
└── automation
```

Markdown 解析器要求 `name` 与 `description`，接受 `when-to-use` 并映射到 `when_to_use`；不再从 `triggers` 列表构建确定性触发器。`SKILL.md` 正文是模型指令，frontmatter 提供路由与运行时元数据。

`SkillSource` 取值 `Bundled` / `Global` / `Plugin` / `Workspace`，优先级 `Bundled < Global < Plugin < Workspace`。注册表为每个重复 ID 保留最高优先级 manifest；插件技能被发布到共享扫描根，从而进入同一快照与 `skill_read` 解析。

## 资格判定

`EligibilityService` 按以下顺序对单条 manifest 评估：

1. 显式 `enabled: false` 直接返回 `Disabled`。
2. `always: true` 直接判为 eligible。
3. 检查当前操作系统。
4. `required-bins` 列表中所有条目必须能在 `PATH` 中解析。
5. `any-bins` 非空时至少有一条能解析。
6. `required-env` 中每个变量都必须存在。
7. `required-config` 中每个点分路径都必须在配置快照中存在。

`skill_status` 与 `full_status` 返回的 `eligible` / `disabled`、缺失的二进制 / 环境变量 / 配置键等结果按技能 ID 排序，便于客户端确定性消费。

## 提示词与延迟加载

只有模型可见的技能会进入提示快照。`scope: disabled` 与 `disable-model-invocation: true` 都会把技能排除在模型目录之外。`scope: system` 为默认；`tool` 与可用工具绑定；`standalone` 仅供显式调用。

提示构建器输出 `<available_skills>` 条目，包含 name、description、可选 `<when>` 提示与正文版本摘要：

```xml
<available_skills>
  <skill>
    <name>Code Review</name>
    <description>对变更后的源代码进行审查</description>
    <when>当代码被编写或修改后</when>
    <version>sha256:a1b2c3d4</version>
  </skill>
</available_skills>
```

模型被要求在使用技能正文前先调用 `skill_read`，发现阶段调用 `skill_list`，并在请求匹配 `<when>` 时主动调用。支撑文件请传入技能相对路径的 `file_name` 由 `skill_read` 读取。

提示预算限制条目数量与完整 description 的字符消耗。超预算时把 description 降级为名称 + 可选触发提示 + 版本，使整库不会被吞没；超出数量上限时附加 `note`，引导模型调用 `skill_list`。

## 安装与配置

技能级启用与 scope 覆盖、依赖偏好以及提示词预算持久化在：

```text
~/.aleph/data/skills.toml
```

`InstallExecutor` 挑选当前 OS 的安装规格，支持 `brew` / `apt` / `scoop` / `winget` / `npm` / `uv` / `go` 与 URL 下载。包名与路径参数走严格白名单；下载要求 HTTP/HTTPS URL 且无路径穿越。

内置管理工具：

| 工具 | 职责 |
|---|---|
| `skill_list` | 列出模型可见的技能元数据与文件 |
| `skill_read` | 读取指令或目录内支撑文件 |
| `skill_status` | 返回 eligibility 与安装状态 |
| `skill_install` | 安装声明的依赖 |
| `skill_manage` | 创建、编辑、配置与删除技能 |

`skills.install` 是兼容网关，处理 Git、ZIP 与本地 Markdown 包，并在注册前扫描。统一 `extensions.install` 解析 Hub 的 Skill 条目后通过同一后端路由。

## 生命周期

```text
扫描 → 解析 → 注册 → 资格判定 → 快照 → 提示词
                  └──────────────→ 状态
```

目录重扫描原子地替换注册表；`skill_manage` 变更后立即重建快照。使用统计与生命周期数据保存在技能目录的 `.usage.json` 旁路文件，由 `full_status` 报告；捆绑技能不能通过 SkillSystem 删除。

当指令正文变更，内容摘要变化；模型在继续使用缓存正文前必须重新 `skill_read`。这让模型可见的元数据保持廉价，同时保证指令新鲜。

## 安全边界

技能扫描与依赖安装是相互独立的控制。安装期扫描器会遍历目录内每个可读文件，受单文件大小限制，结果按 safe / caution / dangerous 分类。信任等级决定是否放行。运行时工具执行仍需经 Aleph 的 scoped tool、审批与沙箱控制。
