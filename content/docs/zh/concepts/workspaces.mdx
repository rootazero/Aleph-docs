title: "工作区"
description: "Aleph 如何在 ~/.aleph/ 树中组织配置、会话、记忆、技能、插件、Hub、项目和日志。"
---

Aleph 把所有运行时状态收敛到一个**统一的家目录树** —— `~/.aleph/`（可通过 `ALEPH_HOME` 环境变量覆盖）。本目录描述当前的实际布局；旧的 `~/.config/aleph/`、`facts.lance/`、`evolution.db`、`providers.toml` 等历史约定已全部退役。

> **单源约定**：所有平台统一使用 `~/.aleph/`，无 `XDG_CONFIG_HOME` 之分；测试 / 多副本场景通过 `ALEPH_HOME=/path/to/root` 完整隔离。

## 目录结构

```
~/.aleph/
├── config.toml                  # 主配置（参见 [配置](/docs/zh/getting-started/configuration)）
├── aleph.toml.bak               # 迁移前的自动备份
├── cache/                       # 通用缓存（重启可丢）
├── memory/
│   ├── note/                    # 知识笔记（Markdown + SQLite 索引 + sqlite-vec 向量）
│   ├── raw/                     # 原始来源（用作笔记蒸馏的输入）
│   └── *.db                     # 事实表、图缓存、insights 等 SQLite 数据库
├── skills/                      # 用户级技能（Markdown skill）
├── agents/<id>/skills/          # 当前活跃 agent 的私有技能（优先级最高）
├── plugins/<plugin>/skills/     # 插件捆绑技能
├── runtimes/                    # 能力账本 — 探测、引导、持久化外部工具状态
├── hub_catalog.db                # Aleph Hub 缓存（hub::primer 冷启动填充）
├── projects.json                # 项目存储（参见 projects.* RPC）
├── projects.lock                # 项目存储文件锁
├── data/                        # 运行时数据库（见下）
│   ├── aleph.lock               # 实例锁（`aleph-server start` 入口处 flock；OS 自动释放）
│   ├── sessions.db              # 会话事件日志（SessionEvent SSOT）
│   ├── security.db              # 设备信任、证书指纹、TOFU 信任存储 + 加密 secret vault
│   ├── pairing.db               # 配对与邀请码
│   ├── devices.db               # 设备账本
│   ├── heartbeat.db             # heartbeat 任务 / 探针历史
│   └── scratchpad_bindings.json # session → active-plan 指针（daemon 重启后保持）
├── logs/                        # 网关与运行时日志（tracing，按天轮转 + 7 天保留）
│   ├── aleph-server.log.YYYY-MM-DD
│   └── ...
└── soul.md                      # 全局身份/个性定义（被 .soul/identity.md 等覆盖）
```

> **历史迁移**：`facts.lance/`（LanceDB 旧向量存储）→ 已统一到 `memory/*.db` + `sqlite-vec`；`evolution.db`（技能演化旧库）→ 已统一到 `dream_*` 表；`providers.toml`（旧凭据文件）→ 已并入 `config.toml` 内 `[providers.*]`；`~/.config/aleph/` → 已统一到 `~/.aleph/`。

## 配置文件

### `config.toml`

主配置文件控制所有运行时行为（参见 [配置](/docs/zh/getting-started/configuration) 的完整字段表）。所有字段都支持环境变量插值（`${VAR_NAME}`）。

```toml
# Agent 默认配置（agents_def.rs）
[agents.defaults]
model = "anthropic/claude-sonnet-4"
thinking = "medium"
session_mode = "work"   # chat / work / code（第三轴）
exec_tier = "ask"        # ask / auto / full

# Gateway 配置（含 TLS）
[gateway]
port = 18790
bind = "127.0.0.1"
require_auth = false

[gateway.tls]
# cert 与 key 留空时，核心自动生成自签名证书；
# SAN 自动覆盖主机非环回接口 IP；远程客户端必须 wss
cert = "/path/to/cert.pem"

# 频道配置
[channels.telegram]
enabled = false
token = "${TELEGRAM_BOT_TOKEN}"
allow_from = ["+1234567890"]

[channels.discord]
enabled = false
token = "${DISCORD_BOT_TOKEN}"

# 行为 / 输入模式
[behavior]
input_mode = "halo"   # cut / copy / halo 三选一
hotkey = "double_shift"

# 语音
[voice]
provider = "deepgram"
vocabulary_bias = ["Aleph", "sqlite-vec", ...]
[voice.streaming]
pcm_input = false    # WhisperLiveKit 必须设 true 才能跳过 FFmpeg 解码

# Heartbeat
[heartbeat]
enabled = true
# 详细配置见 [Heartbeat 自动化](/docs/zh/automation/heartbeat)
```

### 凭据存储

API 密钥与秘密由 **OS 钥匙串** 保管，AES-256-GCM 加密存放在 `data/security.db`，从**不以明文**写入 `config.toml`。MCP 服务器通过 Aleph 的 WASM 凭据注入边界在启动时**逐服务器注入**，避免子进程原始继承。

## 会话存储（`data/sessions.db`）

会话事件日志为**单源真值**（`session_events` 表）；`MessageProjector` 把事件物化到 `messages` 表，启动时 `ProjectionReconciler` 回填转写。事件 Schema 由 `src/session/events.rs` 定义；projector 与 reconciler 分别在 `src/gateway/session_projector.rs` 与 `src/gateway/projection_reconciler.rs`。

**会话密钥**使用分层格式，对代理、通道和范围进行编码：

| 密钥格式 | 示例 | 说明 |
|------------|---------|-------------|
| `agent:main:main` | 共享会话 | 跨通道默认会话 |
| `agent:main:telegram:dm:user123` | 每用户 DM | 隔离的 Telegram 对话 |
| `agent:main:discord:group:guild-id` | 群组聊天 | Discord 公会对话 |
| `agent:main:cron:daily-summary` | Cron 任务 | 计划任务会话 |
| `agent:main:loop:<loop_id>` | 循环会话 | GoalLoop 上下文 |
| `agent:main:goal:<goal_id>` | 目标会话 | GoalStore 上下文 |
| `agent:main:heartbeat:<task_id>` | Heartbeat | 周期守护会话 |

## 内存存储（`memory/`）

内存子系统只用一个存储后端：**SQLite + sqlite-vec**，加上笔记层（`memory/note/` 的 Markdown 文件 + SQLite 索引）。

- **事实表**：`memory/facts*.db` —— `notes`、`notes_sources`、`notes_provenance`、`notes_graph_cache`、`notes_graph_insights`（4-signal community-aware recall + Louvain refinement）
- **原始来源**：`memory/raw/` —— 蒸馏输入；笔记层据此回填 `[[wikilink]]` 边
- **图缓存 / insights**：每次 `GraphRecomputeStage` 后落地到 `notes_graph_cache` / `notes_graph_insights`（spawn_blocking，零 LLM）

LanceDB 与旧的 graph.db 单文件数据库已被整合。

## 技能 / 插件目录

### 技能

按优先级顺序扫描的根（详见 [发现](/docs/zh/concepts/discovery)）：

1. `~/.aleph/agents/<id>/skills/` —— **当前活跃 agent 的私有技能**（最高优先级）
2. `~/.aleph/skills/` —— 用户级
3. `<project>/.aleph/skills/` —— 项目级（原生）
4. `<project>/.claude/skills/` —— 项目级 Claude Code 兼容（同冲突时被项目级 `.aleph/` 压制）
5. `~/.aleph/plugins/<plugin>/skills/` —— 插件捆绑技能（由 `extension_manager` 权威拥有）

每个技能位于自己的子目录中（OpenCode 兼容发现），并以 `SKILL.md` 标记文件为有效凭证：

```
~/.aleph/skills/
├── code-review/
│   └── SKILL.md
└── git-commit/
    └── SKILL.md
```

### 插件

```
~/.aleph/plugins/
├── my-plugin/
│   ├── aleph.plugin.toml    # V2 推荐清单
│   ├── package.json         # (Node.js 插件)
│   ├── dist/
│   │   └── index.js
│   └── src/
│       └── index.ts
└── wasm-tool/
    ├── aleph.plugin.toml
    └── plugin.wasm
```

文件监视器（`notify-debouncer-full`）在文件更改后 ~600 ms 内触发扩展系统的热重载 —— `reload` 在 load guard 下串行化（修复了并发重载竞态）。

## Hub 缓存（`hub/`）

`src/hub/primer.rs` 在启动时把官方 MCP 预设、官方插件与官方技能集合统一投影进 `hub_catalog.db`。每次启动合并条目并标 `via {source}` 印记；后台由 `hub_catalog_sync` 从 Aleph Hub 拉取增量更新。详见 [扩展商店](/docs/zh/concepts/extensions-store)。

## 项目存储

`projects.json` + `projects.lock` 存储项目元数据；RPC 入口 `projects.list` / `projects.add` / `projects.create_blank` / `projects.remove` / `projects.touch` / `projects.get`。文件锁防止并发损坏。

## 工作区（Workspace）存储

工作区是面向用户的「多工作区并存」抽象 —— 切换工作区即可切换默认通道 / 风格 / agent 绑定。RPC 入口：

- `workspace.create` / `workspace.list` / `workspace.get` / `workspace.update` / `workspace.archive`
- `channels.set_agent` —— 绑定通道到指定 agent（**要求 agent 存在**；先前接受不存在 agent 的回归已修复）
- `agents.bindings` —— 查询当前 agent ↔ channel 绑定

后端为 SQLite `AgentEnvStore`（非 `~/.aleph/projects.json`）；定义在 `src/gateway/agent_env/`。

## 身份 / Soul 文件

Aleph 使用分层身份系统，可以在多个级别指定 soul 定义：

```
优先级 (从高到低):
┌─────────────┐
│  会话       │  ← 通过 RPC 运行时覆盖
├─────────────┤
│  项目       │  ← 项目目录中的 .soul/identity.md
├─────────────┤
│  全局       │  ← ~/.aleph/soul.md
├─────────────┤
│  默认       │  ← 内置空清单
└─────────────┘
```

全局 `soul.md` 定义默认个性；委托角色链与签名者所有权由 `data/security.db` 中的设备/密钥记录支撑。

## 日志

运行时日志存放在 `logs/`：

- `aleph-server.log.YYYY-MM-DD` —— 按天轮转 + 7 天保留的 tracing 结构化日志

Aleph 使用 `tracing` crate + 结构化日志；可通过 `RUST_LOG` 环境变量配置日志级别。`ALEPH-BOOT` marker 标记每次启动的边界（裸 stdout/stderr 流上），便于运维定位每次启动的窗口（详见 [守护进程](/docs/zh/concepts/daemon)）。

## 热重载

配置更改通过文件监视自动检测（去抖动 500 ms）：

```
~/.aleph/config.toml 已修改
    │
    ▼
去抖动 (500ms) → 解析新配置 → schema 验证
    │
    ▼
应用更改：
  • 重启受影响的接口
  • 更新路由规则（routing_rules.*）
  • 热更 [execution] max_runs_global / max_runs_per_agent
  • 发出 config.changed 事件
```

**新增可热重载字段**：项目存储、Hub 同步 TTL、`[voice] vocabulary` 偏置词列表（限部分段）。

## 多代理 / 集群工作区

集群联邦（参见 [集群](/docs/zh/architecture/cluster)）中，**中心核**拥有完整 `~/.aleph/`；**节点**只持有受控子集（按 `[cluster.node].sync_paths`）。节点键按 **Unicode 归一化**，CJK 节点名正确工作（之前按字节切片会断裂）。
