本页介绍 Aleph 统一 Extension 模型中的 **Plugin** Kind。Plugin 可以打包技能、代理、命令、钩子、MCP 服务器配置、WASM 能力与后台服务。Skill 与 Mcp 是同级 Kind；[扩展商店](/docs/zh/concepts/extensions-store) 在同一个目录中呈现三者。

插件宿主位于 `src/extension/`，不是 Hub 目录，也不是模型提供商注册表。

## 插件结构

Aleph 推荐 Claude Code 兼容清单 `.claude-plugin/plugin.toml`：

```text
my-plugin/
├── .claude-plugin/
│   └── plugin.toml
├── skills/
│   └── code-review/SKILL.md
├── agents/
│   └── reviewer.md
├── commands/
│   └── check.md
├── hooks/
│   └── hooks.json
└── .mcp.json
```

组件路径可在清单里覆盖；不写时使用上面的默认路径。没有清单的插件只要包含被识别的组件目录或文件，也可以被自动发现。

## 清单格式

`.claude-plugin/plugin.toml` 使用 Claude Code 风格的扁平字段，并提供可选的 `[aleph]` 扩展段：

```toml
name = "diagnostics"
version = "1.0.0"
description = "系统诊断"
repository = "https://example.com/diagnostics"
skills = "./skills"
agents = "./agents"
commands = "./commands"
hooks = "./hooks/hooks.json"
mcp-servers = "./.mcp.json"

[author]
name = "Example"

[aleph]
runtime = "mcp"
entry = ".mcp.json"

[aleph.permissions]
network = true
filesystem = "read"
env = true
shell = false
background = false

[[aleph.services]]
name = "metrics"
start_handler = "start_metrics"
stop_handler = "stop_metrics"
auto_start = true
```

清单解析顺序：

1. `.claude-plugin/plugin.toml`
2. `.claude-plugin/plugin.json`
3. `aleph.plugin.toml`，仅作兼容格式保留，会打印警告
4. 兼容适配器与对已识别组件布局的自动发现

当前清单不再包含模型 provider 配置段。模型提供商仍由 Aleph 核心 provider 配置管理，不会通过插件能力声明。

## Runtime 类型

| Runtime | 加载方式 | 用途 |
|---|---|---|
| `static` | 纯 Markdown 组件，无需可执行 runtime | 技能、代理、命令 |
| `mcp` | `.mcp.json` 通过 `McpManager` 加载 | Node.js、Python 等使用 MCP 的外部进程 |
| `wasm` | Extism WASM runtime | 沙箱计算与声明的 WASM 能力 |

当前宿主不再保留独立的直连 Node.js 插件 runtime。Node.js 插件一般就是由 MCP 子系统启动的 MCP server。

## ExtensionManager 流程

```text
作用域发现
    ↓
清单适配与校验
    ↓
来源冲突解决
    ↓
PluginRegistry 注册
    ├── tools
    ├── hooks
    ├── services
    ├── skills 与 commands
    └── agents
    ↓
PluginLoader
    ├── Static
    ├── MCP
    └── WASM
```

管理器同时共享进程级 `SkillSystem`，发布插件技能根，刷新代理目录，并把已启用的 MCP 插件同步到 MCP 管理器。

## 发现与优先级

作用域目录在存在 agent 与 project 时按以下顺序解析：

1. agent-level：`~/.aleph/agents/<id>/plugins/`
2. local：`<project>/.aleph/plugins.local/`
3. project：`<project>/.aleph/plugins/`
4. user：`~/.aleph/plugins/installed/`

插件源在出现重复 ID 时按 `Config > Workspace > Global > Bundled` 排序。最高优先级候选项被激活，较低优先级条目保留为 `overridden`。`.disabled` 标记会让目录被跳过。

同一规范作用域下，每个插件 ID 只选中一份安装。项目目录和本机项目目录共用项目作用域，同 ID 的插件包可以分别属于项目与全局。在已授权的项目内，裸 ID 选择整个项目插件包，即使该包已停用或缺少请求的贡献。没有已授权的项目上下文时，普通调用只看到全局包。`plugins.list` 返回 `scope_kind` 和精确的 `selector`（全局 `g:<id>` 或项目 `p:<digest>`），Gateway 按调用方权限解析该实例。WASM 与 MCP 的注册和退役都遵循精确的所有者身份（`src/extension/visibility.rs`、`src/extension/plugin_target.rs`、`src/extension/lifecycle.rs`）。

## 命名与注册

插件组件使用 `plugin:component` 限定名，内置组件保持短名。注册表同时保留短名兼容键；短名冲突不会移除任一限定组件，且先注册者保留短名 key。

清单适配器将插件组件转换为 `CapabilityDeclaration`（`src/extension/capability.rs`）。注册器按类别进行校验和分发。

| 层级 | 声明 |
|---|---|
| Core | `Tool`、`Hook`、`Skill` |
| Important | `Agent` |
| Pluggable | `Service`、`McpServer`、`Context` |

`commands/` 下的 Markdown 按命令型技能注册。`Context` 声明携带上下文描述符和 WASM 传输出口，调用时另行检查授权。运行时的能力描述符、所有权与租约见[能力模型](../capabilities/capability-model)。

## MCP 插件接线

MCP 类型插件由加载器读取 `.mcp.json`，替换 `${CLAUDE_PLUGIN_ROOT}` 与 `${ALEPH_PLUGIN_ROOT}`，并把每个 server 限定为 `plugin:<plugin-id>/<server-name>`。

已启用插件的 server 通过 `McpManager::add_transient_server` 注册。它们是仅运行时、由插件生命周期管理的：不会被写入用户持久化 MCP 配置；卸载插件时其瞬态 server 与工具注册也会被清理。

## 钩子

钩子系统有两种执行形态：

| 形态 | 执行 | 作用 |
|---|---|---|
| `interceptor` | 顺序、阻塞等待 | 可改写输入、追问、阻止、拒绝或改写输出 |
| `observer` | 并行、非阻塞 | 仅做记录或反应，不影响被保护操作 |

第三种「resolver / 先得者胜出」形态未在生产中提供。事件触发点决定哪些形态可用。matcher 仅基于 `tool_name` 匹配，所以在没有工具名的事件上加 matcher 永远不会触发；运行时清单会把这种配置报告为 `reachable: false` 并附 issue。

命令与 HTTP 钩子输出限制为 64 KiB；钩子超时上限 300 秒；命令与 HTTP 动作按需走 operator 同意闸。

## WASM 与权限

WASM 由 Extism 加载，使用声明的能力描述工作区、HTTP、凭证、速率限制、工具调用与密钥。插件权限声明覆盖网络、文件系统、环境、shell 与后台服务。`[[aleph.services]]` 声明要求 `background = true`。

这些声明描述插件可以注册或请求的内容。工具执行仍会经过共享的 scoped-tool、审批与沙箱强制点。

## 热重载与生命周期

Watcher 监听清单与组件变更。`reload` 在 load guard 下串行化，并发重载不会互相覆盖状态。插件卸载在删除前会停止其服务、移除运行时注册、清理瞬态 MCP server。

单插件重载**先预检再拆**。新版本先被解析与身份校验，WASM 插件的 guest module 先编译（只编译，不运行），此时旧版本还在服务。预检判定新版本有缺陷，就地停下：旧版本不拆、插件行不动，错误是 `plugin '{id}' was not reloaded, the previous version is still running: {reason}`。

准入被拒不算新版本的缺陷——那是操作员的决定——所以它照样拆掉旧版本，并把拒绝记录下来。没有旧版本在跑时，预检失败按普通挂载处理：失败写进插件行。

预检覆盖不到的失败依然存在：链接/实例化错误、MCP server 启动、service 启动都只在挂载时出现，那时插件处于未挂载状态。

## 网关与 CLI 命名空间

规范的 Claude Code 兼容网关命名空间是单数形式：

| 方法族 | 用途 |
|---|---|
| `plugin.list` | 列出插件 |
| `plugin.install` | 统一安装来源分类 |
| `plugin.update` | 原子升级并比对版本 |
| `plugin.enable` / `plugin.disable` | 启用或禁用插件 |
| `plugin.reload` | 重新加载插件 |
| `plugin.uninstall` | 卸载插件 |
| `plugin.marketplace.*` | 维护插件市场后端 |

复数 `plugins.*` 方法保留为兼容别名。市场安装会先暂存一份、校验可选的 SHA-256，然后原子重命名；插件的持久数据目录位于安装树之外。

## 代码位置

- `src/extension/mod.rs` — `ExtensionManager`
- `src/extension/manifest/` — 清单适配与解析
- `src/discovery/` — 扫描与冲突解决
- `src/extension/registry/` — 插件组件注册表
- `src/extension/loader.rs` — Static / MCP / WASM 加载
- `src/extension/mcp_config/` — `.mcp.json` 解析与限定
- `src/extension/hooks/` — 钩子执行与同意
- `src/extension/runtime/wasm/` — WASM runtime
- `src/extension/watcher.rs` — 热重载
