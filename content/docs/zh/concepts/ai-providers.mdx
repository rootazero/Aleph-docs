Aleph 通过对象安全的 `AiProvider` trait 暴露模型后端。协议适配器把统一消息历史、工具、媒体与生成设置转换为各上游 API，而 decorator 在不把恢复策略放进代理循环的前提下增加模型覆盖、思考等级、计量、MoA 与提供商故障转移。

## Provider 契约

核心调用是 `AiProvider::process(RequestPayload) -> ProviderResponse`。Provider 还会报告协议以及实际服务的 provider/model hint，使行为选择、定价与归属使用真正处理请求的端点，而不是 wrapper 名称。

流式路径使用 `execute_streaming_dyn` 与 `supports_streaming`。最外层 decorator 必须保持流式能力。默认实现会把完整响应重放到 sink，因此缺少专门实现时只会从实时流式降级为批量交付，而不会静默丢失输出。

## 配置

Provider 是复数顶层表中的条目：

```toml
[providers.primary]
protocol = "anthropic"
models = ["claude-sonnet-4-6"]
enabled = true

[providers.local]
protocol = "ollama"
models = ["qwen3"]
base_url = "http://127.0.0.1:11434"
enabled = true

[general]
default_provider = "primary"
fallback_providers = ["local"]
```

`models` 有顺序，第一项是默认模型。`model = "..."` 仍是向后兼容的输入别名。常用字段包括 `protocol`、`models`、`base_url`、`enabled`、请求与流空闲超时、上下文窗口覆盖、采样控制、缓存保留、模型行为及协议特定选项。

API key 是从加密 vault 加载的仅运行时值，不会由 `ProviderConfig` 持久化。应使用 provider 设置或密钥管理界面，而不是把凭证写入 provider 表。

单数 `[provider.<name>]` 路径无效。Provider 条目也没有 `max_failures` 字段；故障转移成员关系与策略单独配置。

## 故障转移遍历

`FailoverProvider` 是包裹实时 primary 与有序 provider/model 候选链的 decorator。Harness 只看到一个 provider，不实现重试，也不选择 fallback。

每个请求中，provider 层会：

1. 解析实时 primary 与有效 fallback 成员。
2. 应用显式本地/云端路由策略与能力要求。
3. 按配置顺序或负载均衡策略排列合格候选。
4. 尽可能跳过已打开熔断器或处于 provider/model 冷却期的候选。
5. 按类型化失败决策原地重试或推进到下一候选。
6. 记录健康、冷却、负载、用量、实际 provider 与实际 model。

配置的 fallback 名称引用 `[providers]` 中的 key。未配置显式链时，生产链可从实时 provider registry 派生 fallback 成员，因此新增或移除 provider 会影响下一个请求。遍历与 `route_status` 共用 `effective_fallback_names`，所以诊断描述的就是实际使用的链。

流式候选只能在尚未发出用户可见内容时故障转移。一旦内容到达 sink，emission guard 会停止遍历，避免把第二个 provider 的答案接到第一个 provider 的半截答案后面。

## 实时路由状态

`[route]` 控制本地/云端偏好、可选云端升级、负载均衡、provider target 与速率上限。`RouteHandle` 把完整路由状态存入一个 `ArcSwap`：写入以原子方式发布一个完整 generation，每个请求读取一个一致快照。因此下一个请求要么看到全部旧字段，要么看到全部新字段，不会看到撕裂混合。

候选槽位与端点 tier 是不同概念。Primary 槽拥有显式选择的模型；fallback 槽使用各自模型目录。本地/云端 tier 只用于路由策略与成本排序。

## 可靠性与核算

- 瞬时过载、超时与限流失败使用有界重试和退避决策。
- 熔断器、provider 冷却与 model 冷却状态在全局链和单代理链之间共享。
- Provider 错误响应体读取与流空闲间隔均有界。
- 执行吞吐窗口时会计入 cache read 与 cache creation token。
- Metering 将成本与用量归属到实际服务的 provider/model。
- `route_status` 暴露链成员、健康、冷却、负载与路由决策。

故障转移热路径借用请求对话，而不是为每次尝试克隆完整历史。Provider 重构还删除了约 2,000 行不可达的平行实现，使 `AiProvider`、协议适配器与 failover 路径成为受维护的运行时。

## 代码位置

- `src/providers/mod.rs` — `AiProvider` 与 provider 构建
- `src/providers/protocols/` — 协议适配器
- `src/providers/http_provider.rs` — HTTP 执行与实时流式
- `src/providers/failover/` — 候选遍历、决策、熔断与冷却
- `src/providers/route_policy.rs` — 候选门控与排序
- `src/providers/route_handle.rs` — 原子实时路由快照
- `src/providers/route_observe.rs` — `route_status` 渲染
- `src/config/types/provider.rs` — `[providers.<name>]` 条目 schema
