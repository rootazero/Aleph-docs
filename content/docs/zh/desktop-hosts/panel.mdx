默认发布路径由 NSH WebView 加载 Gateway 提供的 Leptos/WASM Panel；浏览器也打开同一地址。TSX AppView 是 macOS 上显式启用的开发入口。

## Panel 是什么

Panel 有两个渲染器：`interfaces/webchat/Cargo.toml` 定义 Rust + Leptos 的 `aleph-panel`，编译为 WASM；`interfaces/panel/App.tsx` 是 TSX Panel 入口，由 `interfaces/panel/nsh.json` 声明其宿主能力。两者共用 `shared/ui_logic/src/panel/mod.rs` 的运行时无关模型。共用的是模型，不是同一个前端包。

## 两条构建链

| 构建产物 | 由谁加载 |
|---|---|
| Leptos WASM：`interfaces/webchat/dist/` | 发布版 `aleph-server` 在编译时嵌入，运行时从二进制读取（`src/gateway/control_plane/assets.rs`）。 |
| TSX Web：interfaces/panel/out-web/ | Gateway 的原生 TLS 路由可在 `/v1/panel/` 从磁盘提供静态包（`src/gateway/server/mod.rs`、`src/gateway/server/connection/web_v1.rs`）。 |
| TSX 原生 bundle：interfaces/panel/out-bundle/ | NSH 桌面壳开启 `tsx-panel` 后在编译时嵌入（`desktop/nsh-shell/src/panel_surface.rs`）。 |

### Leptos WASM（默认发布产物）

发布流程校验并使用已提交的 Leptos WASM 资源，不在发布任务中重建 WASM（`.github/workflows/aleph-app-release.yml`）。`src/gateway/control_plane/assets.rs` 的 `rust_embed` 将 `interfaces/webchat/dist/` 编入发布版 `aleph-server`。运行中的发布版不会从磁盘读取该目录。

刷新时按顺序执行三步：

1. 运行 `just wasm`，重建 `aleph_panel.js`、`aleph_panel_bg.wasm`、`tailwind.css` 和 `index.html` 等资源。配方将 Rust 库编译到 `wasm32-unknown-unknown`，经 `wasm-bindgen` 生成 Web 输出，并执行与 `just check-dist` 相同的 JS/WASM 配对检查（`justfile`、`scripts/check_panel_dist.mjs`）。
2. 运行 `cargo build --release -p alephcore --bin aleph-server`，把新的 `interfaces/webchat/dist/` 编入二进制（`Cargo.toml`、`src/gateway/control_plane/assets.rs`）。
3. 停止旧进程，再用新二进制启动。以本地 release 构建为例，运行 `./target/release/aleph-server stop`，再运行 `./target/release/aleph-server start`（`src/bin/aleph-server/cli.rs`）。只跑 `just wasm` 不会刷新仍在运行的发布版。

### TSX Panel

| 命令 | 用途（配方见 `justfile`） |
|---|---|
| `just panel-tsx-test` | 运行 `nsh test`、`nsh check`，以及 `interfaces/panel/web/host.test.mjs` 的 Node 测试。 |
| `just panel-tsx-web` | 先运行 `nsh check`，再用 `nsh package --target web` 生成 interfaces/panel/out-web/。 |
| `just panel-tsx-bundle` | 先运行 `nsh check`，再用 `nsh build` 生成 interfaces/panel/out-bundle/。 |

Web 打包不会自动启用静态路由。将 Gateway 配置 `[gateway]` 下的 `panel_web_dir` 指向 interfaces/panel/out-web/，原生 TLS 路由才会在 `/v1/panel/` 挂载这个磁盘目录；未配置则不挂载（`src/gateway/config.rs`、`src/gateway/server/mod.rs`、`src/gateway/server/connection/web_v1.rs`）。

### 模块化 Panel（可选）

`panel-modular` 是 Leptos 的可选 feature，不是 TSX 构建路径。它默认关闭；开启后由 `interfaces/webchat/src/app.rs` 渲染 `PanelShell`（feature 定义见 `interfaces/webchat/Cargo.toml`）。`just wasm-modular` 将模块化构建放入 interfaces/webchat/.panel-modular-dist/ 暂存，并在那里执行报告和测试；默认发布仍使用 `interfaces/webchat/dist/`（`justfile`、`.github/workflows/aleph-app-release.yml`）。

## NSH 桌面宿主如何嵌入 TSX Panel

### 编译开关

`tsx-panel` 默认关闭，当前接入的是 macOS 的 NSH JS 运行时（`desktop/nsh-shell/Cargo.toml`、`desktop/nsh-shell/src/app.rs`）。开启后，如果 `bundle.js` 或 `capabilities.json` 缺失，构建会失败并提示先运行 `just panel-tsx-bundle`（`desktop/nsh-shell/build.rs`）。

### 原生组件 `aleph/panel-surface`

`desktop/nsh-shell/src/panel_surface.rs` 用 `include_str!` 把 bundle 和能力清单编入壳二进制，并注册 `aleph/panel-surface`。组件在 NSH 的 `AppView` 中加载 JS 源码。同一时刻最多一个 surface；第二个不会加载 Panel。

### 宿主函数

`interfaces/panel/nsh.json` 声明五个宿主函数，并申请 `openUrl` 权限（只允许 https 与 http 两种 scheme）。桌面由 `desktop/nsh-shell/src/panel_host.rs` 实现，Web 由 `interfaces/panel/web/host.js` 实现。

| 函数 | 两端的行为（见上述实现） |
|---|---|
| `aleph.rpc` | 接收 `method` 和 `params`，返回 `result` 或含 `code`、`message` 的 `error`。 |
| `aleph.pair` | 桌面恒返回错误，由操作系统认证 Desktop IPC；Web 将设备令牌或一次性票据提交给 `/v1/session`。 |
| `aleph.connect` | 发起连接；断线后可用它重新连接。 |
| `aleph.connection` | 读取连接状态；同名事件在状态变化时携带 `state`、`endpoint`、`subject`、`pairing`。 |
| `aleph.fontScale` | 设置 Panel 的文字大小：数字是系统字号的倍数，`null` 表示跟随系统；可接受范围 0.5 到 3，越界时返回 `font scale must be a number from 0.5 to 3`。 |

桌面侧把 `aleph.fontScale` 挂在 `aleph/panel-surface` 上（surface 拥有 `AppView`），Web 侧改根元素的 `font-size`（16px 为 100%）。

除 `aleph.connection` 外，宿主还会下发 `aleph.event` 事件，形状是 `{ topic, data }`：

- 桌面把 Gateway 推来的流事件包成 `stream.<type>` 主题（`desktop/nsh-shell/src/panel_host.rs`）。
- Web 把带 topic 的通知原样转发（`interfaces/panel/web/host.js`）。
- 桌面在丢掉帧之后，先发一条自己的 `connection.stale` 事件（`data` 里是丢帧数），提醒 Panel 重新拉取而不是相信自己那份视图。
- 实时帧不重放：换连接之后旧连接的事件不再投递。

### 选择渲染器

在支持 `tsx-panel` 的构建中，非 QA 启动设置 `ALEPH_SHELL_PANEL=tsx` 会挂载 `aleph/panel-surface`；未设置时挂载 `web_view`，不同时运行两者。无效或不受支持的显式选择会让壳拒绝启动，而不是回退到 WebView（`desktop/nsh-shell/src/app.rs`）。

在 macOS 上，先用 `--desktop-ipc` 指定 socket 路径并启动 Gateway（`src/bin/aleph-server/cli.rs`），再运行：

```sh
just shell-tsx-dev /absolute/path/to/socket
```

配方先重建 bundle，再带 `tsx-panel` 启动壳，并把传入的绝对路径设为 `ALEPH_SHELL_PANEL_IPC`（`justfile`、`desktop/nsh-shell/src/panel_host.rs`）。

## 宿主与 Panel 的通道

TSX 桌面和 Web 使用上节的宿主函数。下述消息、校验和导航只适用于 NSH 的 Leptos WebView 路径：`desktop/nsh-shell/src/app.rs` 在挂载 `web_view` 时启动桥接，页面通过 `window.nsh.postMessage` 向宿主发消息（`desktop/nsh-shell/src/panel_bridge.js`）。WebView 加载连接目标的根路径，不在 URL 中携带凭据或启动材料（`desktop/nsh-shell/src/shell_host.rs`、`shared/client/src/connection_target.rs`）。

### 消息形状

WebView 桥接使用带 `kind` 标签的 JSON。`shared/protocol/src/panel_shell.rs` 的 `ShellRequest` 和 `PanelReply` 用 kebab-case 标签并拒绝未知字段。

| 方向 | `kind`（见 `shared/protocol/src/panel_shell.rs`） |
|---|---|
| 宿主到 Panel | `probe`、`credentials-ready`、`open-chat`、`credential-reply`、`autostart-reply` |
| Panel 到宿主 | `ready`、`chat-opened`、`notify`、`credential-request`、`autostart-request` |

`CredentialCall` 用 `operation` 区分 `load`、`save` 和 `delete`；`CredentialReply` 用 `outcome` 表示结果，`AutostartStatus` 用 `status` 表示登录项状态（`shared/protocol/src/panel_shell.rs`）。

### 校验与限制

- 壳启动时生成形如 `aleph-shell-v1:<uuid>:` 的随机前缀，宿主只接收带该前缀的页内消息，JSON 负载上限为 16 KiB（`desktop/nsh-shell/src/app.rs`、`desktop/nsh-shell/src/panel_bridge.rs`）。
- 页内脚本仅在顶层窗口、且 `location.origin` 匹配预期来源时安装。每次加载生成一个 32 字符的小写十六进制 `document`；绑定文档的消息必须匹配当前文档，导航时宿主清理文档状态并使旧凭据租约失效（`desktop/nsh-shell/src/panel_bridge.js`、`desktop/nsh-shell/src/panel_bridge.rs`、`shared/protocol/src/panel_shell.rs`）。
- 通知标题须非空且不超过 256 字节，正文不超过 2048 字节（`shared/protocol/src/panel_shell.rs`、`desktop/nsh-shell/src/panel_bridge.rs`）。

### 导航流程

宿主在最多 15 秒的探测窗口内发送 `probe`，每次等待回复 350 毫秒。Panel 回 `ready` 并提供 `document`，宿主再发 `credentials-ready`。收到精确的 `aleph://open` 或点击 Chat 通知时，宿主待文档就绪后发送 `open-chat`，最多等 2 秒接收 `chat-opened`；超时则丢弃该次动作，不重放（`desktop/nsh-shell/src/panel_bridge.rs`）。

## 传输矩阵

| 渲染路径 | 到 Gateway 的传输 | 认证与准入 |
|---|---|---|
| Leptos（浏览器或 WebView） | 旧 `/ws` 上的 WebSocket JSON-RPC（`interfaces/webchat/src/context.rs`、`src/gateway/server/mod.rs`）。 | 沿用旧入口的认证；`system.hello` 只协商协议，不建立调用者身份（`src/gateway/server/connection/upgrade.rs`、`src/gateway/handlers/system_hello.rs`）。 |
| TSX（NSH 桌面） | `aleph.rpc` 走 `AlephClient::connect_local` 建立的本地 Desktop IPC 连接，macOS 用 Unix socket（`desktop/nsh-shell/src/panel_host.rs`、`shared/client/src/connection.rs`）。 | 同账号由操作系统认证；Unix socket 的父目录须由该用户持有、权限为 `0700`（`shared/client/src/local_ipc.rs`、`src/gateway/server/connection/local_ipc.rs`）。 |
| TSX（Web） | 同源 `wss://…/v1/ws`，子协议 `aleph.protocol.v1`。二进制消息由 4 字节大端长度和 UTF-8 JSON 组成，首帧为 `system.hello`（`interfaces/panel/web/host.js`、`shared/protocol/src/framing.rs`）。 | 原生 TLS 路由校验来源，`POST /v1/session` 签发短期、仅限当前主机的 Cookie，引用现有的设备凭据（`src/gateway/server/connection/web_v1.rs`）。 |

Desktop IPC 与 Web v1 共用 Gateway 的[协议 v1 方法清单](../gateway/protocol-v1)，实现见 `src/gateway/server/connection/mod.rs`。

## 已知限制

- 桌面 TSX 只连本地 Desktop IPC；例如以 `--connect` 指定的 WebSocket 目标会返回 `unavailable`，不会回退到 WebSocket。`ALEPH_SHELL_PANEL_IPC` 是 socket 路径，但布局存储键的 endpoint 部分固定为 `desktop-ipc`，不随 socket 路径变化（`desktop/nsh-shell/src/panel_host.rs`、`interfaces/panel/shell/Shell.tsx`、`shared/ui_logic/src/panel/layout.rs`）。
- 桌面发布使用默认构建，打包 NSH、`aleph-server` 及其内嵌的 Leptos 资源。`tsx-panel` 默认关闭（`desktop/nsh-shell/Cargo.toml`、`.github/workflows/aleph-app-release.yml`）。
- TSX 尚未覆盖全部经典 Panel 标签页；需要经典渲染器的标签页会显示不可用提示（`interfaces/panel/shell/Shell.tsx`）。
- TSX 侧的 `aleph:memory-nebula` 标签页由 Gateway 注入声明，依赖 `graph.query`、`graph.search`、`graph.node_detail` 三个方法都已挂载；未挂载时该标签页不存在（`src/gateway/handlers/panel_capabilities.rs`、`src/gateway/handlers/mod.rs`）。

> **状态：规划中** — S4 的一致性快照与持久观察事件回放见 `docs/superpowers/specs/2026-11-22-nsh-panel-modular-refactor-design.md`。当前 TSX 获取的是能力快照（`interfaces/panel/shell/Shell.tsx`），这不等同于会话或任务状态的恢复；Gateway 的 `system.hello` 没有宣布快照或回放特性（`src/gateway/handlers/system_hello.rs`）。
