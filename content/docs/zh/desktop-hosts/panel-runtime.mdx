本页说明 Panel 由什么组成：一份与运行时无关的模型层，加上读这份模型的两套渲染器。宿主视角（构建、嵌入、宿主通道）见 [Panel 宿主](./panel)；插件 UI 的对外契约见 [插件 UI](./plugin-ui)。

## Panel 运行时是什么

Panel 的代码分成模型（model）和渲染器（renderer）两层。模型决定「有哪些标签页、哪些能挂载、按什么顺序显示」，渲染器只负责把结果画出来、处理用户操作。

| 层 | 代码位置 | crate | 说明 |
|---|---|---|---|
| 模型层 | `shared/ui_logic/src/panel/` | `shared-ui-logic`（feature `panel`） | 注册表、描述符投影、快照来源、连接作用域的发现、稳定 ID 布局；只依赖 `aleph-protocol` |
| Leptos 渲染器 | `interfaces/webchat/` | `aleph-panel` | Rust + Leptos，编译为 WASM；模块化 Panel 部分在 `interfaces/webchat/src/panel/`，需 feature `panel-modular` |
| TSX 渲染器 | `interfaces/panel/` | `aleph-panel-ui` | NSH UI set `aleph/panel`；Desktop 与 Web 渲染同一份 TSX 源码 |

**两套渲染器读同一份模型实现（`shared_ui_logic::panel`），不是两份逻辑。** `shared/ui_logic/src/panel/mod.rs` 的模块注释原文是：

> Runtime-neutral Panel model shared by every Panel renderer. These modules depend only on `aleph_protocol` ... The Leptos Panel and the TSX Panel read the same code, so the read-side index has a single implementation.

两套渲染器的接入方式：

- Leptos 侧：`interfaces/webchat/Cargo.toml` 中 `panel-modular = ["shared-ui-logic/panel"]`，`interfaces/webchat/src/app.rs` 与 `interfaces/webchat/src/context.rs` 在该 feature 下直接调用 `shared_ui_logic::panel::projection` 与 `shared_ui_logic::panel::discovery`。
- TSX 侧：`interfaces/panel/Cargo.toml` 以 `default-features = false, features = ["panel"]` 依赖 `shared-ui-logic`，`interfaces/panel/src/lib.rs` 是对模型的薄绑定。

<Callout type="warn" title="默认构建仍是常规 Leptos Panel">
`interfaces/webchat/Cargo.toml` 的默认 feature 是 `legacy-terminal`，`panel-modular` 需要显式开启；不开时 `interfaces/webchat/src/lib.rs` 不编译 `pub mod panel;`。TSX 渲染器在桌面宿主里同样是可选项：`desktop/nsh-shell/Cargo.toml` 的 feature `tsx-panel` 默认关闭，且只在 `ALEPH_SHELL_PANEL=tsx` 时挂载（`desktop/nsh-shell/src/main.rs`）。
</Callout>

## 模型层：shared/ui_logic/src/panel/

模型层由五个模块组成（`shared/ui_logic/src/panel/mod.rs`），在 `shared/ui_logic/src/lib.rs` 中由 `#[cfg(feature = "panel")]` 控制编译：

| 模块 | 职责 |
|---|---|
| `shared/ui_logic/src/panel/registry.rs` | 标签页成员关系与启用状态，不做加载、不产生 UI 副作用 |
| `shared/ui_logic/src/panel/projection.rs` | 把能力快照校验后投影成注册表，并把路由解析成挂载目标 |
| `shared/ui_logic/src/panel/source.rs` | 不可变的能力快照来源 |
| `shared/ui_logic/src/panel/discovery.rs` | 按连接 epoch 与请求代次做栅栏的快照发现状态 |
| `shared/ui_logic/src/panel/layout.rs` | 可持久化的布局：顺序、隐藏、激活项，以及恢复规则 |

前四个文件原本位于 `interfaces/webchat/src/panel/`，在提交 `2f541e81a`（2026-11-23）中整体搬到 `shared/ui_logic/src/panel/`；`shared/ui_logic/src/panel/layout.rs` 是随 TSX 渲染器新增的。

### 标签注册表

`TabRegistry`（`shared/ui_logic/src/panel/registry.rs`）是一个按 `PanelTabKey` 索引的小型注册表。文件头注释：「Pure tab membership and enabled mount projections; no loading or UI effects.」

| 方法 | 含义 |
|---|---|
| `new(builtins)` | 由宿主初始化内置条目，重复的 key 被拒绝而不是覆盖 |
| `insert_or_replace(descriptor)` | 插件条目的注册与替换；占用内置命名空间返回 `RegistryError::BuiltInShadowed`；替换时清空该条目的资源完整性 |
| `remove(key)` / `get(key)` | 移除与查询 |
| `rows()` | 全部条目，按 `(order, key.qualified())` 排序，状态行仍可查询 |
| `ordered()` | 只保留 `PanelTabStatus::Enabled` 的条目，即可挂载候选 |
| `active_after_removal(removed)` | 按投影顺序选出除被移除 key 之外的第一个可挂载条目 |
| `source_revision()` | 当前注册表对应的快照修订号 |
| `set_asset_integrity()` / `asset_integrity()` | 按 key 记录与读取资源完整性摘要 |

- 内置命名空间常量 `BUILTIN_NAMESPACE = "aleph"`，注释写明「Only the host's explicit built-in initialization may populate this namespace.」
- `validate_descriptor` 要求 `plugin_id`、`tab_id`、`label`、`entry` 非空，`plugin_id` 与 `tab_id` 不含 `:`（qualified 键以冒号分隔），`entry` 通过 `valid_relative_entry`，`api_major` 等于 `PANEL_UI_API_MAJOR`。
- `RegistryError` 只有三个变体：`BuiltInShadowed`、`DuplicateKey`、`InvalidEntry`。

### 描述符投影

`PanelProjection`（`shared/ui_logic/src/panel/projection.rs`）只持有一个 `TabRegistry`，负责把协议层的声明变成「本连接可以挂载的标签页」：

- `builtins(label)` 只用内置终端来源构造投影；`from_snapshot(snapshot)` 从能力快照构造。
- `replace_snapshot(snapshot)` 原子替换：修订号不大于当前值时返回 `PanelProjectionError::StaleSnapshot`，校验失败时保留旧投影。
- 快照中任一声明的 `source_revision` 与快照 `revision` 不一致，整份快照以 `RevisionMismatch` 拒绝。
- `validate_declaration` 按来源分别校验：`BuiltIn` 必须在 `aleph` 命名空间、信任级别为 `Verified`；`Community` 不能占用 `aleph`、信任级别为 `Trusted`、权限须通过 `supported_community_permission`、必须带资源完整性，入口须位于 `./tabs/<plugin_id>/<plugin_version>/` 之下。
- `PanelProjectionError` 的每个变体都有稳定原因码 `reason_code()`，例如 `invalid_identity`、`unacceptable_trust`、`missing_asset_integrity`、`stale_snapshot`、`selection_unavailable`。

路由解析：

| 方法 | 行为 |
|---|---|
| `select_route(path, projection)` | 返回 `PanelRoute`：路径不是 `/terminal` 时为 `Legacy`；是 `/terminal` 但没有投影或终端条目未启用时为 `Unavailable`；否则为 `Modular(PanelTabKey)` |
| `route_key(path)` | 只把 `/terminal` 解析到已启用的内置终端 key |
| `explicit_key(path)` | 只解析 `/panel/<plugin_id>/<tab_id>` 两段路径，且两段都必须通过 `valid_identity_segment` |
| `select_explicit(key, source_revision)` | 调用方必须提供当前修订号，否则 `StaleSnapshot`；条目不存在或未启用时为 `SelectionUnavailable` |

### 快照来源

快照来源（`shared/ui_logic/src/panel/source.rs`，文件头：「Immutable Panel UI capability snapshots; no plugin lifecycle or asset loading.」）只产出快照，不负责写入：

```rust
pub trait PanelUiCapabilitySource {
    fn snapshot(&self) -> PanelUiCapabilitySnapshot;
}
```

- `BuiltInTerminalSource`：修订号 `0`，只含一条 `BuiltIn` 终端声明。终端 tab id 在 `panel-tab-spike` 构建下是 `terminal-pilot`，否则是 `terminal`。
- `FixturePanelUiCapabilitySource`：测试夹具；`community_fixture_snapshot()` 只在 `panel-tab-spike` 下存在。

### 连接作用域的发现

`PanelDiscoveryState`（`shared/ui_logic/src/panel/discovery.rs`）把快照绑定在连接上，按连接 epoch、请求代次和快照修订号三重栅栏决定是否接受。它只管发现，不把声明投影成挂载。

| 方法 | 行为 |
|---|---|
| `begin_connection(epoch)` | 为新连接开始一次查询，保留上一份快照，自增请求代次并进入 `Loading`；旧 epoch 返回 `None` |
| `accept_snapshot(epoch, snapshot)` | 用当前请求代次接受快照 |
| `accept_snapshot_for_request(epoch, request_generation, snapshot)` | 只接受当前持有状态的那次请求的结果 |
| `accept_context_snapshot_for_request(...)` | 同上，同时接受 `PanelUiContextSnapshot` 携带的项目上下文；同一连接内项目上下文代次倒退时视为过期请求 |
| `invalidate_context()` | 发起项目选择前调用：推进上下文 epoch 与请求代次，清空快照并进入 `Loading` |
| `mark_error(epoch, message)` | 只对当前 epoch 与请求代次生效，清空快照并置为 `Error` |
| `disconnect(epoch)` | 推进请求代次并置为 `Disconnected`，不伪造空快照 |
| `snapshot()` / `status()` | 读取当前快照与状态 |

- `PanelDiscoveryStatus`：`Disconnected`、`Loading`、`Ready`、`Error { message }`。
- `SnapshotUpdate`：`Accepted`、`StaleEpoch`、`StaleRequest`、`StaleRevision`，分别对应连接 epoch 不符、请求代次被超越、快照修订号不新。
- `decode_snapshot(value)` 把 JSON 解码成 `PanelUiCapabilitySnapshot`，不经过任何浏览器投影。

### 稳定 ID 布局与恢复

`shared/ui_logic/src/panel/layout.rs` 定义可持久化的标签布局。文件头注释给出了它的边界：

> A layout stores only stable `PanelTabKey`s and plain data. It never stores descriptors, entries or permissions, so restoring a layout can rearrange what the current snapshot offers but can never make a tab mountable.

| 符号 | 说明 |
|---|---|
| `PanelLayout { version, order, hidden, active }` | 布局本体，`order`、`hidden`、`active` 都只是 `PanelTabKey` |
| `LAYOUT_VERSION` | 当前布局版本，值为 `1` |
| `STORAGE_PREFIX` | 私有常量 `"aleph.panel.layout.v1"` |
| `layout_storage_key(endpoint, subject)` | 有 subject 时为 `aleph.panel.layout.v1:<endpoint>:<subject>`，否则为 `aleph.panel.layout.v1:<endpoint>`；没有 subject 时同一设备上的用户共用该端点的布局 |
| `LayoutSlot::Live(key)` / `LayoutSlot::Unavailable(key)` | 恢复后标签栏上的一个位置 |
| `LayoutRepair::Corrupt` / `LayoutRepair::UnknownVersion(u32)` | 存储的布局被默认布局替换的原因 |
| `RestoredLayout { layout, slots, repair }` | 恢复结果：要写回的布局、可见位置、修复原因 |

存储键中的 subject 来自 `system.hello` 结果的可选不透明字段 `HelloResult.subject`（`shared/protocol/src/system_hello.rs`），由 Gateway 的 `subject_for` 按用户生成（`src/gateway/handlers/system_hello.rs`）。它只用于客户端存储键，不是身份，客户端不得从中推导权限；旧 `/ws` 入口或 Gateway 没有密钥时缺省，此时布局按端点共享。

编辑方法都只改纯数据：`PanelLayout::move_one(key, forward)` 与相邻项交换、`PanelLayout::set_hidden(key, hidden)`（隐藏激活项会清空 `active`）、`PanelLayout::select(key)`（只记录激活项，是否可挂载由恢复决定）、`PanelLayout::default_for(registry)` 按 `ordered()` 生成默认布局。

`restore(raw, registry)` 的规则：

1. 没有存储值时使用默认布局；JSON 损坏、缺 `version` 时报 `Corrupt`，版本不是 `LAYOUT_VERSION` 时报 `UnknownVersion`，两者都退回默认布局。
2. 顺序为「存储的顺序」后接「注册表新出现的可挂载 key」，去重。
3. 未隐藏的 key 中，属于当前 `ordered()` 的成为 `Live`，其余成为 `Unavailable`。
4. 存储的激活项只有仍是 `Live` 时才保留，否则取第一个 `Live`。

由此得到三条不变量：布局只存稳定 `PanelTabKey` 与纯数据；恢复只能重排当前快照已有的标签，不能让任何标签变成可挂载；快照不再提供的标签渲染为 `Unavailable` 占位，渲染器永不执行它（`LayoutSlot::Unavailable` 的注释：「Renderers show a placeholder and never execute it.」）。布局损坏只重置表现，不触碰会话或插件。

## 渲染器层

### Leptos 渲染器（interfaces/webchat/）

`interfaces/webchat/` 仍是默认的 Panel 实现（crate `aleph-panel`，编译为 WASM）。常规页面由 `interfaces/webchat/src/app.rs` 渲染；开启 `panel-modular` 后，`interfaces/webchat/src/panel/` 提供模块化 Panel 的浏览器侧部件：

```text
PanelShell            interfaces/webchat/src/panel/shell.rs
  |-- PanelProjection   shared_ui_logic::panel::projection
  |     `-- TabRegistry  shared_ui_logic::panel::registry
  |-- PanelLoader       interfaces/webchat/src/panel/loader.rs
  |-- PanelSdk          interfaces/webchat/src/panel/sdk.rs
  `-- CapabilitySurface interfaces/webchat/src/panel/capability_surface.rs
```

- `PanelShell(projection: PanelProjection, initial_tab: Option<PanelTabKey>)`（`interfaces/webchat/src/panel/shell.rs`）把导航交给 `registry.rows()`，把插件挂载点放进 `data-panel-sidebar-root` 与 `data-panel-content-root` 两个 div。
- `PanelHostState`（`interfaces/webchat/src/panel/mod.rs`）用 `Arc<Mutex<TabRegistry>>` 持有共享模型中的注册表，只有 Shell 修改它。
- 路由与发现：`interfaces/webchat/src/app.rs` 调用 `PanelProjection::builtins`、`select_route`、`explicit_key`、`from_snapshot`；`interfaces/webchat/src/context.rs` 的 `refresh_panel_discovery` 驱动 `PanelDiscoveryState`。
- Leptos 侧当前不使用 `shared/ui_logic/src/panel/layout.rs`；稳定 ID 布局目前只由 TSX 渲染器使用。

以下三节描述的都是 **Leptos 侧** 的机制。插件标签页的 DOM 模块 ABI（`describe` + `mount`）只存在于这一侧，TSX 渲染器不加载这类模块。

### Leptos 侧：加载与失败

`interfaces/webchat/src/panel/loader.rs` 的文件头：「Browser-local loading. The shared host registry is a descriptor projection only.」

1. `PanelLoader::activate(key, sidebar_root, content_root, sdk)`：找不到描述符为 `InvalidDescriptor`，条目不是 `Enabled` 为 `Cancelled`，`api_major` 不匹配为 `UnsupportedApiMajor`。
2. 浏览器桥 `interfaces/webchat/src/panel/loader/browser.rs`（「WASM-only JS bridge. Never exports DashboardState or transport handles.」）调用 `interfaces/webchat/index.html` 注册的 `globalThis.__alephLoadPanelModule`，实现为 `interfaces/webchat/panel_loader.js` 的 `loadPanelModule`：要求模块同时导出 `describe` 与 `mount`，并按 `sha256-` SRI 校验完整性。
3. `deactivate()` 释放当前挂载并作废本次加载；`reconcile()` 在投影变化后核对描述符仍然有效且为 `Enabled`，否则退化为 `deactivate()`。撤销只释放 UI，不触发 provider 或 session 的生命周期。

`PanelLoadError` 的变体（`interfaces/webchat/src/panel/loader.rs`）：

| 变体 | 触发条件 |
|---|---|
| `ImportFailed` | 模块导入失败 |
| `AssetFetchFailed` | 入口资源获取失败（含一次性凭据获取失败） |
| `InvalidAssetIntegrity` | 完整性字段格式非法 |
| `IntegrityMismatch` | 摘要与实际资源不符 |
| `InvalidDescriptor` | 注册表里没有对应描述符 |
| `UnsupportedApiMajor` | `api_major` 与 `PANEL_UI_API_MAJOR` 不一致 |
| `MountFailed` | 模块挂载抛错 |
| `UnmountFailed` | 模块卸载抛错 |
| `Cancelled` | 条目不是 `Enabled`，或加载被取消 |

### Leptos 侧：插件模块 ABI

插件模块拿到的是 `PanelSdk`（`interfaces/webchat/src/panel/sdk.rs`）这一层窄 ABI。文件头注释：

> Browser modules receive only the narrow SDK ABI, never this adapter's private DashboardState or Shell context. Same-origin code is trusted/verified code, not sandboxed by these permission checks.

- **不是沙箱**：权限检查只决定调用是否允许，不提供隔离；信任分级见 `shared/protocol/src/panel.rs` 的 `PanelUiTrust`。
- 公开方法：`invoke`、`subscribe`、`connection`、`navigate`、`theme`、`locale`、`dispose`；浏览器侧实际交给模块的是 `BrowserPanelSdk`（`interfaces/webchat/src/panel/loader/browser.rs`）。
- `PanelSdkError`：`Denied`、`InvalidMethod`、`InvalidNavigation`、`Disposed`。拿不到宿主上下文、自己的标签页不在注册表或未启用，都是 `Denied`。
- `subscribe` 需要具体 topic 的 `events.subscribe:<topic>` 权限；每个订阅最多缓存 256 条事件（`SUBSCRIPTION_PENDING_CAPACITY`），溢出丢最旧的。

### Leptos 侧：能力 UI 表面

能力 UI 表面（capability surface）呈现 Core 持有的 UI 能力，与插件标签页是两套机制：

- 组件在 `interfaces/webchat/src/panel/capability_surface.rs`，订阅 `DISPLAY_TOPIC = "capabilities.ui.display"`，渲染后调用 `capabilities.ui.ack` 确认。
- 协议消息 `UiAttachment`、`UiDisplayMessage`、`UiRenderAck` 定义在 `shared/protocol/src/capability.rs`。
- 归属在 Core：`UI_NAMESPACE = "aleph/ui"`（`src/capability/ui.rs`），Gateway 侧实现在 `src/capability/ui_surface.rs`。插件不能自己声明一块核心表面。

### TSX 渲染器（interfaces/panel/）

`interfaces/panel/` 是 NSH 应用（`interfaces/panel/nsh.json`：`id` 为 `com.aleph.panel`，`name` 为 `Aleph Panel`，`version` 为 `0.1.0`，`rust` 指向本目录）。Rust 部分是 crate `aleph-panel-ui`（`interfaces/panel/Cargo.toml`，依赖 `nsh-core = "=0.6.0"`）。

`interfaces/panel/src/lib.rs` 用 `#[native_module("aleph/panel")]` 暴露 UI set，导出模块 `PanelModel`。文件头写明它是「A thin binding over the runtime-neutral Panel model」，TSX 壳只调用这些函数、不重新实现规则；值以 JSON 跨界（TS 侧为 `unknown`）。

| 函数 | 调用的模型 |
|---|---|
| `view(snapshot, stored_layout)` | `PanelProjection::from_snapshot` + `restore`；返回 `revision`、`tabs`、`slots`、`layout`、`stored`、`repair`、`projectionError` |
| `layout_key(endpoint, subject)` | `layout_storage_key` |
| `move_tab(stored, key, forward)` | `PanelLayout::move_one` |
| `set_hidden(stored, key, hidden)` | `PanelLayout::set_hidden` |
| `select(stored, key)` | `PanelLayout::select` |

TSX 侧自己渲染三个内置模块（`SHELL_MODULES`，组件在 `interfaces/panel/modules/`）：

| key | label | icon | order | 组件 |
|---|---|---|---|---|
| `aleph:overview` | Overview | `layout-dashboard` | -30 | `interfaces/panel/modules/Overview.tsx` |
| `aleph:sessions` | Sessions | `messages-square` | -20 | `interfaces/panel/modules/Sessions.tsx` |
| `aleph:capabilities` | Capabilities | `blocks` | -10 | `interfaces/panel/modules/Capabilities.tsx` |

- 这三个模块以 `BuiltIn` 声明并入 Core 快照，与 Core 的内置条目走同一套投影校验；Core 已声明同名 key 时保留 Core 的描述符。
- 快照缺失、格式错误或被投影拒绝时，只保留这三个模块并在 `projectionError` 中报告原因码，绝不挂载被拒快照的任何部分。
- 每个 tab 带 `renderer` 字段：三个内置模块为 `tsx`，**其余 tab 为 `dom`，即 Leptos Panel 的 DOM 模块 ABI，在 TSX 侧显示为不可用**。
- 挂载的模块拿到 `interfaces/panel/shell/sdk.ts` 的 `PanelSdk`（`invoke`、`subscribe`、`connection`、`navigate`、`dispose`），绑定一个 tab key 与一个连接代次；`dispose()` 或连接代次推进之后，旧调用的结果被丢弃而不是送达模块。这里的 `subscribe` 监听的是连接状态，不是 Leptos 侧的事件 topic。
- 壳的其余部分在 `interfaces/panel/shell/`：`interfaces/panel/shell/Shell.tsx`、`interfaces/panel/shell/LayoutEditor.tsx`、`interfaces/panel/shell/PairingForm.tsx`、`interfaces/panel/shell/view.ts`。

### TSX 宿主函数

TSX 壳通过 `interfaces/panel/nsh.json` 的 `capabilities` 段里的 `host` 列表申请四个宿主函数。函数契约写在 `interfaces/panel/web/host.js` 的文件头：

```text
"aleph.rpc"        { method, params } -> { result } | { error: { code, message } }
"aleph.pair"       { bootstrap_ticket } | { device_token } -> { result: null } | { error }
"aleph.connect"    null -> opens a new socket (after a drop)
"aleph.connection" null -> the current connection state
事件 "aleph.connection"  { state, endpoint, subject, pairing }
```

同一份 TSX 源码有两个宿主适配器：

| 目标 | 适配器 | 连接 |
|---|---|---|
| Web | `interfaces/panel/web/host.js` | 同源 Protocol v1 WebSocket（子协议 `aleph.protocol.v1`，4 字节大端长度前缀帧，首帧 `system.hello`）；浏览器缺 `WebSocket` 或页面 origin 时上报 `unavailable` 且从不连接 |
| Desktop | `desktop/nsh-shell/src/panel_host.rs` | 只连本地 Gateway 的 Desktop IPC；由 `desktop/nsh-shell/src/panel_surface.rs` 的原生组件 `aleph/panel-surface` 承载 |

两个适配器在没有 Gateway 连接时都以 `PANEL_HOST_UNAVAILABLE`（-32090）应答，这个码由客户端产生，Gateway 从不返回。帧格式的 golden 向量在 `shared/protocol/tests/fixtures/v1_frames.json`，Web 适配器的测试是 `interfaces/panel/web/host.test.mjs`。宿主一侧的细节见 [Panel 宿主](./panel)。

## 协议契约

### Panel v1 方法与常量

定义在 `shared/protocol/src/panel.rs`：

| 常量 | 值 | 用途 |
|---|---|---|
| `PANEL_UI_API_MAJOR` | `1` | Panel UI API 主版本，描述符的 `api_major` 必须等于它 |
| `PANEL_UI_CAPABILITY_SNAPSHOT_METHOD` | `"panel.capabilities.snapshot"` | 只读 RPC，取规范能力快照 |
| `PANEL_PROJECT_SELECT_METHOD` | `"panel.project.select"` | 为已认证设备设置服务端持有的项目选择 |
| `PANEL_PROJECT_GENERATION_HEADER` | `"x-aleph-panel-project-generation"` | 响应元数据，供宿主做栅栏，从不作为请求授权 |
| `PANEL_HOST_UNAVAILABLE` | `-32090` | 宿主适配器无 Gateway 连接时的错误码 |

主要类型：

| 类型 | 作用 |
|---|---|
| `PanelTabKey` | `plugin_id` + `tab_id`；`qualified()` 拼成 `plugin:tab` |
| `PanelTabDescriptor` | `key`、`label`、`icon`、`order`、`entry`、`api_major`、`trust`、`permissions`、`status`、`status_detail` |
| `PanelTabStatus` | `Enabled`、`Disabled`、`Incompatible`、`Failed` |
| `PanelUiTrust` | `Verified`、`Trusted` |
| `PanelUiCapabilityOrigin` | `BuiltIn`、`Community` |
| `PanelUiCapabilityDeclaration` | 描述符加 `origin`、`plugin_version`、`asset_integrity`、`public_base`、`source_revision` |
| `PanelUiCapabilitySnapshot` | `revision` + `declarations`；`new()` 按来源（内置在前）再按 qualified key 排序 |
| `PanelProjectSelection` / `PanelUiContextSnapshot` | 项目选择（`project_id`、`generation`）及携带它的快照 |

Gateway 侧，`src/gateway/server/connection/mod.rs` 的 `V1_METHODS` 是 v1 入口共用的方法集：`health`、`sessions.list` 与 `PANEL_UI_CAPABILITY_SNAPSHOT_METHOD`。快照 handler 在 `src/gateway/handlers/panel_capabilities.rs`。

### 描述符校验

协议层的校验函数（`shared/protocol/src/panel.rs`）被注册表与投影共用：

- `valid_identity_segment`、`valid_version_segment`、`valid_path_segment`：身份段、版本段、路径段的字母表。
- `valid_relative_entry`：入口必须是相对路径，拒绝空串、以 `/` 开头、含 `\` 或 `:` 的值。
- `valid_asset_integrity`：`sha256-` 前缀加 32 字节 base64 摘要。
- `supported_community_permission`：社区条目的权限白名单，`events.subscribe` 必须带具体 topic，不接受通配。

## 数据流总览

```text
panel.capabilities.snapshot (Gateway)
        |
        v
PanelDiscoveryState          discovery.rs   epoch / 请求代次 / 修订号栅栏
        |  PanelUiCapabilitySnapshot
        v
PanelProjection              projection.rs  逐条校验声明，整份接受或整份拒绝
        |
        v
TabRegistry                  registry.rs    rows() 全部状态行 / ordered() 可挂载
        |
        +--> Leptos: PanelShell -> PanelLoader -> DOM 模块 (describe + mount)
        |
        +--> TSX:    PanelModel.view() -> Shell.tsx -> 内置 TSX 模块

存储的布局 (aleph.panel.layout.v1:<endpoint>[:<subject>])
        |
        v
restore(raw, &TabRegistry)   layout.rs      -> RestoredLayout { layout, slots, repair }
        |
        v
LayoutSlot::Live (可挂载)  /  LayoutSlot::Unavailable (占位，永不执行)
```

布局一侧目前只接入 TSX 渲染器（`interfaces/panel/src/lib.rs`）。
