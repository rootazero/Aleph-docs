---
title: "首次配置"
description: "使用当前 CLI、配置文件和 Panel 完成 Aleph 首次配置"
---

当前版本的 `aleph-server` CLI **没有** `wizard` 子命令。`src/wizard/` 提供的是供 Gateway/客户端使用的会话式流程框架，不等同于 `aleph wizard` 命令。

## 1. 创建配置文件

Aleph 默认读取 `~/.aleph/config.toml`；可用 `ALEPH_HOME` 覆盖根目录。

```bash
mkdir -p ~/.aleph
```

最小配置示例：

```toml
[general]
default_provider = "claude"

[providers.claude]
provider_type = "claude"
enabled = true
api_key = "${ANTHROPIC_API_KEY}"
models = ["<当前模型目录中的模型 ID>"]

[policies]
mode = "work"
exec_tier = "auto"

[gateway]
host = "127.0.0.1"
port = 18790
```

模型 ID 会随提供商更新，请以当前模型目录和 Panel 中的提供商列表为准，不要复制过期的静态模型名。

## 2. 配置凭据

可通过环境变量插值提供密钥：

```bash
export ANTHROPIC_API_KEY="sk-ant-..."
```

生产环境建议使用 Aleph 的加密机密管理，而不是把密钥明文写入配置文件。相关 CLI：

```bash
aleph-server secret --help
```

## 3. 检查并启动

```bash
aleph-server doctor
aleph-server start
```

Gateway 默认监听 `127.0.0.1:18790`；WebSocket endpoint 为 `ws://127.0.0.1:18790/ws`。浏览器 Panel 使用同一端口的 HTTP 页面。

## 4. 设置会话策略

全局默认值位于 `[policies]`：

- `mode = "chat" | "work" | "code"`：只控制工具呈现面，默认 `work`
- `exec_tier = "ask" | "auto" | "full"`：控制审批策略，默认 `auto`

会话模式还可在 Panel 中切换，或由模型调用 `session_set_mode` 工具更新。`[sandbox.command_policy]` 始终是不可被执行等级降低的安全硬底。

## 5. 配置远程访问

非环回绑定必须使用原生 TLS、可信 TLS 反向代理，或显式选择不安全远程传输。推荐原生自签名 TLS：

```toml
[gateway]
host = "0.0.0.0"
port = 18790

[gateway.tls]
enabled = true
```

启用 TLS 后，若 `cert_path` 与 `key_path` 均为空，Gateway 会生成自签名证书。NSH 桌面应用连接远程 Gateway 时，使用 HTTPS 源站和操作系统信任的证书。NSH 的连接探测会拒绝自动生成的自签名证书（`desktop/nsh-shell/src/gateway_probe.rs`）。

## 6. 配置消息通道

Telegram、Discord 和 iMessage 的字段与访问策略由当前通道 schema 定义。建议在 Panel 中配置，或对照对应接口文档编辑 `config.toml`：

- [Telegram](/docs/zh/interfaces/telegram)
- [Discord](/docs/zh/interfaces/discord)
- [iMessage](/docs/zh/interfaces/imessage)

配置完成后重启核心，或按照当前配置热重载影响分类操作。
