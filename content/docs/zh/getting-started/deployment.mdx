## 前台运行

```bash
aleph-server doctor
aleph-server start
```

Gateway 默认监听 `127.0.0.1:18790`，WebSocket endpoint 为 `/ws`。

## 系统服务

`service install` 会生成当前平台的用户级服务描述、启用服务并立即启动：

```bash
aleph-server service install
aleph-server service status
```

支持的管理动作：

```bash
aleph-server service enable
aleph-server service disable
aleph-server service uninstall
```

不存在 `aleph-server service start` 子命令。安装器使用当前可执行文件的绝对路径，并由系统服务管理器运行 `aleph-server start`。

| 平台 | 服务描述 |
|------|----------|
| macOS | `~/Library/LaunchAgents/ai.aleph.server.plist` |
| Linux | `~/.config/systemd/user/aleph-server.service` |
| Windows | 用户登录触发的 Task Scheduler 任务 |

Linux 日志与状态：

```bash
systemctl --user status aleph-server.service
journalctl --user -u aleph-server.service -f
```

在部分 Linux 发行版上，开机前无登录会话时需要启用 linger：

```bash
sudo loginctl enable-linger "$USER"
```

优先使用 `service install`，不要复制包含固定二进制路径的手写 plist 或 systemd unit。

## 直接启用原生 TLS

远程访问必须使用安全传输。无需反向代理时，可启用进程内 TLS：

```toml
[gateway]
host = "0.0.0.0"
port = 18790
allow_insecure_remote = false

[gateway.tls]
enabled = true
# cert_path = "/path/to/cert.pem"
# key_path = "/path/to/key.pem"
# san = ["aleph.example.com"]
```

`cert_path` 与 `key_path` 为空时会生成自签名证书。远程客户端连接 `wss://<host>:18790/ws`，Panel 首次连接通过 TOFU 审批证书。

## 反向代理

反向代理需要转发 HTTP 页面和 `/ws` 的 WebSocket upgrade。Gateway 本身可以保持环回监听：

```toml
[gateway]
host = "127.0.0.1"
port = 18790

[gateway.trusted_proxy]
enabled = true
trusted_ips = ["127.0.0.1", "::1"]
```

只有 `trusted_ips` 中的直接对端才能提供可信的 `X-Forwarded-For` 与 `X-Forwarded-Proto`。

### Nginx

```nginx title="/etc/nginx/sites-available/aleph"
upstream aleph_gateway {
    server 127.0.0.1:18790;
}

server {
    listen 443 ssl;
    server_name aleph.example.com;

    ssl_certificate     /etc/letsencrypt/live/aleph.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/aleph.example.com/privkey.pem;

    location / {
        proxy_pass http://aleph_gateway;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 86400s;
    }
}
```

### Caddy

```txt title="Caddyfile"
aleph.example.com {
    reverse_proxy 127.0.0.1:18790
}
```

## 容器

当前源码树没有维护 Dockerfile 或 Compose 文件，因此本页不把示例容器配方声明为官方支持的部署产物。自建镜像时至少需要：

1. 使用 Rust 1.99+ 构建 `aleph-server`；
2. 持久化 `ALEPH_HOME`；
3. 将容器内 `[gateway].host` 设为 `0.0.0.0`；
4. 只在宿主机环回地址发布端口，或在前方部署 TLS 代理；
5. 显式运行 `aleph-server start`。

## 验证与监控

```bash
aleph-server status
aleph-server gateway call health
```

文件日志位于 `~/.aleph/logs/`，实际文件名由当前日志配置决定。系统服务优先查看 launchd、journald 或 Task Scheduler 的状态与日志。

## 备份

最稳妥的方法是停止写入后备份整个 `ALEPH_HOME`。至少保留：

- `config.toml` 与 `defaults.toml`
- `data/`、`memory/` 与 `artifacts/`
- 用户安装的 `skills/` 与 `plugins/`

不要依赖旧文档中的固定数据库文件名；以当前运行版本实际创建的目录为准。

## 安全检查

- 仅本机使用时保持 `gateway.host = "127.0.0.1"`
- 远程访问使用原生 TLS 或可信 TLS 反向代理
- 保持 `allow_insecure_remote = false`
- 使用 `aleph-server pair` 生成单次配对票据，不在 URL 中传播共享 token
- 保持 `[sandbox.command_policy]` 硬底，并按风险选择 `exec_tier`
- 配置通道 allowlist 与配对策略
