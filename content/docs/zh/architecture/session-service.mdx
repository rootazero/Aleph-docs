---
title: "会话服务"
description: "每会话的仅追加事件日志，配合进程内 tokio actor。"
---

会话服务为每个 Aleph 会话提供持久的、仅追加的事件存储。它取代了原有的 `messages` 表，改用由 SQLite 支撑的结构化事件日志，从而支持崩溃恢复、实时订阅与精确的状态重建。

关于网关如何管理会话，请参阅[网关架构](./gateway)。关于智能体工具链如何消费事件，请参阅[智能体工具链](./harness)。

---

## 概览

`InProcessActorSessionService` 是默认实现。它为每个会话 spawn 一个 tokio 任务。每个任务（`SessionActor`）在启动时从 SQLite 重放事件，然后服务命令，直到收件箱关闭或空闲超时触发。

**位置**：`src/session/in_process.rs`

关键属性：

- **仅追加**：事件永远不会被修改或删除 —— 只能追加到日志末尾。
- **持久**：所有事件在确认前已持久化到 SQLite。
- **每会话一个 actor**：每个会话拥有自己的 tokio 任务，保证顺序与隔离。
- **实时订阅**：消费者可以订阅实时事件流。

## 公共接口

`SessionService` trait 是公共接口：

```rust
#[async_trait]
pub trait SessionService: Send + Sync + 'static {
    /// 确保 actor 在跑；返回当前 head seq
    async fn attach(&self, id: SessionId) -> Result<SessionHandle, SessionError>;

    /// 追加 + 同步持久化；返回新 seq
    async fn emit_event(&self, id: &SessionId, event: SessionEvent) -> Result<EventSeq, SessionError>;

    /// 半开读区间 [from, to)
    async fn get_events(
        &self,
        id: &SessionId,
        from: Option<EventSeq>,
        to: Option<EventSeq>,
    ) -> Result<Vec<SessionEventRecord>, SessionError>;

    /// 实时事件扇出
    async fn subscribe(
        &self,
        id: &SessionId,
    ) -> Result<broadcast::Receiver<SessionEventRecord>, SessionError>;

    /// 强制替换 actor（崩溃恢复）
    async fn wake(&self, id: &SessionId) -> Result<SessionHandle, SessionError>;

    /// 停止 actor，保留事件
    async fn detach(&self, id: &SessionId) -> Result<(), SessionError>;
}
```

**位置**：`src/session/service.rs`

`SessionId` 是 `crate::routing::session_key::SessionKey` 的别名 —— 会话以网关其他各处使用的同一个 key 标识。

## 实现

`InProcessActorSessionService` 持有从 `SessionId` 到该会话 actor 的 mpsc 收件箱的路由表：

```rust
pub struct InProcessActorSessionService {
    store: Arc<dyn SessionEventStore>,
    senders: RwLock<HashMap<SessionId, mpsc::Sender<ActorCommand>>>,
    broadcasters: RwLock<HashMap<SessionId, broadcast::Sender<SessionEventRecord>>>,
    idle_timeout: Duration,
}
```

**位置**：`src/session/in_process.rs`

每个 `SessionActor`（在 `src/session/actor.rs` 定义）在启动时从 SQLite 重放事件，维护内存中的状态（`src/session/state.rs`），并一直处理命令直到关闭。每个 actor 的状态存放在 `src/session/state.rs`；事件类型存放在 `src/session/events.rs`。

## 存储

事件存储在 SQLite 表中：

```sql
CREATE TABLE session_events (
    session_id   TEXT    NOT NULL,
    seq          INTEGER NOT NULL,
    turn_id      TEXT,
    event_type   TEXT    NOT NULL,
    payload_json TEXT    NOT NULL,
    created_at   INTEGER NOT NULL,
    PRIMARY KEY (session_id, seq)
);
```

**位置**：`src/session/store.rs`

加上两个支撑索引（`idx_session_events_session_turn`、`idx_session_events_session_type`）。

| 属性 | 值 |
|----------|-------|
| 写入模式 | 同步（确认前 fsync） |
| SQLite 模式 | WAL（预写日志） |
| 排序 | `(session_id, seq)` 主键强制每个会话单调递增 |

## 事件 schema

`SessionEvent` 是一个 `#[non_exhaustive]` 枚举，覆盖：

| 类别 | 变体 |
|----------|----------|
| 生命周期 | `SessionCreated`, `SessionWoken`, `SessionDetached`, `SessionForked` |
| 运行边界 | `RunStarted`, `RunFinished` |
| 回合边界 | `TurnStarted`, `TurnEnded` |
| 消息 | `UserMessage`, `AssistantMessage`, `AssistantRunMeta`, `SystemMessage` |
| 工具调用 | `ToolCallRequested`, `ToolCallApproved`, `ToolCallDenied`, `ToolResult`, `ToolError` |
| 子代理委派 | `SubagentSpawned`, `SubagentReturned` |
| 预算 / 压缩 | `BudgetUpdated`, `CompactionPerformed` |
| 错误 | `Error` |

**位置**：`src/session/events.rs`

辅助类型：`EventSeq`、`TurnId`、`MessageContent`、`ToolOutput`、`RunOutcome`、`TurnTrigger`、`TurnOutcome`、`ApprovalSource`、`ErrorKind`、`Timestamp`。

## 投影

不是所有消费者都想要原始事件。`project_messages` 辅助函数把事件区间折叠为经典的消息历史视图：

```rust
pub fn project_messages(
    events: &[SessionEventRecord],
) -> Vec<ProjectedMessage>;
```

**位置**：`src/session/projection.rs`

它把 `RunStarted`、`TurnStarted`、`UserMessage`、`AssistantMessage`、`ToolCallRequested`、`ToolResult`、`TurnEnded`、`RunFinished` 折叠成一个线性的 `Vec<ProjectedMessage>`，看起来就像旧的 `messages` 表 —— 对 LLM 上下文窗口和 UI 渲染很有用。

## wake() 语义

`wake(session_id)` 是崩溃恢复机制：

1. **关闭旧 actor**（如有），宽限期 5 秒。
2. **在 spawn 新 actor 前捕获 `prior_head`**。
3. **Spawn 全新 actor** —— 它从 SQLite 重放所有持久化事件。
4. **发出 `SessionWoken { prior_head }`** 标记写入日志。
5. **返回新的 `SessionHandle`**。

中途崩溃的 Harness 会表现为一条没有匹配 `TurnEnded` 的 `TurnStarted` —— 替换上来的 Harness 自己决定是重试、放弃还是用 `Error` 事件关闭回合。

| 参数 | 值 |
|-----------|-------|
| 空闲超时 | 30 分钟 |
| 关闭宽限期 | 5 秒 |

**集成测试**：`tests/session_wake_recovery.rs`

## 网关 RPC 关系

网关 `session.*` RPC 方法仍然在 `SessionManager`（`src/gateway/session_manager/`）。一个双写垫片（`src/session/shim.rs`）把每个 `SessionManager` 的追加镜像进 `SessionService`，让 `session_events` 与遗留的 `messages` 表并行保持填充。

```
网关 RPC（session.append、session.get 等）
        │
        ▼
┌─────────────────┐     ┌──────────────────┐
│  SessionManager │────►│  遗留 messages   │
│                 │     │  表              │
└────────┬────────┘     └──────────────────┘
         │
         │ 双写垫片（src/session/shim.rs）
         ▼
┌─────────────────┐     ┌──────────────────┐
│  SessionService │────►│  session_events  │
│                 │     │  表              │
└─────────────────┘     └──────────────────┘
```

未来阶段会把网关 RPC 直接迁移到 `SessionService`，届时会移除垫片。
