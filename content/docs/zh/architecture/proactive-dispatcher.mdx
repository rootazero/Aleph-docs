> 文档历史版本中的 `daemon::dispatcher` 模块、顶层 `daemon` 目录、`ProposedAction` / `PolicyEngine` / `DispatcherMode` 枚举**已全部移除**。本页描述当前 `src/tasks/cron/` 与 `src/tasks/heartbeat/` 中的真实代码，附 `src/tasks/shared/`、`src/runtimes/` 协作。

主动后台任务现在由两条正交的服务组成：
- **Cron**（`src/tasks/cron/`）—— 计划任务，按 cron 表达式 / 间隔 / 一次性触发
- **Heartbeat**（`src/tasks/heartbeat/`）—— 周期探针 + L1 probe + L2 LLM 判官

它们共享 `src/tasks/shared/`（`clock` / `delivery` / `schedule` / `reaper`）。

---

## 概览

主动调度支持：
- **Cron 计划** —— cron 表达式 / 间隔 / 一次性 / 链式触发（`on_success` / `on_failure`）
- **Heartbeat 探针** —— 周期性 L1 探针 + 主动 wake，由 LLM 判官决定
- **Runtimes 能力 ledger** —— `src/runtimes/` 通过 Probe → Bootstrap → Register 三阶段管理外部工具（python / node / uv / ffmpeg / yt-dlp ...），持久化到 `~/.aleph/runtimes/ledger.json`
- **失败告警 / 投递管道** —— `DeliveryEngine` 把执行结果推送到 webhook / 通知
- **事件总线广播** —— `CronTaskChanged` / `HeartbeatTaskChanged` 推送面板（取代轮询）

## Cron（`src/tasks/cron/`）

```
src/tasks/cron/
├── mod.rs            # 模块入口；导出 CronService / CronJob / ScheduleKind 等
├── config.rs         # CronJob / CronJobView / ScheduleKind / JobStateV2 / CronConfig
├── store.rs          # JSON 原子持久化
├── executor.rs       # 实际执行（执行任务，调用 harness）
├── history.rs        # 运行历史
├── alert.rs          # FailureAlertConfig / FailureAlert 投递
├── chain.rs          # on_success / on_failure 触发（带 cycle detection）
├── template.rs       # Prompt template 渲染（变量替换）
├── stagger.rs        # Hash-based stagger（多个 cron 错峰）
├── carryover.rs      # 跨 daemon 重启的 carryover
├── webhook_target.rs # Webhook 投递目标
└── service/          # ServiceState / ops / timer / concurrency / catchup
    ├── mod.rs
    ├── ops.rs
    ├── timer.rs
    ├── concurrency.rs
    └── catchup.rs
```

`ScheduleKind` 支持：
- `Cron { expression }` —— 5/6 字段 cron 表达式
- `Interval { every_secs }` —— 周期性
- `At { timestamp }` —— 一次性（执行后自动停用）

链式触发由 `chain.rs` 在 `on_success` / `on_failure` 上注册后续 job；cycle detection 阻止自循环。

执行完成后 `DeliveryEngine` 把结果以 `DeliveryTarget::Webhook | DeliveryTarget::Notification | ...` 投递；`FailureAlertConfig` 控制失败告警的频率 / 渠道。

### 启动期注册

完整 RPC 由 `src/bin/aleph-server/commands/start/builder/handlers/agents.rs::register_cron_handlers` 在启动期装配，替换 `cron.*_stub`：

| RPC | 作用 |
|---|---|
| `cron.list` | 列出所有 cron jobs |
| `cron.get` | 取出单条 |
| `cron.create` | 新建（带 `CronConfig.validate()`） |
| `cron.update` | 更新 |
| `cron.delete` | 删除 |
| `cron.status` | 当前执行状态 |
| `cron.run` | 立即触发一次 |
| `cron.runs` | 运行历史 |
| `cron.toggle` | 启用 / 暂停 |

每个成功的写入还会发布 `GatewayEventFrame::CronJobChanged` 事件到 `gateway::event_bus`，面板订阅后能即时刷新（取代 polling）。`carryover::bootstrap_global_carryover_sweeper()` 在首次构造时（`OnceLock` 守卫）全局 spawn 一次 carry-over sweeper。

## Heartbeat（`src/tasks/heartbeat/`）

```
src/tasks/heartbeat/
├── mod.rs            # 模块入口；导出 HeartbeatService / HeartbeatTask
├── config.rs         # HeartbeatConfig / HeartbeatTask / HeartbeatTaskView
├── store.rs          # 持久化
├── executor.rs       # 执行探针
├── probe.rs          # L1 探针
├── dedup.rs          # 去重（避免重复触发）
├── wake.rs           # WakeQueue
├── history.rs        # 探针历史
└── service/          # HeartbeatServiceState / ops / timer
    ├── mod.rs
    ├── ops.rs
    └── timer.rs
```

`HeartbeatService` 维护 `state` + `wake_queue` + 可选 `event_bus`。`wake_queue` 是外部主动 wake 触发器（例如守护进程检测到事件，希望触发立即探针）。

完整 RPC 由 `register_heartbeat_handlers` 装配：

| RPC | 作用 |
|---|---|
| `heartbeat.list` | 列出所有探针 |
| `heartbeat.get` | 取出单条 |
| `heartbeat.create` | 新建 |
| `heartbeat.update` | 更新 |
| `heartbeat.delete` | 删除 |
| `heartbeat.toggle` | 启用 / 暂停 |
| `heartbeat.wake` | 主动 wake 触发（Guardian Judge LLM 判官决定是否需要主动唤醒，**payload 隐藏密钥**） |
| `heartbeat.runs` | 探针历史 |

写入同样发布 `HeartbeatTaskChanged` 事件到 `gateway::event_bus`。

### Guardian Judge

Heartbeat 探针的 LLM 判官：
- 26.7.21+：**payload 隐藏密钥**——敏感凭据不出现在判官 prompt 中
- Heartbeat 探针**拒绝使用危险工具与确认门控工具**

## Runtimes 能力 Ledger（`src/runtimes/`）

```rust
// src/runtimes/mod.rs
pub mod bootstrap;
mod  capability;
pub mod ensure;
pub mod ledger;
pub mod os;
pub mod post_install;
pub mod probe;
pub mod specs;

pub use bootstrap::{dependencies, has_spec, install, BootstrapError, BootstrapResult};
pub use capability::{format_entries_for_prompt, RuntimeCapability};
pub use ensure::ensure_capability;
pub use ledger::{CapabilityEntry, CapabilityLedger, CapabilitySource, CapabilityStatus};
pub use os::TargetOs;
pub use post_install::PostInstallError;
pub use probe::ProbeResult;
pub use specs::{
    find_spec, select_install, supported_on_current_os,
    InstallStrategy, OsInstall, PostInstallAction, RuntimeSpec, SPECS,
};

pub fn get_runtimes_dir() -> Result<PathBuf>;  // ~/.aleph/runtimes/
```

`CapabilityLedger` 取代旧的 `RuntimeRegistry`，仅追踪每个能力的状态（`Missing | Probing | Bootstrapping | Ready | Stale`），从不下载或安装——下载 / 安装由 `Bootstrapper` 完成，检测由 `Prober` 完成。持久化到 `~/.aleph/runtimes/ledger.json`。

三阶段流程：
1. **Probe** —— 检测系统 PATH + Aleph 管理的二进制
2. **Bootstrap** —— 通过 shell 脚本安装缺失工具
3. **Ledger** —— 把状态写入 `ledger.json`

`ensure_capability(name, &ledger)` → `Result<bin_path>` 是 `exec` 层用于 PATH 注入的统一入口。

## 历史：已移除的 components 模块

本页早期版本记载过一个顶层 `components` 薄壳模块（`mod.rs` + `types/`），承载旧 EventHandler 链路（`IntentAnalyzer` / `TaskPlanner` / `ToolExecutor` / `LoopController` / `SessionRecorder` / `SessionCompactor`）的共享域类型。该链路在 Harness 迁移期间已删除，剩余骨架随后作为死脚手架整体删除（提交 `682e49adc`，"components: cut entire module"）。cron / heartbeat 不依赖它；事件系统位于 `src/event/`。

## 与历史"daemon::dispatcher"的差异

- **没有 `ProposedAction` / `PolicyEngine` / `DispatcherMode`**——风险评估、策略执行由执行引擎的 `PermissionLayer` + `ContextRuleLayer` + `SmartFilter` 统一处理
- **没有顶层 `daemon` 目录**——cron / heartbeat 直接位于 `src/tasks/`
- **没有独立的通知队列 / 调度 DAG**——通知通过 `DeliveryEngine` 与 gateway `event_bus` 走总线
- **没有 `ActionExecutor` 子组件**——执行通过 `execution_engine::RunRequest` 复用现有 harness
