弹性系统是 Aleph 的持久化与状态层。`src/resilience/` 经过 agent-loop 迁移后**只保留数据库层（`StateDatabase`）和共享类型**——治理、协作、感知、恢复中间件已迁出；高层恢复逻辑由 `src/agents/` 中的 harness 与 gateway 的事件总线协同完成。

> `src/resilience/mod.rs` 在 26.7.x 的迁移后只导出 `database` 与 `types`：
> ```
> pub mod database;
> pub mod types;
> ```
> Recovery、collaboration、shadow replay 子模块不再存在；它们的功能由 `src/agents/swarm/tasks/`、`src/harness/trace.rs`、`src/gateway/event_bus.rs` 协作完成。

## StateDatabase

`StateDatabase` 是弹性系统的持久化支柱，基于 SQLite（rusqlite）：

| 表 / 实体 | 用途 | 关键字段 |
|---|---|---|
| **AgentEvent** | 分层事件持久化（骨架 + 脉冲） | `task_id`, `seq`, `event_type`, `is_structural` |
| **AgentTask** | 任务状态与恢复元数据 | `id`, `status`, `risk_level`, `lane`, `checkpoint_snapshot_path` |
| **TaskTrace** | Shadow Replay 的执行追踪 | `task_id`, `step_index`, `event`, `timestamp` |
| **group_chat** | 群聊历史 | per-team 持久化 |
| **memory_events** | memory 系统事件 | 写入记录 |
| **paired_users** | 配对用户记录 | pairing |
| **channel_offsets** | 通道读取偏移 | 用于 webhook / event source resync |

`memory_stats` 与 `agent_usage_total` 由 `AgentUsageTotal` / `MemoryStats` 导出，被 `src/memory/` 中的 recall 与 experience-store 子模块复用。

### 事件层级：骨架和脉冲

事件遵循两层持久化模型：

```rust
impl AgentEvent {
    // 结构化事件（Skeleton）—— 立即持久化
    pub const TYPE_TASK_STARTED:      &str = "task_started";
    pub const TYPE_TOOL_CALL_STARTED:  &str = "tool_call_started";
    pub const TYPE_TOOL_CALL_COMPLETED:&str = "tool_call_completed";
    pub const TYPE_ARTIFACT_CREATED:   &str = "artifact_created";
    pub const TYPE_TASK_COMPLETED:     &str = "task_completed";
    pub const TYPE_TASK_FAILED:        &str = "task_failed";

    // 流式事件（Pulse）—— 持久化前批量处理
    pub const TYPE_AI_STREAMING:       &str = "ai_streaming";

    pub fn structural(task_id, seq, etype, payload) -> Self { /* is_structural = true */ }
    pub fn pulse(task_id, seq, etype, payload)      -> Self { /* is_structural = false */ }
}
```

**骨架事件**代表必须在崩溃后存活的状态转换。它们同步写入并用于恢复。**脉冲事件**是高频流式数据（逐 token 输出），可批量处理并可在不影响正确性的情况下丢弃。

## 核心类型（`src/resilience/types.rs`）

### `AgentTask`

```rust
pub struct AgentTask {
    pub id: String,
    pub parent_session_id: String,
    pub agent_id: String,              // "explorer" / "coder" / ...
    pub task_prompt: String,
    pub status: TaskStatus,
    pub risk_level: RiskLevel,
    pub lane: Lane,
    pub checkpoint_snapshot_path: Option<String>,
    pub last_tool_call_id: Option<String>,
    pub recursion_depth: u32,
    pub parent_task_id: Option<String>,
    pub created_at: i64,
    pub updated_at: i64,
    pub started_at: Option<i64>,
    pub completed_at: Option<i64>,
    pub metadata_json: Option<String>,
}
```

辅助构造器：`AgentTask::new`（默认 `Pending` + `Subagent` lane）、`with_parent_task`（递归深度）、`with_lane`、`should_auto_resume`（仅 `RiskLevel::Low`）、`needs_resume_confirmation`（仅 `RiskLevel::High`）。

### `TaskStatus`

```rust
#[serde(rename_all = "snake_case")]
pub enum TaskStatus {
    Pending,
    Running,
    Completed,
    Failed,
    Interrupted,   // 系统关闭时被打断
    Idle,          // Session-as-a-Service 暂停
    Swapped,       // 上下文换出到磁盘
}

impl TaskStatus {
    pub const fn is_recoverable(&self) -> bool {
        matches!(self, Self::Running | Self::Interrupted)
    }
}
```

### `RiskLevel`

```rust
pub enum RiskLevel { Low, High }
```

- `Low`：只读操作；重启时安全自动恢复
- `High`：写操作；需用户确认

### `Lane`

```rust
pub enum Lane { Main, Subagent }
```

- `Main`：用户交互、中止命令（高优先级）
- `Subagent`：后台工作（正常优先级）

主通道不会被子代理工作饿死。面向用户的请求（对话、中止命令）始终获得优先调度。

### `TaskTrace`

```rust
pub struct TaskTrace {
    pub id: i64,                // 数据库分配
    pub task_id: String,
    pub step_index: u32,        // 0-based
    pub event: AgentTraceEvent, // 来自 aleph_protocol
    pub timestamp: i64,
}

impl TaskTrace {
    pub fn new(task_id, step_index, event) -> Self;
    pub fn with_timestamp(self, ts: i64) -> Self;   // 替换 new() 设的 wall-clock；用于 ordered fixture
    pub const fn event_kind(&self) -> &'static str;
}
```

`AgentTraceEvent` 来自 `aleph_protocol`（统一协议 crate）；`task_id` 与 `step_index` 由调度器写入；`event_kind()` 返回稳定字符串用于索引与过滤。

## Shadow Replay 与状态恢复

### 状态机示意

```
                 ┌──────────┐
                 │ Pending  │
                 └────┬─────┘
                      │ start
                 ┌────▼─────┐
         ┌──────│ Running  │──────┐
         │      └────┬─────┘      │
     SIGTERM       │        │   error
         │         │ success │     │
     ┌────▼──────┐  │  ┌────▼────┐ │
     │Interrupted│  │  │Completed│ │
     └───────────┘  │  └─────────┘ │
                    │              │
                    └─► Failed ◄───┘
```

`is_recoverable()` 只在 `Running` 或 `Interrupted` 上返回 `true`——这两个状态由 `RiskLevel` + trace 可用性驱动恢复决策。

### 决策逻辑（由 `agents/swarm/tasks/` + `harness/trace.rs` 协作实现）

```
对于每个 status = Running | Interrupted 的任务：
    │
    ├── trace 不可用？
    │   └── Skip（"没有可用的执行追踪"）
    │
    ├── RiskLevel::Low？
    │   └── AutoResume（Shadow Replay + 继续）
    │
    └── RiskLevel::High？
        └── PendingConfirmation（等待用户审批）
```

只读操作（文件搜索、代码分析）可安全自动重试；写操作（文件修改、shell 命令）需要人工确认，因为自中断以来系统状态可能已经改变。

## Trace 数据流

```
执行期：每个 step 产生一个 LoopTraceEvent
    │
    ▼
harness::trace::TraceSink::on_trace（src/harness/trace_sink.rs）
    │
    ▼
GatewayTraceSink → TraceFlushHandle → TracePersistence::record
（src/gateway/execution_engine/trace_sink_adapter.rs、callback.rs）
    │
    ▼
task_traces 表（INSERT 见 src/resilience/database/traces.rs:133，
表结构见 src/resilience/database/state_database/schema.rs:261）
```

`TraceSink` 的实现方**不得阻塞**：sink 是在 harness 的异步任务里被调用的，一旦阻塞就等于把整个 harness 循环压住。所以生产路径用 `GatewayTraceSink`，它同步转发进 `TracePersistence::record`，而后者为每个事件 spawn 一个写任务并持有句柄供 `flush` 使用——harness 侧那次调用因此从不阻塞。

无人值守的运行另走 `UnattendedRedactingSink`（`src/gateway/execution_engine/unattended_redacting_sink.rs`）：脱敏在**写入端**只做一次，`task_traces` 行、频道消息与 WS `agent_trace` 镜像共用同一份已脱敏内容。重放由 trace replay 处理器（`src/gateway/handlers/trace_replay.rs`）只读 `task_traces` 表完成。

`LoopTraceEvent::SessionCompleted`（`src/harness/trace.rs:59`）是「一次运行结束了」的结构化事实：`outcome` / `iterations` / `tool_calls_made` / `total_tokens` / `hit_limit` / `final_text` / `terminate_reason`（`src/orchestrator::dispatch::TerminateReason`，精确的循环退出原因）。用量聚合则直接扫 `task_traces` 中 `event_kind = 'provider_usage'` 的行（`aggregate_usage_by_agents`，`src/resilience/database/traces.rs:298`），不另建统计表。

## 失败关闭
