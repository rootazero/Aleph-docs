> **本页替代旧的「世界模型」章节**。源码中并不存在 `daemon::worldmodel` 模块或 `WorldModel` / `CoreState` / `EnhancedContext` / `PendingAction` / `ActivityType` 等类型——这些概念在 26.7.x 治理拓扑重构后已被替换为下面描述的 `loop_graph` 层与 `graph_topology` 提示层。

## 概览

`loop_graph` 是叠加在 Aleph 核心之上的**治理拓扑层**（governance topology），给多代理 / 自改进系统提供一对闭合的拓扑边，回答单循环的四种失败模式（Goodhart、参考盲、环冲突、测量衰减）：

- **锚点（anchor）** —— 不可反驳的测量
- **冻结（frozen）** —— 在其它地方强制执行的规则
- **根（root）** —— 人类提供的「更好」定义（`origin=human` 由 store 强制）
- **配对（watches）** —— 监督关系
- **层级（owns_reference）** —— 引用归属
- **仲裁（arbitrates）** —— 冲突裁决
- **审计（audits）** —— 闭环审计日志

源码：`src/loop_graph/`（`mod.rs` / `service.rs` / `store.rs` / `templates.rs` / `types.rs`）。Store 由 `init_global(Arc<LoopGraphStore>)` 在 boot 时安装一次（`OnceCell`），未初始化的进程读为「无 graph 子系统」（fail-soft）。

边界（R7/R9/R10）：该模块只做脚手架——拓扑存储、结构 lint、事实渲染。任何**语义性裁决**（这是否廉价？这个引用是否错了？冲突哪边胜？）都是普通的 LLM turn，由 `templates.rs` 与 `loop-governance` skill 引导；它**位于 `src/harness/` 之外**，graph 为空时每个 turn 的成本为零。Dreaming 与其它 optimizer 在这里没有写路径——拓扑是 held-out layer，监督它们。

## graph_topology 提示层

`graph_topology` 不是独立模块，而是 `src/thinker/layers/graph_topology.rs` 中的一个 **PromptLayer**：

```rust
pub struct GraphTopologyLayer;

impl PromptLayer for GraphTopologyLayer {
    fn name(&self) -> &'static str { "graph_topology" }
    fn priority(&self) -> u32 { 1754 }                 // 排在 standing_goal 之前
    fn paths(&self) -> &'static [AssemblyPath] {
        &[AssemblyPath::Basic, AssemblyPath::Cached]
    }
    fn stability(&self) -> LayerStability { LayerStability::Dynamic }
    fn supports_mode(&self, mode: PromptMode) -> bool { mode != PromptMode::Minimal }

    fn inject(&self, output: &mut String, input: &LayerInput) {
        let Some(ctx) = input.context else { return };
        let Some(topology) = ctx.graph_topology.as_deref() else { return };
        if topology.is_empty() { return };
        output.push_str("<loop_graph_context>\n");
        output.push_str(&crate::thinker::xml_util::escape_xml(topology));
        output.push_str("</loop_graph_context>\n\n");
    }
}
```

被治理的会话每个 turn 都会被告知自己在治理拓扑中的位置——谁在监督它、谁拥有它的引用（以及修改引用的 proposal-note 路径）、哪些锚点约束它、根引用原文是什么。模型不需要「记住」这个图。

缓存纪律：渲染内容**仅来自 graph 行**——没有时钟、没有计数器——所以未变更的 graph 字节稳定。**未治理的会话（`None`）不输出任何东西**：零成本，对所有不在图中的会话不产生影响。

## 与 1-2-3-4 模型的关系

```
┌───────────────────────────────────────────────────────────────┐
│   1. 核心 (alephcore)                                          │
│      ├── harness/        Think→Act 循环                       │
│      ├── thinker/        提示组装（含 GraphTopologyLayer）    │
│      └── ...                                                    │
│                                                                  │
│   ▲ loop_graph 叠加在 1 之上（不改变 1-2-3-4）                 │
│   │   - 拓扑存储 + Lint + 事实渲染                              │
│   │   - 语义裁决交给 LLM turn                                   │
│   ▼                                                              │
│   loop_graph/  (src/loop_graph/)                                 │
│      ├── store.rs       LoopGraphStore (SQLite)                  │
│      ├── service.rs     GraphService                             │
│      ├── templates.rs   模板提示                                │
│      └── types.rs       NodeKind / EdgeKind / Origin            │
└───────────────────────────────────────────────────────────────┘
```

graph 与完成度判断**无关**——它只描述关系，不告诉 harness 何时停止。`AgentHarness` 仍然由 `TurnState::Done` / `max_iterations` / `ToolLoopVerifier` / 连续失败上限来决定停手。

## 多代理 × graph 融合

- **团队节点（team node kind）** —— `NodeKind::Team`，把多代理系统融合进 graph。
- **审计环（audit ring）** —— 闭合审计动作日志。
- **客观 ACL** —— 按图节点身份授权（`origin=human` 不可绕过）。
- **胜利声明 watcher** —— 团队 / 循环完成触发审计。
- **内置 `loop-auditor` agent** —— 审计 / 监督默认走独立上下文证据。

## 配置

graph 是**进程内全局**（`OnceCell<Arc<LoopGraphStore>>`），不在 TOML 中配置。其生命周期与 store 数据库一致：

- 启动期：`LoopGraphStore::open(&dir)` 安装到 `init_global(...)`。
- 运行期：进程内任意处通过 `loop_graph::global()` 读访问。
- 测试：`loop_graph::set_global_for_test(store)`。

## 代码位置

- `src/loop_graph/mod.rs` —— `LoopGraphStore` + `NodeKind` / `EdgeKind` / `Origin` 重导出 + `init_global` / `global`。
- `src/loop_graph/store.rs` —— SQLite 持久化层（节点 / 边 / origin=human 强制）。
- `src/loop_graph/service.rs` —— `GraphService`（写入 / lint）。
- `src/loop_graph/templates.rs` —— 模板提示（给 LLM turn 用）。
- `src/thinker/layers/graph_topology.rs` —— 把拓扑注入系统提示的 `GraphTopologyLayer`。

## 26.7.x 补充

### `loop_graph` 是叠加层，不是替换

26.7.21+：`loop_graph` 不改变 1-2-3-4 模型——它叠加在核心之上，给多代理系统补上治理拓扑（团队节点 / 审计环 / 客观 ACL / 胜利声明 watcher）。harness 不知道 graph 的存在。

### graph_topology = 唯一进入提示的形态

26.7.21+：graph 不让 harness「询问」拓扑（会破坏缓存纪律）；相反，`GraphTopologyLayer` 在每个 turn 把当前 topology 渲染成 `<loop_graph_context>` 段，让模型读到。
