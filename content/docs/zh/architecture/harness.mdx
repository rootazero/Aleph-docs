# 工具链

`AgentHarness` 驱动编排器分发的每一次 flow 的 **Think → Act** 循环。所有代理执行——包括子代理生成——都经过 `Orchestrator::dispatch` → `AgentHarnessRunner::run` → `AgentHarness`。工具链由编排器构建，接收预解析的依赖项（`SessionService`、`ToolService`、`Sandbox`、`AiProvider`，以及可选的 `PowerCapability`）。

**位置**: `src/harness/`

---

## 内部循环

```
┌────────────────────────────────────────────────┐
│                AgentHarness                    │
├────────────────────────────────────────────────┤
│  ┌──────────┐   ┌──────────┐   ┌──────────┐    │
│  │ 准备     │──▶│ 思考     │──▶│ 解析     │    │
│  │ • 预算   │   │ • LLM    │   │ • 解析   │    │
│  │ • 上下文 │   │ • 决定   │   │ • 工具   │    │
│  │ • 验证   │   └──────────┘   └────┬─────┘    │
│  └──────────┘                      │           │
│                             ┌──────┴─────┐     │
│                             │  行动      │     │
│                             │ • 执行     │     │
│                             │ • 并发     │     │
│                             └──────┬─────┘     │
│                                    │           │
│                             ┌──────┴─────┐     │
│                             │ 完成       │     │
│                             │ • 跟踪     │     │
│                             │ • 持久化   │     │
│                             │ • 决策     │     │
│                             └────────────┘     │
└────────────────────────────────────────────────┘
```

准备阶段向上下文预算查询压力信号，挑选正确的 paradigm，并询问验证器链。思考阶段调用提供商、应用输入/输出护栏、合并瞬态上下文。解析阶段解析响应并决定是否执行。行动阶段执行工具调用——串行或按资源声明并发。完成阶段刷新跟踪事件、把事件写入 `SessionService`、并发出 `TurnStep`。

## 核心结构

```rust
pub struct AgentHarness {
    deps: HarnessDeps,                         // 构建时注入的所有依赖
    stall_tracker: Option<StallTracker>,       // 失速检测的活动追踪器
    hit_limit: AtomicBool,                     // 任何上限触发提前退出时置位
    total_tokens: AtomicU64,                   // 整个 run 的累计 token
    terminate_reason: Mutex<TerminateReason>,  // 精确的循环退出原因
    tool_timeline: Mutex<Vec<ToolInvocation>>,  // 每个工具的耗时 / 成功
}
```

`AgentHarness` 除计数器外没有状态——所有真实状态都在 `SessionService`。依赖通过 `HarnessDeps` 在构建时注入。

## 循环输出类型

`src/harness/trait_def.rs` 定义循环控制接口：

```rust
pub enum TurnState {
    Continue,   // 再跑一个 Think→Act 轮次
    Done,       // 循环结束；不再需要轮次
}

pub struct TurnStep {
    pub state: TurnState,
    pub executed: usize,                // 本轮成功执行的工具调用数
    pub vetoed: bool,                   // 验证器驳回了本轮（强制 Continue + 重试）
    pub split_child: Option<SessionId>, // 若分裂出子会话则为子会话 id
}

pub enum HarnessError {
    Llm(AlephError),
    Tool(ToolError),
    Session(SessionError),
    Cancelled,
    StalledTurn { elapsed: Duration },  // Think 超过 turn_timeout；Act 由各工具自己的时钟约束
}
```

编排器通过 `Arc<dyn HarnessRunner>` 多态分发工具链运行。旧的工具链 trait 及其默认 `run()` 循环没有消费者；独立且未使用的会话驱动 trait 已在 `01ba2bd2f` 中移除。

外层循环 `AgentHarness::run` 反复调用 `run_turn_internal`，直到它返回 `TurnState::Done` 或 `CancellationToken` 触发。

## Act 阶段并行组

Act 按 **资源声明** 给工具调用分桶，**桶内**并发 / **桶间**串行。工具声明以下三种之一：

| 声明 | 含义 |
|------|------|
| `Shared` | 与任何其他声明无冲突 |
| `Exclusive { Global }` | 互斥整个执行（如全局配置、worktree） |
| `Exclusive { Paths }` | 互斥一组特定的文件路径 |

两个基于模型**原始**参数被判定为不相交的调用必须保持不相交：若任何护栏**改写**了参数（PII 掩码），整批必须串行化——否则两个不同路径可能塌成同一个占位符而发生竞态。

跨批去重：在同一批或跨批中重复的 `(name, args)` 复用首次结果，不会执行两次。

每次调用的耗时由其**工具自身**的预算限定，在 `src/tools/scoped/dispatch.rs::execute_inner` 处收口。run 级 `turn_timeout` 只约束 Think；每调用超时在下一轮 Think 中表现为 `ToolError::Timeout`。

## 工具循环验证器

`src/verification/` 提供轮次级的后置验证链，在 Think 与 Act 之间被询问。阻塞型裁决强制多走一次 `Continue`，让模型对失败做出反应。验证**不是**硬停启发式：只有模型显式 `stop` 才能干净地结束一个轮次。

## 睡眠抑制器

每个 Think→Act 轮次通过 `PowerCapability::inhibit_sleep("Aleph agent loop")` 获取一个平台睡眠抑制。在 macOS 上它返回 `PreventUserIdleSystemSleep` 类型的 `IOPMAssertion`；在 Linux 与 Windows 上由桌面平台层做等效接线。返回的 RAII 守卫在其被丢弃的瞬间释放断言，所以一个长时间运行的代理轮次不会被主机空闲静默截断。

守卫在 Think 阶段顶端（`src/harness/agent/think.rs`）获取，并在轮次返回时自动释放——成功、错误或取消均可。

```bash
pmset -g assertions | grep "Aleph agent loop"
```

轮次完成的瞬间断言从列表中消失。

实现文件：
- `PowerCapability` trait: `desktop/shared/src/traits/power.rs`
- macOS IOPMAssertion FFI: `desktop/macos/src/sleep_inhibitor.rs`
- 工具链接线: `src/harness/agent/think.rs`
