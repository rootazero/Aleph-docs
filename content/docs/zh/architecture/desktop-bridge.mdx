本页说明 Aleph 如何截屏、读无障碍树、模拟输入、访问日历联系人等桌面能力：这些能力由哪些 crate 定义和实现、运行在哪个进程里、哪些调用会转给平台原生助手，以及出错时如何恢复。

## 桌面能力层是什么

桌面能力层是一组 Rust 库，**直接编译进 `aleph-server`**，不是独立进程：

| crate | 路径 | 作用 |
|---|---|---|
| `aleph-desktop` | `desktop/shared/` | 定义能力 trait、共享实现、Swift 助手客户端 |
| `aleph-desktop-macos` | `desktop/macos/` | macOS 实现 |
| `aleph-desktop-linux` | `desktop/linux/` | Linux 实现 |
| `aleph-desktop-windows` | `desktop/windows/` | Windows 实现 |

根 `Cargo.toml` 里 `alephcore` 直接依赖 `aleph-desktop`，并按目标平台分别依赖三个平台 crate。平台对象在进程内构造（`src/executor/builtin_registry/builder/constructor/mod.rs`、`src/bin/aleph-server/commands/start/builder/handlers/settings.rs`）。

各能力通过聚合 trait `DesktopPlatform`（`desktop/shared/src/platform.rs`）暴露。其中 `ax()` 与 `power()` 返回 `Option`，平台可以声明不提供该能力。

<Callout type="info" title="不要与 Panel 桥混淆">

本页的「桥」指 `aleph-server` 与 macOS Swift 助手之间的 JSON-RPC 通道。桌面宿主与 Panel 之间的 `desktop/nsh-shell/src/panel_bridge.rs` 是另一回事，见 [Panel 宿主](../desktop-hosts/panel)。

</Callout>

## 两条实现路径

### 进程内 Rust 实现

大多数能力直接在 `aleph-server` 进程内执行。例如 macOS 的系统能力用 objc2 原生调用（`desktop/macos/src/system/mod.rs`），自动化走 `osascript` 与 `shortcuts` 命令行（`desktop/macos/src/automation.rs`），阻止休眠用 IOPMAssertion（`desktop/macos/src/sleep_inhibitor.rs`）；Linux 与 Windows 没有常驻助手进程，实现位于各自平台 crate 内，按需调用系统 API 或系统命令行工具。`docs/reference/DESKTOP_BRIDGE.md` 把这种分工定为设计：剪贴板、应用启动、窗口枚举、屏幕录制这类轻量路径留在 `aleph-desktop` 进程内。

### 委托给 Swift 助手

只有 macOS 会把较重的采集与识别能力委托给 Swift 助手进程：相机、音频、Vision OCR、语音、EventKit、联系人等（`docs/reference/DESKTOP_BRIDGE.md`）。Swift 包位于 `desktop/macos/bridge/`，`desktop/macos/src/pim.rs` 的注释写明 PIM 实现委托给 `aleph-bridge` Swift CLI，经长期存活的 JSON-RPC 客户端通信。客户端 `SwiftBridge` 定义在 `desktop/shared/src/bridge/client.rs`，只有 macOS crate 使用它。

每个 `aleph-server` 进程只有一个共享助手实例，首次使用时才启动（`desktop/macos/src/lib.rs` 的 `SHARED_BRIDGE`）。助手可执行文件按以下顺序查找（同文件的 `resolve_helper_path`）：

1. 环境变量 `ALEPH_BRIDGE_PATH`
2. `~/.aleph/helpers/AlephBridge`
3. 与当前可执行文件同目录
4. 开发构建产物：Swift 包 `desktop/macos/bridge/` 下的 `.build/release/AlephBridge`

助手只有一种运行模式：无参数启动，通过 stdin/stdout 收发 JSON-RPC，stdin 收到 EOF 或父进程死亡时退出（`desktop/macos/bridge/Sources/AlephBridge/main.swift`）。

### 协议

协议定义在 `shared/protocol/src/desktop_bridge/`，按行分隔的 JSON-RPC 2.0。信封类型（`shared/protocol/src/desktop_bridge/envelope.rs`）：

```rust
Request       { jsonrpc, id: u64, method, params: Option<Value> }
Response      { jsonrpc, id: u64, result }
ErrorResponse { jsonrpc, id: Option<u64>, error: RpcError }
RpcError      { code: i32, message, data: Option<Value> }
Notification  { jsonrpc, method, params }
```

请求 ID 是递增的 `u64`。

服务器自定义错误码（`shared/protocol/src/desktop_bridge/errors.rs`）：

| 常量 | 值 | 客户端映射为 `DesktopError` |
|---|---|---|
| `ERR_PERMISSION_DENIED` | -32001 | `PermissionDenied { kind, guide }`；`data` 无法解析为指引时为 `BridgeFailed` |
| `ERR_NOT_IMPLEMENTED` | -32002 | `NotImplemented` |
| `ERR_PLATFORM` | -32003 | `PlatformError` |
| `ERR_TIMEOUT` | -32004 | `BridgeTimeout` |
| `ERR_HELPER_CRASHED` | -32005 | `BridgeFailed` |
| `ERR_BRIDGE_DISABLED` | -32006 | `BridgeDisabled` |

映射函数是 `desktop/shared/src/bridge/client.rs` 的 `map_bridge_error`，未知错误码同样落到 `BridgeFailed`。

方法分七个命名空间（`shared/protocol/src/desktop_bridge/methods/`），每个命名空间有默认超时，个别方法覆写：

| 命名空间 | 方法 | 默认超时 | 覆写 |
|---|---|---|---|
| `bridge.*` | `bridge.handshake`、`bridge.ping` | 5 s | `ping` 2 s |
| `ax.*` | `query_focused`、`query_tree`、`query_by_role`、`set_value`、`perform_action`；通知 `ax.mutation` | 15 s | `query_focused` 3 s |
| `input.*` | `click`、`double_click`、`type_text`、`key_combo`、`key_button`、`scroll`、`drag`、`hover`、`cursor_position`、`mouse_button` | 2 s | `click`、`double_click` 5 s |
| `media.*` | `media.camera.snap`、`media.camera.clip`、`media.audio.list_devices`、`media.audio.record`、`media.audio.record_start`、`media.audio.record_stop`、`media.speech.transcribe_file` | 60 s | `media.camera.snap` 10 s，`media.audio.list_devices` 5 s，`media.audio.record_stop` 15 s |
| `perm.*` | `perm.check`、`perm.guide`、`perm.open_settings` | 10 s | — |
| `pim.*` | `notes`、`calendar`、`reminders`、`contacts`、`mail` 五组共 24 个方法 | 60 s | — |
| `screen.*` | `screen.capture`、`screen.ocr`、`screen.list_displays` | 10 s | `ocr` 20 s，`list_displays` 5 s |

`input.*` 的投递方式有 `DELIVERY_TARGETED = "targeted"` 与 `DELIVERY_GLOBAL = "global"` 两种（`shared/protocol/src/desktop_bridge/methods/input.rs`）。窗口与剪贴板操作不走助手协议，在进程内完成。

## 助手生命周期与故障处理

### 惰性启动

`SwiftBridge::ensure_running`（`desktop/shared/src/bridge/client.rs`）在第一次调用时启动助手：三路标准流都用管道，`kill_on_drop(true)`，助手放进自己的进程组；助手的 stderr 逐行转发到 tracing 目标 `bridge_stderr`。握手协议版本 `BRIDGE_PROTOCOL_VERSION = 2`。检查与启动在同一把状态锁内完成，不会重复启动。

读循环在助手 stdout 收到 EOF 时排空在途请求、重置状态槽位并记一次崩溃；代际计数器防止过期的读循环误改新助手的状态。启动失败本身也记作一次崩溃。

### 退避与禁用

退避与禁用逻辑在 `desktop/shared/src/bridge/supervisor.rs`，客户端以 `SpawnGate::new(5, 10 min)` 构造：

| 机制 | 代码行为 |
|---|---|
| 退避阶梯 | `Backoff::next_delay`：1 s、2 s、4 s、8 s、16 s，之后封顶 30 s |
| 阶梯复位 | 助手存活满 `STABLE_UPTIME`（10 s）后再死亡，阶梯从头开始；单纯成功启动不复位 |
| 退避期内调用 | 不真正启动，返回 `DesktopError::BridgeBackoff`，消息形如 `helper recovering; retry in Ns` |
| 禁用阈值 | 10 分钟窗口内的失败次数**超过** 5 次，即第 6 次失败时，进入禁用 |
| 禁用后调用 | 立即返回 `DesktopError::BridgeDisabled("restart threshold exceeded")`，直到服务器重启 |

### 每次调用的超时

挂死但不关闭 stdout 的助手不会触发 EOF，因此每次调用都有截止时间。`SwiftBridge::call` 按 `rpc_timeout_for` 取值：先查方法覆写，再查命名空间默认值（`shared/protocol/src/desktop_bridge/methods/mod.rs` 的 `suggested_timeout_ms`），都没有时用 `DEFAULT_RPC_TIMEOUT`（1 分钟）。超时返回 `BridgeTimeout`，助手继续运行。

时长随参数变化的调用用 `call_with_timeout` 显式给出截止时间（`desktop/macos/src/lib.rs`）：`media.camera.clip` 与 `media.audio.record` 为请求时长加 `CAPTURE_TIMEOUT_MARGIN_SECS`（30 s），`media.speech.transcribe_file` 为 `SPEECH_TRANSCRIBE_TIMEOUT`（5 分钟）。

### 父进程死亡看门狗

`aleph-server` 的 SIGTERM 处理会调用 `std::process::exit`，绕过 Rust 的 `Drop`，助手的 stdin 不一定会被关闭。为此助手内置看门狗（`desktop/macos/bridge/Sources/AlephBridge/RPC/ParentWatch.swift`）：

- 快速路径：对父进程 PID 注册 `DispatchSource` 进程退出事件（kqueue），注册后再复查一次以避免竞态；
- 兜底路径：每 10 s 检查 `getppid() <= 1`，成立则输出 `aleph-bridge: parent died, exiting` 并 `exit(0)`。

### 错误类型

`DesktopError`（`desktop/shared/src/error.rs`）的变体：`NotAvailable`、`ScreenCapture`、`InputFailed`、`OcrFailed`、`WindowFailed`、`NotImplemented`、`BridgeFailed`、`BridgeTimeout`、`BridgeBackoff`、`BridgeDisabled`、`PlatformError`、`PermissionDenied { kind, guide }`。调用方据此区分「助手无响应」「助手在崩溃循环」「系统权限未授予」。

## 工具编排层

`src/builtin_tools/desktop/` 是面向智能体的工具编排，运行在 `aleph-server` 进程内，只通过 `DesktopPlatform` 调用平台能力，不直接调用系统 API：

| 文件 | 职责 |
|---|---|
| `mod.rs`、`types.rs` | `DesktopTool` 与参数类型 `DesktopArgs` |
| `native.rs` | 指针与键盘动作，选择输入轨道 |
| `ax.rs` | 三个只读的无障碍查询，基于 `DesktopPlatform::ax()` |
| `observe.rs` | 动作之后的观察 |
| `gui_locate.rs` | 自然语言描述到屏幕坐标（`desktop_gui_locate`） |
| `set_of_marks.rs` | 标记集截图（`desktop_som`） |
| `verify_state.rs` | 基于无障碍树的三态后置条件校验 |
| `focus_gate.rs` | `type_text` 之前的焦点预检 |
| `perm.rs` | 权限检查（`desktop_check_permissions`） |

### 两条输入轨道

`src/builtin_tools/desktop/native.rs` 的 `enum Rail { Targeted(i32), Global }` 区分两种投递：

- **定向**（targeted）：事件只投进一个目标进程的队列，不移动用户光标。参数里给出 `pid`、`app` 或 `window_id` 即选择定向轨道。
- **全局**（global）：经系统级 HID 事件注入，会移动用户光标。

在支持定向输入的平台上，全局指针默认被拒绝，除非配置 `[desktop] allow_global_pointer = true`（`src/config/types/desktop.rs`）。拒绝是有意的失败关闭，不会静默退回全局轨道。是否支持定向输入由 `supports_targeted_input` 决定：trait 默认返回 `false`，各 `*_targeted` 方法默认返回 `NotImplemented`（`desktop/shared/src/traits/screen.rs`），目前只有 macOS 返回 `true`（`desktop/macos/src/screen.rs`）。

## 红线对应

红线 R1「大脑与四肢绝对分离」要求 `src` 中不直接调用平台系统 API，核心只定义能力契约，物理实现由平台侧提供（`docs/reference/REDLINES.md`；另见 [红线](../philosophy/redlines)）。

- `src/builtin_tools/desktop/` 是工具编排，只依赖 `DesktopPlatform` trait，所以不违反 R1。
- 平台实现全部位于 `desktop/{macos,linux,windows}`。`docs/reference/DESKTOP_BRIDGE.md` 写明 `alephcore` 的 `src/` 不链接 AVFoundation、Vision、AppKit、CoreGraphics、Speech。
- R1 有一处明文例外：进程隔离相关的内核操作必须由派生子进程的父进程就地发起（`docs/reference/REDLINES.md`），这类代码不属于桌面能力层。

## 历史：独立的 aleph-bridge 进程

- Swift 助手最早按「每次调用派生一次」的 CLI 子命令方式工作。`ParentWatch.swift` 的注释仍提到这种一次性子命令模式，但当前 `AlephBridge/main.swift` 只保留 JSON-RPC 模式。
- 2026-04-24 的一组提交把它改为长期存活的子进程：`7ed5a051d` 把 bridge 拆为 `desktop/shared` 内的独立模块，`92533821d` 引入长期存活的 `SwiftBridge` 客户端（stdin/stdout 上按行分隔的 JSON-RPC），`1fc069a49` 加入退避重启与禁用模式。
- 当前助手只承担 macOS 上较重的采集与识别能力；macOS 的媒体能力已不再有 Rust 侧的 AVFoundation 实现，统一经助手（`desktop/macos/src/lib.rs`）。
- 2026-08-09 移除了 `media.audio.mic_meter` 方法及其超时覆写（`shared/protocol/src/desktop_bridge/methods/media.rs` 的注释）。
