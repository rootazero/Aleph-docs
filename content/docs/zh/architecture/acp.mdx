`acp` 模块实现 [Agent Client Protocol (ACP)](https://github.com/agentclientprotocol/agent-client-protocol)，把外部 CLI 工具作为一等 ACP adapter 集成进 Aleph。

> 文档历史版本的 `AcpManager::create_session / send_message / stream_response` 已被 `AcpAdapterManager`（`src/acp/manager/`）替代。会话生命周期、持久化与重新授权都集中在 `manager/` 子模块下。

## 概览

ACP 管理外部 CLI 工具作为 ACP adapter，支持两种执行模式：
- **`NativeAcp`** —— 持续 stdio 上的完整 ACP 协议（Gemini CLI `--acp`）。lazy-start 会话，子进程死了自动重启
- **`Oneshot`** —— 每次 prompt spawn 新进程（Claude Code `--print`、Codex `exec`）。无持久会话

支持的 adapter：Claude Code、Codex（OpenAI）、Gemini CLI，以及 `acp/adapters/custom.rs` / `acp/adapters/generic.rs` 暴露的任意 CLI harness。

## 核心组件

### `AcpAdapterManager`（`src/acp/manager/mod.rs`）

```rust
pub struct AcpAdapterManager {
    pub(super) adapters: RwLock<HashMap<String, Arc<dyn AcpAdapter>>>,
    pub(super) configs:  RwLock<HashMap<String, AcpAdapterEntry>>,
    pub(super) sessions: /* NativeAcp harness 的活跃会话，按 (harness_id, cwd) 键控 */,
}

pub struct SessionEntry {
    pub session: Arc<AsyncMutex<AcpSession>>,
    pub cancel:  CancelHandle,        // 直写 session/cancel 给子进程 stdin
}
```

支持：
- 运行时动态 harness 注册 / 注销（harness_admin）
- 启动期 `wire_persistence` 从磁盘恢复 sessions
- 并发 prompt 在同一 (harness, cwd) 通过内层 mutex 串行化；不同 key 并行推进
- `cancel` 不需要持有 session mutex——能中断正在 in-flight prompt

### `AcpAdapter` trait（`src/acp/adapter.rs`）

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum AdapterMode {
    NativeAcp,  // 完整 ACP 协议（initialize → session/new → session/prompt）
    Oneshot,    // 每次 prompt spawn 新进程，读 stdout
}

#[async_trait]
pub trait AcpAdapter: Send + Sync {
    fn id(&self) -> &str;                  // "claude-code" / "codex" / "gemini"
    fn is_available(&self) -> bool;
    async fn execute(&self, cwd: &str, args: &[String]) -> Result<AcpOutput>;
    // …
}
```

`AdapterMode::as_str` 给出稳定的 wire 标签（`native_acp` / `oneshot`），与 serde rename 对齐。

### `AcpSession`（`src/acp/session.rs`）

```rust
pub struct AdapterConfig { /* command / args / env / mode */ }
pub struct PersistedAcpSession { /* harness_id / acp_session_id / cwd / session_name / created_at */ }
pub struct AcpSession { /* harness_id / acp_session_id / cwd / adapter */ }
pub struct CancelHandle;       // 可 clone；直写 session/cancel 给子进程 stdin
```

`AcpSession::harness_id()` / `acp_session_id()` / `is_alive()` / `cancel_handle()` 是常用句柄。

### 会话事件

```rust
pub enum AcpSessionEvent {
    Created { harness_id, acp_session_id, cwd, session_name: Option<String> },
    Removed { harness_id, cwd, session_name: Option<String> },
}

pub type PersistenceHook = Arc<dyn Fn(AcpSessionEvent) + Send + Sync>;
```

`session_name` 为 `None` 表示默认未命名 session；`Some(name)` 表示同一 `(harness, cwd)` 下的并行命名 session（仿 acpx 的 `-s backend` / `-s frontend`）。`PersistenceHook` 用于磁盘持久化；独立于 live-broadcast 的 `AcpSessionsChangedNotifier`（用于 `acp.sessions.changed` 推送）。

## 运行模式

### 工具模式（Tool Mode）

LLM 通过 ACP adapter 分派只读操作：

```
LLM ──> Tool Call ──> ACP Adapter ──> External CLI
         (只读)        (claude-code read)
```

### 代理模式（Agent Mode）

用户直接与外部工具对话：

```
User ──> Aleph ──> AcpAdapterManager ──> External CLI
              (完整读/写)
```

## RPC 接口（启动期 `register_acp_handlers` 注册）

| 分组 | 方法 |
|-------|---------|
| Adapter CRUD | `acp.create`、`acp.delete`、`acp.get`、`acp.list`、`acp.update` |
| Adapter 预设 | `acp.presets`、`acp.presets_meta`、`acp.test`、`acp.set_enabled` |
| 会话 | `acp.sessions_list`、`acp.sessions_cancel`、`acp.sessions_shutdown` |

完整注册位于 `src/bin/aleph-server/commands/start/builder/handlers/agents.rs::register_acp_handlers`（同一文件里的 `register_cron_handlers` / `register_heartbeat_handlers` 同源）。

## 配置

```toml
[acp]
enabled = true
default_adapter = "claude-code"

[acp.adapters.claude-code]
command = "claude"
args = ["--output", "json"]

[acp.adapters.codex]
command = "codex"
args = []
```

## 进程隔离内核

ACP 会话由进程隔离内核支撑：沙箱 restricted-token / job-object / AppContainer / integrity-level / SID·ACL 系统调用在 spawn 时就地发起（[R1 例外](/docs/zh/philosophy/redlines#r1-大脑与四肢绝对分离brain-limb-separation)）。
