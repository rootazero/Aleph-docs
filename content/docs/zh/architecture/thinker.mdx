# 思考器

思考器负责所有 LLM 交互与提示组装。唯一的公共入口是 `thinker::PromptBuilder`，它包装了一个 `PromptPipeline`。旧的 `agent_loop::PromptBuilder` 在工具链迁移（第 6/7 阶段）期间被删除。

**位置**: `src/thinker/`

---

## 组件

| 组件 | 文件 | 用途 |
|-----------|------|---------|
| `PromptBuilder` | `prompt_builder/` | 为子代理与主循环路径构建系统提示 |
| `PromptPipeline` | `prompt_pipeline.rs` | 基于有序层列表的可组合提示组装引擎 |
| `PromptLayer` | `prompt_layer.rs` | 单个层的 trait；声明 priority / paths / stability |
| `PromptConfig` | `prompt_builder/` | 用户可调的提示开关（`language`、`extra_files`、…） |
| `InteractionManifest` | `interaction.rs` | 频道能力感知（paradigm + capabilities + constraints） |
| `SecurityContext` | `security_context.rs` | 策略驱动的权限 |
| `ContextAggregator` | `context.rs` | 把 interaction + security 调和为 `ResolvedContext` |
| `PromptMode` | `prompt_mode.rs` | `Full` / `Compact` / `Minimal` 模式过滤 |
| `IdentityFiles` | `identity_files.rs` | 已加载的 `SOUL.md` / `IDENTITY.md` / `AGENTS.md` / `TOOLS.md` / `HEARTBEAT.md` |

| `MessageAssembler` | `src/gateway/message_assembly/assembler.rs` | 单一 reducer，对一次 run 的流式可见文本做归约；实时剥离推理 / 记忆包装（唯一消费者：执行引擎的 event drain） |

## PromptBuilder

```rust
// 子代理内联提示（扁平字符串，无缓存分裂）
let prompt = builder.build_system_prompt(&tools);

// 主循环提示分裂为可缓存的 Stable 前缀 + Dynamic 后缀
let prompt = builder.build_system_prompt_cached_with_mode(&tools, &soul, profile, PromptMode::Full);

// 代理定义（子代理角色标头 + 协议块）
let prompt = builder.build_for_agent(&agent_def, &tools, &soul);
```

主循环路径发出一个 `SystemPromptPart` Stable 前缀（可被 LLM 提供商缓存）和一个无标记的 Dynamic 尾部。Cached 路径是生产入口；Basic 路径用于内联子代理提示。

## 36 层

`PromptPipeline::default_layers()` 注册 **36 层**（按优先级排序），由 `test_default_layers_count` 锁定（`assert_eq!(pipeline.layer_count(), 36)`）。**19 层**位于 **Stable** 前缀区（优先级 `< 1700`，符合 section 级缓存资格），**17 层**位于 **Dynamic** 后缀区（优先级 `>= 1700`，从不缓存）。区分由 `stable_layers_come_before_dynamic` 锁定。

### Stable 区（优先级 < 1700）

内容很少变化——符合提供商的 section 级缓存资格。

| 优先级 | 层 | 说明 |
|----------|-------|-------|
| 50 | `SoulLayer` | `~/.aleph/agents/{id}/SOUL.md` |
| 55 | `AgentRoleLayer` | 子代理角色标头 + 协议块 |
| 60 | `CuratedMemoryLayer` | 预渲染的 `<CuratedMemory>` + `<UserProfile>` 信封 |
| 70 | `StrategyLayer` | 活动的 StraTA 策略（焊接的 `<strategy>` 信封） |
| 75 | `ChainContextLayer` | 子代理委派深度（根 ⇒ 静默） |
| 100 | `ProfileLayer` | `AGENTS.md` 工作空间覆盖 |
| 200 | `RoleLayer` | 基础助手角色 |
| 300 | `EnvironmentLayer` | 进程不变的一半（Stable 事实：机器 / OS） |
| 400 | `RuntimeCapabilitiesLayer` | 检测到的 Python / Node / FFmpeg 运行时 |
| 502 | `ToolRuntimeStateLayer` | 30s-TTL 工具健康缓存的快照 |
| 600 | `SecurityLayer` | 跨工具安全姿态（仅 Static 区事实） |
| 605 | `ProtocolTokensLayer` | Background paradigm 的 JSON-RPC 协议令牌 |
| 700 | `OperationalGuidelinesLayer` | Background 操作规则 |
| 800 | `MultiStepConductLayer` | 自主 scratchpad 规划 + 交互式进度叙述 |
| 810 | `ProviderGuidanceLayer` | `model_behaviors/{family}.md` 基线 + 增量 |
| 900 | `SessionBudgetLayer` | 解析后的 per-run `iteration_cap` |
| 950 | `CitationStandardsLayer` | 引用格式 |
| 1050 | `SkillInstructionsLayer` | 活动技能指令 |
| 1100 | `SpecialActionsLayer` | 自我纠错日志 + flagging |
| 1300 | `GuidelinesLayer` | 一般指南 |
| 1600 | `LanguageLayer` | `[general] language` 配置的响应语言 |

### Dynamic 区（优先级 ≥ 1700）

每个请求的内容——从不缓存。17 层（由 `dynamic_names.len() == 17` 锁定）。

| 优先级 | 层 | 说明 |
|----------|-------|-------|
| 1701 | `RuntimeContextLayer` | 每 run 变化的一半（cwd、时间）——与 `EnvironmentLayer` 分离 |
| 1702 | `ToolRuntimeStateLayer` 原本位于 502；移至 Dynamic，避免探测翻转使缓存前缀失效 |
| 1715 | `DoctorRepairHintLayer` | WebRich paradigm + 失败的 doctor 检查 |
| 1720 | `VoiceModeLayer` | 语音转写轮次 |
| 1725 | `McpInstructionsLayer` | 已连接的 MCP 服务器指令 |
| 1730 | `IdentityFilesLayer` | `IDENTITY.md` / `TOOLS.md` / `HEARTBEAT.md` |
| 1735 | `ExtraFilesLayer` | `[prompt.extra_files]` |
| 1740 | `MemoryProtocolLayer` | 跨工具记忆写入指引 |
| 1750 | `TimerLoopLayer` | 活动 watch loop 状态 |
| 1753 | `GraphTopologyLayer` | loop-graph 治理拓扑 |
| 1754 | `StandingGoalLayer` | 活动常驻目标 |
| 1755 | `ExecutionPlanLayer` | 至少有 1 项的活动 scratchpad 计划 |
| 1756 | `StrategyPointerLayer` | 在读头附近回显策略护栏 |
| 1757 | `SessionContextGuideLayer` | 带有压缩摘要的历史 |
| 1758 | `OperatingEnvelopeLayer` | 审批 tier + usage mode（Dynamic，使 composer 药丸翻转不会让前缀失效） |
| 1760 | `AgentCatalogLayer` | 可用子代理目录 |
| 1799 | `ProviderGuidanceLayer` 运行时增量 | 每请求 `behavior_name` 解析 |

已作为死注入面删除的层：`ToolsLayer`（文本 schema 回退；原生 `tool_use` 总是胜出）、`ToolUsageGrammarLayer`、`ThinkingGuidanceLayer`、`GenerationModelsLayer`、`CustomInstructionsLayer`、`InboundContextLayer`、`SessionResumeLayer`、`McpResourceIndexLayer`、`McpToolIndexLayer`、`HydratedToolsLayer`、`SkillModeLayer`、`HeartbeatLayer`、`ResponseFormatLayer`、`MemoryAugmentationLayer`。R9 三把棘轮（`reachable_layers`、`scaffold_bytes_ratchet`、`no_sentence_is_stated_twice`、`no_environment_fact_is_stated_twice`）锁住存活集合。

## 组装路径

`AssemblyPath` 只有**两个**变体——幽灵路径正是层静默消失的途径，所以每个变体有且仅有一个入口。

| 路径 | 说明 |
|------|-------------|
| `Basic` | 子代理内联提示——单一扁平字符串，无缓存分裂。入口：`PromptBuilder::build_system_prompt`（subagent_spawner）。 |
| `Cached` | 主循环提示——分裂为可缓存的 Stable 前缀 + Dynamic 后缀。入口：`PromptBuilder::build_system_prompt_cached_with_mode`（harness_bridge::prompt_build）。 |

原来的 `Hydration` / `Soul` / `Context` 路径已被撤回；它们最后的真实调用方早在数月前就已迁出，提示侧代码已不可达。

## 骨架字节棘轮

`prompt_contract::scaffold_bytes_ratchet` 跨 5 个 paradigm 测量 always-on 提示骨架，并强制 `SCAFFOLD_CEILING_BYTES = 5_913`（2026-07-26，WebRich 最坏情况）。上限取跨 paradigm 的最大值而非单一选定的 paradigm，因为没有 paradigm 占主导：

```
Background  4,904 B  （守护进程默认 paradigm）
CLI         ~5,140 B
Messaging   ~5,200 B
WebRich     5,913 B   ← 上限（Background 独有 + MultiStepConductLayer + DoctorRepairHintLayer）
Embedded    ~5,000 B
```

字节预算由 `aleph-server prompt-size --path cached --paradigm <paradigm>` 测量，作用于 `production_shaped` 的 `LayerInput`——后者会填上 4 个始终存在的字段（`runtime_context`、`approval_tier`、`session_mode`、`sandbox_summary`），确保棘轮的视野与网关实际发出的字节一致。

---

## 会话模式

`chat` / `work` / `code` 是用户选定的工具**呈现面**的静态分区，与权限正交（审批仍由 exec tier 决定）。每个模式在 `OperatingEnvelopeLayer` 加上一行缓存稳定的提示，使模式翻转把字节从缓存前缀移至 Dynamic 后缀。

---

## UnifiedMessage 与 ProviderDelta

`UnifiedMessage` 是 LLM 无关的中间消息表示；`ProviderDelta` 是流式输出（`TextDelta` / `ThinkingDelta` / `ToolCallDelta`）。单一 `MessageAssembler` reducer 拥有组装中的消息并实时剥离内联 `<think>` 块。工具链桥接（`src/harness/agent/think.rs`）把借用的 `HarnessCallback` 包成 `DeltaSink`，让实时 token 增量在提供商流式输出时进入网关回调。

---

## `tool_search` 元工具

26.7.7+ 渐进式工具披露：请求携带**静态**的核心工具集 + 全量工具目录名称列表，加 `tool_search` 作为按需加载 schema 的元工具。模型 100% 驱动发现；工具链不做任何基于消息内容的工具过滤（R10「5 不」#2）。静态分区同样位于 `src/tools/scoped/`（allowlist / 权限 Deny / 健康闸门 `retain` 链），那在工具层，不在工具链。

## R10 的三把棘轮

| 测试 | 文件 | 守护 |
|------|------|--------|
| `reachable_layers` | `src/thinker/prompt_contract.rs` | 每个注册层要么在某些 paradigm 下贡献内容，要么列入 `CONDITIONALLY_SILENT` 并说明唤醒它的会话内容 |
| `scaffold_bytes_ratchet` | `src/thinker/prompt_contract.rs` | always-on 提示在所有 paradigm 下 ≤ `SCAFFOLD_CEILING_BYTES` |
| `no_sentence_is_stated_twice` | `src/thinker/prompt_contract.rs` | 跨层句子级重复被禁止 |

`aleph-server prompt-size` 报告任意 paradigm 的实际字节数与逐层明细。

## 思考级别

```rust
pub enum ThinkingLevel {
    Off,        // 无扩展思考
    Minimal,    // budget_tokens: 1024
    Low,        // budget_tokens: 2048
    Medium,     // budget_tokens: 4096（默认）
    High,       // budget_tokens: 8192
    XHigh,      // budget_tokens: 16384
}
```

级别经由 `FlowRequest::think_level` 传递，并被转发进 `HarnessRunner::run`，写入 `HarnessDeps` 让每个 `RequestPayload` 都带上它。原生不支持扩展思考的提供商优雅降级——OpenAI 的 o-series 路径原生接受该级别，Gemini 用 `thinkingPreface` 提示词拐弯。

## 流式架构

```
LLM 响应流
    │
    ▼
┌─────────────────────────────────────────┐
│ 提供商（HTTP / 原生 SDK）                │
│   • 流式块 → ProviderDelta               │
│   • TextDelta  → 实时预览                │
│   • ThinkingDelta → 推理通道             │
│   • ToolCallDelta → 由汇编器折叠         │
└────────────────────┬────────────────────┘
                     │
                     ▼
           MessageAssembler（单一 reducer）
             • 拥有进行中的消息
             • 实时剥离内联 `<think>`
             │
             ▼
       AssistantMessage（SessionEvent）
```

工具链的 `CallbackSink` 把借用的 `HarnessCallback` 桥接进提供商层的 `DeltaSink`；文本与思考增量被转发用于实时预览，工具调用与簿记增量由提供商的 `DeltaCollector` 折叠，并通过组装好的 `ProviderResponse` 浮出。
