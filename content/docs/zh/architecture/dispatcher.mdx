# 分发器

分发器就是 `Orchestrator`——网关聊天入口与驱动每个 run 的工具链之间的缝。它**不**建模多步 DAG 计划：旧的 `TaskGraph` 概念已在第 6/7 阶段工具链迁移时退役。今天的编排器职责是：接受任意 channel 发来的 `FlowRequest`，解析正确的 `FlowSpec` + 沙箱 + 工具链，并生成产出 `FlowOutcome` 的 `HarnessRunner` 任务。

**位置**: `src/orchestrator/dispatch.rs`

> **注意**：源码树中没有独立的 dispatcher 模块。历史上的 Dispatcher 模块——`ToolRegistry`、`RiskEvaluator`、`ToolIndex`、`HydrationResult`——已在第 6/7 阶段工具链迁移期间被解散。工具聚合现在位于 `src/tools/registry.rs`，执行器位于 `src/executor/`，工具调用护栏位于 `src/tools/scoped/`。

## 拓扑

```
网关（聊天入口、协议适配器）
   │ FlowRequest { agent_id, input, tool_service, trace_sink, … }
   ▼
编排器（解析 AgentDef + FlowSpec，构建 HarnessDeps，分发）
   │ HarnessRunner::run
   ▼
AgentHarness（Think → Act 循环、验证器、压缩）
   │ 使用
   ├── SessionService  （每个会话的仅追加事件日志）
   ├── ToolService     （工具目录 + 执行）
   ├── Sandbox         （执行环境、能力账本）
   └── AiProvider      （LLM）
   │
   ▼
FlowOutcome → 网关渲染响应
```

所有代理执行——包括子代理生成——都通过编排器 → 工具链路由。工具链内部没有独立的分发器；Think 阶段解析模型的工具调用，Act 阶段执行它们。

## 编排器状态

```rust
pub struct Orchestrator {
    pub flow_registry: Arc<FlowRegistry>,
    pub routing_overrides: Arc<RoutingOverrides>,
    pub default_routing: Arc<HashMap<AgentId, FlowId>>,
    pub session_service: Arc<dyn SessionService>,
    pub sandbox_factory: SandboxFactory,
    pub harness: Arc<dyn HarnessRunner>,
    pub subagent_routing: Option<ProviderChain>,
    pub agent_registry: Option<Arc<AgentRegistry>>,
    active_sessions: Arc<Mutex<HashSet<String>>>,
}

#[async_trait]
pub trait HarnessRunner: Send + Sync {
    async fn run(
        &self,
        session_key: String,
        spec: FlowSpec,
        input: FlowInput,
        sandbox: Arc<dyn Sandbox>,
        event_tx: broadcast::Sender<FlowStreamEvent>,
        cancel: CancellationToken,
        tool_service: Option<Arc<dyn ToolService>>,
        trace_sink: Option<Arc<dyn TraceSink>>,
        interaction_manifest: Option<InteractionManifest>,
        workspace_override: Option<PathBuf>,
        max_iterations_override: Option<u32>,
        transient_context: Option<String>,
        think_level: Option<ThinkLevel>,
        envelope: TurnEnvelope,
        model_directive: Option<SessionModelPref>,
    ) -> Result<FlowOutcome, FlowError>;
}
```

`Orchestrator::with_subagent_routing` 与 `with_agent_registry` 在启动时挂上 provider chain 与共享 agent registry，让生成的子代理看到用户自定义 agent 和故障转移链。

## 七步分发

`Orchestrator::dispatch` 是固定序列（设计 §6）。每一步只做一件事；失败即短路调用。

| # | 步骤 | 源码 |
|---|------|------|
| 1 | 由显式 `flow_id` 或按 agent 路由解析 `FlowSpec` | `flow_registry.resolve` / `resolve_flow_id` |
| 2 | 强制深度闸门（`MAX_FLOW_DEPTH`） | `resolver::depth_guard` |
| 3 | agent 查找下放到 `HarnessRunner`（它持有 `AgentRegistry`） | — |
| 4 | 解析会话 key + 获取每个会话的锁 | `resolver::resolve_session` + `active_sessions` |
| 5 | brain 选择下放到 `HarnessRunner`（`ProviderRegistry` 在它那里） | — |
| 6 | 配置沙箱（per-request `sandbox_override` 短路工厂） | `sandbox_factory` |
| 7 | 生成工具链任务；把 event / completion / cancel 接回调用方 | `tokio::spawn(harness.run(...))` |

生成动作还在新任务内部重建 `current_project_root` 与 `current_agent_id` task-locals——`tokio::spawn` 不继承 task-locals，而 per-project 记忆缝（`note_manage`、检索汇编器、会话压缩）以及 agent 范围的技能发现（`~/.aleph/agents/<id>/skills`）都读取这些环境值。工具链显式接收 `workspace_override` 用于 CWD + 提示上下文，但 task-locals 必须重新设置，跨会话工具才能看到正确的作用域。

## FlowHandle

```rust
pub struct FlowHandle {
    pub session_key: String,
    pub events: broadcast::Receiver<FlowStreamEvent>,
    pub completion: oneshot::Receiver<Result<FlowOutcome, FlowError>>,
    pub cancel: CancellationToken,
}
```

`FlowStreamEvent` 携带实时增量（`Delta`、`Reasoning`、`ToolCallStart`、`ToolCallDone { duration_ms }`、`ContextGauge`、`SafetyBlock`）以及终止事件 `Complete(FlowOutcome)`。`cancel` 把 `CancellationToken` 传播进工具链任务；取消表现为 `FlowError::Cancelled` 与 `TerminateReason::Cancelled`。

## FlowOutcome

```rust
pub struct FlowOutcome {
    pub final_text: String,
    pub iterations: u32,
    pub tool_calls_made: u32,
    pub total_tokens: u32,
    pub hit_limit: bool,                  // TerminateReason 的向后兼容别名
    pub terminate_reason: TerminateReason,
    pub duration_ms: u64,
    pub token_breakdown: TokenBreakdown,
    pub tool_timeline: Vec<ToolInvocation>,
    pub estimated_cost: Option<CostEstimate>,
    pub context_tokens: u32,
    pub context_window: u32,
    pub serving_model: Option<String>,
    pub serving_provider: Option<String>,
}
```

`TerminateReason` 区分工具链退出的每一个上限位点：`Completed`、`HitMaxIterations`、`ContextBudgetExhausted`、`StallTimeout`、`TurnTimeout { phase }`、`ConsecutiveFailureCap`、`VerifierVeto`、`EmptyResponseExhausted`、`StopHookHalt`、`MaxOutputTokensExhausted`、`ReactiveCompactExhausted`、`Cancelled`，以及 `BudgetExhaustedPartialResult { reason, partial_summary }`——后者在预算上限触发时已经发出有用部分文本时升级（策略由 `escalate_partial_result` 守门）。

`DiminishingReturns` 变体**仅为向后兼容保留**——收益递减的硬停在 R10 下被移除。

## Act 阶段并行组

Act（位于 `AgentHarness::act`）按 **资源声明** 给工具调用分桶，**桶内**并发 / **桶间**串行。工具声明以下三种之一：

| 声明 | 含义 |
|------|------|
| `Shared` | 与任何其他声明无冲突 |
| `Exclusive { Global }` | 互斥整个执行 |
| `Exclusive { Paths }` | 互斥一组特定的文件路径 |

串行模式仅在单调用、并发被禁用、重复调用、或无并行组时回退。两个基于模型**原始**参数被判定为不相交的调用必须保持不相交；任何护栏改写（PII 掩码）会使整批串行化。

跨批去重：在同一批或跨批中重复的 `(name, args)` 复用首次结果。
