> **已删除——历史参考。** 独立的 ClawHub 客户端模块（源码树中的顶层 `clawhub` 模块）不再存在于源码树中。ClawHub 的专属设置标签页已被移除；其发现职责被纳入[扩展商店](/docs/zh/concepts/extensions-store)，以**扩展**为统一概念，按功能类别浏览技能、插件和 MCP 服务器。

如今 ClawHub 仍可通过 **Hub 目录的长尾来源标签**访问：`src/hub/types.rs::ExtensionProvenance::via = "clawhub"`（参见 `src/hub/catalog_client.rs::CatalogEntry.via` 的 `via: "clawhub"` wire 形态）。商店代理读取某个 URL / 仓库安装任何已编排源未覆盖的扩展。下文结构仅作为历史参考。

---

## 历史概览

ClawHub 集成原本让 Aleph 能够：

- **浏览技能** —— 搜索和发现社区技能
- **安装技能** —— 从注册表下载并安装
- **同步元数据** —— 保持技能元数据最新

## 历史架构（已删除）

```
ClawHubClient  （src/clawhub/client.rs——已删除）
  ├── HTTP 客户端 (reqwest)
  ├── 类型 —— 请求/响应模式   （src/clawhub/types.rs——已删除）
  └── 认证 (API token)
```

## 如今的接入路径

- **Hub 目录**（`src/hub/`）作为**扩展**的统一发现层
- ClawHub 内容以 `via: "clawhub"` 的 provenance 标签流入 Hub 目录（`catalog_client.rs` 测试明确 wire `via` 字段）
- 兼容命名空间 `ClawHub` 仍被识别（参考 `src/skill/guard.rs::is_hidden_dir` 与 `src/tools/markdown_skill/spec.rs`）
- 一等源现在是 Claude / Aleph 插件市场、Official MCP Registry、Docker MCP Catalog

## 历史 RPC

历史上曾提供 `clawhub.search` / `clawhub.browse` / `clawhub.detail` / `clawhub.install` 等 RPC；这些端点已在当前源码中移除。
