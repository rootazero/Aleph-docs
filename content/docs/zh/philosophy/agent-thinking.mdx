Aleph 的代理不是一个简单的请求-响应聊天机器人。它是一个认知架构，旨在有目的地追求目标、推理复杂任务并从经验中学习。本页描述了驱动每个代理交互的思维模型 —— 从 Think→Act 循环到平衡速度与深度的双过程认知。

该思维模型借鉴认知科学，特别是 Daniel Kahneman 的双过程理论，并通过 Rust 中的具体架构模式实现。Harness 的角色是**薄**脚手架——所有智能决策由 LLM 一次推理调用自然完成（R10）。

## Think→Act 循环

每个代理交互都遵循 **Think → Act** 循环。这是驱动 Aleph 行为的基本循环：

```
     ┌──────────┐
     │  Think   │  推理该做什么：分类意图、
     │          │  检索经验、规划行动
     └────┬─────┘
          │
          v
     ┌──────────┐
     │  Act     │  执行计划：调用工具、生成
     │          │  响应、修改状态
     └────┬─────┘
          │
          v
     （模型显式 stop → 完成）
```

> 历史上的 OTAF（Observe–Think–Act–Feedback）已退役——`src/agent_loop/` 在 Harness 迁移期间（第 6/7 阶段）被删除。Harness 现在只承载 Think→Act 轮次，**不参与任何推理**（R10「笨循环」）。

### Think

Think 阶段是双过程认知运作的地方（下面详细描述）。模型：

1. 解析用户意图（LLM 一次调用自然完成——Harness 不分类意图）
2. 检索相关上下文（按需 progressive-disclosure 工具 + 记忆系统）
3. 生成计划（LLM 推理 + Thinker 的 prompt 层次）
4. 定义成功（除模型显式 stop 外，Harness 不做完成度判断——R10「5 个不」之 3）

### Act

Act 阶段通过工具系统执行计划：

- **工具调用**：调用内置工具、MCP 服务器、插件或技能
- **资源并发声明**：工具声明 fs/network/process 资源冲突；Act 按声明分桶并行调度，桶内并发、桶间串行
- **去重与备忘**：相同 `(name, args)` 在批次内或跨批次的二次调用复用首次结果
- **响应生成**：为用户生成文本、代码或结构化输出
- **状态修改**：更新记忆、会话状态、签名操作账本
- **子任务编排**：通过 FlowRunTool / Team 创建子代理

所有操作都通过安全守卫系统。潜在危险的操作在执行前需要显式审批（Ask / Auto / Full 三级执行权限 + `[sandbox.command_policy]` 硬底）。

### 完成

只有**模型显式 stop** 才会结束一个轮次（Harness 不会做确定性完成度判断——R10「5 个不」之 3）。`max_iterations` 仍然作为安全上限存在，但实际的「够用」判断由模型做出。

## 双过程认知

受 Daniel Kahneman 的《思考，快与慢》启发，Aleph 实现了双过程认知架构，包含两个互补的系统：

### 系统 1：快速且直观

系统 1 是快速的、基于模式匹配的层。它基于积累的经验提供快速的「直觉」：

- **经验检索**：对过去成功任务完成的向量相似性搜索
- **快速分类**：立即将请求分类为简单（直接处理）或复杂（启动系统 2）
- **think_level = low/off**：默认偏向系统 1

系统 1 是使 Aleph 响应迅速的原因。对于常规任务，模型可以通过识别模式并应用已知解决方案模板几乎立即生成计划。

### 系统 2：缓慢且审慎

系统 2 是深度推理层。它处理直觉不足的情况：

- **LLM 推理**：使用语言模型的完整推理能力来分析复杂问题、生成新颖解决方案和评估权衡
- **think_level = high/xhigh**：偏向系统 2
- **扩展思考**：Claude 的 extended thinking 等
- **多步骤规划**：将复杂目标分解为有序的行动序列，带有依赖关系和回退策略

系统 2 是使 Aleph 具备能力的原因。对于新颖或复杂的任务，模型进行更深入的推理以产生超出模式匹配的解决方案。

### 它们如何协作

两个系统由 LLM 一次调用自然协调——Harness 不参与（**R7 LLM 主权原则**）。模型根据任务复杂度、think_level、可用上下文等因素决定走哪条路。

## 三对维度

Aleph 中有三个用户可调的维度，构成分类用户偏好的核心轴：

| 维度 | 范围 | 默认 | 控制什么 |
|------|------|------|---------|
| `exec_tier`（执行等级） | ask / auto / full | ask | 权限 |
| `thinking`（思考级别） | off → xhigh | medium | 推理预算 |
| `session_mode`（会话模式） | chat / work / code | work | 工具呈现 |

三者是**正交**的。`session_mode` 只对工具**呈现**面做静态分区（progressive-disclosure 核心集 + deferred-tool 层级），**不影响权限**——权限仍由 `exec_tier` 与审批门控制。可在运行时通过 `session_set_mode` 工具切换。

## 第一性原理锚定

在任何任务执行开始之前，Aleph 应用**第一性原理思考**——在开始执行之前定义成功。POE（Principle-Operation-Evaluation）架构在历史中曾起到这个作用，但**已退役**——Aleph 26.5+ 的方法是把 POE 的「智慧」搬到 system prompt 模板中（R9），由 LLM 一次调用自然覆盖所有判断：

```
用户请求 → LLM 推理（含成功定义）→ 执行 → 模型显式 stop
```

Harness 不参与判断意图、不做完成度判断、不做内容审查、不做错误恢复策略选择（**R10 的 5 个「不」**）。Harness 是脚手架，不是认知层。

## 自我学习

思维模型不是静态的。每个成功的任务完成都通过经验固化管道反馈回系统（受 SkillOpt 纪律约束的自我演化）：

1. **记录**：完整的执行跟踪被存储为经验条目
2. **检测**：当积累若干个类似经验时，系统检测到一个重复模式并创建一个候选技能
3. **提升**：当候选技能已被成功重用足够多次且可靠性高时，它被提升为永久技能

永久技能成为系统 1 模式库的一部分，允许模型以更快的思考级别处理以前复杂的任务。这就是代理如何随着时间的推移变得更快、更有能力。

## 整合所有内容

1. **Think→Act 循环** 提供时刻到时刻的执行循环
2. **双过程认知** 平衡速度（系统 1）与深度（系统 2）
3. **思考级别** 将认知努力与任务复杂度相匹配
4. **第一性原理锚定** 确保模型始终知道其目标（在 prompt 中，不在中间件中）
5. **三对维度** 给出用户可调的控制面（exec_tier × thinking × session_mode）
6. **自我学习** 将成功执行转化为可重用的技能

结果是一个不仅仅响应提示，而是**有目的地追求目标、从经验中学习并知道何时请求帮助**的代理。
