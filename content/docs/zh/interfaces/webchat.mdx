WebChat 是 Aleph 的内置基于 Web 的聊天接口。它是一个 **WebAssembly Panel**（`interfaces/webchat/`），由 Gateway 的 HTTP 服务器直接提供，与 WebSocket 端点并存。Panel 是一个 Leptos 应用，挂载到浏览器 `<body>`，通过与其他 Aleph 客户端相同的 JSON-RPC 2.0 协议与 Gateway 对话。

源码入口见 `interfaces/webchat/src/lib.rs`；静态资源服务见 `src/gateway/control_plane/server.rs`。

## 架构

```text

│  │  ┌──────────┐  ┌───────────┐  ┌──────────────────┐    │  │
│  │  │ 消息历史  │  │  输入区域  │  │  流式传输面板     │    │  │
│  │  └──────────┘  └───────────┘  └──────────────────┘    │  │
│  └──────────┬─────────────────────────────────────────────┘  │
│             │ WebSocket（JSON-RPC 2.0）                      │
└─────────────┼────────────────────────────────────────────────┘
              │
┌─────────────┼────────────────────────────────────────────────┐
│             ▼                                                  │
│  ┌────────────────────────────────────────────────────────┐  │
│  │              Gateway HTTP Server                        │  │
```

`interfaces/webchat/src/lib.rs` 导出 WASM 入口：

```rust
#[wasm_bindgen(start)]
pub fn main() {
    panic_overlay::install();
    appearance::init_appearance();
    mount_to_body(app::App);
}
```

Panel 是一个单页应用（SPA）。macOS 应用、[桌面宿主](/docs/zh/desktop-hosts/overview)与 CLI 使用的同一套 JSON-RPC 协议，由 Gateway 在 `/ws` 端点上对外暴露。

## Panel 拓扑

`PanelMode` 有 **10 个变体**：Chat、Dashboard、Memory、Agents、Teams、Projects、Terminal、Extensions、Settings、More。主切换器 `ALL_MODES: [PanelMode; 8]` 包含其中八项（不含 Extensions 和 More），Settings 也在切换器内。定义与导航见 `interfaces/webchat/src/components/mode_sidebar.rs`、`interfaces/webchat/src/components/nav_menu.rs`。

| 分区 | 路由 | 用途 |
|---------|-------|---------|
| Chat | `/chat` | 主对话界面 |
| Dashboard | `/dashboard` | 状态、活动与概览 |
| Memory | `/memory` | 记忆中心 |
| Agents | `/agents` | 浏览和配置智能体 |
| Teams | `/teams` | 多智能体团队 |
| Projects | `/projects` | 项目管理 |
| Terminal | `/terminal` | 操作员终端 |
| Settings | `/settings` | 配置 |

`PanelMode::from_path` 将 `/memory`、`/agents`、`/teams`、`/projects`、`/extensions`、`/dashboard`、`/more`、`/settings`、`/terminal` 映射到对应变体，其余路径回退到 Chat（`interfaces/webchat/src/components/mode_sidebar.rs`）。

- **Extensions**（`/extensions`）与 **More**（`/more`）可达但不参与主切换器。Extensions 故意省略：启动入口在 Chat 侧边栏的 advanced-features 区、项目管理之下；`label_of` / `icon_of` 保留 Extensions 分支仅供触发按钮使用（`interfaces/webchat/src/components/nav_menu.rs`）。详见[扩展商店](/docs/zh/concepts/extensions-store)。
- **Terminal** 导航项对所有人显示，但服务端只允许 operator；拒绝由视图解释，避免把“不允许”误解为“不存在”（`interfaces/webchat/src/components/nav_menu.rs`、`interfaces/webchat/src/components/mode_sidebar.rs`、`src/gateway/handlers/pty.rs`）。
- **More** 是手机端管理分区菜单；桌面不会路由到这里（`interfaces/webchat/src/components/mode_sidebar.rs`）。

按设备族划分的 UI 位于 `interfaces/webchat/src/platform/wide/`、`interfaces/webchat/src/platform/phone/`；tablet 仍是待补屏幕的骨架，不代表已完成的多标签 UI（`interfaces/webchat/src/platform/tablet/mod.rs`）。

## 配置

### Gateway 配置（隐式）

WebChat 使用 Gateway 的 HTTP 服务器。以下绑定与连接数默认值见 `src/gateway/config.rs`：

```toml
[gateway]
host = "127.0.0.1"
port = 18790
max_connections = 100
```

### 显式 WebChat 配置

Panel 由 Gateway 的 ControlPlane 提供，不是独立的 WebChat channel HTTP 服务。静态资源入口见 `src/gateway/control_plane/server.rs`；浏览器来源校验使用 `[gateway]` 的 `allowed_origins`，见 `src/gateway/config.rs`。

### 静态文件目录

Panel 资源在构建时从 `interfaces/webchat/dist/` 通过 `rust_embed` 嵌入二进制，运行时不读取可配置的磁盘目录（`src/gateway/control_plane/assets.rs`）。无扩展名的未知路径回退到嵌入的 `index.html`，不依赖 `fallback_file` 配置（`src/gateway/control_plane/server.rs`）。

## WebSocket 协议

旧 `/ws` 是历史兼容入口，目标协议为 [Protocol v1](/docs/zh/gateway/protocol-v1)；入口实现见 `src/gateway/server/connection/web_v1.rs`。

WebChat 使用标准 JSON-RPC 2.0 协议通过 WebSocket 与 Gateway 通信。

### 连接

```javascript
const ws = new WebSocket("ws://127.0.0.1:18790/ws");
```

旧 `/ws` 入口先发送 `connect` 握手（`src/gateway/handlers/connect.rs`）：

```json
{
  "jsonrpc": "2.0",
  "id": "1",
  "method": "connect",
  "params": {
    "minProtocol": 1,
    "maxProtocol": 1,
    "client": {
      "id": "webchat",
      "version": "1.0.0",
      "platform": "web"
    },
    "role": "operator"
  }
}
```

### 发送消息

`agent.run` 的 `message` 是 `input` 的兼容别名；`session_key` 可选（`src/gateway/handlers/agent.rs`）。

```json
{
  "jsonrpc": "2.0",
  "id": "msg-001",
  "method": "agent.run",
  "params": {
    "message": "今天天气怎么样？",
    "session_key": "agent:main:main"
  }
}
```

### 接收流式事件

订阅流式事件以实时接收响应：

```json
{
  "jsonrpc": "2.0",
  "id": "sub-001",
  "method": "events.subscribe",
  "params": { "topics": ["agent.*", "run.*"] }
}
```

事件作为 JSON-RPC 通知到达：

```json
{
  "jsonrpc": "2.0",
  "method": "stream.response_chunk",
  "params": {
    "type": "response_chunk",
    "run_id": "run-123",
    "seq": 1,
    "delta": "Hello",
    "full_text": "Hello",
    "content": "Hello",
    "chunk_index": 0,
    "is_final": false,
    "is_intermediate": false
  }
}
```

### 事件类型

订阅使用主题名；流式交付使用 JSON-RPC 通知方法名，两者不可混用。`events.subscribe` 的参数是 `topics` 数组（`src/gateway/handlers/events.rs`）；主题与通知映射见 `src/gateway/events/frame.rs`，通知封装见 `src/gateway/event_bus.rs`。

| 订阅主题 | 通知方法 | 描述 |
|-------|-------|-------|
| `agent.response.chunk` | `stream.response_chunk` | 文本增量 |
| `agent.tool.start` | `stream.tool_start` | 工具执行开始 |
| `agent.tool.end` | `stream.tool_end` | 工具执行完成 |
| `run.accepted` | `stream.run_accepted` | 运行已接受 |
| `agent.run.complete` | `stream.run_complete` | 运行完成 |
| `agent.run.error` | `stream.run_error` | 运行错误 |

## 静态文件服务

`/` 提供嵌入的 `index.html`；资源按嵌入路径查找，缺失且含扩展名的路径返回 404，无扩展名路径回退到入口页。响应使用 `Cache-Control: no-cache`，资源支持 ETag 重验证（`src/gateway/control_plane/server.rs`）。

## 嵌入网站

以下示例使用 iframe 加载 Gateway 提供的 Panel（`src/gateway/control_plane/server.rs`）。

### iframe 嵌入

```html
<iframe
  src="http://localhost:18790"
  width="400"
  height="600"
  style="border: none; border-radius: 12px;"
></iframe>
```

### CORS 配置

跨来源 WebSocket 升级使用 `[gateway].allowed_origins` 白名单；这不是为独立 WebChat HTTP 服务配置 CORS。默认不要开启 `allow_any_origin`（`src/gateway/config.rs`）。

```toml
[gateway]
allowed_origins = ["https://your-website.com", "https://app.your-website.com"]
```

## 认证

`connect` 握手区分本机回环授权、设备令牌、配对凭据及历史共享令牌；缺失或无效的凭据不会使远程连接自动获得授权（`src/gateway/handlers/connect.rs`）。不要用旧的 `require_auth = false` 示例作为安全配置。

<Callout type="warn">
远程部署应使用 TLS 并配置可信来源；非回环明文默认被拒绝（`src/gateway/config.rs`）。
</Callout>

## 会话管理

以下示例使用主会话密钥；`agent.run` 允许显式传入 `session_key`（`src/gateway/handlers/agent.rs`）：

```
agent:main:main
```

WebChat UI 可以指定自定义会话密钥以支持多个对话：

```json
{
  "method": "agent.run",
  "params": {
    "message": "你好",
    "session_key": "agent:main:webchat:session-1"
  }
}
```

会话持久化由共享会话管理器处理，其 SQLite 连接见 `src/gateway/session_manager/mod.rs`。

## InteractionManifest

`InteractionManifest` 仍存在于 `src/thinker/interaction.rs`。`src/gateway/channel.rs` 将 `webchat` / `webrich` / `web` / `webhook` 映射为 **WebRich**；以下使用真实构造函数生成范式默认清单；默认能力包括 RichText、CodeHighlight、MultiGroupUI、Streaming、MermaidCharts、ImageInline、Canvas。约束默认 `max_output_chars: None`、`supports_streaming: false`、`prefer_compact: false`，不代表所有浏览器或消息大小都没有限制：

```rust
use alephcore::thinker::interaction::{InteractionManifest, InteractionParadigm};

let manifest = InteractionManifest::new(InteractionParadigm::WebRich);
```

清单中的 `MermaidCharts` 是范式能力声明；不将它等同于当前 Panel 已实现 Mermaid 渲染。具体渲染能力以 `interfaces/webchat/src/components/markdown.rs` 为准。

## 健康检查

HTTP 服务器提供存活探针（`src/gateway/server/probe.rs`）：

```bash
curl http://127.0.0.1:18790/health
```

这可用于监控和负载均衡器健康检查。

## 故障排除

| 问题 | 检查 |
|---------|----------|
| 页面空白 / 资源 404 | 检查运行中的二进制是否嵌入了完整 Panel 构建（`src/gateway/control_plane/assets.rs`） |
| WebSocket 连接被拒绝 | 核对 Gateway 地址、TLS 与 `allowed_origins`（`src/gateway/config.rs`） |
| 认证失败 | 检查 `connect` 凭据；不要依赖已过时的 `require_auth` 开关（`src/gateway/handlers/connect.rs`） |
| 流式传输不工作 | 核对 `events.subscribe` 的 `topics` 及 `stream.response_chunk` 通知处理（`src/gateway/handlers/events.rs`、`src/gateway/events/frame.rs`） |
| SPA 路由异常 | 无扩展名路径才回退到嵌入入口页（`src/gateway/control_plane/server.rs`） |
