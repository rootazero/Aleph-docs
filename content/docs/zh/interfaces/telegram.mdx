Telegram 接口使用 [teloxide](https://github.com/teloxide/teloxide) 框架将 Aleph 连接到 Telegram Bot API。它支持直接消息、群聊、文件附件、内联键盘、Markdown 格式、forum topic 以及 tapback 风格的反应。

## 能力

| 功能 | 状态 |
|---------|--------|
| 文本消息 | 支持 |
| Markdown (MarkdownV2) | 支持 |
| 照片 | 支持（发送和接收） |
| 文档 | 支持（发送和接收） |
| 音频 | 支持（发送和接收） |
| 视频 | 支持（发送和接收） |
| 语音消息 | 支持（接收） |
| 内联键盘 | 支持 |
| 回复线程 | 支持 |
| 消息编辑 | 支持 |
| 消息删除 | 支持 |
| 输入中指示器 | 支持 |
| 反应 | 支持（`setMessageReaction`） |
| 流式协议 | `EditBased` |
| 最大消息长度 | 4,096 字符 |
| 最大附件大小 | 50 MB |

## 前置条件

<Steps>
<Step>

### 使用 BotFather 创建机器人

1. 打开 Telegram 并搜索 [@BotFather](https://t.me/BotFather)
2. 发送 `/newbot` 并按照提示命名你的机器人
3. BotFather 会回复你的 **机器人令牌**（格式：`123456789:ABCdefGHIjklMNOpqrsTUVwxyz`）
4. 安全保存此令牌——它是你机器人的认证凭据

</Step>
<Step>

### 配置机器人设置（可选）

在 BotFather 中，你可以自定义你的机器人：

- `/setdescription` — 设置个人资料中显示的机器人描述
- `/setabouttext` — 设置 "关于" 文本
- `/setuserpic` — 上传个人资料图片
- `/setcommands` — 定义命令菜单（例如 `/start`、`/help`）
- `/setprivacy` — 如果你想让机器人看到所有群组消息（不仅仅是命令和提及），禁用 "隐私模式"

</Step>
</Steps>

## 配置

### 最小配置

```toml
[[channels]]
id = "telegram"
channel_type = "telegram"
enabled = true

[channels.config]
bot_token = "123456789:ABCdefGHIjklMNOpqrsTUVwxyz"
```

### 完整配置参考

```toml
[[channels]]
id = "telegram"
channel_type = "telegram"
enabled = true

[channels.config]
# 来自 @BotFather 的机器人令牌（必需）；支持 ${ENV_VAR} 扩展
bot_token = "${TELEGRAM_BOT_TOKEN}"

# 不带 @ 的机器人用户名（连接时自动检测）
bot_username = "my_aleph_bot"

# 入站消息的 DM 策略：open | allowlist | pairing | disabled
dm_policy = "pairing"

# 群组消息策略：open | allowlist | disabled
group_policy = "open"

# DM 的电话号码 / 用户 id 白名单
allow_from = [123456789, 987654321]

# 群组白名单
allowed_groups = [-1001234567890]

# 群组聊天中需要 @mention（默认：true）
require_mention = true

# 群组中提及检测的机器人名称
bot_name = "Aleph"

# 轮询间隔（默认：1）
polling_interval_secs = 1

# 处理时发送输入中指示器（默认：true）
send_typing = true

# 失败消息的最大重试次数（默认：3）
max_retries = 3
```

<Callout type="warn">
切勿将机器人令牌提交到版本控制。使用环境变量（`${TELEGRAM_BOT_TOKEN}`）或密钥管理器。
</Callout>

### 环境变量模式

最简单的设置使用单个环境变量：

```bash
export TELEGRAM_BOT_TOKEN="123456789:ABCdefGHIjklMNOpqrsTUVwxyz"
```

## 适配器结构

Telegram 接口被拆分为 `src/gateway/interfaces/telegram/` 下一组职责单一的模块：

| 模块 | 职责 |
|--------|----------------|
| `bot_instance.rs` | 每个配置的账号对应一个 teloxide `Bot` |
| `config.rs` / `config_v2.rs` | `TelegramConfig` 与多账号 `TelegramConfigV2` |
| `config_resolver.rs` | 把多账号配置解析为单一有效视图 |
| `access.rs` | 粗粒度 DM/群组预过滤（`AccessController`）——只丢弃明显应丢弃的流量 |
| `approval.rs` | `TelegramChannelApprovalCapability`（交互式审批按钮） |
| `chunking.rs` | 长消息分片 |
| `delivery.rs` | 出站发送流水线 + 速率限制处理 |
| `error_cooldown.rs` | 每会话错误冷却 + 输入中断路器 |
| `handlers.rs` | bot 派发 handler（命令、回调、文本） |
| `mention.rs` | `@mention` 解析 / 剥离 |
| `offset.rs` | 持久化轮询 offset 跟踪器（与 iMessage BlueBubbles 共享） |
| `polling.rs` | 长轮询循环 |
| `reaction_handler.rs` | 处理状态反应（👀 / 👍 / 👎） |
| `sticker.rs` | sticker 处理 |
| `streaming/` | `EditBased` 流式（lane tracker、orchestrator、telegram event emitter） |

适配器**不拥有**配对状态。它把未知发送者交给入站路由；路由才是 access / pairing / allowlist 决策的**单一来源**（参见[接口概览](/docs/interfaces/overview)）。

## Access / Pairing / Allowlist——单源到路由器

`AccessController::check_message()` 返回三种裁决之一（`src/gateway/interfaces/telegram/access.rs`）：

- `Allowed`——已静态白名单，或 DM 策略是 `open` / 平凡禁用。
- `NeedsPairing`——DM 策略是 `pairing` 且发送者尚不为人知。适配器把消息交给路由；路由负责配对码签发、过期与审批（`channel.pairing.list` / `approve` / `reject` / `revoke`）。
- `Denied`——静默丢弃（群组不被允许、DM 策略 `disabled` 等）。

不再有每频道的配对数据库：26.7.21 移除了频道本地配对存储。配对状态由 Gateway 的 `PairingStore`（SQLite）持久化，操作员在 Panel 中通过 `channel.pairing.approve` / `reject` 处理新配对请求。`TelegramConfigV2 → ChannelConfig` 桥接把所有 DM/群组/白名单规则送进路由，因此在 `config.toml` 中改一处就是路由强制的一处。

## 长轮询 vs Webhook

Aleph 支持两种从 Telegram 接收更新的模式：

### 长轮询（默认）

机器人定期向 Telegram 的服务器请求新更新。这是默认设置，开箱即用，无需额外基础设施。

**优点：**

- 无需公共 URL 或 SSL 证书
- 在 NAT 和防火墙后工作
- 设置简单

**缺点：**

- 稍高的延迟（可通过 `polling_interval_secs` 配置）
- 保持与 Telegram 服务器的持久连接

### Webhook 模式

Telegram 通过 HTTPS POST 请求将更新推送到你的服务器。在频道配置中通过 `webhook` 段启用。

**优点：**

- 更低的延迟（即时交付）
- 对高流量机器人更高效

**缺点：**

- 需要公共 HTTPS 端点
- 需要有效的 SSL 证书（或带 `certificate` 字段的自签名证书）

## 用户和群组白名单

### 查找用户 ID

Telegram 用户 ID 是数字。要查找用户的 ID：

1. 让用户向 [@userinfobot](https://t.me/userinfobot) 发送消息
2. 或使用 `getUpdates` API 查看原始消息数据

### 白名单行为

```toml
# 空列表 = 允许所有人（受 dm_policy 约束）
allow_from = []

# 仅允许特定用户
allow_from = [123456789, 987654321]
```

当 `dm_policy = "allowlist"` 且发送者不在 `allow_from` 中时，消息被静默丢弃。当 `dm_policy = "pairing"` 且发送者尚未被批准时，路由签发配对码。

### 群聊行为

当 Aleph 在群组中收到消息时：

1. 检查组 ID 是否在 `allowed_groups` 中（或列表为空）
2. 检查发送者是否在 `allow_from` 中（或列表为空）
3. 如果两者都通过，将消息路由到 Agent

<Callout type="info">
默认情况下，Telegram 机器人在 "隐私模式" 下只能看到提及机器人的消息或以 `/` 开头的消息。如果你想让 Aleph 看到群组中的所有消息，请通过 BotFather 禁用隐私模式（`/setprivacy`）。
</Callout>

## 媒体处理

### 接收媒体

Aleph 从所有支持的 Telegram 媒体类型中提取附件：

| 媒体类型 | MIME 类型 | 说明 |
|-----------|-----------|-------|
| 照片 | `image/jpeg` | 选择最大可用分辨率 |
| 文档 | 来自元数据 | 最大 50 MB 的通用文件 |
| 音频 | 来自元数据或 `audio/mpeg` | 带元数据的音乐文件 |
| 视频 | 来自元数据或 `video/mp4` | 带缩略图的视频文件 |
| 语音 | 来自元数据或 `audio/ogg` | Opus 编码的语音消息 |

媒体消息的标题被提取为消息文本。如果消息同时有标题和媒体，标题成为 `text` 字段。

### 发送媒体

出站附件根据 MIME 类型分发：

- `image/*` — 作为照片发送（`sendPhoto`）
- `audio/*` — 作为音频发送（`sendAudio`）
- `video/*` — 作为视频发送（`sendVideo`）
- 其他所有 — 作为文档发送（`sendDocument`）

附件可以提供为：

- **内存字节**（`data` 字段）
- **本地文件路径**（`path` 字段）
- **远程 URL**（`url` 字段）

## 内联键盘

Telegram 接口支持用于交互式提示的内联键盘按钮。审批系统使用此机制让用户直接在聊天中批准或拒绝工具执行：

```
Aleph wants to execute: shell_exec("ls -la")

[Allow Once] [Allow Always] [Deny]
```

当用户点击按钮时，回调查询通过 Gateway 路由回并由审批桥（`TelegramChannelApprovalCapability`）处理。按钮上的加载指示器通过 `answerCallbackQuery` 自动关闭。该桥是双向的：Discord 上的回复在同一流程中原地编辑原消息。

## 会话路由

每个 Telegram 对话获得唯一的会话密钥：

| 上下文 | 会话密钥 |
|---------|------------|
| 与用户 12345 的 DM | `agent:main:dm:12345` 或 `agent:main:telegram:dm:12345` |
| 群组 -100123 | `agent:main:telegram:group:-100123` |
| Forum topic | `agent:main:telegram:topic:{thread_id}` |

确切的格式取决于你的 `dm_scope` 设置（参见[接口概览](/docs/interfaces/overview)）。

## 消息格式

Aleph 使用 Telegram 的 **MarkdownV2** 解析模式发送消息。支持以下格式：

| 语法 | 结果 |
|--------|--------|
| `*bold*` | **bold** |
| `_italic_` | *italic* |
| `` `code` `` | `code` |
| ```` ```language\ncode``` ```` | 带语法高亮的代码块 |
| `[text](url)` | 超链接 |

<Callout type="warn">
MarkdownV2 需要转义特殊字符（`_`、`*`、`[`、`]`、`(`、`)`、`~`、`` ` ``、`>`、`#`、`+`、`-`、`=`、`|`、`{`、`}`、`.`、`!`）。Aleph 在格式化出站消息时自动处理此转义。
</Callout>

## 错误处理

Telegram 接口处理常见的失败场景：

| 错误 | 行为 |
|-------|----------|
| **无效的机器人令牌** | 启动时通过 `getMe` API 调用检测；频道进入 `Error` 状态 |
| **速率限制** | 遵守 Telegram 速率限制；ChannelRegistry 在 `RateLimited` 上重试（`SendRetryPolicy`，默认 2 次重试，绑定 `retry_after` 上限） |
| **网络故障** | 长轮询自动重新连接；Webhook 模式依赖 Telegram 的重试 |
| **用户不在白名单中** | 静默丢弃；若 `dm_policy = pairing`，路由签发配对码 |
| **空消息** | 跳过（无文本且无附件） |
| **服务消息** | 忽略（加入/离开通知、置顶消息等） |
| **每会话卡死** | `ErrorCooldown` 在异常状态的会话上短路输入与重试 |

## 验证

机器人令牌在两个阶段进行验证：

1. **格式检查**（配置加载）—— 令牌必须非空并包含冒号（格式：`<bot_id>:<hash>`）
2. **API 检查**（频道启动）—— 调用 `getMe` 验证令牌并检索机器人的用户名和 ID

如果任一检查失败，频道报告 `ConfigError` 或 `AuthFailed` 错误并且不开始轮询。

## 故障排除

| 问题 | 解决方案 |
|---------|----------|
| 机器人不响应 | 检查 `config.toml` 中频道是否启用，并确认路由收到了消息（在配对存储里查看发送者 id） |
| 机器人忽略群组消息 | 通过 BotFather 禁用隐私模式（`/setprivacy`）或确保机器人被提及 |
| 日志中 "User not in allowlist" | 将用户的数字 Telegram ID 添加到 `allow_from`，或在 Panel 中批准待处理的配对码 |
| "Failed to verify bot token" | 使用 `curl https://api.telegram.org/bot<TOKEN>/getMe` 验证你的令牌 |
| 消息延迟 | 减少 `polling_interval_secs` 或切换到 Webhook 模式 |
| 格式显示损坏 | Aleph 使用 MarkdownV2；检查特殊字符是否被双转义 |
