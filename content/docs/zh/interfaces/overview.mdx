Aleph 通过**接口**（也称为频道）与用户通信——可插拔的适配器，将消息平台桥接到 Gateway 的统一消息总线。单个 Aleph 实例可以同时为 Telegram、Discord、iMessage、WebChat、CLI 以及其余已支持的频道族提供服务，所有这些都共享同一个 Agent 大脑、记忆和工具生态系统。

## 架构

每个接口遵循相同的数据流：

```
平台 API ──> 接口适配器 ──> InboundMessage ──> ChannelRegistry
                                                  │
                                          InboundMessageRouter
                                       （单源：access / pairing /
                                        allowlist / session key /
                                        agent binding）
                                                  │
                                                Harness
                                                  │
平台 API <── 接口适配器 <── OutboundMessage <── 响应
```

`ChannelRegistry`（`src/gateway/channel_registry.rs`）管理所有活动接口的生命周期。启动时它读取频道配置，通过 `ChannelFactory` 实例化每个启用的接口，调用 `start()`，并对外暴露一个共享的 `broadcast::Receiver<InboundMessage>` 以及类型化的出站 `send` 路径。此后每条入站消息都汇入同一队列，每条出站回复也经由同一个适配器派发。

**InboundMessageRouter**（`src/gateway/inbound_router/`）是访问策略、配对、白名单强制、去重、群聊处理与会话密钥解析的**单一来源**。每个频道适配器把原始消息交给路由；适配器只做粗粒度预过滤（在到达路由前丢弃明显不应放行的流量）；路由是唯一签发配对码、决定谁能抵达 Agent 的地方。配对状态由单一的 `PairingStore`（`src/gateway/pairing_store.rs`）持久化。

## Channel Trait

所有接口都实现 `src/gateway/channel.rs:738` 处定义的 `Channel` trait，无论底层平台如何，都提供统一的 API：

```rust
#[async_trait]
pub trait Channel: Send + Sync {
    /// 频道元数据（id、name、type、status、capabilities）
    fn info(&self) -> &ChannelInfo;

    /// 共享的可变状态（status + 入站 broadcast sender/receiver）
    fn state(&self) -> &ChannelState;

    fn id(&self) -> &ChannelId { &self.info().id }
    fn channel_type(&self) -> &str { &self.info().channel_type }
    fn status(&self) -> ChannelStatus { self.state().status() }
    async fn health(&self) -> ChannelHealth { self.state().health().await }
    fn capabilities(&self) -> &ChannelCapabilities { &self.info().capabilities }

    /// 审批下发能力（默认 None；支持审批的频道 opt-in）
    fn approval_capability(&self) -> Option<Arc<dyn ChannelApprovalCapability>> { None }

    async fn get_pairing_data(&self) -> ChannelResult<PairingData> { Ok(PairingData::None) }
    async fn list_active_pairing_codes(&self) -> ChannelResult<Vec<(String, u64)>> { Ok(vec![]) }

    async fn start(&mut self) -> ChannelResult<()>;
    async fn stop(&mut self) -> ChannelResult<()>;
    async fn send(&self, message: OutboundMessage) -> ChannelResult<SendResult>;

    /// 订阅入站消息——每个订阅者拿到自己的 broadcast receiver
    fn inbound_subscribe(&self) -> broadcast::Receiver<InboundMessage> {
        self.state().inbound_subscribe()
    }

    async fn send_typing(&self, conversation_id: &ConversationId) -> ChannelResult<()>;
    async fn mark_read(&self, message_id: &MessageId) -> ChannelResult<()>;
    async fn react(&self, conversation_id: &ConversationId,
                   message_id: &MessageId, reaction: &str) -> ChannelResult<()>;
    async fn edit(&self, conversation_id: &ConversationId,
                  message_id: &MessageId, new_text: &str) -> ChannelResult<()>;
    async fn delete(&self, conversation_id: &ConversationId,
                    message_id: &MessageId) -> ChannelResult<()>;

    /// 列出 Agent 可寻址的对话（只读，仅路由元数据）
    async fn list_conversations(&self, query: &str, limit: usize)
        -> ChannelResult<ConversationPage>;

    fn native_stream_handler(&self) -> Option<Arc<dyn NativeStreamHandler>> { None }
}
```

每个接口还有一个 **ChannelFactory**，在运行时从 JSON 配置创建实例：

```rust
#[async_trait]
pub trait ChannelFactory: Send + Sync {
    fn channel_type(&self) -> &str;
    async fn create(&self, config: serde_json::Value) -> ChannelResult<Box<dyn Channel>>;
}
```

## 频道能力

并非每个平台都支持每个功能。每个频道声明一个 `ChannelCapabilities` 结构体（`src/gateway/channel.rs:384`），以便 Agent 调整其行为：

```rust
pub struct ChannelCapabilities {
    pub attachments: bool,
    pub images: bool,
    pub audio: bool,
    pub video: bool,
    pub reactions: bool,
    pub replies: bool,
    pub editing: bool,
    pub deletion: bool,
    pub typing_indicator: bool,
    pub read_receipts: bool,
    pub rich_text: bool,
    pub max_message_length: usize,    // 0 = 无限制
    pub max_attachment_size: u64,     // 0 = 无限制
    pub stream_protocol: StreamProtocol, // None | EditBased | Native
}
```

独立的 `StreamProtocol` 枚举区分「完成后再发送」（`None`）、「编辑同一条草稿消息以流式追加」（`EditBased`——Telegram、Discord）以及「原生支持流式」（`Native`——Teams）。

## InteractionManifest

除了原始能力之外，Aleph 还使用 **InteractionManifest** 系统通知 AI 当前频道可以做什么。每个频道属于一个 `InteractionParadigm`：

| 范式 | 频道 | 能力 |
|----------|----------|-------------|
| **CLI** | CLI | 富文本、代码高亮、流式传输 |
| **WebRich** | WebChat、桌面应用 | 完整交互式 UI、canvas、mermaid 图表、流式传输 |
| **Messaging** | Telegram、Discord、iMessage 等 | 富文本、内联图片 |
| **Background** | Cron 作业、webhooks | 仅静默回复 |
| **Embedded** | 最小 UI 上下文 | 无特殊能力 |

清单告诉 AI 它是否可以使用 Mermaid 图表、交互式按钮、canvas 绘图或流式传输——因此它会根据用户屏幕上实际渲染的内容定制其输出格式。

## 会话密钥解析

当消息到达任何接口时，Gateway 会解析一个 **SessionKey**，确定要加载哪个对话历史记录。会话密钥编码完整上下文：

| 会话类型 | 密钥格式 | 示例 |
|-------------|-----------|---------|
| **Main** | `agent:{id}:main` | `agent:main:main` |
| **DM (按对话方)** | `agent:{id}:dm:{peer}` | `agent:main:dm:user123` |
| **DM (按频道-对话方)** | `agent:{id}:{channel}:dm:{peer}` | `agent:main:telegram:dm:user123` |
| **群组** | `agent:{id}:{channel}:group:{peer}` | `agent:main:discord:group:guild456` |
| **任务** | `agent:{id}:{type}:{task}` | `agent:main:cron:daily-summary` |
| **临时** | `agent:{id}:ephemeral:{uuid}` | `agent:main:ephemeral:a1b2c3` |

**DmScope** 策略控制如何隔离直接消息：

- **`Main`** — 所有 DM 共享主会话（跨用户的对话合并）
- **`PerPeer`** — 每个用户获得自己的会话，跨频道共享（默认）
- **`PerChannelPeer`** — 每个频道上的每个用户获得单独的会话

<Callout type="info">
**身份链接**允许你跨频道映射同一个人。如果 Telegram 上的用户 `123` 和 Discord 上的用户 `456` 都是 "john"，他们的 DM 会话可以在 `agent:main:dm:john` 下统一。
</Callout>

## 路由绑定

你可以使用路由绑定将特定频道、用户或公会绑定到不同的 Agent。解析遵循优先级链：

1. **Peer** — 特定用户/聊天匹配（最高优先级）
2. **Guild** — Discord 公会或 Slack 工作区匹配
3. **Team** — 团队级匹配
4. **Account** — 特定账户匹配
5. **Channel** — 频道类型匹配（例如，所有 Telegram 到一个 Agent）
6. **Default** — 回退到默认 Agent

```toml
# 将所有 Telegram 消息路由到 "personal" Agent
[[bindings]]
agent_id = "personal"
[bindings.match_rule]
channel = "telegram"
account_id = "*"

# 将特定 Discord 公会路由到 "work" Agent
[[bindings]]
agent_id = "work"
[bindings.match_rule]
channel = "discord"
guild_id = "123456789"
```

## 功能编译

Aleph 默认编译所有频道适配器；频道通过配置（`config.toml`）启用，而非编译时功能开关。iMessage 的 *local* 传输由 `#[cfg(target_os = "macos")]` 门控——BlueBubbles 传输可在任何 OS 上运行，因此 `BlueBubblesChannel` 处处可用。

## 频道配置

所有频道都通过 Aleph 配置文件（`~/.aleph/config.toml`）进行配置。文件监视器检测到更改并在较短的间隔内热重载：

```toml
[channels.telegram]
enabled = true
token = "${TELEGRAM_BOT_TOKEN}"

[channels.discord]
enabled = true
token = "${DISCORD_BOT_TOKEN}"
allowed_guilds = [123456789]

[channels.imessage]
# Local（仅 macOS）：轮询 ~/Library/Messages/chat.db
# 和/或
# BlueBubbles（任意 OS）：REST + webhook 对接 BlueBubbles 服务器
enabled = true
db_path = "~/Library/Messages/chat.db"
poll_interval_ms = 1000
```

配置支持 `${ENV_VAR}` 扩展用于密钥，因此令牌永远不需要以明文存储。
