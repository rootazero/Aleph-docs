# 更新日志

Aleph 遵循 CalVer（`26.7.21` 这种格式）。每个月发布若干次，版本号与 `VERSION` 文件和 `alephcore` crate 一致。破坏性变更会在 release notes 中显著标记，但 1.0 之前 API 与架构仍可能演进。本页覆盖至 2026-11-28。

`VERSION` 在 2026-09-25 之后仍是 `26.9.1`——下面 2026-09-26 到 2026-11-28 的条目记录的是 `main` 分支上**已合入但尚未发版**的变更。

<Callout type="info">
  本页是从 Aleph 主仓库 `CHANGELOG.md` 与 git 历史派生的**文档视角**摘要：突出**用户可见**的变化（特性、CLI/RPC、配置、安全），并省略纯内部重构细节。完整记录请参阅 [Aleph `CHANGELOG.md`](https://github.com/rootazero/Aleph/blob/main/CHANGELOG.md)。
</Callout>

## 2026-11-28 — 作用域插件组合与 Panel RPC

- **作用域插件组合**（`c1a207dc9`）。全局和项目作用域可分别安装同 ID 的包。Claude Code、Pi 和 DeepSeek Harness 支持的声明由同一个插件管理器发布。见[插件包](./capabilities/plugin-package)。
- **Linux 配对 JSONL 输入**（`dc934f14c`、`92f0b080b`）。符合条件的会话经操作员批准后，可向固定 jq 检查器提交记录或发送 EOF。见[内置工具](./tools/builtin)。
- **Panel RPC 方法**。共享的 v1 清单涵盖模型选择、定址笔记变更、澄清和语音轮次。见[协议 v1](./gateway/protocol-v1)。

## 2026-11-26 — 记忆自我进化闭环收口

记忆侧把「反思 → 纠正 → 蒸馏」这条链补成了可验收的闭环：依赖缺失在尝试之前就报出来，反馈批次先校验再推进游标，继任笔记先发布并验证再退役旧笔记。

### 新增

- **依赖就绪状态先行**（`7bd692733`）——梦境运行在尝试之前就把缺失的依赖报给模型；缺依赖就失败关闭，并且不覆盖上一次运行的结果。
- **反馈批次的恢复与校验**（`41b38ac2b`）——推进游标之前，先恢复并校验已持久化的反馈批次。
- **继任笔记先发布再退役**（`66c82a1bd`）——公共写入器先校验后继的 Markdown / SQLite / FTS 状态，再退役原文。
- **校准与门禁记录**（`25ab346ce`、`9bac9d613`）——自我演化契约的校准报告与最终门禁结论。

### 变更

- **合并上游**（`7fb540b44`）与 **反思器分支**（`fbf1cfe53`）——两者都落在 `main` 上。

## 2026-11-24 — 桌面宿主与协议 v1 收口：双 Panel 渲染器、共享 TSX shell、一套 v1 方法集

桌面形态与线协议同时换代：Panel 拆成两套渲染器并共享一份 UI 逻辑层，Gateway 收敛出一套 v1 方法集，桌面 IPC 先落在只读 Unix 通道与分级启用的 Windows 命名管道上。

### 新增

- **Panel 双渲染器 + 共享 UI 逻辑层**（`shared/ui_logic/src/panel/`）——同一份面板逻辑产出三份资产：Leptos WASM（`interfaces/webchat/dist/`，经 `src/gateway/control_plane/assets.rs` 的 `rust_embed` 打包）、TSX Web 包（interfaces/panel/out-web/，经 `[gateway].panel_web_dir` 挂在 `/v1/panel/`）、TSX bundle（interfaces/panel/out-bundle/，经 `desktop/nsh-shell/build.rs` 的 `include_str!` 嵌入宿主）。
- **TSX 共享 shell**（`interfaces/panel/`）——布局、SDK 代际与 web 宿主；面板布局改为可持久化的稳定 ID。
- **协议 v1 方法集**（`src/gateway/`）——`health` / `sessions.list` / `panel.capabilities.snapshot` 三个方法，附带 `panel_routes` 与 CSP；Gateway 在 TLS 路由器上挂载原生 TSX Web 的 v1 ingress。
- **`system.hello` 的 per-user subject**（`src/gateway/`）——握手响应带一个按用户派生的 `subject`：HMAC-SHA256、域分隔 `aleph.panel.subject.v1\0`、取前 16 字节 hex。它**不是**身份凭据，只用于把同一用户的多个连接关联起来。
- **桌面 IPC**（`desktop/nsh-shell/`、`src/`）——只读 Unix IPC（opt-in）与 Windows 命名管道 IPC（分级启用）；客户端改走有界帧。
- **记忆图的共享读契约与星云只读面**（`5e1707f89`、`cd3ef045d`）——记忆图按统一契约对外只读，节点身份就是笔记路径；星云以只读 v1 面的形式落地。
- **NSH Panel 里的只读星云渲染**（`e8cc2e7b1`）——星云在共享 NSH Panel 内渲染，不引入第二套业务 UI。
- **Panel 偏好、主题令牌与命令规则**（`e795fca40`）——面板偏好与主题令牌收进共享 UI 逻辑层。
- **命令面板与可重绑快捷键**（`c3712ff8d`）——Panel 内提供可搜索的命令面板，快捷键可重新绑定。
- **固定双栏外壳与外观设置**（`10ff3bc39`）——面板外壳固定为两栏，并接上外观设置。

### 变更

- **频道冷声明**（`src/gateway/`）——声明式频道配置不再在启动时激活，只有显式 start 才把被禁用或被声明的频道拉起来（`9976b7840`）。
- **移除 severed 配置、链接与适配器线路**（`3df8e0401`）——审计发现的断线配置被删掉，不再留在配置面里当噪音。
- **面板文本大小在桌面与网页生效**（`779cd18c5`）——面板的字号设置同时作用于桌面端与网页端。
- **`live_events` 推送与 v1 端点上的 `chat.*`**（`e0972bd96`）——实时事件推送落到 v1 端点上。
- **带实时流的 TSX Chat 模块**（`1280a3647`）——Chat 模块在 TSX 侧实现并接到 v1。

## 2026-09-25 — Workflow 对标 round-4 (Budget · Determinism · Fan-in/out · Structured Output)

把 workflow 编排从「声明式 + 复用 dispatcher」进一步演化为「可预算、可静态守护、可 fan-in/out、可强制 schema」的复合体；不引入 vm/JS 运行时，不改 harness。

### 新增

- **WorkflowRunBudget 运行预算**（`src/workflow/budget.rs`）——`WorkflowRunBudget { total: Option<u64>, spent: AtomicU64 }` 提供 `remaining()` / `try_charged(cost)` / `snapshot()`；uncapped 走 `total=None` 旁路（不用 `u64::MAX` 假上限）；超额拒绝且不动 `spent`。`materialize` 入口读 `WorkflowDef::budget`。本轮只挂「挂在哪里」，`cost` 固定为 1，token/字符估算不在本轮。
- **Determinism 静态审计**（`src/workflow/determinism.rs`）——`audit_step_prompt(prompt) -> Vec<DeterminismFinding>` 手写逐字符扫描，识别 `{now}` / `{time}` / `{timestamp}` / `{uuid}` / `{guid}` / `{random}` / `{random:N}` / `{rand}` 运行时变量引用；双花括号 `{{name}}` 不在扫描范围（确定性字面替换）。save/import 时作为 advisory warn 跑一遍。
- **Parallel Step Group 并行步骤组**（`src/workflow/def.rs` + `src/workflow/compile.rs`）——`WorkflowStepDef.parallel_group: Option<String>` 字段；同组 sibling step 在 materialize 时共享 `[workflow_parallel_group, workflow_parallel_index, workflow_parallel_size]` 三元 metadata，index 取声明顺序。dispatcher 不新增并行运行时——Aleph 本就并行跑无依赖 step。
- **Collect Step 汇流步骤**（`src/workflow/collect.rs`）——`WorkflowStepKind::Collect` 变体 + `collect_from: Vec<String>` + `reduce: Option<CollectReduce>`；`CollectReduce::{Concat | JsonArray | First}`，未设 reduce 时 materialize 静默填 Concat；collect step 自己不发 agent run，fan-in 由 dispatcher 达成。
- **`fail_unanswered_clarify` 清理器**（`src/teams/dispatcher/schedule/reclaim.rs`）——`TeamDispatcher::fail_unanswered_clarify`（24h grace，默认禁）；纯函数谓词 `should_fail_unanswered_clarify` 守边界。

- **提供商故障转移在每次请求时克隆整段会话**并以非原子方式发布路由状态——约 2,000 行不可达的 provider 代码被删除。
- **扩展生命周期竞态**——并发 `reload` 现在在 load guard 下串行；格式错误的插件结果不再被掩盖为 `ServiceResult::ok`；`AuthorInfo` 解析使用最左分隔符。
- **集群节点键按字节切片**，CJK 节点名断裂——现在按 Unicode 归一化。
- **macOS 截屏与录音轨道**——屏幕录制通过 `setSourceRect` 裁剪到所请求区域（按物理像素而非点）；完成时验证产生了输出再报告成功；OCR、窗口捕获、媒体、输入、截屏轨道上的类型化 bridge 错误被保留而不是扁平化；`screen_record` 序列化错误会向上传播而不是变成 `null`。
- **Harness ratchet 收紧至当前 `CEILING`**（`src/harness/tests/budget.rs:795` 守）——通过移除 `DiminishingReturnsDetector` 硬停（R10 禁止循环内确定性完成判断）。卡住的运行受 `max_iterations` + 工具循环验证器 + 模型自身停止控制。代码是权威；本文档数字只是 `CEILING` 的副本。
- **会话与团队完整性**——`retire_from` 原子；关闭超时被上报；活跃团队名通过部分索引保证唯一；团队协议文本与工件内容大小加封顶；`sessions` 与 `tasks` 增加 presence opt-in、加哈希的 carryover 文件名、确定性的模板环境排序。
- **线缆请求 id 不再用 UUID**——换成原子计数器，从 `aleph-protocol` 移除该依赖；一个编译失败的自定义 regex 不会再把合法的 regex 一并丢弃。

## 26.7.18 — 自签名 TLS + 客户端 TOFU

远端访问发布：与 26.7.17 的进程内 gateway TLS 形成闭环。两端在中间相遇。

### 修复

## 26.7.7 — MoA 持续顾问 + 渐进式工具披露 + 真多会话并行

大型能力发布。头条是 **Mixture-of-Agents（MoA）持续顾问**——任何代理轮次现在可被一个顾问模型面板影子化，视图被聚合成回复。伴随：**渐进式工具披露**（per-turn token 节省，把非核心工具 schema 折叠到按需 `tool_search` 之后）；**真多会话并行**（运行闸门从 per-agent 移到 per-session）；**`[[wikilink]]` 笔记生命周期**（带重命名级联与来源）；**深化的记忆星图画布**；**叙述引领的聊天流**配 live-follow 工作区；以及在底层重建的**会话单源真值事件日志**。

### 新增

- **MoA 持续顾问**——新的虚拟 `MoaProvider` 把一轮 fan-out 到一个可配置的顾问模型面板（带每顾问超时、提示缓存断点、签名缓存），然后一个聚合器模型合成回复。预设完全通过对话由新的 `moa` 工具创作与切换（会话激活 + 预设 CRUD）、`/moa` 一次性命令（操作者门控）以及 Panel 可视化配置页。顾问 token 花费追踪在自己用量桶中，VESR 把聚合器记为执行模型，所以 MoA 永不污染主模型的核算。
- **渐进式工具披露 + `tool_search`**——非核心工具 schema 现在被折叠成只有 name + description（轻量 catalog），节省了大量 per-turn 工具 schema token；模型通过 `get_tool_schema` 按需拉回完整 schema。新的自包含 `tool_search` 元工具（BM25 ranker，无依赖）让模型发现延迟工具；MCP 工具可通过 `[tools] defer_mcp_tools` 被推入该延迟层级。
- **真多会话并行**——运行闸门从 per-agent 锁移到 per-session 的 `SessionRunRegistry`，所以一个代理可以在多个会话同时运行，而任意单会话保持互斥。一个 run-lifetime `ConcurrencyLimiter` 强制全局 + 每代理上限，从 `[execution]` 配置热重载；一个服务器权威的 running-set 广播驱动 CLI / TUI / Panel 上统一的 "running" 点与 run-slots 仪表。
- **`[[wikilink]]` 笔记生命周期**——笔记现在解析 `[[wikilinks]]`（带别名），通过策略链解析并记录来源（`resolved_by` / `status` / `label`），重命名级联（包括类型化关系），用 tombstone 删除语义与定向的入站回填。梦境守护进程物化未链接-提及的软边。
- **深化的记忆星图画布**——图视图现在按社区重心引力聚类，按近期度与置信度让节点变亮，按关系种类（语义 / 相关 / 共召回 / 关键词 vs. wikilink 骨架）给边上色，加入 pan（shift / middle-drag）到轨道相机。节点详情显示 backlinks 与路径面包屑。
- **叙述引领的聊天流 + live-follow 工作区**——转写现在读起来像叙述，运行中以紧凑的单行工具行（状态符号、实时用时），完成后 `✓N steps`。工作区窗格变成 live-follow 前台会话（带 pin）的工具详情查看器。
- **会话单源真值事件日志**——`session_events` 现在是规范日志；`MessageProjector` 把事件物化到 `messages` 表，启动时 `ProjectionReconciler` 回填转写，消息携带 `tool_call_id` / `tool_name` + `AssistantRunMeta` 戳。旧会话被回填并在锁定的 invariant 后读取。
- **Computer-use 语义交互**——新的 `set_value` / `ax_action` 可访问性动作，带无状态定位器评分的写入验证；`observe` 参数融合 act→observe（返回 post-state / 截图），恢复提示被附加到工具失败后让模型自纠正。
- **消息流汇编器**——单一 `MessageAssembler` reducer 现在拥有装配后的消息，在流排空时实时剥离内联 `<think>>` 块，并把流式与最终文本都通过同一个共享 sanitize 原子路由。
- **Live-热重载的执行上限**——`[execution]` run-cap 段现在是 Live：通过 arc-swap 全局信号量，改变 `max_runs_global` / `max_runs_per_agent` 不需要重启。

### 修复

- **会话侧栏显示原始 `<system-reminder>`**——per-turn 提醒（工作目录等）现在作为每轮 transient recall 上下文传递，而不是被前缀到持久化的用户消息。

- **沙箱 stdin / timeout 硬化**——命令沙箱中的 stdin EOF 处理与前台 timeout 钳制被加固。

- 等等——详见 CHANGELOG 26.7.7 段。

## 26.7.1 — 上下文"永不破"保证 + 真实上下文用量仪表

Harness 可靠性与抛光发布。头条是**上下文"永不破"保证**——代理循环现在总是压缩并继续，而不是在某轮中途切断。伴随**真实、抗重载的上下文用量仪表**、**登录自启在三种产品形态上落地**、以及聊天流中工具调用的扁平化、可折叠重设计。

### 新增

- **上下文"永不破"保证**——之前可能通过 `FinalReply` 提前结束的轮次（critical/strict 预算违规、反应式压缩重试耗尽、分会话失败软化）现在总是路由过 `compact_to_fit` 然后继续。加一个确定性的 `truncate_to_fit` 底作为最后手段——加固反对孤立的 `tool_result` 消息——所以一轮永远不会再中途默默停止。
- **真实 per-model 上下文用量仪表，抗重载**——聊天上下文用量百分比现在由核心侧计算（遵守任何 `context_window` 配置覆盖）并被持久化在助手消息本身上，所以它在标签切换与历史重载后还在而不是重置。新会话通过本地预算 dry-run（零 LLM 调用）显示 `≈N%` 估算，第一轮后自纠正为真实数字。
- **登录自启在三种产品形态上落地**——完整桌面 App 与 Lite Panel shell 都获得可工作的 "Launch at Login" 切换（Settings → General / 托盘菜单）；独立 `aleph-server` 获得新的 `service` 子命令加安装器默认，开箱即作为系统服务启动（launchd / systemd-user / Task Scheduler）。
- **扁平化、可折叠的聊天工具调用展示**——聊天流中的工具调用与结果渲染成紧凑的、单行变化的步骤条（完成后 `✓N steps`），溢出的部分用全详情侧面板代替，而不是嵌套 `<details>`/JSON-tree 部件。
- **`system.open_path` 桌面能力**——新的跨平台原语，用 OS 默认处理器（`open` / `xdg-open` / `start`）打开文件或 URL。
- **更广的运行时探测覆盖**——安装目录探测现在额外检查 Homebrew 的 `rustup` keg、MacPorts、asdf shims、Nix profile 路径（macOS/Linux），加上扩展的 Windows 搜索路径（`node` / `playwright-cli`）。

### 修复

- **Linux 上独立服务器自更新**——安装器现在把新 `aleph-server` 二进制下到临时文件并原子重命名到位；原地覆写在 Linux 上会因 `ETXTBSY` 失败。
- **完整桌面 App 中"登录自启"切换从未出现**——切换到 `tauri-plugin-autostart` 插件命令（带匹配的 capability grant），它们在任意 origin 上都能工作。
- **Updater 签名密钥轮换**——之前的 Tauri 更新签名密钥对无法使用，两个产品形态的应用内自动更新都坏了；新密钥对通过 CI 接入。
- 跨平台会话目录命名在文件后端的读路径上自愈，聊天侧栏的 async 读现在抵御 disposed signal，修复快速切会话时的偶发 panic / no-op。

## 26.6.29 — iMessage 通道 + iOS Panel + VESR 动态模型路由

大型多日发布。头条是全新的 **iMessage 通道（via BlueBubbles）**（让 Aleph 在任意 OS 上通过 iMessage 触达你）；**iOS Panel 长成真正的 iPhone + iPad 应用**（原生配对、iPad 多任务、TestFlight）；以及 **VESR 动态模型路由**——Aleph 现在从自己验证过的履历中学习哪个模型真正能干活，而不是写死的路由器。加分：一类**网页抓取 provider**、更丰富的**多代理团队 / 看板**表面，以及**在聊天还在跑的时候往里打字**。

### 新增

- **iMessage 通道（BlueBubbles）**——新的消息通道，在任意 OS 上通过 iMessage 触达你（BlueBubbles 传输，本机 macOS 发送被单独门控）。出站文本与附件、入站 webhook + catch-up 轮询（带 offset 对账与 GUID 去重）、群/聊天发送、reactions / typing / read-receipts（门控在 BlueBubbles 私有 API）。
- **iOS Panel 现在是真正的 iPhone + iPad 应用**——原生配对屏（shake-to-reconfigure、Keychain 支撑的连接存储、加载失败回退）；完整 iPad 支持（设备族、全屏、方向、Split View / Stage Manager 多任务、平板专属布局、触摸人体工学）；内部 **TestFlight** 分发。
- **VESR 动态模型路由**——替代确定性路由器，Aleph 记录每个完成运行的 outcome 并在运行开始时回忆一份 per-model 履历（k-NN over sqlite-vec），所以模型能看到哪些模型在此类工作上**实际**表现过。
- **网页抓取 provider 类别**——`crawl4ai` 与 `firecrawl` 现在是 UI 可配的一类抓取 provider（URL → markdown），vault 存储密钥，自动在失败时回退到内置抓取。
- **更丰富的多代理团队 / 看板**——看板抽屉现在驱动完整任务生命周期（approve / reject，加 waiting-review / paused / skipped 列，任务不再消失），实时子代理树（节点身份、实时事件、树 RPC），操作者可调的广播防风暴守卫，每任务执行超时覆盖。
- **聊天还在跑的时候往里打字**——队列中的消息渲染为流内 "ghost" 气泡，在下一轮边界通过 steering flush，或立即强制插入（Esc + ⚡）。宽布局与手机布局都可用。
- **粘性的单聊天 Todo / 计划面板**——输入框上方一个永远可见的计划部件；计划变更时，旧计划沉入聊天流作为一个胶囊。
- **真实 per-model 上下文用量仪表**——核心权威的占用与窗口（遵守任何 `context_window` 配置覆盖），跨标签持久化。
- **MCP 增强**——广播 sampling 能力、协商协议版本、接线 `max_failures`、加 `post_install` 字段、出厂 `zhipu-vision` 与 `unreal-engine` 预设。
- **工具改进**——`file_read` 现在支持图片（`image_read`），未变更的文件读取通过读缓存在轮次间去重。
- **Panel 中的灵魂原型选择器**，3D 记忆星图的视觉/性能一轮（per-node twinkle、曲贝塞尔边、突出链、bloom 复调、顶点着色器闲置漂移、隐藏时渲染跳过）。

### 修复

- **steering 中途时 "Model returned empty response"**——在工具调用与其结果之间注入消息不再产生非法消息序列；工具结果保持连续，所以 OpenAI 兼容代理不再默默返回空响应。
- **macOS 本地网络隐私**——守护进程现在嵌入稳定的 `CFBundleIdentifier` Info.plist 并在构建时重新签名，所以它出现在本地网络隐私列表中，自托管 SearXNG / Firecrawl 不再因 "Network error" 失败。
- **路由故障转移归属**——frozen model + provider 现在从模型指令而不是 `failover` 包装名归因，修复压缩的可用性/归属。
- `firecrawl` 永不被持久化为 `[fetch]` 后端（它是从 search 配置派生的）；网关在 token 轮换时关闭远程会话，保留环回。
