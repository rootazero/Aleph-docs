# Aleph Capability 与 NSH Panel 文档对齐设计

## 目标与依据

以 Aleph `main` 的 `1b959fdf46f592928aa3143b8dcf99798551391d` 为依据，让中英文读者从首页、概念导航和构建说明中理解当前架构。用户已于 2026-11-28 确认范围。

- 一切需要被 Agent、Runtime 或其他系统动态发现、调用、替换、订阅或管理的能力，都是 Capability。通过描述符、所有者、可见性、策略、租约和 provider 生命周期说明如何组合。以实际挂载路径为依据说明每类能力的支持程度。
- NSH 0.6.0 是桌面发布宿主。默认 NSH WebView 和浏览器使用 Gateway 提供的共享 Leptos/WASM Panel。macOS 上显式启用的 TSX AppView 是单独的开发路径。Tauri 专属构建、SDK、发布和桥接说明退出当前产品文档。

## 方案

- 原页逐条修正能保留现有页面地址，但会留下多份 Capability 入门及插件运行时说明。
- 用户确认采用概念合并与运行路径更新。新增 Capability 导览，以模型、信任与后端、槽位和插件包为详细参考。退役重复的能力系统和扩展系统页面，将现行内容分别迁入能力模型和插件宿主页，并为中英文旧入口设置重定向。保留有日期的变更记录。
- 以 TSX AppView 作为生产 Panel 编写文档需要生产切换的上游证据。当前默认启动和发布均依赖共享浏览器产物。

## 交付与验证

同步双语标题、导航、内部链接、术语和对外文档入口。补齐本轮发现的源码锚点、RPC 方法和发布状态漂移，尤其是已合入的 Shell Capability 范围。门禁基线继续为零。验收运行九道文档门和生产站点构建，并验证两种语言的旧入口和新入口。
